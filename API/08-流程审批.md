# 流程审批

Handler 是 `POST /AjaxServers/Common.ashx`，不是 `Flow.ashx`。页面脚本是 `Scripts/Page/IhgFlow.js`，历史记录在 `Scripts/JSCOMM/public.js` 的 `GetFlowHistory`。

发文流程的 `flow_type` 抓包值是 `CO`。页面结束流程时传 `CONST.FLOWTYPE.COUNSEL`，与这次抓包的 `CO` 是同一条流程。`flow_sub_type` 为空。

案件页上那张业务流程图不是这里的接口。配案、核稿、递交、发文各自走到哪，看 [12-案件流程图.md](12-案件流程图.md) 的 `GetCaseBusFlow`。

`GetFlowSubmit` 是提交流程，没有重新调用。其余三个是只读，已用一封已有发文核对响应字段。人员姓名、意见和备注没有写入本文。

## GetUrgencyList

缓急下拉。只有 `Call=GetUrgencyList` 和 `log_pagename=IhgFlow.aspx`。

响应：`UrgencyList` 数组，本次 3 条。

| 字段 | 类型 |
|---|---|
| urgency_id | GUID |
| urgency_code | 字符串，长度 2 |
| urgency_name | 字符串，长度 2 |
| seq | 整数 |

`ClientInfo.Result=false` 且 `Status=true`。页面用 `urgency_id` 作选项值，`urgency_name` 作文字。

## GetFlowInfo

读取当前流程节点。邮件页和结束流程前都会调。

| 参数 | 说明 |
|---|---|
| Call | `GetFlowInfo` |
| obj_id | 发文 `mail_id` |
| flow_type | `CO` |
| flow_sub_type | 空 |
| log_pagename | `mail.aspx` 或 `IhgFlow.aspx` |

响应顶层：`Result`、`NewHistoryGuid`、`ClientInfo`。

`NewHistoryGuid` 是一个新的 GUID 字符串。`Result` 是对象，不是数组。

| 字段 | 类型 |
|---|---|
| obj_id / flow_id / cur_node_id / create_user_id | GUID |
| flow_type | `CO` |
| flow_sub_type | 空字符串 |
| node_code | 字符串，本次长度 3 |
| node_name_zh_cn / node_name_en_us / node_name_ja_jp | 节点名 |
| status | 整数 |
| dept_id | 字符串。`base` 表示基础流程 |
| dept_full_name | 字符串 |
| is_skip / is_enabled | 布尔 |
| is_parallel / need_all_audit | 整数 |
| update_time / last_update_time | 日期，并带 `_dd`、`_mm`、`_ss` |
| cn_name / cur_user_id / urgency_id / user_list / reject_node_id / reject_user_id / reject_cn_name | 当前办理人、缓急、退回节点。本次有的为空 |

结束流程的页面脚本把 `Result` 当成这个对象，读取 `obj_id`、`status`、`flow_id`、`flow_type`、`flow_sub_type`、`cur_node_id`、`node_code`。

## GetFlowHistory

审核记录。

| 参数 | 说明 |
|---|---|
| Call | `GetFlowHistory` |
| obj_id | 发文 ID |
| log_pagename | `mail.aspx` |

响应：`Result` 数组、`flow_activity` 对象、`ClientInfo`。

`Result` 一行：

```text
history_id, obj_id, seq, node_id, node_code, next_node_code, flow_type,
node_name_zh_cn, node_name_en_us, node_name_ja_jp,
audit_user_id, audit_cn_name, audit_time, audit_time_dd, audit_time_mm, audit_time_ss,
audit_type_zh_cn, audit_type_en_us, audit_type_ja_jp,
remark, node_remark, flow_step_remark, score, allow_edit
```

`flow_activity` 是当前活动节点，14 个字段：

```text
obj_id, flow_type, node_id, node_code, node_name, status, allow_edit,
create_user_id, last_user, audit_user_id, audit_cn_name,
node_remark, now_remark, flow_step_remark
```

页面把 `Result` 最后一行当作当前活动，并用 `flow_activity.audit_user_id` 判断当前用户是否在办理人列表里。

## GetFlowSubmit

打开提交弹层时加载可选节点。`log_pagename=IhgFlow.aspx`。请求字段来自刚读到的 `GetFlowInfo.Result`，不是写死的 `dept_id=base`。2026-09-30 的抓包里 `status=-1`，`cur_node_id`、`node_code`、`cur_user_id` 都是空字符串。

请求字段：

```text
Call=GetFlowSubmit
obj_id
flow_id
flow_type=CO
flow_sub_type=
dept_id
dept_full_name
status
cur_node_id
cur_user_id
node_code
cn_name
is_skip
is_enabled
urgency_id
update_time
update_time_dd
update_time_mm
update_time_ss
log_pagename=IhgFlow.aspx
```

成功响应顶层是 `flow_type_name`、`ClientInfo`、`Result`。这次 `ClientInfo.Status=true`，`ClientInfo.Result=false`，节点仍在 `Result` 数组里。不要用 `ClientInfo.Result` 判断这份读取是否成功。

这次 `Result` 有 3 个节点：

| 顺序 | node_code | 办理人 | 其他 |
|---|---|---|---|
| seq 1，next 为 2 | `FIRST` | 空 | `allow_edit=true`，`is_parallel=0`，`need_all_audit=0`，`allow_skip` 为空字符串 |
| seq 2，next 为 3 | 空字符串 | `user_list_id` 与 `user_list_name` 用 `;` 对齐，这次有多名办理人 | `user_type` 为用户，`allow_edit=true`，`is_parallel=0`，`need_all_audit=0` |
| seq 3，next 为 0 | `END` | 空 | `allow_edit=false` |

节点上还有 `node_id`、`list_id`、`flow_id`、`node_name_zh_cn`、`node_name_en_us`、`node_name_ja_jp`、`user_list`。`user_list` 这次是字符串，不是对象数组。人员姓名不写入本文。

`GetApendNextNode` 用 `flow_id`、`cur_node_id`、`obj_id`、`list_id`。这次 `Result` 为 `null`，提交参数不使用它。

`GetPicProcessCount` 用下一节点的 `node_id` 和全部分号拼接的办理人 `user_id`。响应 `Result` 是 `{ user_id, count, cn_name }`。这次只用于页面显示待办数量，提交参数不使用它。

`GetUrgencyList` 这次有 3 档，`urgency_code` 依次是 `CM`、`UR`、`EU`，`seq` 为 1、2、3。提交用的是 `seq=1` 那一档。

`GetFlowLastStatus` 参数是 `obj_id`、`flow_type=CO`、`log_pagename=IhgFlow.aspx`。`status=-1` 时 `last_status` 为 `null`。

## EndEmailFlowd

邮件页「结束流程」。`mail.js` 的 `Mail.EndFlow`。先只读 `GetFlowInfo`，再用它的 `Result` 组参。`Mail.ashx`。这次抓包没有执行。

```text
Call=EndEmailFlowd
f_obj_id           Result.obj_id
f_cur_status       Result.status
f_status           固定 5000
f_allow_edit       固定 0
f_flow_id          Result.flow_id
f_flow_type        Result.flow_type
f_flow_sub_type    Result.flow_sub_type
f_cur_node_id      Result.cur_node_id
f_cur_node_code    Result.node_code
f_next_node_id     固定 5A0F9ABF-0816-4FBB-A682-212FDDBE5224
f_next_node_code   固定 END
f_audit_type_id    固定 submit
```

回调不读响应字段，只要回调被调用就关闭页面。不能把它当成审核通过或邮件已经发出。
