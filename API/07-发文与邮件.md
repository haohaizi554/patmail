# 发文与邮件

文件查询和期限监控在选定类型后都进入 `Forms/mail/mail.aspx`。邮件页的读取请求相同，创建发文的 Call 不同。

---

## MailCustomer

文件查询发文。来源：`HAR/选择发文类型并确定`、`HAR/跳转到发文`。

```http
POST /AjaxServers/Notice.ashx
```

页面：`FileSearchMail.aspx`。

| 参数 | 说明 |
|---|---|
| Call | 固定 `MailCustomer` |
| _file_ids | 文件 GUID，分号分隔。本次是 2 个 ID |
| _file_names | 文件名，分号分隔，段数与 `_file_ids` 相同 |
| mailtype | 发文类型 GUID |
| mailstyle | 本次为 `1`，页面默认是「同客户合并发文」 |
| log_pagename | `FileSearchMail.aspx` |

`FileSearch.js` 的成功条件是响应里有 `objid`。有值时打开 `Forms/mail/mail.aspx?objid=` 加上这个 GUID。响应 234 字节，正文未保存，这个写接口没有重新调用。

期限监控不调用这个 Call，而调用同 Handler 的 `LimitMailCustomer`，且不提交 `_file_names`。见 [09-期限监控.md](09-期限监控.md)。

---

## 邮件页读取

`HAR/跳转到发文` 与 `HAR/期限监控跳转发文页面` 的 `Mail.ashx` 读取序列一致。参数和列配置见 [09-期限监控.md](09-期限监控.md) 第 4 节。

## SaveMailInfo

保存邮件草稿。来源：`HAR/提交发文（要获取客户）`。期限监控这组 HAR 没有再次抓到它。

```http
POST /AjaxServers/Mail.ashx
```

`log_pagename=mail.aspx`。已出现的字段：

```text
Call=SaveMailInfo
mail_id
mail_type
customer_id
mailset_id
mail_to
mail_cc
mail_bcc
mail_subject
mail_body
is_zip
zip_pwd
renamezip
reply_date
proc_ids
express_id
message_id
subject_desc
mail_tags
finish_ctrl_proc
log_pagename
```

本次 `is_zip=0`，`mail_bcc` 为空。收件人、主题和正文未写入本文。

`mail.js` 的 `Mail.SaveMailInfo` 与上面的字段一致。请求里的压缩包重命名键是 `renamezip`，`GetMailInfo` 返回的对应键是 `rename_zip`。成功回调看的是 `ClientInfo.Status`，为真时提示保存成功，并再调 `SaveMailRalteCaseFile`。响应 187 字节，正文未保存，没有重新调用。
