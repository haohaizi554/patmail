# 客户要求（不发文）

2026-09-29 抓包 `HAR/客户要求获取`。32 个业务请求全部 `200`，Chrome 这次没有把响应正文写入 HAR，下面的响应键来自页面脚本，长度来自 HAR。

页面脚本：`Scripts/Page/Customer/customer.js`。客户列表走 `Scripts/JSCOMM/public.js` 的 `Ajax.LoadLayuiTable`。要求表和联系人表走 `Scripts/JSCOMM/Table.js` 的 `JClient.UI.Sheet`。

客户名称、客户编号和人员姓名没有写入本文。

这条链路在客户资料页读取**客户级**要求。不打开 `mail.aspx`，不调用 `MailCustomer` 或 `LimitMailCustomer`。案件级要求仍是 `PatentAction.ashx` 的 `GetDemandBuCaseid`，见 [09-期限监控.md](09-期限监控.md) 和 `patmail-extension/docs/case-demand-asset.md`。

## 调用顺序

| 步骤 | 页面 | 作用 |
|---|---|---|
| 1 | `Forms/customer/customerlist.aspx` | 按名称查出客户，行上有 `customer_id` |
| 2 | `forms/customer/Addcustomer.aspx?customer_id=` | 打开该客户。`log_pagename=Addcustomer.aspx` |
| 3 | 点击页签 `lidemand` | 才发出 `GetCustomerDemand` |

这次从客户页数据加载完到点击「客户要求」，间隔约 8 秒。页签回调是 `Customer.TabSelect`，`id=lidemand` 时调用 `Customer.GetCustomerDemand`。打开客户页本身不会拉要求表。

要读到要求，业务上只依赖第 1 步的 `customer_id` 和第 3 步的 `GetCustomerDemand`。中间那组初始化请求是页面自己带出来的。

## GetCustomerDemand

客户要求表。只认 `customer_id`。

```http
POST /AjaxServers/Customer.ashx
```

`JClient.UI.Sheet` 在 `Customer.GetCustomerDemand` 传入的 `Call`、`customer_id` 之外自动附上分页参数。`demandlist` 的主键属性是 `demand_id`。

| 参数 | 本次 | 说明 |
|---|---|---|
| Call | `GetCustomerDemand` | |
| customer_id | 客户 GUID | 空字符串时页面不发请求 |
| pageIndex | `1` | 从 1 开始 |
| pageSize | `10` | 表控件默认 |
| _PK | `demand_id` | |
| searchKey | 空字符串 | 表头搜索框 |
| colsel | 见下 | 当前可见列，分号包裹 |
| log_pagename | `Addcustomer.aspx` | |

```text
;sn;case_type;demand_type;file_name;demand_name;demand_desc;update_user;create_user;update_time;create_time;is_disabled;demand_id;
```

| 列 | 页面用途 |
|---|---|
| sn | 序号 |
| case_type | 案件类型显示名 |
| demand_type | 要求类型 |
| file_name | 附件名 |
| demand_name | 标题 |
| demand_desc | 描述。单元格用 `RenderDemandDetail` 去掉 HTML 标签后展示；点击后 `ShowDemandDetail` 对原文做 `HTMLDecode` 再铺开 |
| update_user / create_user | 更新人、创建人显示名 |
| update_time / create_time | 更新时间、创建时间 |
| is_disabled | 停用标记 |
| demand_id | 主键。行 `id` 和 `tr.data("row")` 都用它 |

`structMySheetData` 读顶层 `TableRows` 和 `TableRowsCount`。`TableRows == null` 时这一页不画行。行对象挂在 `tr.data("row")` 上，描述弹层读的就是这个对象里的 `demand_desc`，所以列表响应里要有描述原文，不必再打详情接口。

这次响应 4776 字节。同页只有 `ClientInfo` 的请求是 180–210 字节，这一页带回了表格数据。总条数和是否还有第 2 页，正文未保存，不能写。

`demand_desc` 在编辑页按 HTML 保存，读的时候要 `HTMLDecode`。列表单元格会再去掉标签，交给人看的原文以弹层那份为准。

和案件要求表的列不同。案件要求 `GetDemandBuCaseid` 的 `colsel` 只有 `demand_type`、`demand_name`、`demand_desc`。客户要求多了案件类型、附件、人员、时间和停用标记。
