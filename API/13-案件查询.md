# 案件查询

来源：桌面上的 `183.36.43.66.har`。44 条请求里，案件查询页是前 4 条，页面为 `ICSearch.aspx`。文号、案件名称和人员姓名没有写入本文。HAR 没有放进仓库。

期限监控 `GetLimitMonitorCaseList` 按还没结束的处理事项出数，事项结束后不再出现在那张表里。案件查询按案件出数。`is_proc=false` 时，事项是否结束不影响这条案子还在不在。查到 `case_id` 之后，处理事项停在哪个发文节点仍用 [12-案件流程图.md](12-案件流程图.md) 的 `GetCaseBusFlow`。

这次抓包的第一下查询已经带了我方文号，不是打开页面的空表。空白打开、查无此号、翻到第 2 页、模糊查询、`is_proc=true`、一个请求里塞多个文号，都没有出现在这份 HAR 里。

```http
POST /AjaxServers/{Handler}.ashx
Content-Type: application/x-www-form-urlencoded; charset=UTF-8
```

HTTP 200，`Content-Type: text/plain`。鉴权仍是浏览器会话，见 [00-通用约定.md](00-通用约定.md)。

## 4. 接着读处理事项的发文状态

`ICSearchList` 只回答案子在不在。事项名称在表格里，不在这张列表里。

1. 用我方文号调 `ICSearchList`，`is_proc=false`，`case_type` 用上面的专利类型。
2. 在 `TableRows` 里用去掉空白、忽略大小写之后的 `case_volume` 对上 `case_id`。对不上就是库里没有这个文号。
3. 用这个 `case_id` 调 `GetCaseBusFlow`，`log_pagename` 用 `CaseManage.aspx`。读法见 [12-案件流程图.md](12-案件流程图.md)。
4. 在 `ProcInfo` 里用 `ctrl_proc` 的显示名对处理事项，不要用 `proc_status`。同名事项有多条时，任意一条发文未结束就是已提交审核；没有未结束、但有已结束，是已经审核通过；对上了事项、却没有发文子流程，是还没提交审核。显示名一条都对不上，是没有这项处理事项，不能当成还没提交。

`GetProcList` 和 `ProcInfo.proc_status` 都不是发文节点。`node_code` 转成大写后是 `END` 才算这条发文结束，空字符串不是结束。
