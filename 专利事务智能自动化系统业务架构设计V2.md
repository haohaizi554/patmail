# 专利事务智能自动化系统 - 业务驱动架构设计文档

版本：V2.0

------------------------------------------------------------------------

# 1. 项目定位

本系统目标不是简单网页自动化，而是构建：

> 浏览器插件入口 + API 自动执行引擎 + 业务规则配置中心 +
> 自适应页面学习能力

解决传统人工操作：

-   登录系统
-   查询案件
-   筛选文件
-   根据客户规则生成通知
-   配置收件人/抄送人
-   提交流程
-   等待审核

全部由人工完成的问题。

最终目标：

    用户配置一次
            ↓
    系统学习业务规则
            ↓
    后续自动执行
            ↓
    人工只负责最终审核

# 3. 为什么采用 API First + DOM Fallback

系统面对的是老式 ASP.NET 系统：

特点：

-   页面逻辑复杂
-   接口隐藏
-   字段可能变化
-   前端JS动态生成

因此采用双通道。

``` mermaid
flowchart TD

A[业务数据]

A --> B[API接口]

A --> C[页面DOM]


B --> D[数据标准化]

C --> D


D --> E{数据校验}


E -->|一致| F[正常执行]

E -->|API缺失| G[DOM补充]

E -->|结构变化| H[重新学习]

H --> I[更新Schema]

I --> F
```
