# PatMail

专利发文辅助。在已登录的 EASY 页面上查询案件和期限，按工作流表格创建发文，并把信交给当前登录人审核。人工仍在原站完成审核；插件不结束流程，也不代点通过。

仓库里是方案、接口记录和 Chrome 插件。没有独立后端。安装、构建和发文操作见 [patmail-extension/README.md](patmail-extension/README.md)。

## 现在能做的事

工作台从浮窗「打开工作台」进入。左侧有首页、文件管理、期限监控、客户管理、发文映射、发文任务、发文记录、文件查询模板、邮件草稿和工作流。系统设置在头像菜单里。

发文任务是当前主路径：

1. 在工作流里准备 PCT 提醒或鹏城专案，选定发文类型。
2. 在发文任务传入 `.xlsx`。表格提供客户、处理事项、IPR、技术负责人和第一联系人。邮箱列不参与发信。
3. 期限监控只列出还没结束的事项。表格文号另外走案件查询，已经结束的事项也能对上。
4. 勾选还没提交审核的事项，点「提交到 EASY」。

同一客户、收件人和抄送都相同的事项合成一封。创建时把这些处理事项的内部编号用分号拼进一次 `LimitMailCustomer`，`mailstyle` 为 `1`。收件人按工作流规则从发文页联系人里对上邮箱后写入，再 `MailSubmit` 给当前登录人。原站预填的来文通知 `chenjch02@pcl.ac.cn` 在每次写入前去掉。

收件人规则：

| 工作流 | 收件人 | 抄送 |
|---|---|---|
| PCT 提醒 | 表格里的 IPR | 发文页商务 |
| 鹏城专案 | 技术负责人（去掉括号里的拼音） | 表格里的 IPR，以及发文页商务 |
| 工作流里写下的特例客户 | 第一发明人 | 表格里的 IPR |

进度在「提交到 EASY」弹窗里。每一行左边是时间，进度条右边是百分比。底部实时显示成功、失败、异常的件数；中途停掉时另计跳过。跑完后日志最后一行写出同样的统计。查询条件下面不再逐封粘贴「已提交」。

表格里的收件人或抄送对不上邮箱时，这一封不提交。回传后这些事项的审核状态标为「异常」，底色是浅橙。换表或换工作流会清掉这个标记。对不上包括：联系人里没有这个邮箱、对上多个邮箱、发文页没有商务邮箱、发明人没有可用邮箱。

写开关在系统设置，没存过时默认打开。扩展还没读完存储之前视为关闭。关掉后不会创建发文，也不会提交。

## 接口

服务是 ASP.NET WebForms，统一入口 `POST /AjaxServers/*.ashx`，动作由 `Call` 分发。站点是 `http://183.36.43.66:88`。鹏城客户资料在 `https://ip.pcl.ac.cn:81`。

和发文直接相关的调用：

| 动作 | 成功看什么 |
|---|---|
| `LimitMailCustomer` | `ClientInfo.Status=true`，并且有 `objid`。`Result=false` 仍可能已创建。`NeedConfirmFillAgency=true` 时停，不代为确认 |
| `SaveMailInfo` | `ClientInfo.Status=true` |
| `MailSubmit` | `ClientInfo.Result=true` 且 `Status` 不为 false。`finishdate` 为 false |
| `GetCaseBusFlow` / `ICSearchList` | 只读。用来判断事项停在哪，以及回传审核状态 |

`EndEmailFlowd` 不调用。下一节点若是结束、并行审核或需要全部审核，这一封不提交。创建或提交的响应无法确认时，不自动再创建、不自动再提交。

细节和尚未调用的接口见 [API/README.md](API/README.md)。

## 当前限制

- 审核状态的案件查询回传一次最多 40 件。超过的文号不会出现在这次回传请求里。
- 同一组合并后若对上了多种发文类型，整批勾选都不创建。
- 特例客户的计划抄送是 IPR。写入前仍要求商务邮箱出现在抄送里，因此这类信目前会停住，并让后面的信不再继续。
- 一封信的创建、写地址和提交走 30 秒通道。超时后页面会先收到失败，原站上的请求仍可能做完。提交账本在当前标签页，只留最近 500 个事项。
- 客户管理里另存的发文方式（一案一封、按第一联系人）不会改变发文任务这次的合并。发文任务固定按同客户、同收件人抄送合成一封。
