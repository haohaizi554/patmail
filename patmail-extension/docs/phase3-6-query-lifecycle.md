# Phase 3.6 查询运行

## 两个标识

`queryFingerprint` 是规范化查询条件的 SHA-256。分页、每页条数和排序不进入这个指纹。

`querySessionId` 是 Background 用 `crypto.randomUUID()` 签发的本次查询运行 ID。同一条件再点一次查询，指纹可以相同，运行 ID 必须不同。页面自己编造的 ID 如果对不上已签发的活动运行，不能获得可信来源。

## 同一次运行

用户开始查询时创建运行，并记录 `pageSize` 和 `sortFingerprint`。

随后的上一页、下一页和刷新当前页，必须带上这次签发的 `querySessionId`，并且满足：

- 相同查询指纹
- 相同账号、EASY 标签页和连接版本
- 相同每页条数和排序

改变每页条数时，不能把旧页拼进新布局。继续旧运行会被拒绝，需要重新开始一次查询。

## 页面更新

每一页保存自己的 `fileIds` 和该页文件快照。

重新读取某一页时，用新的文件集合替换该页。有效文件索引只保留仍被本次运行里至少一个有效页面引用的文件。

文件同时出现在两页时，第一页更新后它消失、第二页仍有它，来源只保留第二页。不会因为第一页的更新把第二页的引用一起删掉。

同一文件在不同页面上的名称、描述、客户或案件字段不一致时，保留冲突标记，不挑选后一次覆盖前一次。

## 不自动混合

`resolveSelectedFiles` 只读取选择上携带的 `querySessionId`。

不会在用户换成另一次查询后，从旧运行里按文件 ID 自动提升可信等级。

所选文件的运行 ID 不一致时，结果带 `MIXED_QUERY_SESSION`。任务级来源保持未完整可信。

旧运行在同布局重新开始后标为 `STALE`，不能再给新选择提供来源。
