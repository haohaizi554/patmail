# Phase 2.1 真实 Chrome 验收清单

自动化已用本地 Mock + Chromium 验证请求链路；下面的真实 EASY 账号/数据验收 **PENDING**，需在已授权的现场环境完成。过程中不要记录、复制或上传真实 Cookie、账号密码或完整用户模型。

1. 在 `patmail-extension/` 执行 `pnpm install`、`pnpm test`、`pnpm typecheck`、`pnpm build`、`pnpm test:e2e`。
2. 打开 `chrome://extensions`，启用开发者模式，选择「加载已解压的扩展程序」，指向 `patmail-extension/dist`。确认 Manifest V3 正常加载且无扩展错误。
3. 打开 `http://183.36.43.66:88`，使用本人获授权的账号在原网站正常登录。刷新页面，确认右侧仅有一个 PatMail 浮窗，原网站按钮和表单仍可用。
4. 在「文件查询」查看 EASY 登录状态，点击「重新检测」。确认真实 `GetUserModel` 返回后显示「已登录」；若显示「无法确认当前登录状态」，记录脱敏的响应字段名与现场响应结构差异，不要改成假成功。
5. 输入一个确认已有文件的我方文号并查询。确认浏览器网络面板请求仅为同源 `POST /AjaxServers/CaseInfo.ashx`、`Call=GetSearchFiles`，表单编码正确，未在代码/日志中出现 Cookie 值。
6. 核对文件名称、文件描述、我方文号、申请号、客户名称、官方发文日、文件状态；可选缺失字段应显示「暂无」，不能出现 `undefined` 或 `[object Object]`。
7. 以另一条有效条件测试分页「下一页」「上一页」和「刷新」；确认条件保留、结果页码正确、没有触发原网站的查询或提交按钮。
8. 用确定无结果的条件查询，确认显示「没有符合条件的文件」；清空所有条件再查，应提示「请输入查询条件」且不发全库请求。
9. 在原网站退出或让会话失效，再查询或点击「重新检测」；应显示失效/未登录并阻止后续查询。恢复登录后重新检测可继续使用。
10. 切到「页面扫描」，确认 L2 Scanner 仍能扫描且排除 PatMail 自身；测试浮窗拖动、收缩、展开、关闭与页面刷新后重新出现。
11. 在 EASY 首页和已使用的 `FileSearch.aspx` iframe 页面分别确认浮窗可见、查询不依赖 iframe 已打开、原站 jQuery/Layui/WebForms 行为正常。若现场配置与文档不同，记录配置差异再调整 `src/api/config.ts`。

现场验收记录建议只写日期、Chrome 版本、页面路径、成功/失败与脱敏错误码。真实请求体、用户模型、Cookie 和业务文件内容不进入仓库。
