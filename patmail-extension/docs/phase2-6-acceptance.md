# Phase 2.6 验收

日期：2026-09-26。

## 已做的验收

`pnpm test`：14 个文件，110 项通过。原有 Phase 1 至 Phase 2.5 测试保留。

`pnpm typecheck` 和 `pnpm build` 通过。

自动化覆盖了这些行为：

- 保存前展示差异；重读后差异变化则不保存。
- 同一运行实例里，一个指纹只进入一次 `MailCustomer`。
- 两个执行存储共享一块存储区时，不能保证只创建一次。
- 指纹按当前选择、规则版本、用户和站点重算。
- 文件关联未核验时不读取流程。
- `UNKNOWN` 不自动重试。
- `GetFlowInfo`、`GetFlowHistory`、`GetUrgencyList`、`GetFlowSubmit` 的解析，以及空流程、无效响应、登录失效、502 和 503。
- 历史节点和当前活动节点分开。
- 多个下一节点不自动取第一个。
- 当前用户在或不在候选列表、同名审核人、只有姓名没有 GUID。
- 并行和全部审核不能组成可提交参数。
- Mock 参数里的 `mail_id`、`flow_id`、下一节点和审核人。
- 版本冲突、未知响应、重复提交。
- 生产门禁下 `requestSent` 保持 false。

## 没有做的真实环境验收

本轮没有登录 EASY，没有打开已有发文，也没有把 PatMail 的流程模型和原网站页面逐项对照。下面各项都还没在真实环境勾选：

1. 读取 `GetFlowInfo`。
2. 读取 `GetFlowHistory`。
3. 读取 `GetUrgencyList`。
4. 读取可选节点。
5. 核对当前办理人和当前用户 GUID。
6. 核对当前用户是否在候选审核人里。
7. 对照原网站流程界面。

写接口没有拿正式发文试请求。`FlowSubmit` 和 `EndEmailFlowd` 的响应正文仍然缺失，生产写开关保持关闭。

浮窗没有在真实 EASY 页面里点击。浏览器工具打不开目标站点的已登录邮件页，所以界面只做到了类型检查、构建和组件接线。

## 剩余风险

- 跨标签页的 `chrome.storage` 写入不是原子操作。同实例互斥盖不住这个窗口，所以真实创建和真实流程提交继续禁用。
- `GetFlowSubmit` 的响应正文未保存。面板上的下一节点在真实环境里还不能当作已核对数据。
- `user_list` 的分隔格式未确认。除了 Mock 数组和单个 GUID 加姓名，其他格式不会自动选人。
- `FlowSubmit`、`EndEmailFlowd` 和审核写接口都没有已核对响应。
- 发文自定义 handler 的地址没有确认，不会改道调用。
