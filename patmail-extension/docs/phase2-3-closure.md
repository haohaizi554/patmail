# Phase 2.3 遗留问题收口

日期：2026-09-24。以下是 Phase 2.4 开始前要求收口的项目。代码和单测已处理；真实 EASY 核对仍按 [phase2-4-acceptance.md](phase2-4-acceptance.md) 保持 PENDING。

| 遗留项 | 状态 | 说明 |
|---|---|---|
| 文件描述只展示根和第一级 | 已修复 | `FileTypeNodeRow` 按 `childIds` 递归。节点 ID 不变。默认折叠。搜索、多选和已选回显保留。上层 trail 含当前 ID 时停止展开 |
| 手工查询和历史模板的描述显示不一致 | 已修复 | 两处都调用 `resolveFileDescriptionDisplay`。历史显示文本不能把未解析 ID 标成已解析 |
| 字典缓存失效后的旧请求 | 已修复 | 每个缓存键有世代。失效、强制刷新和案件类型切换会增加世代。旧请求返回后不能写回。同一世代的并发请求仍合并 |
| 无用户 ID 时配置跨账号 | 发文配置已隔离 | 查询模板仍可能写到 `unscoped`。发文规则只有 GUID 用户才写入 `patmail.mail.v1`。没有 GUID 时只保存在当前页面内存，界面写明归属，切换身份后不读取上一份 |
| 真实字典、文件描述树、历史模板 | 未现场验证 | 继续 PENDING。单测和 mock 不代替现场通过 |

Phase 2.2 的模板切换竞态、查询范围和损坏配置只读仍保持 Phase 2.3 已收口的状态。历史模板的真实环境同样继续 PENDING。
