# Phase 2.9 报告

日期：2026-09-26。开发停在现场验收工具、证据库和受控测试写协议。没有进入生产自动发文。

## 1. 用户命名空间

`AutomationPanel` 不再使用 `"session"`。空用户和非 GUID 只能生成内存计划，界面说明身份尚未确认，计划不会持久化，也不能执行。用户 A 的任务不会出现在用户 B 的列表里。

## 2. 任务快照

`structuredClone` 复制文件、客户绑定、规则、收件人、签名、标题和正文。之后修改界面对象不会改变已生成的任务。客户身份快照包含 Profile、名称、EASY GUID、绑定来源和确认状态。EASY GUID 变化会使任务 `STALE`。

## 3. 指纹排序

相等的主键比较结果是 0，并继续比较次级键。同一组映射颠倒传入顺序后摘要不变。收件人和抄送的数组顺序保留。

## 4. 租约

完整生命周期由 Background 处理。未发送的租约在重启后释放。已发送的变为 `UNKNOWN`。`markSent` 失败时测试写不会调用 fetch。版本过期的消息被拒绝。

## 5. 存储

任务和证据使用扩展上下文的 IndexedDB。迁移在同一次 readwrite 事务中完成。并发测试里，旧任务迁移和新任务保存之后两条都还在。

## 6. 只读验收

Runner 拒绝写接口和 Mock。502、登录失效和字段不一致记为失败。本环境现场结果是 PENDING。

## 7. 证据与 HAR

证据等级不能由 Mock 或静态 `responseCaptured` 提升。验证器在真实成功条件确认前保持未知。HAR 导入会去掉 Cookie、Authorization、Set-Cookie、正文和邮箱，并忽略其他 Origin 和未知 Call。

## 8. 测试写

默认白名单为空。没有现场 PASS、没有证据、任务过期或用户未确认时都是 `BLOCKED`。未知响应不自动重试。`PRODUCTION_WRITE` 不是可进入的模式。
