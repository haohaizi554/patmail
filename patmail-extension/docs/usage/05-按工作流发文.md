# 按工作流发文（PCT 提醒）

这是插件的核心页面。从上到下分四块：基本选择、开关行、核对结果、期限表。

## 基本选择

| 控件 | 作用 |
|---|---|
| 工作流 | 选一条工作流。内置「PCT提醒」和「文件管理」，也可以选自己搭的 |
| 发件人 | 选发件邮箱。默认跟工作流走，手动换过就按你选的 |
| 表格 | 上传 .xlsx。支持「提醒申请PCT」「PCT进国家」多张表一起读，读多少行会在提示里报出来 |

表格要求带「我方文号」「处理事项」两列，客户名称、第一客户联系人、IPR、邮箱、技术负责人有就用。进国家表有客户文号用贵方案号发文类型，没有就用我方案号。

## 顺延补人（补）

表格里同一客户只写第一行联系人是常见写法，插件自动往下补：

- 默认（整块）：同一客户的行连成整块时，第一行之后的空行沿用第一行，页面标「（补）」；中间隔了别的客户就断开，断开后再出现的新块只认新块自己的第一行。
- 「同客户隔行也顺延补上」勾上后：同一客户不管中间隔了多少别的客户，空行都沿用该客户最近一行。
- 这一档只在核对前可改；开始核对或表格里已有仲裁结果后锁死，避免和写回的结论冲突。

联系人、IPR、技术负责人三列都按这个口径补。

## 开关行（四个）

| 开关 | 默认 | 作用 | 什么时候能改 |
|---|---|---|---|
| 核对完状态之后自动开始仲裁（如果有缺失） | 开 | 整表核对一结束就自动把空着的行交给仲裁，不用手点 | 随时 |
| 已发文未管制的行允许发文 | 开 | 状态为「已发文，事项未管制完成日」的行允许勾选提交；提交时先弹警示框逐行列出，要你确认「核对过，继续提交」才能发。去掉勾选后这类行不能勾、不进仲裁 | 核对中、仲裁中锁定；都结束后到发文阶段恢复 |
| 没要求时仲裁只写技术联系人 | 关 | 勾上：客户要求没写发给谁时，仲裁把著录项目里的技术联系人写成收件人。不勾：这类行一律拿不准留空，交给「全选联系人」兜底。两种口径下，客户要求明确写了发给谁的行都照要求写 | 只在核对前，核对一开始就锁 |
| 同客户隔行也顺延补上 | 关 | 见上一节 | 只在核对前，核对一开始就锁 |

四个开关都记在本地，下次打开保持原样。锁定的开关半透明，要改就重新读一次表格。

## 核对

传完表格自动开始：按我方文号（对不上再补查客户文号）去 EASY 查案件和发文流程，把每行的「流程状态」填出来，顺带暂存客户要求和著录项目给仲裁用。核对中不能勾选。

流程状态的含义：

| 状态 | 含义 |
|---|---|
| 还没提交审核 | 还没有发文流程，可以提交 |
| 已提交审核 | 有发文流程没走完，待审核中，不能再发 |
| 已经审核通过 | 发文流程已结束 |
| 不用发 | 这项事项已完成，不用再发 |
| 已发文，事项未管制完成日 | 发文都发完了，只是完成日没写，默认允许再发但要弹警示 |
| 库里没有 | EASY 里查不到这个文号 |
| 没查成 | 这次没查到，可以重查 |
| 异常 | 多条记录对不上，要人工看 |

## 仲裁

核对结束后，IPR 还空着的行可以交给 AI 仲裁：

| 按钮 | 作用 |
|---|---|
| 交给助手仲裁空着的收件人和抄送（分 N 批） | 把空行按客户分批交给本地模型。只有核对结束后能点 |
| 导出核对表 | 核对完导出 xlsx，原表基础上加状态列 |
| 仲裁结果 N | 打开结果板，看每行裁了谁、依据是什么 |

仲裁规则（当前口径会写进批次说明里）：

- 收件人只在 IPR（技术联系人）、发明人、客户联系人三种身份里选。
- 客户要求明确写了发给谁、抄送谁，就按要求写，任意组合；点名了技术联系人也要照写。
- 没勾「没要求时只写技术联系人」时，没要求写发给谁的行一律拿不准留空，之后由「全选联系人」兜底。
- 商务、登录人、密送由系统在提交时默认追加，仲裁写了也会被丢掉。
- 写回的行标「（仲）」，拿不准的不写。

## 期限表与提交

核对结果落在下面这张期限表里，按钮从左到右：

| 按钮 | 作用 |
|---|---|
| 查询表单（模板 + 各条件） | 也可以不传表格直接按条件查期限，或套用查询模板 |
| 全选本页 N | 勾上当前页所有能勾的行 |
| 全选所有 N | 跨页全选 |
| 全选所有（非补非仲）N | 只勾既没标（补）也没标（仲）的行 |
| 确认勾选 N | 把当前勾选记下来，作为提交范围 |
| 取消勾选 | 去掉当前勾着的行，不改已经确认的提交范围 |
| 提交到 EASY | 唯一的提交按钮，见下面 |
| 上一页 / 下一页 | 翻页 |

「提交到 EASY」一个按钮管两类行（优先仲裁、全选兜底）：

- 有收件人名字的行（仲裁写回的（仲）、顺延补上的（补）、原表就有的）：按写回的收件人和抄送创建发文。
- 还空着的行：按那封发文规则里「客户联系人」一组的人写收件人（等价于在 EASY 发文页把勾选框全勾上），业务人员进抄送，邮箱无效的人跳过。
- 同一客户里收件人相同的几件会合成一封信；「已发文，事项未管制完成日」的行在提交前弹居中警示框，逐行列出文号、事项、客户。

提交过程在进度浮窗里看：进度条、每封信的日志、成功/失败/异常/跳过统计。发出去的行会自动取消勾选并不再参与下一次提交。
