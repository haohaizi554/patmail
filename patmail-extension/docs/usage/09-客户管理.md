# 客户管理

维护客户档案和这位客户发文要用的默认配置。

## 列表操作

| 按钮 | 作用 |
|---|---|
| 联系人 | 打开这位客户的联系人名单 |
| 查询 | 打开客户的查询条件（文件查询或期限监控二选一） |
| 备注 | 写一句备注 |
| 编辑 | 改客户资料 |
| 删除 | 删除客户配置 |

## 编辑表单

| 控件 | 作用 |
|---|---|
| 重新读取（客户名单 / 审核人 / 发件邮箱 / 发文类型） | 从 EASY 重新拉对应名单 |
| 使用默认 | 发文方式、审核人、发件邮箱直接套默认值 |
| 发文方式 | 这位客户按哪种方式合并发文 |
| 审核人 | 提交给谁审核 |
| 发件邮箱 | 默认发件邮箱 |
| 发文类型 | 这位客户常用的发文类型 |
| 客户要求 | 读取 EASY 客户页的要求原文，仲裁时用作材料 |
| 备注行 | 同一客户有多条配置时写一句分辨 |

保存（继续保存）/ 另存一套 / 取消。

## 中小客户的名单来源

中小客户模式下，客户名单不走原站接口（三万多家，响应要二三十分钟），改用打包进扩展的数据库快照：

- 快照来自备份数据库的客户表（编号 + 名称），构建时打进扩展；「重新读取客户」只会重读这份文件，不会去拉接口。
- 名单量大时下拉只显示前 100 条，以输入关键词搜索为主，底部会提示还有多少条没显示。
- 名单要更新时有两种方式：设了 `DB_PWD` 环境变量再跑 start.py，每次启动都会自动拉最新名单；或单独运行 patmail-extension/scripts/pull-sme-customers.py 后重新构建。没设 `DB_PWD` 或拉取失败时，沿用上一次的快照文件。
