# Phase 2.4 交付报告

日期：2026-09-24。本阶段在现有插件上完成发文规则和本地草稿预览后停止。没有开始 Phase 2.5。

## 已实现

- 文件描述树改为递归行，保留原始 ID，可展开、搜索、多选和回显。环节点停止继续展开。默认不展开全部。
- `resolveFileDescriptionDisplay` 同时用于手工查询和历史模板。未解析 ID 不会被历史显示文本标成已解析。
- 字典缓存使用世代。失效后的旧请求不能写回缓存。同一世代的并发请求仍合并。
- 发文配置独立存储。有用户 GUID 才写入 `chrome.storage.local`。没有 GUID 时只留在本次页面，并在界面标明归属。
- 查询结果可单选、当前页全选、查看、清空。选择键是文件 ID，翻页不丢失。
- 客户发文方式、文件描述到发文类型的映射、收件人和抄送、当前操作员签名、标题规则、正文补充。
- 只读 `LoadMailType`。形状不符时失败，不生成虚构 GUID。
- 同客户同描述合并，或单个来文拆分。跨客户、不同描述、未知客户、空描述、重复文件都不会合成一封有效草稿。
- 本地草稿预览和校验。规则变更后需要重新生成。预览写明这是 PatMail 本地结果。
- 没有发送按钮，也没有发文写接口。

## 当前限制

- 查询模板在没有用户 GUID 时仍可能使用 `unscoped`。发文规则不会使用这个范围。
- 标题数量注入的锚点在界面里固定为「关于」，是否注入、以及没有锚点时的策略由配置决定。
- 发文类型树只用于选择 GUID，不在本阶段做层级发文。
- 预览不能发送，也不能在 EASY 落成草稿。
