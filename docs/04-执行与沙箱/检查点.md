# 检查点

Lobster 把多步工具管道收成一次确定的工具调用。有副作用的步骤停在批准或输入门上，返回恢复令牌。批准之后从停住的地方继续，不把前面的步骤再跑一遍。检查点属于这个运行器，不是另一份编排登记处。语法小，超时、输出上限、沙箱和允许名单由运行时执行，不由每段脚本自己记得。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 编排 | Lobster：管道是数据。一次调用返回整段结果或一个恢复令牌 | 委派和 cron 是多次模型回合。看板是任务队列 | Agent 工具。父回合等摘要 |
| 批准 | 发送、张贴、删除一类副作用停住，直到显式批准 | 工具批准在执行前。中间件先改参数 | `canUseTool` 允许、询问或拒绝 |
| 恢复 | 令牌接着跑。前面的步骤不重放 | 后台委派不跨进程。回绕是剪历史，不是从管道中段继续 | 侧链还在就可以再读 |
| 和脚本 | 每步仍可调 CLI。更丰富的写法可以生成 `.lobster` 文件 | 代码执行是内核，不是带恢复令牌的管道 | 无这套 DSL |

## OpenClaw

没有 Lobster 时，多步工作是模型一轮轮调工具，人在中间说下一步。Lobster 把编排放进有类型的运行时。一次调用可以返回整段管道的结构化结果。需要批准时状态是 `needs_approval`，带提示、条目和 `resumeToken`。再用这个令牌恢复。

它是受约束的小语法，不是通用脚本。批准和恢复是耐久的内建原语。管道是数据，便于记日志、做差异、重放和审阅。语法小，校验才现实。超时、输出上限、沙箱检查和允许名单由运行时强制。单步仍然可以调用任意 CLI 或脚本。想用更富的编写语言时，用别的工具生成 `.lobster` 文件。

这和蜂群不同。蜂群是代码模式里的 JavaScript，扇出很多收集者，脚本自己取结果。Lobster 是一条管道上的门。这也和 `/goal` 不同。目标是同一条会话里的循环，由判断模型说完成、继续或堵住。Lobster 的门在运行器里，不靠模型记得停下来问。

转向和批准仍是 Gateway 的。Lobster 的恢复令牌不绕过工具策略，也不把已经拒绝的副作用变成已经执行。

## Hermes

副作用工具走批准。参数在批准前可以被中间件改写。没有「一次工具调用跑完整段管道、停在令牌上、再从不重放的前缀继续」。要跨重启的重复工作用 cron。要多人协作的队列用看板。委派的孩子给出摘要，父回合继续。回绕剪的是已存转录，并且要当场确认。它不恢复一条停在中段的管道。

## Claude Code

每一步工具调用单独过允许、询问或拒绝。拒绝可以停整轮。停止钩子还可以要求再跑。没有恢复令牌把已经成功的前缀跳过。计划模式是会话内的写限制，不是管道数据。
