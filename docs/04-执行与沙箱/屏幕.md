# 屏幕

无头 Linux 上，每个机器人有自己的 Xfce 屏幕。电脑使用和有头浏览器在这块屏幕上动作，画面流进桌面应用。人可以在登录、二次验证、验证码或付款时接手，再把控制交还。关掉笔记本，屏幕仍在网关主机上。终端若在沙箱里，屏幕也在那个沙箱里，和 shell 在一起。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 有头桌面 | 节点上的系统。没有按 profile 一块、流回应用的 Xfce | 每个 profile 一块屏幕、一份浏览器配置和自己的 cookie | 无 |
| 后台输入 | 节点命令和浏览器标签 | 无障碍树的电脑使用不移动系统光标。有头屏幕是另一块给人看的表面 | 编辑器 |
| 边界 | 沙箱和工具策略 | 屏幕不是安全边界。同一操作系统用户上的进程够得着套接字。租约只挡住工具 | 工作区权限 |
| 安装 | 无这套静默安装合同 | 不在更新时偷偷装 VNC。缺了由人在主机上装 | 无 |

## Hermes

网关主机是 Linux 服务器、云虚拟机或 Hermes Cloud 时才提供这块屏幕。macOS 和 Windows 主机已经有真实显示器，不提供这块窗格。TigerVNC 的 `Xvnc` 和 Xfce 组件要在主机上。`hermes update` 和新安装不替机器装它们。缺了时，桌面的屏幕窗格显示在主机上安装。一次点击在网关主机上跑包管理器，sudo 口令在遮罩卡片里送到那台主机，不保存。Hermes 自己以 root 跑时（容器里常见），安装直接跑包管理器，没有 sudo，也没有口令卡片。不是 root 且主机没有 `sudo` 时，窗格和 CLI 打印要在主机上跑的命令。官方镜像里网关是无特权用户且没有 `sudo`，窗格给出 `apt-get` 那一行，由操作者以 root 在容器里执行一次。

每个 Hermes profile 有自己的屏幕、浏览器配置和 cookie。屏幕是工作面。这些机器人共享主机的用户、文件和网络。RFB 套接字、X 显示、浏览器配置和控制租约文件都属于网关的操作系统用户。同一用户下的另一个机器人，以及这个机器人自己的 `terminal`，都可以直接够到它们，绕过窗格和租约。租约是 `computer_use` 和浏览器工具上的工具级围栏。Chromium 的 DevTools 端口在环回上，主机上任何本地用户都够得着，Chromium 没有按用户限制它。每个机器人一个操作系统用户不在这块屏幕的范围内。主机上有不可信的本地用户时，把机器人放到不同的主机。

WebSocket 桥最多把租约决定缓存 250 毫秒，再读租约文件。另一个进程做的接手在这个窗口内生效。无论窗口多长，机器人的工具结果都会被租约世代作废。观看者的 `display_ticket` 单次使用、30 秒，放在 URL 查询里，因为 noVNC 不能协商 WebSocket 子协议。反代的访问日志可能记下已经用过的票。

终端后端是 docker、ssh 或 singularity 时，屏幕在沙箱里面，电脑使用和浏览器不越出那条边界。

后台的电脑使用走无障碍树和合成输入，不把系统光标拽走。有头屏幕是给人看着动手、再交还的那一块。两块都在同一台网关主机上时，仍共享那个操作系统用户。

## OpenClaw

配对的节点在那台设备上执行。浏览器是管理过的标签。权限模式和执行批准仍在。没有「每个 agent 一块 Xfce、流回控制界面、登录时接手再交还」这一份租约。

## Claude Code

没有远端有头桌面，也没有 30 秒的观看票。人在本机编辑器里操作。
