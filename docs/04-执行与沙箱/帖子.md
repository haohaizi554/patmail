# 帖子

搜 X 是只读的。结果带来源引用，不能当成已经发帖、点赞或改过账号状态的证据。要改状态，用会打到 X API 的那条路，并用它的返回确认。一般网页仍走网页搜索和抓取。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 只读搜索 | `x_search` 始终走 xAI Responses | 同一工具。SuperGrok 登录或 `XAI_API_KEY`。服务端由 Grok 搜并带回引用 | 无专门的 X 工具 |
| 改状态 | 不在这条搜索里 | `xurl` 技能做发帖、回复、点赞、私信和原始接口 | 无 |
| 证据 | 搜索不是浏览器，也不是已登录的写操作 | 搜索答案从不证明写发生了。写要看 `xurl` 或 API 的返回 | 工具结果是当时的输出 |
| 和网页 | 讨论和表态用 X 搜索。普通页面用抓取 | 同样分开。抓取不是标签页 | `WebSearch` 不是 X |

## Hermes

`x_search` 打到 xAI 的 Responses 接口。Grok 在服务端搜索，返回带原帖引用的综合结果。要用它看当前的讨论、反应和主张。普通网页继续用 `web_search` 和 `web_extract`。

`xurl` 技能做精确的、带登录的 API：发帖、回复、读、点赞、私信、时间线、提及、上传媒体和原始 v2。不要用它去做 Grok 那种综合公开研究，如果 `x_search` 可用而且不需要登录账号的上下文。反过来，不要用 `x_search` 去发帖或证明账号状态变了。

混合时，先用搜索找到公开帖子，目标清楚后再用 `xurl read` 或精确命令。任何改变状态的动作，必须由 `xurl` 的输出或 X API 的响应确认。搜索给出的答案不是写已经发生的证据。

钥匙是 xAI 的，不是把 X 的口令交给模型。站点登录库若另有保存，仍按源站注入，模型看不见口令。搜索结果是外部正文，不该自动写进每条会话都加载的记忆。

## OpenClaw

`x_search` 同样始终走 xAI Responses，并且不是浏览器自动化。选定搜索提供商之后，没被选中的钥匙是未激活表面。网络来源的工具结果把这一轮剩余的助手输出标成不可信。下一条用户消息才清除污点。

## Claude Code

没有分开的只读 X 搜索和已登录写接口。`WebSearch` 的结果是工具输出，受字符预算。它同样不能当成某个账号已经完成写操作的证据。
