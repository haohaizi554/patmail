# 位置

频道分享的位置收成两份。正文里是一行简短坐标。名称、地址和说明进不可信的元数据 JSON，不写进用户正文。坐标六位小数。精度四舍五入到整米。来源是钉、地点或实时共享。没写来源时按内容推断。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 入站 | LINE、Matrix、Telegram、WhatsApp 收成同一形状 | 平台适配器把自己的消息交给会话 | 无频道位置 |
| 正文 | `📍` 加坐标和 `±` 米。实时共享用另一行前缀 | 适配器决定信封 | 无 |
| 名称和地址 | 围栏里的不可信 JSON。缺的字段省略 | 外部正文按不可信处理的规则在各平台自己的元数据里 | 无 |
| 出站 | 消息工具和插件 SDK 用同一个 `NormalizedLocation`。只有坐标就是钉 | 各适配器的发送 | 无 |

## OpenClaw

目前支持 LINE 带标题和地址的位置消息、Matrix 的 `m.location` 和 `geo_uri`、Telegram 的钉与场所与实时位置、WhatsApp 的位置消息和实时位置消息。

钉和有名字的地点在正文里是同一行坐标。名字和地址只进元数据块。实时共享的正文前缀不同，坐标格式相同。

上下文里的字段：纬度、经度、可选的精度米数、可选的名称、地址、来源、是否实时、可选说明。频道没给来源时，实时共享推断为 `live`，带名称或地址的推断为 `place`，其余是 `pin`。

提示渲染把名称、地址和说明当不可信元数据，走和其它频道上下文相同的有界 JSON。模型不该把这块 JSON 当成用户亲自写进正文的句子。坐标行是规范化后的文本，精度已经收成整米。

出站用同一形状。只有坐标表示一枚钉。频道若原生支持场所，可以把名称加地址映射成场所卡片。

## Hermes

位置若由某个平台适配器收到，作为该条消息的内容进入会话。没有这四家频道共用的「正文只有坐标、名称进不可信 JSON」规范化。外部内容的污点规则仍在：声明来自网络的工具结果会把这一轮剩余的助手输出标成不可信。位置说明若被当成用户正文灌进去，就少了这道拆分。

## Claude Code

没有频道位置解析。地理信息若出现，是人贴进对话或文件里的文本。
