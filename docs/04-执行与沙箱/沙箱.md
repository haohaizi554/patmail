# 沙箱

沙箱决定工具在哪跑。工具策略决定哪些名字出现在这一轮。提权是从普通沙箱里把 `exec` 放回主机的窄口。三道门叠在一起。拒绝永远赢。沙箱不会把已经被策略拿掉的工具变回来。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 默认 | 沙箱关。工具在 Gateway 那台主机上 | 终端默认本机。可选 Docker、SSH 和几种云 | 命令在用户机器上，由权限模式约束 |
| 隔离单位 | `agent`、`session` 或全体共享一个环境 | profile 的家目录，加上终端后端的工作目录 | 计划模式、worktree、权限询问 |
| 逃逸 | `elevated` 只对 exec，且绕不过「必须沙箱」的角色 | 危险命令走批准，不是换一台机器 | `bypassPermissions` 仍挡必须人参与的工具 |
| 网络出口 | 绑定和镜像按后端。挂上 docker.sock 等于把主机交出去 | 可选的出口代理在请求离开前换密钥 | 工具自己的网络，外加 SSRF 防护钩子 |

## OpenClaw

Gateway 进程留在主机上。打开沙箱时，进去的是工具执行。默认 `mode: off`。`non-main` 只沙箱非主会话。主会话键固定是 `agent:<agentId>:main`，`session.scope` 为 `global` 时是 `global`，不能改成别的字符串。群和频道有自己的键，所以在 `non-main` 下总会进沙箱。`all` 是每个会话都进。

`scope` 决定环境份数。`agent` 每个 agent 一个容器。`session` 每个会话一个。`shared` 所有被沙箱的会话共用一个，此时按 agent 的 docker、ssh、browser 覆盖被忽略。后端默认 `docker`，还可以是 `podman`、`ssh`、`openshell`、`crabbox`。

操作者角色可以把 `sandbox` 设为 `required`。这个要求在会话创建时定死。后端起不来就失败关闭，不退回主机。提权、Gateway 主机和节点主机都不能绕过。默认 `inherit` 才跟着 agent 的 mode 走。

管理员可以对一个空闲聊天单独 `sessions.patch` 设 `sandboxMode: "off"`。`null` 恢复配置。要 `operator.admin`。角色要求的沙箱不能被这次补丁关掉。更新要带上期望的会话 id、生命周期修订和当前沙箱选择，对不上就拒绝，避免改到已经被替换的聊天。有 run 在跑时先停掉。Gateway 提交前再查一次，不在回合底下改隔离。这个选择跨重启和重置还在。分出去的新聊天不继承。同一聊天里恢复检查点则保留。清掉选择不删除已经有的容器，也不影响别的聊天。

工作区可见性是 `none`、`ro`、`rw`，和绑定挂载分开。`docker.binds` 按你写的模式把主机路径送进容器。省略模式时默认读写，源码和秘密更适合 `:ro`。`shared` 范围只用全局绑定。绑定源检查两次：规范化路径一次，再沿最深的已存在祖先解析一次。通过符号链接父目录逃出允许根或撞上禁止路径的绑定会被拒绝。叶子还不存在也检查。把 `/var/run/docker.sock` 挂进去等于把主机控制权交给沙箱。

工具策略在沙箱规则之前。五层：工具轮廓、按提供商的轮廓、全局或按 agent 的 allow/deny、按提供商的 allow/deny、仅在沙箱里再生效的 sandbox 工具策略。`deny` 永远赢。`allow` 非空时，没点名的都挡住。`/exec` 改不了已经被 deny 的 `exec`。允许 `exec` 时，deny 掉 `write` 不会让 shell 变成只读，因为策略看的是工具名，不看命令里面的副作用。`group:runtime`、`group:fs`、`group:sessions`、`group:memory`、`group:web` 这些是策略里的简写，展开成一组工具名。

`tools.elevated` 让 `exec` 跑在沙箱外，默认 `gateway` 主机，目标是节点时则在节点上。只对已授权发送者有效，并记在这个会话上。它打不穿角色要求的沙箱。要彻底禁止 exec，用工具策略 deny。

沙箱默认不带这个 agent 托管的 GitHub 身份。显式 `allowInSandbox` 才把选中的 profile 只读挂到 `/openclaw/github`，并设置 `GH_CONFIG_DIR`。只读挡的是改 profile，不是读凭据。`scope: shared` 拒绝注入这份身份，因为容器可能服务别的 agent。其它后端在打开这个选项时拒绝制备。`openclaw security audit` 会对每个打开的 agent 告警。

`openclaw sandbox explain` 打出有效模式、工作区、挂载、工具策略和该改的配置键。`sandbox list` 看容器。`sandbox recreate` 删掉环境，下次按当前配置重建。

客人访问被撤销后，登记过的后台命令仍带着这份依赖，前台回合结束了也会被取消。关掉浏览器或停掉一轮，不等于撤销这份保留的访问。

## Hermes

终端工具有七个后端：本机、Docker、SSH、Daytona、Modal、Singularity、Vercel Sandbox。孩子进程的环境从 `build_subprocess_env` 来，不从 `os.environ.copy()` 来。为某个 profile 干活的孩子用 `served_profile_child_env`：丢掉启动 profile 的 `.env` 和 `TERMINAL_*` 残留，钉住目标家目录，只叠该目标自己的秘密。contextvars 过不了进程边界，所以在 `Popen` 之前就解析好。

后台进程先向记录的父进程发 SIGTERM，等它在宽限里自己回收孩子，再向快照里还活着的后代发 SIGTERM，最后 SIGKILL。不先杀后代。浏览器或 Electron 的 zygote 若在父进程关机中途被杀，会把退出 0 变成崩溃转储。systemd 的 scope 停掉发生在这次 PID 终止之后，或父进程已经证明死亡之后，不会作为活父进程收到的第一信号。

出口代理是另一道边界。`hermes egress` 在启用时，让离开进程的 HTTP 走 iron-proxy，由代理按映射注入密钥，而不是把密钥放进提示词或命令行。安装走 PM，核对锁定的归档哈希。CA 私钥用 `0600` 写出。Docker 后端在 `proxy.enabled` 时把卷、环境和宿主参数送进容器。和关键出口变量撞名会被发现。这不是文件系统沙箱。它管的是凭据不要随意外流。

危险命令的人机批准写在审批笔记里。批准和沙箱回答的是不同问题：批准问这一次命令能不能跑，后端问它在哪台机器、哪份环境里跑。

profile 之间不共享终端策略。多路复用时，次要 profile 的 `TERMINAL_*` 来自它自己的 scope，不借启动进程的环境。

## Claude Code

没有 Gateway 那种容器模式开关。隔离靠三件产品机制：计划模式先写清要改什么；worktree 把改动放进单独的 git 工作树；`canUseTool` 在每次调用前给出允许、询问或拒绝。`acceptEdits` 可以放过工作区内的安全编辑，工作区外和命令仍常问。`bypassPermissions` 放过多数调用，但标成必须人参与的工具、内容级规则和安全检查仍问。

Bash 在用户机器上执行。兄弟调用可以互相中止，不把整轮判死。权限拒绝写成工具错误或中止整轮，见审批笔记。SSRF 防护在钩子层，不把任意 URL 的抓取当成已经沙箱化的浏览器。

子代理可以用去掉写工具的 Explore 或 Plan 角色，这是工具面收窄，不是另一台容器。验证角色限制改项目文件。这些角色和 OpenClaw 的 `scope: session` 不是同一层。
