# 家目录

工作区是 agent 的家：文件工具和工作区上下文用的工作目录。把它当私有的，也当记忆。它和 `~/.openclaw/` 分开。后者放配置、凭据和会话。工作区是默认的当前目录，不是硬沙箱。相对路径对着工作区解析。绝对路径在没开沙箱时仍能碰到主机别处。要隔离，用沙箱。沙箱开着且工作区访问不是可读写时，工具在 `~/.openclaw/sandboxes` 下的沙箱工作区里操作，不在主机工作区里。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 默认 | `~/.openclaw/workspace`。非 default 的 `OPENCLAW_PROFILE` 变成 `~/.openclaw-<profile>/workspace` | 家目录按 profile。不把 `~/.hermes` 写死 | 这次客户端的项目目录 |
| 覆盖 | `OPENCLAW_WORKSPACE_DIR` 压过上面两者。非默认状态目录把默认工作区留在 `<state-dir>/workspace` | `terminal.cwd` 是消息侧的工作目录 | 工作区或 worktree |
| 多 agent | 花名册里没写 `workspace` 的条目用 `<根>/<agentId>`，根没配则 `<state-dir>/workspace-<agentId>`。给一个共享根起名，并不把它分给某个 agent | 每个 profile 一个岛 | 无这档花名册 |
| 沙箱 | 默认目录不是隔离。隔离是沙箱访问模式 | 终端后端决定命令在哪 | 计划模式限制写 |

## OpenClaw

唯一配置的 agent 继承默认工作区，除非它的条目设置了 `workspace`。显式的多 agent 花名册里，没有 `workspace` 的条目，在配置了 `agents.defaults.workspace` 时用那个根加 agent id，否则用状态目录下的 `workspace-<agentId>`。把一个共享根写出来，并不自动把它指派给某个 agent。

非默认的 `OPENCLAW_STATE_DIR` 仍把默认工作区放在那个状态目录的 `workspace`，包括定时维护和最初的 `main` agent 条目。

备份工作区要把它和 `~/.openclaw` 里的配置、凭据、会话分开看。工作区里的 Markdown 会被当成记忆和引导。沙箱的 `none` 不把这块主机工作区暴露给客人。那是挂载合同。这里的默认路径是没沙箱时文件工具站的地方。

## Hermes

路径用 `get_hermes_home()`。展示用显示函数。一个进程可以服务多个家。终端的工作目录在 CLI 上是进程当前目录，在消息上是 `terminal.cwd`。没有 OpenClaw 这种「profile 名拼进 `~/.openclaw-<profile>/workspace`、共享根起名却不指派」的工作区默认。

## Claude Code

工作区是这次打开的项目。worktree 是另一份检出。没有状态目录和默认工作区分开、并且绝对路径在无沙箱时仍能出工作区这一条 Gateway 说明。权限决定这一次能不能读那条路径。
