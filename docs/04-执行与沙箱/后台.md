# 后台

前台命令等到结束再把输出交回。超时或显式后台则留下一个进程 id，完成时回到把它启动的那条会话。取消不发完成通知。子代理里的后台命令不会自动叫醒子代理，要自己去取结果。停进程时先信号父进程，让它收自己的孩子。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 启动 | `exec`。默认先等 10 秒，再转后台 | `terminal` 的 `background`。完成可通知 | Bash 工具。后台由权限和任务界面呈现 |
| 完成 | 回到原聊天。失败即使别人忙也会叫醒。取消不通知 | `notify_on_complete` 要被内部事件承认。空返回不算接住 | 输出留在工具结果或任务列表 |
| 超时 | 默认 1800 秒。0 表示这次调用不设执行超时 | 守护进程先等宽限再杀幸存的子孙 | 工具超时停这次调用 |
| 秘密 | 出口代理开着时，命令持有自己的代理访问，退出即收回 | 子进程环境默认剥掉提供商钥匙 | 子进程环境由客户端决定 |

## OpenClaw

`exec` 跑 shell。`process` 管理那些后台会话。`yieldMs` 默认 10000 毫秒，到点转后台并返回 `running` 和 `sessionId`，带一截输出尾巴。`background: true` 立刻后台。`awaitResults: true` 把命令留成有主的工具调用，直到进程落定并收齐终端输出。它不能和 `background: true` 一起用。后者是独立服务。

启动失败返回操作系统错误，并释放工人清理，即使没有进程真正起来。托管沙箱工作区的收尾，把每次容器检查、暂停和恢复命令限在 30 秒。失败或超时的操作留下恢复回执，不把不确定的暂停或恢复当成成功。返回后台会话 id 不停止进程超时。要在 Gateway 或沙箱里留一个持久服务，用 `background: true` 加上 `timeoutSeconds: 0`，结束时用 `process` 的 `kill`。主机和工人的生命周期限制仍在。

已结束的会话从完成时刻起按配置的 TTL 过期。每次执行在准入时抓住那个 agent 的保留设置。用另一个 agent 的进程工具，不改变已有结果的寿命。登记簿最多留 50 个已结束会话，以及总共 2,000,000 个保留输出字符，先逐出最旧的。最新完成的那条即使单独超过全局上限，仍保留自己封顶后的每会话合计。`process` 工具被禁止时，`exec` 同步跑，并忽略 `yieldMs` 和 `background`。生出的命令带 `OPENCLAW_SHELL=exec`。

完成唤醒让 agent 继续未完成的工作，不要求新的聊天消息。它指示模型报告还没交付的结果、有意义的结局变化或新的可行动失败，对例行、重复、已被取代或已经恢复的结果保持沉默。这是给模型的指示，不是确定性的通知过滤器，也不关掉完成回合。命令在把它启动的那次聊天里完成。心跳的隔离会话和投递目标管的是周期心跳，不管这次延续。失败的后台命令即使别的会话或自动化正忙，也叫醒起源会话。那条会话还在跑时，完成等到它空闲。超时且没有输出也会叫醒，并带上重试安全说明：重试前先核对外部副作用。手动取消不发完成通知。清理失败仍然通知。安静的前台命令在执行余量没到期时被报成长时间运行。余量到期后，停滞会话恢复可以中止拥有它的运行。输出没变的反复 `poll` 或 `log` 计入循环检测。光是空闲时间过去不算进展。

`process` 被策略禁用时，`exec` 同步跑，忽略让出和后台。启动失败返回操作系统错误，并释放工人清理，即使没有进程真正起来。

后台和让出继承 `tools.exec.timeoutSeconds`，默认 1800，除非这次调用写了自己的超时。返回会话 id 并不取消超时。要在网关或沙箱里放一个长期服务，用 `background: true` 且 `timeoutSeconds: 0`，结束时用 `process` 的 `kill`。

输出留在内存里，直到被轮询或清除，受单会话合计上限。完成后按 TTL 过期，从完成时刻起算。每个 exec 在被接受时抓住当时那个 agent 的保留设置。另一个 agent 的 process 工具不改变已有结果的寿命。登记处最多留 50 个已完成会话和两百万字符，先淘汰最旧的。最新完成的那条即使单独超过全局上限，仍保留自己的单会话帽。

出口代理开着时，每条 Gateway 上的命令跨回合保留自己的代理访问。进程退出、取消、超时或 Gateway 关闭时收回访问并关掉连接。`process kill` 把命令和代理访问一起停掉。

完成叫醒在启用时，让 agent 继续未完成的工作，不要求新的聊天消息。指令要求报告还没送达的结果、有意义的结果变化或新的可行动失败，对常规、重复、已被取代或已经恢复的结果保持沉默。这是给模型的指令，不是确定性的通知过滤器，也不关掉完成回合。

命令在哪条聊天里启动，就在那条会话里完成。回复回到那个聊天或话题。心跳的隔离会话和投递目标不适用于这次继续。失败的后台命令即使别的会话或自动化正忙，也叫醒起源会话。起源会话还在跑，完成就等到它空闲。超时且没有输出也会叫醒，并带上重试安全说明：先核对外部副作用再重试。

人工取消不触发完成通知，即使有过输出。输出仍可用 `process poll` 或 `log` 读到。清理失败仍通知。

后台 exec 不自动叫醒子代理会话。子代理在没有别的完成来源时，必须在让出之前用 `process poll` 收齐结果。请求的停止也要收齐终端结果。

安静的前台命令在执行余量还没过期时，被报告为长时间运行。余量过期后，停滞会话恢复可以中止拥有它的运行。重复的 poll 或 log 若输出没变，计入循环检测。单纯的空闲时间不是进展。

提醒和延迟跟进不用 `sleep` 循环或反复轮询，用 cron。生成的命令带 `OPENCLAW_SHELL=exec`。

沙箱工作区收尾时，每次容器检查、暂停和恢复的命令限 30 秒。失败或超时留下恢复收据，不把不确定的暂停当成成功。

## Hermes

`terminal(background=true, notify_on_complete=true)` 在网关循环上武装监视。完成后开新的一轮。详细程度看 `display.background_process_notifications`。注入要有 `admit_internal_event` 的回执。处理函数返回空不算接受，同一批里已经占用的名额退回，不消耗尝试。

心跳间隔在同一条生成上发出心跳事件，只有增量输出，有最短间隔，所有会话共用登记处里的一条计时线程。渲染 `watch_match` 的界面也要渲染心跳。

停进程时先给记录的父进程 SIGTERM，等 `terminal.daemon_term_grace_seconds`，让它退出并收自己的孩子，再对快照里还活着的子孙 SIGTERM，最后 SIGKILL 仍然忽略的。不要先杀子孙。先杀浏览器的 zygote，会把退出码 0 变成 SIGTRAP。systemd 的 scope 停止只在这次 PID 杀死之后，或父进程已经证明死亡、PID 已被复用时。

子代理结束时杀掉它的后台进程，通知不进父会话。`process_manage` 的 handoff 把所有权转到父任务，完成和收割按新主人走。没交出去的记在结果的 `orphaned_processes` 上。退出了但从没被读过的，记为未读完成。

必须活过重启的工作用 cron，或 `terminal` 的后台加完成通知。后台委派是进程本地的。

硬中断只到达这一轮的活动孩子。后台单元在分发时已经detach。所以停止面还要叫 `interrupt_for_session`。

已经就绪的连续完成可以收成一轮通知。批次不进系统提示。细则在 [积压](积压.md)。

## Claude Code

Bash 可以在后台跑，输出通过任务和工具结果回来。权限在启动前由 `canUseTool` 决定。没有「完成回到 Telegram 那条话题」的渠道合同。取消是客户端对这一轮或这一任务的中断。

工作树和计划模式不额外登记一套进程 TTL。命令的副作用在工作区里，恢复靠转录里已经写下的工具结果，不靠一份内存里的 50 条完成记录。
