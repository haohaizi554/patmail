# 时窗

有的平台给回复留的时间比一轮 agent 短。基类的打字循环预料不到这些。适配器在打字心跳上加自己的一层，不把参数表撑大。LINE 的回复令牌单次使用，入站之后大约 60 秒过期。用它回复是免费的。退到按量的 Push 要付钱。模型没在截止前做完时，要么烧掉付费配额，要么在令牌过期前用它做别的，例如先发一个按钮，让人稍后用新的免费令牌来取缓存的答案。

## 对照

| | Hermes | OpenClaw | Claude Code |
|---|---|---|---|
| LINE | 大约 60 秒的单次回复令牌。慢了可以先发按钮，答案进缓存 | 渠道适配器自己的投递 | 无 |
| WhatsApp | 24 小时后会话不活跃，之后只接受模板消息 | 群和私聊有自己的门 | 无 |
| 短讯 | 没有正在输入，也没有渐进更新。长回复看起来像机器人离线 | 无这道 | 无 |
| 紧回调 | 企业微信一类大约 5 秒。先确认，稍后再用 API 投递。一轮常常要 3 到 30 分钟，回调窗口里塞不下 | Webhook 的 200 只是准入 | 无 |

## Hermes

`_keep_typing` 是打字指示的心跳。模型生成时它在后台跑，回复送达就取消。要在门槛上加平台自己的事，例如 45 秒时发一个「还在想」的气泡，就覆盖这个方法，把自己的任务和 `super()._keep_typing()` 排在一起，并在 `finally` 里拆掉。

始终等待基类的打字心跳。打字本身有用，不要换成自己的，要叠在上面。LLM 结束或 `/stop` 取消运行时，网关取消打字任务。旁路任务必须看见这次取消，否则它会留下，并可能在回复已经送达之后才触发。和 `interrupt_session_activity` 配在一起，清掉用户发出 `/stop` 时留下的界面。LINE 上这表示把回传缓存从待定改成错误，持久的「取答案」按钮就交出「运行被打断」，而不是转圈。

慢回复若把答案缓存起来稍后取，`send` 要认三种模式。这个聊天有待定的回传时，把回复放进缓存，不发可见内容。系统的忙碌确认，前缀是打断、排队、转向或保存那几个符号，绕过缓存，让人看见网关对输入的反应。普通回复仍走回复令牌或 Push。

YAML 桥只翻译这个平台自己的键。环境变量已设置时不覆盖。多路复用的次要 profile 正在加载时从不写进程环境，否则会把那个 profile 的政策钉死在整个进程上。桥返回的值进 `PlatformConfig.extra`。适配器先读 extra，再回退环境。钩子抛出的异常被吞掉并记在调试级别。一个行为不对的插件不会让网关配置加载中止。

## OpenClaw

入站 HTTP 钩子的 200 表示准入，不表示模型做完。要同一次响应里的终态，才打开等待完成。那和「平台给了 60 秒免费回复令牌」不是同一道钟。群和私聊的门在消息进会话之前。

## Claude Code

没有渠道回复令牌。这一次查询可以很长。客户端在工具和文本流上更新，不靠 60 秒的免费回复窗口。
