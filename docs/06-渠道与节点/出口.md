# 出口

离开进程的 HTTP 可以走一台操作者的代理。代理在连接前、DNS 已经解析之后看目的地，用来收窄 DNS 重绑定窗口。Hermes 另外有一台本机的铁代理：它在出站时注入密钥，子进程环境里不放真钥匙。两台都不是对抗模型的进程边界。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 产品是否自带代理 | 不下载、不启动、不证明任何代理。只把客户端指过去 | `hermes egress` 安装钉住版本的 iron-proxy | 无对等的密钥注入代理 |
| 配置 | `proxy.proxyUrl` 优先于环境变量 | `proxy.enabled`。Docker 后端注入 `HTTPS_PROXY` | 客户端自己的网络 |
| 回环 | `gateway-only`、`proxy` 或 `block` | 监听地址按平台选。从不是 `0.0.0.0` | 无 |
| 密钥 | URL 里的凭据在快照和日志里打红。SecretRef 哨兵在最后一道出网前换真值 | 映射文件 0600。代理子进程只用允许名单加映射里的变量名 | 密钥在客户端进程 |

## OpenClaw

运行时的 HTTP 和 WebSocket 可以走操作者管理的正向代理。这是可选的纵深：集中出站、更强的 SSRF 防护、在网络边界审计目的地。代理在连接时评估目的地，发生在 DNS 解析之后、打开上游之前。应用层更早做的 DNS 检查和真正拨号之间的重绑定窗口因此变窄。目的地规则、分段、限流或出站允许名单可以放在这一处，而不必改 OpenClaw。

`proxy.proxyUrl` 是 `http://` 或 `https://`。嵌在 URL 里的凭据当敏感信息，从快照和日志里打红。`proxy.tls.caFile` 用于校验由私有 CA 签发的 https 代理。`proxy.loopbackMode` 默认 `gateway-only`，也可以是 `proxy` 或 `block`，控制回环是否绕过代理。

配置里的 URL 优先于 `OPENCLAW_PROXY_URL`。两者都去掉就关闭。托管的网关服务应把 URL 写进配置，重装之后还在，而不是只靠前台环境变量。

这和秘密运行时的哨兵是两条线。哨兵让模型提供商的真钥匙在离开进程前才换上。正向代理决定流量走哪一台机器。代理看不到的进程内读取仍然能拿到已经解开的秘密。

`secrets.egressProxy` 的变更需要重启 Gateway。普通的 `proxy.proxyUrl` 属于操作者路由，和秘密出口代理的重启分类分开看配置表。

## Hermes

铁代理是凭据注入防火墙。安装经包管理器，核对归档和来源哈希。缺 GPG 时允许只靠哈希安装。明确的签名拒绝则中止。

设置时生成 CA。私钥用 `O_NOFOLLOW` 和 `0600` 写入，不经过默认 umask 的窗口。证书是 `0644`。配置、映射、pid、nonce、审计日志和代理日志都是 `0600`。目录 `0700`。禁止先 `copy2` 再 `chmod`，那会留下 umask 窗口。

映射发现提供商，或从 Bitwarden 拉取名字。再次运行不悄悄把凭据来源从 Bitwarden 降级成环境变量。`--rotate-tokens` 才轮换已有令牌。

启动子进程的环境不用 `os.environ.copy()`。允许名单是 PATH、HOME、区域设置一类，加上映射里引用的变量名。其余留在宿主机。`HTTPS_PROXY` 一类从这份环境里剥掉，避免递归。pid 文件带 nonce。停止时先看 Linux 上的进程开始时间。宽限之后若 pid 已复用，不再 SIGKILL。

监听从不是 `0.0.0.0`。Linux 上若检测得到 docker0，绑定桥网关地址，容器经 `host.docker.internal` 到达。该地址不能是未指定、回环、多播、保留、链路本地或全球地址，避免 PATH 上的恶意 `ip` 注入 `0.0.0.0`。macOS 和 Windows 的 Docker Desktop 绑定回环。检测不到桥时退回环回并警告。活性探测读配置里的绑定主机再探那台主机。写死环回会把绑在桥上的、其实健康的守护进程报成死的。二进制只有单个监听字段。隧道监听在隧道端口，明文 HTTP 在隧道端口加一。发到明文监听的 CONNECT 会被当成普通请求转上游并得到 400。Docker 把 `HTTPS_PROXY` 指到隧道端口，`HTTP_PROXY` 指到加一的端口。指标监听钉在 `127.0.0.1:0`，拿一个临时环回端口。铁代理默认的 `:9090` 和 Hermes 默认隧道端口相同，不钉住就会撞车。

上游默认拒绝回环、链路本地（含实例元数据 `169.254.169.254` 及其 IPv4 映射的 IPv6）、RFC1918、IPv6 本地、CGNAT 和基准测试网段。未指定拒绝表时必须发出这套默认。只有显式的空列表才退出。

钉住的 v0.39 没有 `log.audit_path` 字段。配置接受审计日志参数，但不把它写进渲染出的 yaml。按请求的记录进 `iron-proxy.log`。`audit.log` 仍以 `0600` 和 `O_NOFOLLOW` 预先创建，等以后的版本有单独流时隐私合同已经在。设置向导把创建失败当警告，并把成功说成「预留」，因为这一版守护进程还不写那个文件。版本钉到有该字段之后，预创建变成承重的，向导应再失败出声。

Bitwarden 且不允许环境回退时，缺访问令牌或缺 `project_id`，启动拒绝。`bws secret list` 对某个已映射提供商没有值，构建子进程环境时抛出。退回宿主环境会把 Bitwarden 路径要避免的过期秘密带回来。对 Docker 强制时，`docker_env` 若覆盖出口控制变量或已映射的真环境名，在容器启动前抛出。

审计日志创建失败就抛出，不吞掉。已在监听的 pid 再次 start 是幂等返回。

铁代理减少子进程和环境里的明文钥匙。插件、钩子和技能仍在 agent 进程里，能读 agent 能读的内存。操作系统隔离才是对抗模型的边界。

## Claude Code

抓取和搜索走客户端的 HTTP。SSRF 相关的钩子可以挡目的地。没有一份「连接时再解析一次 DNS」的自带代理合同，也没有把提供商钥匙留在代理映射里、命令行只看到占位符的铁代理。密钥在客户端进程和它启动的子进程环境里。要得到同等的出站审计，得在机器或网络上另放代理，并让客户端走它。
