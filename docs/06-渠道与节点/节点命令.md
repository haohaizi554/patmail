# 节点命令

设备配对之后，节点命令还要过三道才可以调用。节点必须在已认证的连接元数据里声明这条命令。命令必须在配对设备记录上已批准的命令面里。Gateway 按平台和批准推导的允许名单必须包含这条声明的命令。三道之后，本地执行批准和操作系统权限仍适用。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 三道 | 声明、已批准的面、平台允许名单。缺一不可 | 终端批准和工具集。无手机节点命令面 | 本机权限 |
| 配对 | 批准设备不等于批准命令。初次无范围的节点请求可以按网段自动批准设备，命令面仍要另批 | 无这道节点面 | 无 |
| 危险 | 拍照、录像、通讯录新增、日历新增、短信等要一次性持久加入 `commands.allow`。`deny` 永远压过默认和额外允许 | 危险命令走批准 | `canUseTool` |
| 扩大 | 待定扩大期间，只有原先已批准、且仍被声明和允许的命令有效。去掉声明不授予新访问 | 无 | 无 |

## OpenClaw

`openclaw nodes pending` 和 `openclaw nodes approve` 用的请求 id 和设备请求 id 不同。最初未批准的面没有有效命令。

这些行是 Gateway 的政策天花板，不是每台节点应用都实现了的命令。命令可用，还要连接着的节点声明它。Android 只在辅助功能控制开着时广告移动界面命令。桌面节点只在本地电脑控制履行者开着时广告 `computer.act`。当前 macOS 应用不声明政策行里列出的设备和私人数据那一族。

画布插件的默认只加在 macOS：展示、隐藏、导航。iOS、Android、Windows、Linux 和未知平台不接收画布插件默认。对讲的按下说话命令，对任何广告了 `talk` 能力或声明了 `talk.*` 的节点默认允许，与平台标签无关。

桌面宿主命令，例如 `system.run`、浏览器代理、屏幕快照，不在上面的静态平台默认表里。操作者批准一份声明了它们的配对请求之后才可用，之后节点已批准的命令集在重连时带着它们。桌面共享在桌面节点上默认开。Mac 应用的本地开关在设置里。

危险或偏隐私的命令，即使节点声明了，也要一次性持久选择加入 `gateway.nodes.commands.allow`：`camera.snap`、`camera.clip`、`camera.ptz.control`、`screen.record`、`contacts.add`、`calendar.add`、`reminders.add`、`health.summary`、`sms.send`、`sms.search`。`gateway.nodes.commands.deny` 永远压过默认和额外允许项。

插件拥有的节点命令可以再加一道 Gateway 的节点调用政策。它跑在允许名单检查之后、转发到节点之前。原始的 `node.invoke`、命令行助手和专用的 agent 工具共用这道插件权限边界。危险的插件节点命令仍要显式的 `commands.allow`。

节点扩大了声明的命令、能力或权限之后，重连它，看待定，用节点请求 id 批准加宽的面。去掉声明不授予新访问，也不因此需要为一次扩大去批准。

自动批准的网段只适用于第一次的、角色是节点、且没有请求范围的配对。不自动批准升级。它只批准设备。命令和能力面仍要 `nodes approve`。静默的同主机配对同样。SSH 核对过的配对和节点 profile 的设置码会批准初始面，因为两者记下了明确的机器所有权或管理员同意。设备配对本身不得授予命令。

## Hermes

没有手机节点的三道命令面。终端命令走批准和后端。电脑使用若走驱动，是另一条不抢焦点的路径。配对在 Hermes 里是渠道私聊和令牌锁，不是这张节点命令天花板。

## Claude Code

命令在客户端上，由这一次权限决定。没有「声明、已批准的面、平台允许名单」三道，也没有短信和健康摘要要单独加入允许名单的节点政策。
