# 范围

连上 Gateway 的客户端带一个角色。操作者是控制面：CLI、控制界面、自动化和受信任的助手进程。节点是能力宿主，经 `node.invoke` 暴露命令。操作者的 RPC 要操作者角色。从节点来的方法要节点角色。范围是一台受信任 Gateway 内部的护栏，不是多租户隔离。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 角色 | `operator` 或 `node` | 会话令牌。方法在 profile 范围内执行 | 本机用户 |
| 写 | 权限模式的完全要 `operator.admin`。其余模式要 `operator.write` | 批准是人的选择，不是 scope 列表 | `canUseTool` |
| 隔离 | 人和机器要分开，就各跑一台 Gateway、各用一个操作系统用户 | 多 profile 仍是一个操作者。秘密失败关闭 | 无第二角色 |
| 节点 | 配对过的设备。命令经节点角色 | 桌面是渲染器，不是 `node.invoke` | IDE 是客户端 |

## OpenClaw

握手时的 `role` 和 `scopes` 在认证之后决定这个连接能做什么。缺范围就做不了那次 RPC，而不是做完再靠提示词补救。

完全权限模式要求 `operator.admin`。只读、守卫和工作区要求 `operator.write`。个人说明的编辑只要已认证 profile 加 `operator.read`，不要求管理员。这是控制面的分级，不是文件系统的沙箱。

节点角色给 macOS、iOS、Android 和无头宿主。它们暴露命令，不因此变成操作者。把节点的连接当成可以改配置、批准备份或重启 Gateway，越出了角色。

范围不隔离互不信任的人。会话 id 只选路由。要强分离，每人一台 Gateway，各自的操作系统用户或主机。Fleet 的 cell 是这种分离。同一台 Gateway 上的两个操作者范围，仍在一个信任域里。

配对把设备或私聊放进允许集合。范围决定连上之后能调哪些方法。两道都过，一次操作才发生。

## Hermes

WebSocket 用会话令牌。客户端声明自己能回答服务端请求。没声明的旧客户端，提问快速失败。每个 RPC 在会话所属的家目录上绑定秘密和终端范围。只改家目录、不进秘密范围，凭据仍来自启动 profile。

没有操作者和节点两种角色。桌面、TUI 和仪表盘是不同的渲染器，背后是同一类网关方法。消息网关的适配器是另一进程里的平台连接，不是 `node` 角色。

## Claude Code

没有 Gateway 范围。权限是每次工具调用的允许、询问或拒绝。计划模式是会话内的写限制。子代理继承或收窄工具，不连接成一个节点角色。
