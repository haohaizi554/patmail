# 三家 Agent 学习笔记

来源是根目录里的三份浅克隆。日期：2026-10-06。

| 目录 | 项目 | 仓库 |
|---|---|---|
| `openclaw` | 小龙虾 OpenClaw | `github.com/openclaw/openclaw` |
| `hermes-agent` | 爱马仕 Hermes Agent | `github.com/NousResearch/hermes-agent` |
| `claude-code` | Claude Code 2.1.88 源码还原 | `github.com/claude-code-internals/claude-code-runnable` |

Claude Code 这份从公开 npm 包的 source map 还原，版权在 Anthropic，笔记只记录机制，不摘大段源码。三个克隆各自带 `.git`，不属于本插件仓库。

同一机制只留一篇。早先的循环草稿，以及后来用不同标题重写的专道、交接、裁剪、去重、判定、回绕，已经并进留下的那一篇。

## 篇目

### [总览](00-总览/)

- [全景](00-总览/全景.md)：`openclaw.md`、`hermes.md`、`claude-code.md` 只写了嵌入式循环里和「6 步办事」直接相关的机制。
- [openclaw](00-总览/openclaw.md)：嵌入式运行器把一轮对话收成一次 admitted run。
- [hermes](00-总览/hermes.md)：公开入口是 `run_agent.py` 混入的 `TurnFacadeMixin.run_conversation`。
- [claude-code](00-总览/claude-code.md)：这份是 `@anthropic-ai/claude-code@2.1.88` 的 source map 还原，用来学客户端循环。
- [openclaw-运行时](00-总览/openclaw-运行时.md)：这篇写 Gateway、提示词、钩子、算力池和工具面。
- [hermes-运行时](00-总览/hermes-运行时.md)：这篇写入口、提示词三层、工具注册、会话库和网关。
- [claude-code-运行时](00-总览/claude-code-运行时.md)：这篇写这个客户端除此之外的骨架。
- [办事助手可借鉴](00-总览/办事助手可借鉴.md)：对照 `patmail-extension/src/agent/loop.ts` 和 `tools.ts`。
- [现成调用](00-总览/现成调用.md)：对照 `patmail-extension/src`。

### [回合](01-回合/)

- [压缩](01-回合/压缩.md)：三家都把「上下文变长」拆成好几步，并且都规定：工具调用和它的结果不能被切成两半；磁盘上的完整历史还在，变的是下一轮模型看见的窗口。
- [微压缩](01-回合/微压缩.md)：大压缩在窗口快满时一次摘要中间一大段。
- [修剪](01-回合/修剪.md)：会话修剪从模型上下文里裁掉旧的工具结果。
- [静默](01-回合/静默.md)：后台维护用精确的静默记号开头，投递层把它拿掉，用户看不见中间输出。
- [卫生](01-回合/卫生.md)：发给模型之前，OpenClaw 按提供商在内存里修转录形状。
- [缓存](01-回合/缓存.md)：提示缓存复用没变过的前缀：系统或开发者说明、工具定义和其它稳定上下文。
- [窗口](01-回合/窗口.md)：上下文是这一轮真正发给模型的全部：系统提示、这段会话的历史、工具调用和结果、附件。
- [失败转移](01-回合/失败转移.md)：模型失败先分类，再决定原地重试、换账号，还是换模型。
- [重试](01-回合/重试.md)：重试按一次 HTTP 请求，不按多步流程。
- [循环检测](01-回合/循环检测.md)：重复的工具调用有两道闸。
- [思考](01-回合/思考.md)：思考档位先看这一条消息里的指令，再看会话覆盖，再看 agent、模型和全局默认。
- [旁问](01-回合/旁问.md)：`/btw` 对当前会话问一句旁的问题。
- [终答](01-回合/终答.md)：经 Codex 运行时的直接或来源聊天，对内部 WebChat 默认自动投递最终助手文字，和 Pi 运行时的合同一致。
- [模型](01-回合/模型.md)：选中的模型和真正答这一轮的模型可以不同。
- [判断](01-回合/判断.md)：聊天模型负责对话和工具。
- [优选](01-回合/优选.md)：OpenRouter 可以把同一次请求分给不同的底层提供商，并按价格、速度或质量排序，也可以只允许或排除一些名字。
- [本地](01-回合/本地.md)：本机模型可以装成 Gateway 管理的服务，也可以接已经在跑的服务器。
- [资格](01-回合/资格.md)：认证 profile 能不能用，在真正打到模型之前就有稳定的原因码。

### [提示与记忆](02-提示与记忆/)

- [提示词](02-提示与记忆/提示词.md)：系统提示按缓存边界切开。
- [系统提示](02-提示与记忆/系统提示.md)：OpenClaw 为每次 agent 运行自己组装系统提示。
- [人格](02-提示与记忆/人格.md)：语气、操作规矩和用户偏好是三份文件。
- [上下文文件](02-提示与记忆/上下文文件.md)：项目说明在会话开始时装进提示，一条会话只加载一种项目文件。
- [上下文引擎](02-提示与记忆/上下文引擎.md)：管理上下文的策略可以换成插件，但同时只能有一个。
- [技能](02-提示与记忆/技能.md)：技能是给模型看的操作说明，不是新的核心工具。
- [自学](02-提示与记忆/自学.md)：纠正和做成了的做法可以变成以后还能发现的技能。
- [时区](02-提示与记忆/时区.md)：模型看见的时间要有一个参考，而不是混用各提供商的本地钟。
- [语言](02-提示与记忆/语言.md)：界面文案按层查找，命中即停。
- [记忆](02-提示与记忆/记忆.md)：三家都把「这一轮要用的上下文」和「以后还能找回来的事实」分开。
- [主动记忆](02-提示与记忆/主动记忆.md)：主动记忆是对话会话上的深召回。
- [检索](02-提示与记忆/检索.md)：会话搜索查的是过去可见会话里的用户和助手正文，返回会话钥匙、时间和一小段摘录。
- [嵌入](02-提示与记忆/嵌入.md)：记忆搜索把笔记切成小块，向量和关键词并行查，再加权合并。
- [出处](02-提示与记忆/出处.md)：记忆块的出处类存在散文外面：`owner`、`agent`、`untrusted`、`system`。
- [用户](02-提示与记忆/用户.md)：`USER.md` 放稳定的偏好、说话方式、关系和正在做的项目，作为以后会话的指示。
- [出生](02-提示与记忆/出生.md)：新工作区的第一次真实回合才做出生，不是安装向导的一部分。
- [常设](02-提示与记忆/常设.md)：常设命令把「每周五编译报告，只在异常时升级」写进每次会话都会注入的工作区文件。
- [代表](02-提示与记忆/代表.md)：代表是有自己身份的 agent，替组织里的人办事，从不假装成那个人。

### [会话与投递](03-会话与投递/)

- [会话](03-会话与投递/会话.md)：会话是「这串对话算不算同一次」的边界。
- [主会话](03-会话与投递/主会话.md)：个人 agent 默认把所有渠道的私聊收成一条滚动对话。
- [会话控制](03-会话与投递/会话控制.md)：会话行带 `snapshotAt`，是 Gateway 的采样时间。
- [会话工具](03-会话与投递/会话工具.md)：跨会话的列表、历史、搜索、发送和生成，仍受当前工具档案和允许拒绝策略约束。
- [订阅](03-会话与投递/订阅.md)：客户端用一次 `sessions.subscribe` 既可以订阅，又可以装上初始花名册。
- [附着](03-会话与投递/附着.md)：Gateway 拥有会话行、转录、路由元数据和活动运行。
- [转向](03-会话与投递/转向.md)：默认的队列模式是转向。
- [队列](03-会话与投递/队列.md)：入站的自动回复经进程内的车道队列串行，避免多次 agent 运行撞在同一份会话状态上。
- [入站](03-会话与投递/入站.md)：进来的消息先路由到会话键，再去重和防抖，若已有运行就进队列，然后是 agent 运行，最后按渠道限制切块送出。
- [流式](03-会话与投递/流式.md)：模型可以逐段吐出文字。
- [打字](03-会话与投递/打字.md)：打字指示在运行还活跃时发给聊天渠道。
- [进度](03-会话与投递/进度.md)：长时间工作时，渠道上保持一条可编辑的进度消息，而不是堆一串「还在做」。
- [排版](03-会话与投递/排版.md)：出站 Markdown 先解析成共享的中间表示，再按渠道渲染。
- [投递](03-会话与投递/投递.md)：一条进来的消息要先变成会话键，再决定是并进当前轮、等当前轮结束，还是单独开一轮。
- [重置](03-会话与投递/重置.md)：`openclaw reset` 清本地配置或状态，CLI 还在。
- [多人](03-会话与投递/多人.md)：多人模式让几个受信任的人操作同一个 agent。
- [健康](03-会话与投递/健康.md)：会话行不是套接字还活着。
- [斜杠](03-会话与投递/斜杠.md)：以 `/` 开头、单独成条的消息由 Gateway 处理。
- [引用](03-会话与投递/引用.md)：在消息里写 `@` 加一种引用，会把内容展开进这条用户消息，放在附带上下文一节下面。
- [房间](03-会话与投递/房间.md)：没被点名的群消息可以变成安静的房间事件。
- [群聊](03-会话与投递/群聊.md)：群默认是允许名单，没点名的发送者进不来。
- [名单](03-会话与投递/名单.md)：访问组是起了名的发送者列表，定义一次，在频道允许名单里用 `accessGroup:<名字>` 引用。
- [广播](03-会话与投递/广播.md)：实验性的广播让多个 agent 对同一条入站各跑各的会话。
- [反应](03-会话与投递/反应.md)：加或去掉表情反应用 `message` 的 `react`。

### [执行与沙箱](04-执行与沙箱/)

- [审批](04-执行与沙箱/审批.md)：三家都把「工具在不在名单里」和「这一次调用能不能执行」分成两道门。
- [权限模式](04-执行与沙箱/权限模式.md)：一个会话可以收紧文件系统边界，并决定命令升级由谁审。
- [策略](04-执行与沙箱/策略.md)：只读、工具策略和执行批准是代码里的门，不是写在提示里的请求。
- [原生许可](04-执行与沙箱/原生许可.md)：Codex 的 `PermissionRequest` 上，OpenClaw 只在策略做了决定时返回明确的允许或拒绝。
- [沙箱](04-执行与沙箱/沙箱.md)：沙箱决定工具在哪跑。
- [沙箱流](04-执行与沙箱/沙箱流.md)：原生沙箱执行默认不流。
- [沙箱范围](04-执行与沙箱/沙箱范围.md)：沙箱包住工具执行：`exec`、`ls`、读、写、编辑、补丁、进程，以及可选的沙箱浏览器。
- [提权](04-执行与沙箱/提权.md)：沙箱里的 `exec` 默认出不了沙箱。
- [代码执行](04-执行与沙箱/代码执行.md)：模型要跑一段程序时，三家给的表面不一样。
- [后台](04-执行与沙箱/后台.md)：前台命令等到结束再把输出交回。
- [积压](04-执行与沙箱/积压.md)：已经就绪的多条后台完成，在交互界面上收成一轮通知。
- [浏览器](04-执行与沙箱/浏览器.md)：浏览器是 agent 的另一块屏幕。
- [浏览器风险](04-执行与沙箱/浏览器风险.md)：打开浏览器控制，就是给模型一个真浏览器。
- [终端后端](04-执行与沙箱/终端后端.md)：shell、代码执行和建立在 shell 上的文件工具都通过 `create_environment()` 进当前终端后端。
- [电脑](04-执行与沙箱/电脑.md)：电脑使用在后台读无障碍树并投递合成输入。
- [屏幕](04-执行与沙箱/屏幕.md)：无头 Linux 上，每个机器人有自己的 Xfce 屏幕。
- [提问](04-执行与沙箱/提问.md)：结构化提问只在主会话里。
- [中间件](04-执行与沙箱/中间件.md)：观察钩子报告发生了什么。
- [工具目录](04-执行与沙箱/工具目录.md)：工具一多，每轮都把全部 JSON schema 放进上下文。
- [注入](04-执行与沙箱/注入.md)：提示注入不需要公开私聊。
- [富输出](04-执行与沙箱/富输出.md)：助手输出里的投递和渲染走专用通道。
- [挂载](04-执行与沙箱/挂载.md)：一个沙箱 agent 需要主工作区以外的目录时，用 Docker 绑定挂载。
- [工作区访问](04-执行与沙箱/工作区访问.md)：沙箱能看见多少工作区，由 `workspaceAccess` 决定。
- [工作树](04-执行与沙箱/工作树.md)：托管工作树给一次任务自己的分支和检出，临时目录不放进源仓库里面。
- [家目录](04-执行与沙箱/家目录.md)：工作区是 agent 的家：文件工具和工作区上下文用的工作目录。
- [登录](04-执行与沙箱/登录.md)：网站登录的口令在本机加密，填进页面。
- [网页](04-执行与沙箱/网页.md)：搜索和抓取是轻量 HTTP。
- [文档](04-执行与沙箱/文档.md)：`read_file` 把常见文档转成 Markdown 再按偏移阅读。
- [文稿](04-执行与沙箱/文稿.md)：`pdf` 一次分析一份或多份 PDF，返回文本。
- [图像后端](04-执行与沙箱/图像后端.md)：`image_generate` 只是门面。
- [后端](04-执行与沙箱/后端.md)：搜索、抓取、浏览器、图像和视频都是登记处加一个活动名字。
- [语音流](04-执行与沙箱/语音流.md)：语音可以按句播放，不必等整段音频合成完。
- [检查点](04-执行与沙箱/检查点.md)：Lobster 把多步工具管道收成一次确定的工具调用。
- [语言服务](04-执行与沙箱/语言服务.md)：写文件和打补丁之后，先做进程内的语法检查，语法干净再问语言服务器。
- [位置](04-执行与沙箱/位置.md)：频道分享的位置收成两份。
- [交付物](04-执行与沙箱/交付物.md)：消息网关扫描助手回复里的绝对路径和家目录相对路径。
- [媒体](04-执行与沙箱/媒体.md)：生成和理解都是工具。
- [帖子](04-执行与沙箱/帖子.md)：搜 X 是只读的。

### [多代理](05-多代理/)

- [多代理](05-多代理/多代理.md)：三家的「另一个 agent」不是同一种东西。
- [专线](05-多代理/专线.md)：并行专线是一个 Gateway 把不同聊天或房间分给不同 agent，同时把用户感受到的速度保住。
- [让出](05-多代理/让出.md)：子代理登记处拥有跨 `sessions_yield` 的完成。
- [嵌套](05-多代理/嵌套.md)：子代理默认可以递归委派到深度 5。
- [子停](05-多代理/子停.md)：每个生成会话有自己的进程内队列。
- [通告](05-多代理/通告.md)：子代理的结果交给请求者。
- [蜂群](05-多代理/蜂群.md)：蜂群是在代码模式的脚本里扇出很多子代理。
- [看板](05-多代理/看板.md)：看板是一份能熬过进程重启的任务队列。
- [目标](05-多代理/目标.md)：目标是贴在一次会话上的结果，让下一轮还知道要把它做完。
- [轮询](05-多代理/轮询.md)：同一条会话里按时钟再跑一轮，和「做到完成」、和「重启之后仍要跑」是三件事。
- [孤儿](05-多代理/孤儿.md)：Codex 的 app-server 在 Gateway 硬停之后可能还活着。
- [镜像](05-多代理/镜像.md)：选中的模型走 Codex 运行时时，Codex 的 app-server 拥有原生的令牌压力压缩和手动线程压缩。
- [线程](05-多代理/线程.md)：OpenClaw 会话附着到已有的 Codex 线程时。
- [工人边界](05-多代理/工人边界.md)：云工人的转录在 Gateway。
- [云机](05-多代理/云机.md)：云工人把编码工作放到一台用完即弃的机器上。
- [保管](05-多代理/保管.md)：保管技能是随版本发布的操作剧本，只给配置成系统 agent 的那一个。
- [原生转向](05-多代理/原生转向.md)：Codex 运行时上，活动回合的队列转向映射到 app-server 的 `turn/steer`。

### [渠道与节点](06-渠道与节点/)

- [握手](06-渠道与节点/握手.md)：Gateway 先发挑战，客户端再发 `connect`。
- [配对](06-渠道与节点/配对.md)：配对回答的是「这个人能不能跟机器人说话」和「这台设备能不能连上 Gateway」。
- [路由](06-渠道与节点/路由.md)：进来的消息先被渠道接受，再决定哪个 agent 来答，最后决定落在哪把会话钥匙上。
- [心跳](06-渠道与节点/心跳.md)：心跳是系统自己发起的一轮，用来看有没有要告诉主人的事。
- [定时](06-渠道与节点/定时.md)：定时工作是另一条会话，不是把「过两小时再看」写进当前回复里空转。
- [托管定时](06-渠道与节点/托管定时.md)：Chronos 让托管的 Hermes 网关在空闲时可以缩到零，定时任务仍会触发。
- [中继](06-渠道与节点/中继.md)：网关向外拨号连接器，不在进程里实现每一种平台的套接字。
- [时窗](06-渠道与节点/时窗.md)：有的平台给回复留的时间比一轮 agent 短。
- [尾网](06-渠道与节点/尾网.md)：Tailscale 的 Serve 让 Gateway 继续绑在环回上，由 Tailscale 提供 HTTPS、路由。
- [反代](06-渠道与节点/反代.md)：可信反代把认证交给前面的身份代理。
- [限流](06-渠道与节点/限流.md)：Gateway 上有多道彼此独立的限流。
- [节点](06-渠道与节点/节点.md)：配对过的节点是能力宿主：摄像头、屏幕、位置、通知，以及 macOS 上的部件面板。
- [节点命令](06-渠道与节点/节点命令.md)：设备配对之后，节点命令还要过三道才可以调用。
- [语音频道](06-渠道与节点/语音频道.md)：Discord 有两套语音。
- [发现](06-渠道与节点/发现.md)：找 Gateway 有两件事。
- [范围](06-渠道与节点/范围.md)：连上 Gateway 的客户端带一个角色。
- [在场](06-渠道与节点/在场.md)：在场是尽力而为的花名册：这台 Gateway，以及连上来的、人看得见的客户端。
- [客户](06-渠道与节点/客户.md)：第三方操作者或 WebChat 客户端用发布的 Gateway 包，不从仓库里抄协议。
- [单发](06-渠道与节点/单发.md)：`openclaw agent` 从命令行跑一轮，没有入站聊天消息。
- [出口](06-渠道与节点/出口.md)：离开进程的 HTTP 可以走一台操作者的代理。

### [配置与安全](07-配置与安全/)

- [配置](07-配置与安全/配置.md)：配置是带版本的快照。
- [认证](07-配置与安全/认证.md)：OAuth 和 API 钥匙都进认证 profile，按提供商存在每个 agent 的库里。
- [秘密](07-配置与安全/秘密.md)：密钥可以不写在配置明文里，但只要还在同一个进程的内存里，agent 就能读到。
- [秘密引用](07-配置与安全/秘密引用.md)：SecretRef 到处是同一个对象：`source`、`provider`、`id`。
- [锁](07-配置与安全/锁.md)：一个状态目录只该有一个 Gateway 进程。
- [租户](07-配置与安全/租户.md)：一台 Gateway 是一个信任边界，不是一栋楼里的多户隔离。
- [信任](07-配置与安全/信任.md)：一台 Gateway 支持一个信任边界：一个操作者，或彼此信任的一队人。
- [医生](07-配置与安全/医生.md)：检查和修复分开。
- [存储](07-配置与安全/存储.md)：存储位置给产物起一个目的地。
- [恢复](07-配置与安全/恢复.md)：会话库坏了的时候，先保住还能读的正文，再修索引。
- [备份](07-配置与安全/备份.md)：备份是显式做出来的档案，里面有配置、认证 profile、渠道和提供商凭据、会话，以及可选的工作区。
- [版本](07-配置与安全/版本.md)：运行时状态以数据库为准。
- [库检](07-配置与安全/库检.md)：Gateway 对 agent 库的检查，前台等五秒。
- [更新](07-配置与安全/更新.md)：更新先做出一份候选，再停掉正在服务的进程，然后替换运行时。
- [收尾](07-配置与安全/收尾.md)：更新命令进程拥有准入、更新锁和输出寿命、更新前清单、全部 profile 的快照、网关暂停、Git 的选择和暂存与恢复、语法和 …
- [稳定发布](07-配置与安全/稳定发布.md)：稳定发布是一道门。
- [事故](07-配置与安全/事故.md)：怀疑自己的 Gateway 或渠道账号被闯了，先收口，再轮换，再核对，再收集。
- [重启](07-配置与安全/重启.md)：请求的重启先停收新活，再等正在跑的回合和后台任务结束。
- [迁入](07-配置与安全/迁入.md)：`openclaw migrate` 经插件拥有的提供商，把另一套 agent 的状态导入 OpenClaw。
- [证明](07-配置与安全/证明.md)：`openclaw policy check` 把一次干净的检查收成耐久的审计证据。
- [插件](07-配置与安全/插件.md)：插件把能力加在核心外面。
- [插件模型](07-配置与安全/插件模型.md)：插件要单独打一次模型，走 `ctx.llm`。
- [内钩](07-配置与安全/内钩.md)：内部钩子是 Gateway 进程里的 JavaScript 或 TypeScript。

- [钩子层](07-配置与安全/钩子层.md)：Codex 回合外面有三层钩子。
- [钩子入站](07-配置与安全/钩子入站.md)：Gateway 的 HTTP 钩子让外部服务叫醒一个 agent，或提交一轮。

- [部件](07-配置与安全/部件.md)：`show_widget` 在当前表面上显示一份自包含的 HTML。

### [观测与接入](08-观测与接入/)

- [监控](08-观测与接入/监控.md)：Hermes 网关的监控平面按构造不含内容。
- [遥测](08-观测与接入/遥测.md)：更新检查默认每天问一次有没有新版本，带上版本、操作系统、Node 版本、CPU 架构和请求来自哪一面。
- [共享指标](08-观测与接入/共享指标.md)：NeMo Relay 是 Hermes 在有原生轮子的平台上的普通运行时依赖。
- [跨度](08-观测与接入/跨度.md)：已认证的 Gateway WebSocket 客户端可以在每个请求帧上带 W3C 的 `traceparent`。
- [追踪](08-观测与接入/追踪.md)：诊断导出默认不带模型原文。
- [指标](08-观测与接入/指标.md)：Prometheus 文本端点由诊断插件提供，路径是 `GET /api/diagnostics/prometheus`。
- [审计](08-观测与接入/审计.md)：审计账本只记元数据：身份、顺序、出处、动作、状态和规范化的结果码。
- [账本](08-观测与接入/账本.md)：审计账本可以通过 Gateway 协议读。
- [用量](08-观测与接入/用量.md)：用量以提供商报告的额度为准，不用估算的账单冒充配额。
- [账单](08-观测与接入/账单.md)：终端里的账单状态和类型化拒绝都有明确分支。
- [日志](08-观测与接入/日志.md)：控制台给人看。
- [轨迹](08-观测与接入/轨迹.md)：Hermes 把对话轨迹写成与 ShareGPT 兼容的 JSONL，给训练、调试和强化学习用。
- [批处理](08-观测与接入/批处理.md)：批处理把很多条提示各放进一次隔离的 agent 会话，产出带工具统计的轨迹。
- [察觉](08-观测与接入/察觉.md)：几条会话同时做一件事时，人对着工人会话直接说话、或别人改了目标，父亲脑子里的假设就过时了。
- [ACP](08-观测与接入/ACP.md)：ACP 是编辑器用来驱动 Hermes 的一条 stdio JSON-RPC。
- [接入](08-观测与接入/接入.md)：外部程序驱动 Hermes 有三条协议，底下是同一个 `AIAgent`。
- [接口](08-观测与接入/接口.md)：API 服务器把 Hermes 暴露成兼容 OpenAI 的 HTTP 端点。
- [兼容接口](08-观测与接入/兼容接口.md)：Gateway 可以在同一端口上提供一小面 OpenAI 风格的对话补全。
- [上手](08-观测与接入/上手.md)：引导式上手根据用户的应用偏好和观察到的能力建议结果。
- [外借](08-观测与接入/外借.md)：MCP 是向另一个程序借工具。
- [按需](08-观测与接入/按需.md)：选中某个提供商的模型或嵌入请求时，OpenClaw 可以先看健康端点，没起来就拉起子进程，等到就绪再发请求。

## 三家共用的骨架

一次用户消息进入一个有硬上限的循环。模型若给出工具调用，结果必须成对写回，然后进入下一圈；若给出正文，先过闸门再结束。上下文变长时，先裁工具结果，再考虑摘要。系统提示词尽量保持稳定，中途插入的技能、记忆和转向走用户消息或工具结果。失败要留下明确的失败记录，不能被收尾文案盖成成功。
