# 多人

多人模式让几个受信任的人操作同一个 agent。它加上会话的创建者、当前主人和参与历史，以及在场。这些是可用性，不是安全边界。能操作这个 agent 的人，就能让它做这个 agent 能做的任何事。互不该看见对方会话、工具、凭据或文件的人，要分开的 agent，或分开的 Gateway 和主机。不要靠头像或筛选做隔离。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 信任 | 一台 Gateway 里的多人仍是一个信任域 | 多 profile 是同一操作者的岛。秘密按家目录失败关闭 | 本机用户 |
| 三层 | 创建者写一次。主人可改派。参与者最多新增 32 条，后台记，不拖回合 | 会话属于家目录。没有创建者与主人分离 | 转录文件的主人是本机用户 |
| 公开链接 | 和侧边栏的共享、只读、建议、草稿分开。持有者链接只读文本 | 无这套公开转录 URL | 无 |
| 模型账号 | 每人自己的 Gateway profile 账号。新会话优先它。改默认不改旧会话的钉 | 凭据池和 profile 的 `.env` | 客户端登录 |

## OpenClaw

已认证的控制界面管理员，带 `operator.admin`，可以对话式管理这台 Gateway 上的任何自动化，包括从别的频道或别人创建的任务。权威来自这次已准入的管理员回合，不把频道身份对到 Gateway profile。它不转移任务的创建者归属，也不转移排程执行政策。

侧边栏的共享、只读、建议和草稿，管的是已登录的人。这些设置都不产生公开链接。会话创建者或 Gateway 管理员可以显式打开公开访问。拿到由此产生的持有者 URL 的人，可以不登录就读已有和将来的对话文本。工具、推理、文件、图像、部件、隐藏消息和内部元数据排除在外。改派主人不转移这项权威。关掉公开访问，撤销这份发布的每一个 URL。已经下载的副本收不回来。

每一条会话最多三层归属：

- 创建者不可变。创建路径能证明是谁时，新会话写一次 `createdActor`。人的创建者保留来源：核对过的 Gateway profile、频道发送者，或未知的历史归属。只有 profile 创建者能得到隐含的创建者访问，包括经核对过的 profile 合并。对得上的频道、agent 或系统 id 不等于这个人。分享和可见性权威钉在创建者上，主人改了也还在。
- 主人可指派，像议题的负责人。默认是创建者。指派记下是谁、何时改的。侧边栏头像、主人筛选和人员排序跟当前主人。
- 参与者是历史：已认证的人、频道发送者和请求 agent，其已接受的输入指向这条会话。会话自己的 agent 和被动观看者不记。新身份的准入每条会话最多 32 条。修复可以保留已经更大的历史。参与是后台尽力记录，从不拖慢一轮。

显示名和头像在返回会话行时从当前 profile 或 agent 身份解析。参与者聚合不存显示标签。改名不必重写参与历史。

改派用 `sessions.assignOwner`，要 `operator.write`，以及认得出的调用者：已认证的 Gateway profile 或受信任的 agent 身份。按会话可见性授权。agent 主人 id 必须是已配置的 agent。改派之后，提示从「创建者」换成「主人」。

归档和恢复要创建者或 `operator.admin`，升级之后的已有会话也一样。不是创建者的被指派主人不再有这些权限。创建者不可用、或会话没有可用的 profile 创建者时，管理员可以从会话菜单归档或恢复。改派主人不改变归档权威。

`operator.sessions.write` 的已准入操作者，可以让 agent 用仅标签的补丁重命名自己创建的会话。其它会话设置、重置、删除和全局组控制仍受限。默认沙箱对这类非主人写者只露出重命名。显式的沙箱允许和拒绝仍然有效。`operator.write` 可以归档或恢复自己创建的会话，也可以停止自己创建或被指派的会话，仍受会话访问检查。

被指派的人还会在以后合格的回合上选中这条会话的个人说明，包括其他参与者发起的回合。这是提示选择，不是冒充。它不替换请求者的身份或特权，不转移仍属于创建者的分享权威，不授予或撤走访问。个人说明不是保密边界。

创建者来源跟随排程任务和继承的创建政策。必须沙箱是限制，不是 profile 身份的证据。丢掉创建者来源的历史自动化保留归属和内容，不获得猜出来的 profile 授予。改派主人不修复创建者权威。

每人可以给自己的 Gateway profile 登录模型账号。他们开始的新会话优先这个账号，而不是 Gateway 默认。选了账号不保证每一轮都记在这个账号上。有两次登录：Gateway 认出你，提供商再授权你的模型账号。CLI 和网页用选中 Gateway 上的同一份个人账号存储。共享服务器不把个人登录变成共享凭据。系统和 agent 的凭据是另一范围，在跑这份安装的机器上用 `models auth` 管。

四块分开：保存的账号属于你的 profile，一个提供商可以有多份。新聊天默认是新聊天优先的那份，改它不重新钉已有聊天。聊天选择是这一条聊天已经选中的账号，别人和分叉保留这份选择。登录尝试是临时的、可取消的。成功之前不保存账号。

## Hermes

一条会话属于一个家目录。多个人若共用一个进程里的多个 profile，秘密仍然按范围失败关闭，不从启动 profile 的环境里借。没有创建者、主人和参与者三层，也没有持有者 URL 只公开文本、藏起工具和推理。桌面的 Bot 聊天身份是 profile 加上标题恰好为「Bot Chat」的那一行，不是指派的主人。

## Claude Code

会话文件在本机用户的项目里。没有 Gateway 上的公开转录链接，也没有把主人改派给另一个人之后仍把分享权威留在创建者上的分层。
