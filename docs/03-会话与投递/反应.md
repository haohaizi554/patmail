# 反应

加或去掉表情反应用 `message` 的 `react`。加上时 `emoji` 必填。空字符串去掉这个机器人在该消息上的反应，仅限频道支持时。`remove: true` 去掉指定的一个表情，此时 `emoji` 不能空。飞书的 `clearAll` 配空表情，清掉这个机器人放上的每一个反应。取列表是另一个动作 `emoji-list`，不是 `react` 的参数。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 工具 | `message` 的 `react`。控制界面上对频道来源提示的反应，经同一动作镜像 | 消息反应是会话表面的能力，跟平台适配器 | 无频道反应工具 |
| 去掉 | 空表情去掉机器人的。指定去掉要非空表情 | 适配器能做的才做 | 无 |
| 不支持 | Nextcloud Talk 的去掉明确报错，不假装成功 | 工具错误写回 | 无 |
| 名额 | WhatsApp 每条消息一个机器人反应槽，新的替换旧的 | 按平台 | 无 |

## OpenClaw

Discord 和 Slack：空表情去掉该消息上这个机器人的全部反应。`remove: true` 只去掉指定的那个。

Nextcloud Talk 只能加。`emoji` 必须非空。去掉还没有接到删除调用。`remove: true` 以明确错误拒绝，而不是静默什么都不做。Talk 机器人要登记 `reaction` 能力。

Telegram：用 `emoji-list` 看允许的标准反应和数字自定义表情 id。`channels.telegram.actions.reactions` 同时管 `react` 和 `emoji-list`。列表返回当前聊天允许的反应。空表情去掉机器人的反应。`remove: true` 仍要非空表情才能过工具校验。

WhatsApp：空表情去掉机器人的反应。`remove: true` 在内部映成空表情，工具调用里仍要带 `emoji`。每条消息只有一个机器人反应槽。再发一个是替换，不是叠多个表情。

有状态反应的频道上，`trackToolCalls: true` 让运行时把这条已反应的消息复用为同一轮的状态生命周期。Discord 在干活期间保持选中的反应稳定，并用它表示真正的失败，而不是按工具换一圈表情。

频道不支持的形状要报错或按该频道页的合同处理。模型不该把「工具返回了成功」理解成每个频道都叠得上多个表情。

## Hermes

反应能否发出取决于会话所在的平台适配器，以及那次会话是否带着消息表面。工具集里有消息工具，不表示每个平台都有 WhatsApp 那种单槽替换，或飞书那种清空。失败回到工具结果，模型可以换一条路。

## Claude Code

没有频道表情反应。反馈在这次客户端的界面里。
