# 广播

实验性的广播让多个 agent 对同一条入站各跑各的会话。频道允许名单和群激活仍然有效。合格条目里，点到任一已配置的参与者，就可以满足房间的点名门，即使那个人不是平常路由到的 agent。一轮数有上限。名额在并行启动前同步占住，并行的参与者不能把预算花超。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 同一条消息 | `broadcast` 键是 `频道:对端`。每个 agent 自己的会话 | 一条入站进一个运行 profile 的会话 | 一条客户端会话 |
| 人数 | 最多 16 个参与者 | 委派是父回合派孩子，不是对一条群消息扇出多个 profile | 子代理由这一次会话派出 |
| 轮次 | `maxRounds` 默认 1，含首轮，1 到 4。`maxTurns` 默认等于人数，1 到 32 | 无这条协调者预算 | 无 |
| 点名 | 默认只按当前正文里显式的 `@` 选人。一个都没中就全选 | 绑定在准入之后，不是访问控制 | 无 |
| 草稿 | Telegram、Discord、Slack 的合格群线程关掉共享预览，免得互相覆盖 | 流式草稿按适配器合同 | 无 |

## OpenClaw

配置顶层的 `broadcast`。键如 `discord:123456789`、`slack:C0123`、`telegram:-100123`、`whatsapp:1203@g.us`。值可以是 agent id 数组，或严格对象。未知字段拒绝。无限定的对象条目不支持。同一个对端上，带频道限定的 WhatsApp 键优先于无限定键。旧的 WhatsApp 广播数组仍可用。

对象字段：`agents` 必填。`mentionGating` 默认真：选择被显式点到的参与者，一个都没匹配就选择全部。`maxRounds` 默认 1，含首轮。`maxTurns` 默认是参与者个数，统计协调者启动的 agent 运行，通过和失败都算。名额在并行发出之前同步保留。预算小于合格人数时，按配置顺序决定谁先启动。一轮可以通过分块、预览或消息工具发出多条平台消息。那些投递归这次运行和频道传输。`maxTurns` 不计数、不缓冲、也不封顶物理消息条数。

默认预算是每个已配置 agent 一轮。要每人跑两次，把 `maxRounds` 设为 2，并把 `maxTurns` 设成人数的两倍。

选择只用当前入站正文里算一次的显式 `@`。散文里的名字或单独的表情不选中参与者。提及模式先看该 agent 的 `groupChat.mentionPatterns`，再看全局，再看从身份推导的模式。希望点名分得开时，给参与者不同的模式。

普通频道路由仍要有一个 agent。绑定先选出谁做准入，再做群分发。房间被频道配置允许之后，一条点了多个参与者的消息可以让他们都回答首轮，并在预算内于后续轮次上补充。只点一个，就只选那一个进首轮。

Telegram、Discord 和 Slack 对合格的群线程关掉共享的预览和进度草稿，并发参与者不会互相覆盖草稿。最终回复、分块回复和消息工具发送仍然可用。

活的 WhatsApp 检验包括：一条被点名的群消息可以产生两个已配置 agent 各自可见的回复。

这和专道不同。专道是不同房间路由到不同 agent，减轻会话锁和上下文挤占。广播是一条消息同时进入多个会话，并用轮次和启动次数封顶。

## Hermes

一条入站先规范化身份，再进一个运行 profile。多个 profile 是多份家目录，不是对同一条群消息各开一轮再互相跟帖。委派的孩子在父回合里，完成回到父会话。看板工人按任务认领，不按一条入站的 `@` 扇出。

## Claude Code

没有频道广播。多个 agent 是这次编码会话里的子代理或人开的多个客户端。
