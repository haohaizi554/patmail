# 名单

访问组是起了名的发送者列表，定义一次，在频道允许名单里用 `accessGroup:<名字>` 引用。组自己什么都不授予。只有允许名单字段引用了它，它才参与判断。同一个人在不同频道的 id 不会自动翻译，两边都要写上。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 复用 | `accessGroups` 一次，私聊和群的发送者名单都可以引用 | 每个 profile 自己的允许名单。范围里没有就不借用启动环境 | 无频道名单 |
| 通配 | `"*"` 对每个引用该组的频道都检查。频道键只在那个频道匹配 | 平台前缀和规范键由适配器声明 | 无 |
| 匹配 | 用目标频道自己的 `allowFrom` 规则 | `platform_gate_env` | 无 |
| 群政策 | 组引用可以放进 `groupAllowFrom` | 群策略和允许名单仍是准入门 | 无 |

## OpenClaw

静态发送者组的类型是 `message.senders`。`members` 按消息频道 id 分键，另加 `"*"` 给每个频道共享的条目。匹配走目标频道平常的允许规则。Alice 若既有 Telegram id 又有 Discord id，两个都写在对应的频道键下。OpenClaw 不把一个频道的发送者 id 译成另一个。

私聊的 `allowFrom` 和群的 `groupAllowFrom`，以及某个空间上的用户列表，都可以混用组引用和直接条目。组没有被任何允许名单引用时，等于没写。引用了之后，仍要过该频道的私聊政策或群政策。允许名单不是点名门。点名决定要不要跑一轮。名单决定这个发送者能不能进来。

这和操作者范围不同。范围是连上 Gateway 之后能调哪些方法。访问组是消息频道上的发送者集合。两道都过，一条群消息才会成为用户请求。

## Hermes

允许名单、是否允许全部用户和群策略从该 profile 的秘密范围读。多路复用开着且范围已装上时，范围未命中返回默认，不读进程环境里另一份 profile 的名单。共享的名字列表不是 Hermes 的 `accessGroups`。每个平台的键由适配器声明，克隆 profile 时按所有权剥离频道材料。

## Claude Code

没有消息频道的发送者组。谁能让工具跑，由这次客户端的权限决定。
