# 蜂群

蜂群是在代码模式的脚本里扇出很多子代理。程序就是编排，没有另一套图语法。一两个孩子用普通的 `sessions_spawn`。大约五个以上、彼此相似、要用 `Promise.all` 这类控制流收结果时，才用收集者。收集者的孩子不发完成通知，也不能被转向。结果必须由脚本自己取回。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 编排 | 代码模式里的 JavaScript。`agents.run` | `delegate_task` 的批任务。同组一起报告要开独立完成 | Agent 工具。一次父回合里派出 |
| 默认 | 蜂群开着。显式 `tools.swarm: false` 才关。代码模式另外再开 | 批处理默认一组一次完成 | 无收集者开关 |
| 车道 | 每组自己的执行车道。同时 32。活孩子 50。一生 200 | 一次调用的单元占一个池槽。默认同时孩子 3 | 无组预算 |
| 通知 | `collect: true` 的孩子不发完成通知 | 后台完成进父会话的完成队列 | 侧链结束把摘要交回父回合 |
| 工具 | 打开蜂群不授予工具，也不绕过策略 | 叶子去掉再委派。编排者才保留 | 子代理工具可收窄 |

## OpenClaw

省略 `tools.swarm`、空对象、或只写限额，蜂群都是开的。`swarm: { enabled: false }` 关掉功能并留着限额。某个 agent 可以盖过全局：该 agent 的 `false` 只关掉它。只写限额的 agent 对象继承全局开关，所以全局关掉时，这份限额不会把它重新打开。`true` 则即使全局关掉也能为这个 agent 打开。

默认同时 32 个收集者孩子在该组的执行车道里跑，多出来的按 FIFO 排队。一组同时活着最多 50 个。一组一生最多 200 个，用来挡住失控的不断生成。`agents_wait` 一次接受的超时上限 600 秒，调用自己的默认是 30 秒。没写 `agentId` 时用请求者自己的 agent，除非配置了 `defaultAgentId`。未知或不允许的目标直接拒绝，不改派到别的 agent。已有的子代理允许名单仍然有效。

每组的车道独立于父会话普通的子代理上限。每个在跑的孩子要按一条模型流、一个代码模式隔离来预算。提高 `maxConcurrent` 增加模型和 Gateway 的占用，不提高每组活孩子数或一生总数。

要用 `agents.run`、`phase` 和 `log` 这些客人全局，代码模式得开着，蜂群也得开着。这些全局、类型声明和蜂群提示只在目录里有原生的 `sessions_spawn`、并且这次运行的允许名单准许它时才出现。同名的 MCP 工具不算。工具配置、允许或拒绝、提供商规则和沙箱都可以拿掉这个原生工具。代码模式在内部等收集者的结果，不要求单独允许 `agents_wait`。底层工具流则两个都要允许。

已有的 Codex 会话可以留着旧的工具目录。新会话才看得到当前的蜂群表面。

`outputSchema` 要结构化结果。`groupId` 把一批收成一组。打开蜂群从不因此多给工具。

## Hermes

一批 `tasks` 由父回合发出。默认整批一次完成。`delegation.independent_completions` 打开后，同一 `group` 的任务一起报告，没分组的各自报告。单元数不拿去卡池的容量，容量按活着的单元算。

没有「脚本即编排、收集者沉默、不能转向」这一层。叶子不能再派。要跨很多相似孩子，仍是同一次 `delegate_task` 的数组，深度和工具集由委派角色决定。后台委派不跨进程重启。

## Claude Code

扇出是 Agent 工具。每个孩子有侧链。父回合拿到摘要。没有一组 200 次的一生上限，也没有收集者故意不发完成通知。并行停在这次客户端和允许的工具上。
