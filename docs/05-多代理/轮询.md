# 轮询

同一条会话里按时钟再跑一轮，和「做到完成」、和「重启之后仍要跑」是三件事。`/loop` 活在当前会话里。`/goal` 由判断决定还做不做。cron 活在所有会话之外，并且扛得住进程重启。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 会话内时钟 | 心跳是主会话的周期回合，默认大约 30 分钟 | `/loop` 固定间隔，或按回复是否变化自行放慢 | `/loop` 是这套交互的来源 |
| 做到完 | 一会话一个目标。长期意图按事件，不按钟 | `/goal` 由判断给出完成、继续或堵住 | 计划模式是人批准的计划，不是时钟 |
| 重启之后 | cron 有自己的投递和漏跑记账 | cron 至少一次记账，`pending_slot` 防重复 | 无耐久 cron。会话结束循环就没了 |

## Hermes

`/loop` 在当前会话里按节奏重跑一段提示或一条斜杠命令。每次醒来是真正的 agent 回合：重新读现在的状态，做事，报告，然后安静到下一跳。

固定间隔写成 `30s`、`5m`、`2h`。第一跳在下一次空闲轮询就发生，网关大约每 15 秒扫一次。之后按间隔重复，直到停止条件或人把它停掉。

不写间隔时自定节奏。从地板开始，默认 1 分钟。回复不再变化就指数后退，2 分钟、4 分钟、8 分钟，直到天花板，默认 15 分钟。回复和上一次不同，节奏回到地板。变化用本地摘要比较，忽略时间戳。空等不再额外调用模型来判断「变了没有」。

它适合盯部署、队列、让测试变绿、在长会话里看错误率。过夜、要真实时刻表、终端关掉也要跑的，用 cron。有完成定义的单一目标用 `/goal`。

`/loop` 和 `/proactive` 是同一条命令的两个名字。循环一条斜杠命令时，整个参数就是那条命令，例如每 10 分钟 `/recap`。

循环注入的是用户回合，保持角色交替。它不改系统提示。会话被压缩或挂起时，循环跟着这条会话的命运，不另存一份跨重启的任务行。

## OpenClaw

心跳在主会话里按间隔跑一轮 agent，默认大约 30 分钟，用来看有没有到期的事。它不是 `/loop` 那种「把这句话再跑一遍」。完成通知回到把工作启动的那条会话，不借用心跳的投递目标。

长期意图按事件触发，不按钟。钟属于 cron。cron 每次触发一份自己的会话，漏跑按半个周期记账，并有上限。

后台命令完成时叫醒原会话，那是进程事件，不是循环命令。提醒不用 `sleep` 轮询。

## Claude Code

`/loop` 在客户端会话里重复一段提示。离开会话或进程退出，循环停止。没有 Hermes 的自定节奏地板和天花板写在这棵还原树的契约里时，以客户端实现为准。计划模式在人批准计划之前限制写操作。它不按分钟醒来。

要在机器重启后仍运行，这三家里只有 cron 或等价的外部调度器做得到。`/loop` 故意不做。
