# 目标

目标是贴在一次会话上的结果，让下一轮还知道要把它做完。它不是定时任务，不是事件触发，也不是一块可以交给别人的看板。三家里，OpenClaw 把目标留在会话状态里，由人暂停和清除。Hermes 在每轮之后用一个轻量判断决定要不要自动继续。Claude Code 的计划模式是先写计划再改文件，没有跨回合的自动续跑。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 一份会话几个 | 一个。再创建会失败，直到清除 | 一个站立目标，可用新文本替换 | 计划模式是开关，不是目标行 |
| 谁能暂停、清除 | 人，通过 `/goal`。模型不行 | 人。模型不自行清掉循环 | 人退出计划模式 |
| 怎么知道做完 | 模型在核对之后 `update_goal complete`。人也可以 `/goal complete` | 判断模型给出 `done`，或质量门通过 | 没有回合后的判断模型 |
| 上限 | 可选的 token 预算，从创建时的新鲜用量算起 | 默认大约 20 轮。恢复时计数回到 0 | 计划本身不带轮数预算 |
| 和别的工作 | 不是 cron，不是长期意图，不是子代理 | 不创建看板卡片 | 任务板是会话内清单 |

## OpenClaw

目标跟着会话键走，进程重启还在。`/goal`、模型工具和 TUI 页脚看到的是同一份。沙箱若用了另一份策略会话，脱离的命令完成仍回到原来那条用户线程，下一轮还能看见同一个目标。

一条会话同时只有一个目标。已知动作是 status、start、set、create、edit、pause、resume、complete、done、block、blocked、clear。`/goal` 后面如果不是这些词，就当成新目标。`start` 和 `edit` 保留目标内部的换行和缩进，只去掉首尾空白。

状态：

| 状态 | 含义 |
|---|---|
| `active` | 正在追 | 
| `paused` | 人暂停了，或这次运行以错误或超时结束。普通新消息不会自动恢复。重试能恢复的错误不暂停 |
| `blocked` | 人或 agent 报了真实阻塞 |
| `budget_limited` | token 预算到了。目标还在，恢复后从当前新鲜用量重新开一扇窗 |
| `usage_limited` | 留给以后的用量停止。恢复方式相同 |
| `complete` | 终态。再开一个之前要 clear。重复完成保留原来的完成时间 |

`/new` 和 `/reset` 清掉目标，因为它们故意换一份新上下文。

token 预算只有 `create_goal` 能设，`/goal start` 没有这个旗。从目标创建时的新鲜会话用量算起。当时若只有过期或未知快照，就等下一次新鲜快照再当基线，创建之前花掉的 token 不算进预算。没要求预算时，模型应省略这个参数。到预算后变成 `budget_limited`，不删目标。这不是账单帽，提供商配额和上下文窗口仍走原来的用量控制。

模型有三件工具。`get_goal` 读状态、目标和用量。`create_goal` 只在用户或系统说明明确要求时创建，已有目标则失败。`update_goal` 只能标成 `complete` 或 `blocked`。模型不能悄悄暂停、恢复、清除或换一个目标。完成必须对照整项目标核对过，没有必做的剩余。阻塞要同一种阻塞条件连续三个目标回合，普通困难和没打磨完不算。恢复之后这三个回合重新数。预算快用完不能把没做完的工作标成完成。更新状态不代替给用户的回复。

每个带活动目标的用户回合注入一行用户角色上下文：目标文本、继续推进、完全达成前保持活动、同一种阻塞连续三回合才 block、更新之后仍要给出可见的最终回复。长目标会截断。暂停、阻塞、超预算、已完成都不注入，所以人按下的停止会一直有效，直到恢复。

控制界面里，目标模式的文字是字面量。`clear` 和 `/stop` 不会在这个模式里变成命令。开始目标时，目标、用户回合和 run 准入一起保存，然后才确认发送。准入失败则草稿还在，不创建目标。开始和恢复要求内置运行时，以及一份空闲、历史可恢复的本地会话。原生 Codex 和其它外部运行时不排队、不转向进另一轮。

## Hermes

`/goal` 在每一轮结束后用轻量判断模型看最后一次助手回复是否满足目标。不满足就往同一会话送一条继续提示。直到判断为完成、人暂停或清除、或轮数用尽。默认提示是大约 20 轮的预算。这是 Ralph 式循环：目标活过回合边界，人不需要每轮再说「继续」。

判断结果是 `done`、`continue` 或 `blocked`。继续时能看见原因和已用轮数。暂停留下目标。恢复把轮数计回 0。清除丢掉目标。

`/goal -- <文本>` 用来写以控制词开头的目标正文。没有 `--` 时，`pause`、`resume` 这类词会执行控制，后面的文字被忽略。`/goal draft` 先把口语收成完成合同再设上，并开始第一轮。起草不可用时退回自由文本目标。`draft` 必须是整词子命令，`/goal drafting docs` 里的 drafting 是目标正文。

`/goal wait <pid>` 在后台进程还在跑时停掉每轮催促，进程退出再自动恢复。`unwait` 立刻拿掉这道等待。质量门是必须通过的 shell 命令，判断为完成之前要先过门。网关里添加质量门需要明确配置的管理员。列出、去掉和清空门仍可用于恢复。

CLI、TUI、桌面、面板和消息网关共用一个 `/goal` 解析和落库。ACP 目前不提供 `/goal`。消息平台保留自己的访问规则。渲染和排程按表面不同，解析和持久化相同。

`/goal` 不创建看板卡片，不把工作派给另一个 profile，也不扇出。暂停或清除这个聊天里的目标，也不会去领或移动看板任务。看板卡片可以带 `--goal`，那是在这一张卡片自己的 worker 会话里借用同一套继续引擎，不是把聊天目标交到板上。

## 长期意图

OpenClaw 的长期意图是另一层：事件出现时做什么，不按钟点跑。钟点用 cron。季度愿望写进带复查日期的 Markdown，既不是任务也不是触发器。

只有 `commands.ownerAllowFrom` 认得出的渠道主人能用 `intent` 工具创建、列出或取消。其他人看不到这件工具。已认证的管理员和本地 CLI 可以查看和取消已有意图。创建必须有已认证的渠道和发送者身份，缺一就拒绝。

默认冷却 24 小时，最多触发 3 次，90 天过期。默认范围是当前渠道和当前发送者。`anywhere` 或 `anyone` 仍要求创建时的发送者身份，否则后来的渠道回合无法执行一个没有主人的主体。

匹配不用模型。先用 FTS 做关键词预过滤，至少一条触发项里的每个词都出现才算候选。然后在一次同步事务里复核渠道、发送者、过期、冷却和次数，以 SQLite 为准。每轮最多扫 256 条，避免嘈杂触发拖住回复。命中时主回复收到一块有界的隐藏上下文。触发次数加一。次数用尽变成 `done`，过期变成 `expired`。冷却和过期的维护挂在已有的心跳和 cron 回复钩子上，不另起定时器。钩子超时之后的迟到完成不能消耗一次触发。取消必须明示，普通对话不会被推断成取消。

Hermes 没有这层事件意图。要按钟点跑用 cron。要在这个聊天里做到完用 `/goal`。

## Claude Code

`EnterPlanMode` 和 `ExitPlanMode` 把「先说清再改」做成权限状态。退出计划模式可以要求人在场。`VerifyPlanExecution` 是一次核对工具，不是每轮之后的判断模型。会话内的任务工具是清单，重启之后的耐久协作在 Hermes 看板上，不在这份清单里。

没有「同一种阻塞连续三回合才允许标阻塞」的目标行，也没有默认 20 轮的自动续跑。人要继续，就再发一条消息，或使用自己的斜杠命令。
