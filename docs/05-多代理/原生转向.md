# 原生转向

Codex 运行时上，活动回合的队列转向映射到 app-server 的 `turn/steer`。默认队列模式是 `steer` 时，OpenClaw 把转向模式的聊天消息按配置的安静窗口收成一批，按到达顺序合成一次 `turn/steer`。内联图像和已存附件保持原来的图像顺序。已存图像用和新回合相同的注水、大小限制和文件系统限制。附件准备不了，或转向被拒绝，整条消息留在队列里等后续回合。准备和 `turn/steer` 的确认都不表示转录已经提交。发给 Codex 但没有确认的转录提交，不会自动重放。

## 对照

| | OpenClaw 嵌入 | Codex 原生 | Hermes |
|---|---|---|---|
| 打断 | 不打断已经在跑的工具调用。后续调用前再看转向 | 一次 `turn/steer`。确认不是转录提交 | `/steer` 是工具结果之后的用户行 |
| 审查和手动压缩 | 普通转向规则 | 可以拒绝同一轮的转向。OpenClaw 等活动运行结束再开始提示 | 压缩有自己的租约 |
| 自动压缩 | 裁剪和压缩另计 | 普通回合里的自动压缩仍可转向。Codex 把输入缓冲到下一个模型边界 | 压缩是唯一改已发送上下文的路径 |
| 诊断上传 | 轨迹导出要批准，且打红 | `/diagnostics` 获准才调 `feedback/upload`。拒绝则不印 Codex id、不上传 | 监控不含内容 |

## OpenClaw

Codex 确认转录提交之后，OpenClaw 先保存已完成的可见助手项，再保存被转向的用户消息，包括工具或休眠交接之前的项。每一项保持自己的身份，后来的转向不重复它。这段历史前缀和这一轮最终答案的选择是分开的。提交确认的是输入进了历史。它不证明随后的模型请求已经读过它。

审查回合和手动压缩回合可以拒绝同一轮的转向。那时 OpenClaw 等活动运行结束，再开始这条提示。普通回合内部的自动压缩仍保持转向可用。Codex 把输入缓冲到下一个模型边界。

要用默认排队而不是转向，用 `/queue followup` 或 `/queue collect`。

Codex 若报告进程级的诊断日志保存失败，OpenClaw 在 Gateway 日志里记一条警告。每个原生通知在收到时记一次，不在共享那个 app-server 的每个对话里重复。新的 app-server 可以再报一次新的失败。这条路由不修复原生日志失败，也不上传诊断。警告本身不表示对话状态丢了。其它针对任务、配置和无法识别的警告仍进聊天。日志失败从不打断原生连接。这些只给操作者的通知不退回聊天。

`/diagnostics` 在原生 Codex 会话上获准之后，OpenClaw 还对相关 Codex 线程调用 `feedback/upload`，包括列出的线程和可用时生出的 Codex 子线程的日志。上传走 Codex 到 OpenAI 的正常反馈路径。那个 app-server 里关掉了反馈，命令返回 app-server 的错误。完成的诊断回复列出频道、OpenClaw 会话 id、Codex 线程 id，以及已发送线程的本地 `codex resume` 命令。拒绝或忽略批准时，不印这些 Codex id，也不发送 Codex 反馈。上传不代替本地的 Gateway 诊断导出。只想给当前附着的线程做 Codex 反馈、不要完整的 Gateway 诊断包时，用 `/codex diagnostics`。

## Hermes

转向是一条独立的用户消息，放在工具结果之后，不涂进已经落盘的工具行。没有 `turn/steer` 的确认和转录提交分开、未确认就不自动重放这一条原生合同。诊断不把线程日志上传到模型提供商，除非用户自己走别的路径。

## Claude Code

队列和工具执行在客户端。没有 app-server 的 `turn/steer`，也没有「诊断批准才上传线程日志、拒绝则不印线程 id」。
