# 镜像

选中的模型走 Codex 运行时时，Codex 的 app-server 拥有原生的令牌压力压缩和手动线程压缩。OpenClaw 另有自己的转录镜像。`compaction.maxActiveTranscriptBytes` 设成正数时，普通回合和心跳之前检查这份镜像。字节守卫触发，就要选中的宿主上下文引擎做语义压缩，然后才准入这一轮。这次宿主压缩本身不替换、不改写 Codex 的规范原生线程。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 谁压原生线程 | Codex。宿主镜像是另一份 | 上下文压缩器改的是 Hermes 自己的会话 | 客户端分层压缩 |
| 同步失败 | 宿主已提交的压缩不回滚。原生同步是次要的 | 压缩在租约里提交。失败不留半截摘要当已压缩 | 自动压缩失败有断路器 |
| 超时 | 请求原生中断。围栏一直拿到 Codex 报终态或确认中断 | 压缩超时有自己的提交策略 | 有超时 |
| 换代 | 上下文引擎把 OpenClaw 会话换代之后，下一次仍继续同一条原生线程。只有记下的前驱能被收养 | 压缩保持同一个会话 id | 侧链不接这条线程 |

## OpenClaw

宿主镜像压缩提交之后，OpenClaw 可以请求 `thread/compact/start`，去同步一条合格的原生线程。这次请求是次要的。宿主隔离的操作，或原生权威被限制的绑定，不发它。原生同步不可用或失败，不回滚已经提交的宿主压缩。

显式压缩，例如 `/compact` 或插件请求的手动压缩，用 `thread/compact/start` 启动原生压缩。共享客户端的租约一直开着，直到 Codex 发出匹配的 `contextCompaction` 完成项，然后把压缩回合报成完成。终局回合超过配置的压缩超时，OpenClaw 请求原生回合中断。租约和每线程的压缩围栏一直拿着，直到 Codex 报告终态或确认中断 RPC。宽限期内没有确认，就先退役这条连接，再释放围栏。远程连接还拆掉匹配的线程绑定，避免后来的工作叠在未确认的远程回合上。退役连接上的其它回合失败，可以在新客户端上重试。客户端关闭、请求取消或压缩回合失败，返回失败的操作。自动的原生令牌压力压缩仍是 Codex 的事。除了上面的次要同步，OpenClaw 只为显式的手动请求启动原生压缩。

单独的冷压缩不跑提示构建钩子，也不建立普通回合的配置。操作结束后释放订阅。下一次普通回合走正常的恢复路径，核对配置并刷新通用策略。热压缩只归还它实际拿到的配置所有权。

上下文引擎的压缩若轮换了 OpenClaw 的会话代，下一次 Codex 回合、压缩或旁问仍继续同一条原生线程，即使 Gateway 在提交新代之后立刻停了。只有该会话键下记下的前驱可以被收养。恢复的线程执行之前，原生工具目录、连接所有权和监督检查仍然适用。

成功的本地回绕或分支切换是上下文变化。它使旧的原生绑定失效，这是转录变更的一部分，并释放绑定。

## Hermes

压缩改的是这一条 Hermes 会话。没有「宿主镜像提交了、原生线程同步失败也不回滚」这一对所有权。换代若发生，是压缩保持稳定会话 id，或另开压缩谱系，取决于那条路径。Codex 原生线程不在这套合同里。

## Claude Code

压缩在客户端的请求前分层里。没有 app-server 拥有规范线程、宿主只拥有镜像这一分界。手动压缩和自动压缩都在同一条客户端历史上看。
