# 云机

云工人把编码工作放到一台用完即弃的机器上。会话仍在侧边栏里。转录归 Gateway。机器死了或做完了就丢掉。接受的工作区变更和放置记录留在 Gateway。登记是环境所有的，并且可以重放。清理确认释放或确认不存在之后才结束，不会为了找租约再跑一遍开通。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 主人 | 转录在 Gateway。云上是短暂的盒子 | 终端后端可以是 SSH 或容器。会话在家目录的库里 | 本机工作区或 worktree |
| 登记 | 开通前先持久化一份设置身份。第一台认证设备绑死这个环境 | 子进程环境按被服务的 profile 建，不复制启动 profile | 无云节点登记 |
| 失败 | 租约还没返回就失败时，清理解析原来的操作句柄，不重跑开通 | 更新先排水。坏库不继续写 | 进程退出，JSONL 还在 |
| 旧主机 | 节点宿主太旧，完不成工作区排空，保持围住 | 运行时和桌面分开更新。旧后端有窄的回退 | 客户端版本即运行时 |

## OpenClaw

捆绑的 Crabbox 提供商启动盒子，做 profile 设置，再跑 `openclaw connect --ephemeral`。有暖镜像的、来自 Gateway 的项目，在登记节点之前准备已提交的检出和 Node 运行时以便捕获。一个 Crabbox profile 同时支持 OpenClaw 的 `worker-turn` 和 Codex 的 `remote-exec`，走同一条已登记的出站节点传输。OpenClaw 启动受限的 `openclaw worker` 子进程。Codex 在节点上跑它管理的执行服务器，应用服务器和模型认证留在 Gateway。

Gateway 在节点登记前持久化一份设置身份，把第一台认证过的设备身份绑到这个精确环境，开通恢复时复用耐久的设备令牌。初次登记和重放都只为那个节点进程打开工人托管，不改耐久的工人宿主配置。收回或销毁会释放云租约，并去掉这份环境所有的节点配对。开通在返回租约之前失败时，清理解析原操作的句柄，不重跑开通、设置或登记。句柄可以指向一台从未创建的机器。清理只在提供商确认释放或确认不存在之后完成。拆除等待进行中的提供商操作和心跳落定。Crabbox 的释放请求和清理观察有分开的截止时间。OpenClaw 在终止一条卡住的停止命令之前，把两份都预留好。

云会话可以从 GitHub 仓库 URL 和可选的引用开始，Gateway 上不必先有检出。选中的节点取仓库，钉住解析到的提交，并创建会话分支。Gateway 保留源元数据和已接受变更的不可变检查点，不保留检出的副本。只有 SSH 载体的提供商不能准备这种仅仓库的会话。节点宿主运行时必须和工人包一样新。更旧的宿主完不成要求的工作区排空，保持围住。更新配对的节点宿主或重新开通云工人，再重试。

从已有 Gateway 检出创建的会话，仍保留会话自己的托管 worktree 镜像。那条流保留本地和未发布的源。默认 100 份是清理目标，不是准入上限。Gateway 的磁盘检查仍在。

「新工作区」从空开始，不给仓库。OpenClaw 建一个隔离的会话工作区，有自己的内部 Git 元数据，以及同样的托管快照、收回、恢复和清理。它不复制 agent 平常的工作区。Git 是内部依赖。不需要用户仓库或初始提交。

缺少设置环境值、当前 Crabbox CLI 或后端拒绝、或提供商元数据变了，都不能证明更早的尝试什么都没分配。这些失败用原来的操作身份仍可重试。清理解析那个句柄并重试拆除，直到提供商确认释放或确认不存在。它从不为了发现租约而重跑开通、设置或登记。畸形的不可变 profile 永久失败。政策和设置拒绝只在确认清理之后才变成永久。

云工人默认不加入。没配置 profile 时，客户端藏起云目的地，profile 分发不可用。`sessions.dispatch` 对合格的配对设备目标仍可能广告。配置 schema 和只读的环境列表、状态方法仍可用于配置和发现。

## Hermes

终端可以在本机、Docker、SSH 或其它后端。会话库在 profile 的家目录。没有「转录留在 Gateway、机器用完丢弃、登记身份在开通前写死、清理不重跑开通」这一套云工人。远程后端的文件可见性在挂载上解决。子进程环境按被服务的 profile 建，剥掉启动 profile 的钥匙。

## Claude Code

工作在打开会话的那台机器或它的 worktree 上。没有出站节点、短暂云盒和 Gateway 持有的转录分家。
