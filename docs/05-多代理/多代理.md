# 多代理

三家的「另一个 agent」不是同一种东西。OpenClaw 先有路由上的多个 persona，再有一次回合里派出去的子 run。Hermes 的子代理是父回合里的隔离循环，进程重启就没了。Claude Code 的子代理、任务板和团队是三层，都绑在一次编码会话上。

## OpenClaw：一个 Gateway 里的多个 agent

一个 agent 是一整份范围：工作区、`agentDir`（认证、模型注册表）、会话库 `<agentDir>/openclaw-agent.sqlite`。默认 agent 是 `main`，主会话键 `agent:main:main`，工作区在状态目录下的 `workspace`。其它 agent 默认 `workspace-<agentId>`。`agentDir` 不能复用，否则认证和会话撞车。

入站消息靠 binding 把渠道账号指到 agent。技能从该 agent 工作区和共享根加载，再按允许名单过滤。`agents.entries.*.skills` 是替换默认名单，不是合并。插件自己的存储不会因为多了一个 agent 就自动切开。

工作区是默认工作目录，不是沙箱。相对路径落在工作区里，绝对路径在没开沙箱时可以碰到主机其它位置。

创建来源记成 `operator`、`agent` 或 `claw`。agent 请求再建一个 agent 时，系统 agent 把操作摆给操作者，批准之后才创建。`openclaw agents list --tree` 看这棵创建关系。创建者删了，来源仍留在历史上，它的子节点显示在树根。

二级 agent 的 OAuth 过期时，可以读到继承主人同一 profile 上更新的 token，但不把 refresh token 拷进二级库。要独立账号就在那个 agent 上单独登录。手抄凭据只抄可携带的静态 key，不抄 OAuth 材料。

## OpenClaw：一次回合里的子 run 和队列

同一 `sessionKey` 的 CLI、嵌入式和 Codex run 共用 `session:<key>` 车道，先排队再拿执行权，换运行时也不能并行开一轮。入站会话然后再进全局 `main` 车道，并行度是 `agents.defaults.maxConcurrent`。未配置时 `main` 的上限是 `max(8, CPU 并行度 × 4)`。普通子代理用父会话的预算，默认每父 8。Swarm 收集者用组预算，默认 32。

渠道默认 `steer`：消息在工具执行中也能注进当前 run。一条助手消息里，第一个已经开始的调用会跑完，尚未开始的串行尾巴可以被跳过；并行批不会为了转向丢掉调用。每批结束、停止钩子之前检查转向，并把它放在工具结果之后、下一次模型决定之前。运行时不接受转向时，等这轮结束再开新轮。`followup` 只排队。`collect` 在安静窗口后收成一轮，不同渠道或线程仍分开，以免路由串了。`interrupt` 中止当前 run，跑最新一条。

防抖默认 500 毫秒。每会话最多大约 20 条，满了默认丢掉最旧的并留下简短摘要。排队或委派不提升权限：收集和转向要求操作者来源和工具权限兼容，否则按 FIFO 等，不借用当前发送者的权限。已接受的回合在客户端断开后可以继续，但不会延长已撤销的设备权限。

子代理深度和每个控制器的孩子数在循环笔记里：深度 5，每控制器 5 个。上下文引擎可以在 spawn 前准备共享状态，失败时用返回的回滚句柄撤掉。`lightContext` 的隔离子代理跳过这份准备，从轻量 bootstrap 开始。提示词把 `running` 和子 run 结束分开：孩子结束只说明那一次 run 结束。将来再看用 cron，不在 `exec` 里空转。

嵌入式准备每 16 个阶段或至少 8 毫秒同步分发就让一次事件循环，已经在跑的阶段不抢占。打字指示在入队时就发，用户不用等车道。

## Hermes：delegate 和生命周期 API

父回合预算默认 500 次迭代。子代理用自己的 `IterationBudget`，`delegation.max_iterations` 默认 250。两边不共用一个计数器。

`delegate_task` 有两种形状。单任务带目标和可选上下文、工具集。批任务是 `tasks` 数组，同时孩子数默认 3。`background=true` 时父回合先拿到委派 id，结果以后从完成队列回来。默认一批是一次完成；`delegation.independent_completions` 打开后，同一 `group` 的任务一起报告，没分组的各自报告。一次调用的各个单元占一个池槽，单元数不拿去卡容量。

`leaf` 去掉再委派、澄清、记忆、发消息和 cron，保留代码执行。`orchestrator` 保留再委派，要 `delegation.orchestrator_enabled`，深度默认 2。深度大于 0 的委派总是同步，这样停止能顺着孩子自己的活动孩子递归下去。

子进程的后台进程在拆卸时杀掉，完成通知不进父会话。`process_manage(action="handoff")` 把进程主人改成父任务，完成和回收跟新主人走。没交出去的记在结果的 `orphaned_processes` 上。子代理的代码执行内核键是 `<父主人>::child::<子会话>`，孩子在跑时钉住，不被 LRU 挤掉，`cleanup` 时释放。

`output_schema` 对不上时，重试一次仍失败就保持 `completed`，原文留在 `summary`，并带 `schema_valid: false`。不丢孩子的结果。

后台委派活在本进程。要熬过重启就用 cron，或 `terminal(background=True, notify_on_complete=True)`。停止要同时打到活动孩子和已经脱离的后台单元：网关 `/stop`、TUI `session.interrupt`、ACP cancel、CLI `/stop` 都调用 `interrupt_for_session`。中断条目的摘要用孩子最后一段真实助手文本。

插件不直接碰 `delegate_tool`。`ctx.subagent_lifecycle` 在有父回合时才能 `launch`。没有活动父会话就失败关闭。句柄是版本化的不透明能力，伪造的返回 `UNKNOWN`。取消只请求在下一个安全点停下，终态以 `wait` 或 `result` 为准。终态结果不可变，最多大约 32000 字符，不含 transcript 和隐藏推理，带稳定哈希。进程内保留大约一小时。重启后 `reconnect` 返回不可用，不另起一个替代孩子。工具集只能比父更窄。工作目录覆盖和单次超时在能保证隔离之前会被拒绝。

父会话里的 `_last_resolved_tool_names` 是进程全局。子运行包一层保存和恢复，中间读到的可能是孩子的工具名。

## Claude Code

`Agent` 工具生成 `agentId`，包一层子代理上下文，再进同一个 `query`。转录在项目会话下的 `subagents/agent-<id>.jsonl`，可以 resume。general-purpose 工具齐全。Explore 和 Plan 去掉写和再派子代理。verification 限制改项目文件。

主循环看见 `agentId` 就跳过主线程专有的事：延迟探测、工具调用的小模型摘要、进程级键鼠锁的清理、周期任务摘要、停止钩子里的记忆抽取。这些锁是进程级变量，子代理去释放，主线程会以为锁已经不在自己手里。

任务工具是另一层：创建、读取、列出、更新、停止、读输出。团队工具负责建团队、解散和给同伴发消息。协调器在 `src/coordinator` 和 `src/tasks`，不在 `queryLoop` 里面。和 OpenClaw 的渠道子会话、Hermes 的 `delegate_task` 相比，这层绑在编码会话的任务板上。

计划模式和 worktree 是编码隔离，不是子代理：先写计划再改；改动放进单独的 git worktree。`VerifyPlanExecutionTool` 把核对做成一次工具调用。

MCP 工具名单只在两轮之间刷新。一轮进行中不改工具 schema，避免把已经发出的 `tool_use` 和下一轮的名单对不上。
