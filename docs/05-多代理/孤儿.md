# 孤儿

Codex 的 app-server 在 Gateway 硬停之后可能还活着。POSIX 上，每次新开 stdio 孩子之前，OpenClaw 先查已登记的孤儿。启动时还有一次尽力的后台清扫。开孩子之前的检查才是权威。身份写进当前状态目录的 SQLite 插件库，发生在发给 Codex `initialize` 之前。孩子不能在登记耐久之前开始原生回合。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 何时登记 | 发 `initialize` 之前。父和子的进程身份进库 | 进程登记按启动时间和 pid。回收不靠命令名扫描 | 客户端进程随会话 |
| 杀谁 | 只杀登记过的孩子，且原来的 OpenClaw 父进程已经不在 | 先信号父进程，再处理还活着的后代 | 无 Gateway 孤儿清扫 |
| 认错 | 命令行只存摘要。活进程的指纹必须对上才发信号 | 启动时间变了就当 pid 被复用 | 无 |
| 查不清 | 新的 stdio 连接失败，不再生一个孩子。Windows 没有这套登记和恢复 | 查不清就不要当它已死 | 无 |

## OpenClaw

清理只针对登记过的孩子，并且原来的父进程已经不在跑。核对进程 id、启动时间和进程组，再终止孤儿和能发现的后代。记下了命令行指纹时，活进程也必须对上。耐久登记只存摘要，不存原始参数。另一台活着的 OpenClaw、别的状态目录下的登记，以及外部管理的 WebSocket 或 Unix 套接字 app-server，都不动。这些可移植的进程检查不是操作系统级的原子所有权保证。在检查之前已经独立改了父进程的后代，发现不了。

Linux 直接读 `/proc`，包括启动 id 和进程起始 tick。Alpine 和 BusyBox 不需要 `procps`。启动时的身份和命令检查共用 10 秒期限。空的命令行在期限内等待，只要同一套活进程身份仍有效。登记仍要可用的命令指纹。读不了或身份变了就失败。macOS 用固定区域和时区的原生 `ps`。登记检查只看观察者和相关的父子进程。无关的、读不了的进程不挡住这些检查。破坏性清理在发信号前仍要完整的进程树检查和新的身份核对。

必需的进程查不清，或有界清理不能确认登记的孤儿已经消失，新的 stdio 连接就失败，不再生一个孩子。期限失败去看主机负载和 Gateway 日志。拒绝访问去看 Linux 的 `/proc` 或 macOS 的 `ps` 权限。不要为了超时去放宽权限。清理停不掉已核实的孤儿，先检查并停掉那个进程再重试。清理预算用完，重试把剩下的登记做完。

这套恢复依赖生成时的登记。它不发现旧版本留下的未登记孩子，也不扫描命令名来推断所有权。Windows 没有对等的孤儿登记或恢复。

## Hermes

后台进程先对记录的父进程发终止，等它自己收后代，再处理快照里还活着的。pid 被复用时跳过强杀。这和 Codex app-server 的「登记摘要、父进程不在才清、查不清就拒绝再开一个」不是同一条路径。Hermes 不把 Codex 的 stdio 孩子登记在 OpenClaw 的插件库里。

## Claude Code

没有 Gateway 进程在硬停之后按状态目录里的登记去收 app-server。会话在客户端。进程没了，下一次是新的客户端连接。
