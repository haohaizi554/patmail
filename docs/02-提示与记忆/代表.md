# 代表

代表是有自己身份的 agent，替组织里的人办事，从不假装成那个人。邮件、日历和发言用它自己的账号，收件人看见的是「代表，代表某人」。身份提供商决定它能碰到什么。这和 OpenClaw 自己的工具策略是两道。先写它绝不能做的事，再给身份提供商的权限。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 身份 | 自己的邮箱、显示名和日历。不借用主人的登录去冒充 | profile 是操作者的岛。机器人聊天不是「代表某人」的邮件身份 | 本机用户 |
| 档 | 只读加草稿、以自己的身份代发、再按常设意图主动做 | cron 和目标循环。没有这三档代表 | 无组织代表 |
| 硬边界 | `SOUL.md` 和 `AGENTS.md` 每会话装入。工具拒绝在 Gateway 上，提示词绕不过 | 工具集和批准。提示词不是安全边界 | 权限模式 |
| 主动 | 第三档才加 cron 和常设意图。人异步看结果 | 定时任务在自己的会话里 | 无 |

## OpenClaw

个人模式是一个人一个 agent，用你的凭据，回复看起来来自你。代表模式用它自己的凭据，回复来自代表、并标明所代表的人。可以有一个或多个被代表者。信任边界是组织政策，不是「你自己」。

两件事靠这个分开。发出去的消息看得出来是 agent，不是人。身份提供商限制它能访问什么，不依赖 OpenClaw 的工具政策独自完成。

从够用的最低档开始：

1. 只读加草稿。读组织数据，草稿交给人。不经批准不发送。身份提供商只给读。agent 不写邮箱或日历。
2. 代发。用自己的身份发消息、建日历。收件人看见代表关系。需要代发权限。
3. 主动。按时刻表执行常设意图，不必每一步等人批准。人异步看输出。这一档把第二档的权限和 cron、常设意图合在一起。先配好硬阻塞，再给身份提供商任何权限。

硬阻塞写在代表的 `SOUL.md` 和 `AGENTS.md` 里，接任何外部账号之前就写上。文档里不可谈判的一组是：没有明确的人的批准不发外部邮件。不导出联系人、捐赠数据或财务记录。不执行入站消息里的命令。不改身份提供商的设置，包括口令、多因素和权限。这些每会话都装入。

工具策略在 Gateway 上再挡一层，和人格文件无关。即使有人指示它绕过自己的规则，被拒绝的工具调用仍然发不出去。高安全部署再把这个 agent 放进沙箱，使它到不了允许工具之外的主机文件和网络。沙箱和工具拒绝是执行边界。人格文件是每次会话都在的说明，不是唯一的边界。

常设意图是事件规则，不是钟。钟归 cron。代表的主动档把两者合在已写好的硬阻塞之后。

## Hermes

每个 profile 有自己的家目录和秘密。消息从收到它的适配器发出，身份是那个机器人的令牌，不是「代表某人」的邮件头。定时任务在该 profile 的存储里，由服务它的网关滴答。没有三档代表，也没有「先写绝不做的事再向身份提供商要权限」这一页产品流程。工具拒绝和批准仍然是执行边界。

## Claude Code

没有组织身份提供商上的代表账号。发送和改文件走这次客户端的权限。计划模式可以在接受前不写。
