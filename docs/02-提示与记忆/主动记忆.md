# 主动记忆

主动记忆是对话会话上的深召回。默认的 `escalate` 只在这句话像是在问过去、而且确定性记忆通道没有打中可信触发时，才挡住主回复去跑一个召回子代理。心跳、一次性无头运行、子代理和会话之间的投递不跑它。召回失败只少一段隐藏上下文，主回复照常走。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 何时深挖 | 确定性通道弱或空，且这句话有召回意图 | 记忆提供者在回合里 `prefetch` / `sync_turn`。没有默认的阻塞召回子代理 | 回合开始可预取，结果是附件 |
| 谁能被搜 | 插件启用，且是持久的、面向人的会话 | 一个外部提供者，或内置存储。cron 默认跳过 | 会话记忆目录，只读预取 |
| 子代理工具 | 只能调配置好的记忆召回工具。弱关联返回 `NONE` | 叶子子代理去掉记忆工具 | 子代理跳过主线程的记忆抽取 |
| 关掉 | 会话级 `/active-memory off` 暂停两条路径。`off` 模式仍留确定性通道 | 不加载提供者，或该会话 `skip_memory` | 预取失败就少几条附件 |

## OpenClaw

用户消息先走确定性触发召回。打中强的可信匹配，就注入一段有界的隐藏上下文。弱或空，再看这句话有没有召回意图。没有意图，或召回不可用，只加一条固定的、有界的结果说明。有意图才启动主动记忆的深召回子代理。子代理给出相关摘要就注入。给出 `NONE` 就当没有额外上下文。主回复在这之后才生成。

它是对话增强，不是全平台的推理步骤。控制界面和同一条持久聊天路径上的交互渠道可以跑。无头一次性、心跳和后台、通用内部 `agent-command`、子代理和内部帮手不跑。会话之间的消息和孩子完成的投递也不跑，即使它们出现在可见对话里。OpenClaw 用投递来源的类型跳过召回。同一对话里后来的人话，仍按通常的目标和会话规则有资格。

两条对准路径都要求插件已启用，并且是合格的交互式持久对话：

1. 跨对话记住：有效配置 `memory.search.rememberAcrossConversations` 打开时，只对准私人直聊或持久的显式界面会话。
2. 高级主动记忆：对准 `plugins.entries.active-memory.config.agents` 里列出的 agent，并套用插件的聊天类型和聊天 id 控制。

`config.allowedChatTypes` 管的是高级路径。它不能把「跨对话记住」放宽到群或频道。那项产品设置保持仅私人。

`config.mode`：`escalate` 是默认。`always` 在每个合格的对准回合都跑深召回。`off` 关掉深召回，不卸载插件，确定性可信触发通道还在。`rememberAcrossConversations` 仍决定深召回能不能搜其它私人对话。

会话级 `/active-memory off` 把两条路径都暂停在这一次对话上。任一条件失败，这一轮不跑主动记忆，主回复不受影响。

适合有长期记忆可搜、连续性和个人化比提示词逐字节确定更重要的持久会话。自动化、内部工人、一次性 API、以及隐藏个人化会让人意外的地方，不适合。

策划层、出处和梦境写入仍是记忆体系的另一面。主动记忆不把 `untrusted` 洗成主人事实。它只决定要不要在回复前多做一次有界召回。

## Hermes

记忆在回合路径上由 `MemoryProvider` 做同步和预取。失败不改主循环的角色交替。cron 默认 `skip_memory`，心跳式的内部任务也不靠一条阻塞子代理去翻历史。叶子子代理的工具集里没有记忆。

外部提供者同时至多按配置启用的那一个。它不在每条用户消息上先跑「有没有在问过去」的门，再决定要不要挡住主模型。

## Claude Code

记忆预取的结果作为附件进入这一轮，不重建系统提示。预取失败就少几条附件。子代理不跑主线程那次抽取。没有 `escalate` 这种「确定性没命中才阻塞」的模式开关。
