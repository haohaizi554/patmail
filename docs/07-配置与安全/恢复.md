# 恢复

会话库坏了的时候，先保住还能读的正文，再修索引。继续往一个已经结构损坏的文件里写，会把还能打开的库写成打不开。三家的恢复都区分「这一轮被打断」和「磁盘上的历史坏了」。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 正文在哪 | 每个 agent 的 SQLite transcript | `state.db` 的 `sessions` 和 `messages` | 项目目录里的 JSONL |
| 索引 | 同一库里的会话行 | FTS5。坏了可以拆掉，搜索改走 `LIKE` | 无单独的全文索引合同 |
| 回合被打断 | Gateway 重启后最多三次拉起后端 | `resume_pending` 保住会话 id。`suspended` 换新 id | 转录还在就可以 resume |
| 文件坏了 | doctor 导入旧 JSONL。启动发现遗留库就拒绝就绪 | 隔离句柄，停止检查点，正文改记到 JSONL 缓冲 | 损坏的是那一份 JSONL 本身 |

## OpenClaw

Gateway 重启打断的回合会试着沿原会话继续。三次没能开始一次后端回合，恢复预算用尽。真正开始一次后端回合后预算刷新。只是接受、排队或准备，不算。不报告接受的 CLI 后端，要看到助手输出或工具活动才刷新。重放保留已记录的工具调用和结果，复用原来的用户消息。已经有完整回复或更晚的用户消息，就不再重放。预算用尽后 transcript 还在，用新会话或 `/new`、`/reset` 换一份。

运行在助手回复写入之前失败或超时，transcript 里留一条可见的失败说明。嵌套运行即使请求它的那一轮已经结束，仍保留自己的失败说明。

会话行和 transcript 在 `openclaw-agent.sqlite`。旧的 `sessions.json` 和热的 JSONL 只由 `openclaw doctor --fix` 在 Gateway 停掉、备份之后导入。启动若发现遗留库，拒绝就绪，不悄悄用空历史开工。导入时没有 `sessionStartedAt` 的行，尽量从 JSONL 头里补。没有 `lastInteractionAt` 时，空闲新鲜度退回会话开始时间，不退回后来的簿记写入。

隐身线程的 transcript 只在内存里。Gateway 重启或 24 小时到期就删，不归档，也没有这份恢复。

压缩已经写进 transcript 的，取消运行不算回滚。恢复要面对的是压缩之后的历史，加上未总结的尾巴。

## Hermes

`state.db` 里有两类数据。`sessions` 和 `messages` 是正文。`messages_fts*` 和同步触发器是派出来的搜索索引。索引可以暂时拆掉。它不能把一次活的写入或搜索变成对整份转录的无界重建。

FTS 写入或搜索报损坏时，`SessionDB` 在同一事务里记下耐久的 `fts_stale`，拆掉 FTS 同步触发器，然后正文写入重试且不再进派生索引。搜索改用正文行上的 `LIKE`。这次失败的操作本身不跑 `FTS5('rebuild')`。以后打开库时，可以在跨进程准入锁和外来持有者守卫之下重建。重建跑不了，FTS 就保持拆开，正文仍可写。`hermes doctor` 会给出明确的修复命令。

若活写入报的是裸的库损坏或「不是数据库」，损坏在正文的 B 树、schema 或空闲页，而不是 FTS。句柄被隔离：这次写入把有类型的错误传出去，不重试。之后这个句柄上的写入立刻失败，不再碰文件。`close()` 不再打开连接，并跳过显式的 WAL 检查点。继续写才会把还能读的文件写成打不开。现场里，第一次结构错误之后又写了大约 50 分钟，关闭时按错误页号做了检查点，把页 1 写成了 FTS 叶子。跳过显式检查点是第二道。Python 3.12 起还关掉 SQLite 在最后一次连接关闭时的自动检查点，让 `-wal` 留着做取证。3.11 没有这个开关，关闭时仍可能检查点一次，所以重启前要把 `state.db`、`state.db-wal`、`state.db-shm` 一起拷走。这三份是一个活的 SQLite 映像，不要分开 `cp`。

网关和 agent 的刷写把隔离当成文件已被替换。待写的转录进 `sessions/<id>.jsonl`，网关进 `pending_messages/` 缓冲，不进重试队列。不在损坏文件上做那次一次性的 FTS 重建。隔离是整个进程的。共享句柄对所有持有者都是坏的，直到进程在修好或恢复的文件上重启。Gateway 还开着时不要跑 `hermes doctor --fix`。

先停网关，再 `hermes sessions recover --inspect-only`。能恢复再写出一份新的库，或从 `state-snapshots/` 取最新快照。`sessions repair` 默认先做 SQLite 备份，再经守卫下的快照和提升做结构修复。修完后核对健康探测、`fts_stale`、三个 FTS 触发器是否还在，以及 `sessions` 和 `messages` 的行数，然后才启动网关。

压缩把旧行标成 `active=0`，不删。恢复时不要把两代里内容相同的受保护消息当成重复删掉。查活历史只看 `active=1`。

`resume_pending` 是回合被打断、库还好时保住原来的 `session_id`。`suspended` 是 `/stop` 或连续重启失败之后，下次强制换新 id。库隔离时，这两面旗救不了已经写坏的页。

## Claude Code

转录就是项目目录下的 JSONL，外加 `subagents/agent-<id>.jsonl`。没有一份可拆开的 FTS 和一份必须保住的正文表。文件截断或写到一半时，能恢复的是还完整的那些行。resume 依赖元数据和这些行还对得上。

工具结果落在 `tool-results/` 的大文件如果丢了，消息里的指针还在，内容不在。这和 Hermes 把正文留在 `messages` 里、只丢掉 FTS 不同。

压缩、反应式重试和停止钩子作用在还加载得起来的消息列表上。它们不修复磁盘上坏掉的 JSONL。计划模式和 worktree 也不复制一份会话备份。

子代理侧链可以单独 resume。主转录坏了，不会自动用侧链重建成主会话。
