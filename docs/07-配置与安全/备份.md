# 备份

备份是显式做出来的档案，里面有配置、认证 profile、渠道和提供商凭据、会话，以及可选的工作区。档案就是秘密。配置一个存储位置不会自动开始备份。恢复写到指定的目标目录，而不是在活着的 Gateway 上原地覆盖。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 命令 | `openclaw backup create`。可只含配置、可排除工作区、可干跑 | 家目录自己拷。`state-snapshots/`。修库前先停网关并做 SQLite 备份 | 复制项目 JSONL |
| 库 | `backup sqlite` 按全局或按 agent，可放进操作者的 git 仓库 | `state.db`、`-wal`、`-shm` 是一份映像 | 无 SQLite 会话库 |
| 异地 | `--to` 命名的存储位置。保留按日、周、月 | 存储位置不是 Hermes 的一等备份对象 | 无 |
| 校验 | `verify` 再 `restore` 到目标路径 | 修完核对行数和 FTS 触发器再启动 | 文件能打开 |

## OpenClaw

`openclaw backup create` 把状态、配置、认证、凭据和会话打成档案，工作区可选。可以指定输出目录、干跑并给出 JSON、创建后校验、排除工作区或只要配置。异地用已命名的存储位置，并带日、周、月的保留份数。列出、校验和恢复都要指明从哪一份来。恢复的目标是一个目录，例如 `./restored-openclaw`，不是当前正在跑的状态目录。

SQLite 可以单独做紧凑的、校验过的快照，按全局或按某个 agent，放进操作者拥有的 git 仓库，做成有版本的库备份。这和整份 tar 不同。库快照仍含认证 profile。OAuth 令牌在 SQLite 里是明文。备份和拷贝按凭据对待。

存储位置只是目的地。配好它不排程、不搬家。备份命令才把档案送去那里。卸载或重置前可以用干跑看会包含哪些路径。

Gateway 还在写库时做的拷贝，和 Hermes 分开复制 wal 一样危险。先停，或用它自己的 sqlite 快照路径，让 SQLite 给出一致的视图。

## Hermes

更新的快照覆盖每一个 profile 的同一套文件，用来在丢文件时恢复。回滚归 `--backup`。会话库的修复默认先做 SQLite 备份。`state-snapshots/` 里是早先的快照。不要把主文件、WAL 和共享内存拆开拷。FTS 是派生物，可以从正文重建。正文页坏了，快照比在坏文件上继续写更有用。

`hermes doctor --fix` 在网关开着时不要跑。备份若在网关仍在写时用普通文件复制，得到的是半份映像。

`.env` 和 `config.yaml` 都要在档案里，否则恢复出来没有钥匙或没有行为。秘密源在更新时不解析。备份也不该在拷贝时去连保险库。

## Claude Code

转录就是项目里的 JSONL 和子代理侧链。备份是复制这些文件以及 `tool-results/`。没有凭据档案命令。设置文件里的钥匙会跟着客户端配置一起被拷走。没有校验过的 SQLite 快照。
