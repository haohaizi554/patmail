# 配置

配置是带版本的快照。校验失败时继续跑上一份好的，而不是用半份新文件开工。哪些键可以热应用、哪些必须重启进程，要事先分类。秘密和重启端口不是同一类变更。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 文件 | `openclaw.json`，JSON5，可 `$include` | `config.yaml` 行为，`.env` 只放秘密 | 用户设置、项目设置、本地设置 |
| 应用 | 默认 `hybrid`：能热的热，该重启的自动重启 | 多数键下次读取生效。改系统提示的命令默认下一会话 | 设置在新会话或下一轮工具面生效 |
| 坏文件 | 拒绝外部编辑，不回写。上一份运行时继续 | 不可读的配置拒绝被删掉式的覆盖 | 坏设置让该层失效，不发明默认密钥 |
| 原子性 | Gateway 自己的写入发布已提交快照，不等文件监视防抖 | `atomic_config_write` 保留注释和键顺序 | 客户端写设置文件 |

## OpenClaw

Gateway 自动应用带修订号的配置快照。经 Gateway 的写入直接交给重载主人，不等文件监视器的防抖。运行时消费者一直读最后一份成功应用的快照，直到替换事务提交。日志记下修订号，以及它来自 Gateway 写入还是文件编辑。

直接改文件在校验通过之前视为不可信。编辑器的临时文件和改名要先落定。无效的外部编辑被拒绝，并且不回写 `openclaw.json`。OpenClaw 自己的写入在落盘前过同一套 schema。包含文件也被监视。

无效编辑留下上一份好的运行时。重启走正常的启动校验。若 Gateway 写入的最后一次重读发现文件丢了或无效，`config.patch` 或 `config.apply` 返回不可用，并带上已提交的配置细节。它不等下一次文件事件，也不覆盖那次外部编辑。

忙碌的状态库暂时拒绝生命周期租约时，变更保持待定，按有上限的退避自动重试。关停取消待定重试。插件重载排不干已承认的工作时，保留上一份好的运行时。排干超时则在工作结束后自动再试一次。在此之前，`config.get` 的已应用哈希和保存的修订不一致，控制界面显示未应用。Gateway 重启会完整应用保存的配置。

重载模式默认 `hybrid`：热设置马上用，需要重启 Gateway 的自动重启。`off` 仍监视和校验，被动的运行时变更等人工重启。显式的插件生命周期动作仍会应用。旧的 `hot` 和 `restart` 模式由 doctor 收成 `hybrid`。防抖不再可配。

没有匹配规则的路径默认要重启 Gateway。插件提供的规则只在该插件加载时有效。最长匹配的配置前缀决定结果。结果分三类：重启进程、热应用（可以只重启渠道、cron 或心跳）、不调度重载动作但更新快照，让之后的读取看见新值。

默认不需要重启 Gateway 的包括：agent 与模型、认证顺序、广播、钩子、cron、心跳、会话与消息、工具、技能、多数 MCP、记忆引用、插件条目、界面、日志、绑定、批准策略、诊断旗标、更新检查和遥测同意、Gateway 令牌和口令（旧的共享认证客户端会重连）、浏览器配置和 SSRF 策略。需要重启的是其余 `gateway.*`（端口、绑定、认证模式、Tailscale、TLS）、部分发现、MCP Apps 的监听设置，以及 `secrets.egressProxy`。

渠道插件自己声明哪些前缀要重启渠道、哪些是空操作。改 `mediaMaxMb` 会重启渠道运行时，让附件上限一起生效。自动重载保留被人工停掉的账号。改 `session.store` 不迁移对话。绑在旧库上的排队通知以 `store-replaced` 结束。选回旧库不会自动重新武装那次投递。

选中一个带退役安装状态的工作区会被拒绝，并提示 doctor。重载不迁移工作区状态。模型运行时把作者写的设置和目录默认分开。热重载和秘密重载保持这个区分，目录兼容元数据不会变成把原生运行时切回 OpenClaw 的自定义请求覆盖。

## Hermes

行为进 `config.yaml`，秘密进 `.env`。新键靠深合并出现在已有文件里。只有真的要迁移旧结构时才抬高 `_config_version`。每个默认键都要有运行时读者，每个读者都要有登记。否则会出现旋钮不生效，或读者读一个从未展示、从未迁移的键。

所有配置写入走 `atomic_config_write` 或显式的整文件替换。拒绝用省略来删除。注释、键顺序和引号保留。不可读的文件先被守卫挡住。不要对配置路径直接 `yaml.dump`。

三套加载器服务不同表面。CLI 合并默认和用户 YAML。`hermes tools` 和多数子命令走 `load_config`。网关运行时、cron、doctor 走有效用户配置：用户文件、托管覆盖、变量展开、模型键规范化，不灌入默认值。CLI 看得见而网关看不见，通常是用错了加载器。

多路复用时，进程环境不覆盖某个 profile 的 YAML。

改变系统提示的斜杠命令默认推迟到下一会话，`--now` 才立刻生效。这是为了不在对话中途打断前缀缓存。配置里的工具开关、模型选择和备用链可以在下一次解析时生效，不必为此重启整个网关进程。profile 是岛：没有活的配置继承。克隆在创建时拷贝，默认去掉消息渠道秘密。

托管覆盖可以压过 profile 自己的隔离模式。插件隔离读的是合并后的有效配置，这样操作者钉住的策略不会被用户文件悄悄关掉。

## Claude Code

设置分层：用户、项目、本地。项目设置可以进仓库，本地设置不进。权限规则、钩子和 MCP 定义都从这些层来。一层坏了，不把别的层的密钥补进去。

工具允许、询问和拒绝在每次调用前求值。改规则之后，已经在跑的工具调用不会回头重判。下一调用看见新规则。斜杠命令和技能索引在回合之间更新。计划模式是会话内的模式开关，不是改一份全局配置文件然后热重启一个守护进程。

没有 Gateway 式的「无效 JSON 保持上一份进程快照」。客户端下次读取时要么用得上，要么报这层设置无效。
