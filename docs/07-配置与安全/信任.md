# 信任

一台 Gateway 支持一个信任边界：一个操作者，或彼此信任的一队人。互不信任的人要分开的 Gateway，最好再分开操作系统用户和主机。能给这个开了工具的 agent 发消息的人，共享它被委托的工具权威。会话 id 是路由，不是授权令牌。能改 `~/.openclaw` 的人，按受信任的操作者对待。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 默认可见 | 会话可见性默认 `all`。agent 之间默认开。未沙箱的 agent 可以列出、读、搜、发消息到每个 agent 的会话 | 多 profile 的秘密失败关闭。会话搜的是这个家目录 | 本机项目 |
| 沙箱调用方 | 默认夹在自己生出的树上。这限制它当调用方，不向未沙箱的 agent 隐藏它的转录 | 沙箱是终端后端。不是租户 | 权限模式 |
| 只发送 | 窄可见性加每 agent 的发送规则：允许 `sessions_send` 和该回合的回复。不包括历史、搜索、列表、状态或控制 | 无这档「只许问、不许读历史」 | 无 |
| 误读 | 提示注入不是认证绕过。默认关闭的配对网段不是漏洞 | 操作系统隔离才是对抗模型的边界 | 权限询问不是租户 |

## OpenClaw

已认证的操作者是控制面角色，不是按用户的租户角色。具名的操作者角色限制这个队友的连接能做什么。那是协作护栏。

会话工具默认跨整台 Gateway。可见性默认 `all`，agent 之间默认启用。未沙箱、开了工具的 agent 可以碰到每个 agent 的会话，包括其他人的转录。沙箱会话作为调用方默认夹在自己的生成树上。未沙箱的 agent 仍看得到那些转录。要在同一台 Gateway 上放不同信任级别的人格，把可见性设成 `agent` 或 `self`。`tree` 仍允许请求者拥有的原生和 ACP 孩子跨 agent。也可以用允许对，或关掉 agent 之间。强隔离仍是分开的 Gateway。

只发送的委派把窄可见性和 `tools.agentToAgent.send` 配在一起。目标可以是 id 或 `*` 模式。规则允许发送和该已授权回合的回复。不允许历史、搜索、列表、状态、会话控制，或对本来隐藏的状态做观察。全局的 agent 之间限制和沙箱的生成会话夹紧仍然有效。这是允许去问一个更有权限的 agent 做事，不保证它会拒绝泄露或拒绝执行不可信请求。

分诊时常见的误读：Gateway 认证是认调用者，不是要求每一帧都有按消息的签名。会话键选上下文。提示和内容护栏降低模型滥用，提示注入本身不证明认证被绕过。浏览器里的求值在打开时是故意的操作者能力。本地 TUI 的 `!` 是操作者触发的本机执行，不是远程注入。节点配对和节点命令是配对设备上的操作者级远程执行。默认关闭的 `autoApproveCidrs` 不是自动的配对漏洞。默认开启的 SSH 核对也不是默认自动批准。

暴露、私聊政策、反代或公网之前，走暴露手册当起飞和回滚清单。

## Hermes

安全说明里，对抗一个有敌意的模型，边界是操作系统隔离。审批、打红和允许名单是启发式。多 profile 仍是一个操作者的多个岛，秘密在范围里失败关闭。会话搜索默认不会因为「另一个 profile」就变成另一台机器。要互不信任，分开家目录还不够，还要分开进程和用户。

## Claude Code

权限是这一次工具调用的允许、询问或拒绝。计划模式限制写。没有「一台 Gateway 上未沙箱的 agent 默认可读所有人的转录」这一档，因为没有那台共享 Gateway。
