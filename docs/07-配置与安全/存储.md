# 存储

存储位置给产物起一个目的地。配好一个位置不会自动备份，也不会把现有数据搬过去。核心拥有身份、加密和健康检查。提供商负责传送对象。每个消费者自己决定存什么、留多久。OpenClaw 从不创建你写在配置里的那一层根目录。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 默认 | 状态目录里的 SQLite、工作区和媒体 | 家目录：`config.yaml`、`.env`、`state.db`、日志、技能 | 项目目录里的 JSONL |
| 外置 | 文件系统提供商指向已存在的目录。插件可以加对象存储 | 家目录可以是别的路径。不要写死 `~/.hermes` | 转录跟着项目 |
| 初始化 | 先挂好盘、建好目录，再初始化。口令在该进程的环境里 | 配置写入是原子的。库、WAL 和共享内存是一份映像 | 文件出现即转录 |
| 秘密 | 位置上的备份仍可能含明文令牌 | `.env` 和库要当秘密。损坏时不要只拷其中一个文件 | 转录里可能有贴进来的秘密 |

## OpenClaw

一个存储位置是产物的目的地。内置的文件系统提供商支持已经存在的目录，包括外置盘或挂载的网络文件系统。更多提供商来自插件。配置里引用一个内置提供商，会按正常的插件政策启用它的主人插件。显式禁用仍然有效。对象存储要按那个插件的步骤建桶、配 SecretRef，并初始化位置。

先在目标盘上建好目录，再初始化。进程看见的必须是绝对路径。`OPENCLAW_STORAGE_PASSPHRASE` 放在跑 CLI 或 Gateway 的那个进程的环境里，并在秘密管理器里留一份能恢复的拷贝。

初始化在位置根写下 `openclaw-storage.json`。用同一套加密设置和口令再跑一次是安全的。运行时操作从不创建这个标记。空的挂载点不得在系统盘上悄悄变成存储。位置名是 1 到 63 个小写字母、数字或连字符，以字母或数字开头。加密要么是口令，要么是显式的字符串 `none`。文件系统提供商拒绝缺失的根，也从不覆盖已有的对象键。提供商设置是有界的 JSON：最多 32 层、4096 个值、每个对象 512 个键、字符串最长 65536、序列化后 256 KiB。带秘密的设置，包括访问钥匙和嵌套凭据，必须用合法的 SecretRef。引用一直是引用，直到提供商经核心秘密解析器要值。

有口令时，核心在提供商收到对象流之前加密，读的时候解密。`OCSTOR1` 用 scrypt 导出主钥匙，每个对象用单独的钥匙做带认证的 AES-256-GCM 分段。错误口令得到 `wrong-key` 并拒绝访问。改配置里的口令不会把已有数据重新加密。口令和位置标记都要留着。丢掉任一个都可能让加密对象读不出来。对象名和初始化标记对存储提供商仍可见。加密保护的是对象内容。`none` 只作为显式的操作者选择，例如目的地已经有磁盘加密。

备份落在位置里的 `backups/<命名空间>/`。命名空间默认是清理过的主机名。第一次上传写下 `owner.json` 认领，含耐久的 Gateway 设备 id、主机名和认领时间，加密设置和归档相同。备份在归档前和保留前都查这份认领。不同的设备 id 拒绝备份并记下失败的尝试，免得主机名撞车却共享保留。保留从不删这份认领。故意接管命名空间要显式传认领旗标，例如换了硬件。两台安装都会继续跑时，优先用分开的命名空间。恢复是只读的：列表、校验和恢复不要求也不改认领。恢复出来的安装带着原来的设备身份，可以继续自己的命名空间。同时跑的克隆拷贝共享那份身份，必须用自己的命名空间，以免共享保留。

配置位置不等于排程备份，也不移动已有数据。要备份仍得有单独的复制或调度。cell 的状态目录挂进容器后，里面的 SQLite 含有明文 OAuth 令牌。那份拷贝是凭据，即使旁边还有一个只放遗留恢复钥匙的目录。

会话、认证 profile 和转录在每个 agent 的库里。日志默认在临时目录按天滚动，目录不安全时改到用户范围的临时路径。这些都不是「配一个存储位置就会自动迁走」的对象。doctor 在 Gateway 停掉之后才导入退役的 JSONL。启动若发现遗留库，拒绝就绪。

## Hermes

路径经 `get_hermes_home()`。展示用另一函数。不要在代码里写死家目录。profile 各自一份家。克隆出来的是岛，没有活的继承。

`state.db`、它的 WAL 和共享内存文件是一个活映像。分开复制会得到打不开的库。快照在 `state-snapshots/`。FTS 是派生物，可以拆。正文损坏时隔离句柄，跳过检查点，待写内容进 JSONL 缓冲。

FTS 写入或搜索报损坏时，记下耐久的 `fts_stale`，在同一事务里去掉 FTS 同步触发器，规范写入不再走派生索引，搜索改用规范行上的 `LIKE`。失败的那次活操作从不跑 `FTS5('rebuild')`。稍后打开可以在跨进程准入锁和外来持有者守卫下重建。重建跑不了就保持拆开，规范写入仍可用，doctor 给出明确的修复命令。

正文、模式或空闲列表上的 `SQLITE_CORRUPT` 或 `SQLITE_NOTADB` 没有 FTS 出处时，句柄被隔离。失败的写入把类型化错误传出去，不重试。之后在这个句柄上的写入立刻失败，不再碰文件。`close()` 之后不再重新打开连接，并且跳过显式的 WAL 检查点。现场里，句柄在第一次结构错误之后继续写了大约 50 分钟，关停时按错误页号检查点了 15 页，把还能读的损坏文件写成完全打不开。Python 3.12 及以上还关掉 SQLite 自己在最后一条连接关闭时的检查点，让 `-wal` 旁路留下来做取证。3.11 没有这个开关，关闭时仍可能检查点一次，所以重启前要把库、WAL 和共享内存一起拷走。隔离按进程。共享句柄对每个持有者保持中毒，直到进程在修好或恢复的文件上重启。网关还开着时不要跑 `hermes doctor --fix`。待写转录进 `sessions/<id>.jsonl` 和网关的 `pending_messages/` 暂存，不进重试队列。损坏文件上从不跑那次一次性的 FTS 重建。

配置的原子写保留注释。秘密只在 `.env` 和运行时内存。存储位置若只同步了 `config.yaml` 而漏了 `.env` 和库，恢复出来的是没有钥匙、没有会话的壳。

日志和更新收据在家目录的 `logs/`。技能在家目录的 `skills/`。这些跟随家目录，不跟随当前工作区。

## Claude Code

转录是项目下的 JSONL，子代理在 `subagents/`。没有单独的存储位置对象，也没有「初始化之前拒绝创建根目录」的提供商。备份就是复制这些文件。文件写到一半时，能恢复的是还完整的行。大工具结果若在 `tool-results/`，指针还在、文件丢了，内容就不在。
