# 稳定发布

稳定发布是一道门。构建器单独成功不是稳定发布。尝试用的引用是锁。最终标签是发布回执。两种标签都不是工作流触发器。金丝雀构建有自己的定时工作流。仓库里提交的项目版本始终是 `0.0.0`。发布任务从被准入的引用推导载荷版本，并盖到隔离的构建树上。不要在 `main` 上改版本文件。

## 对照

| | Hermes | OpenClaw | Claude Code |
|---|---|---|---|
| 版本文件 | 主干上保持 `0.0.0`。版本从被准入的引用来 | 日历版本。npm 发布不可变 | 客户端版本 |
| 锁 | 任何版本只要有一个未完成的尝试，就挡住新的 `release` | 扩展稳定缺注册表数据是错误，不退回 `latest` | 无 |
| 绿和发布 | 最终标签在发布时造，不在变绿时造。镜像在自己的测试通过后推送，先不动 `stable` 和 `latest` | 完整发布验证封一份不可变执行计划 | 无 |
| 部分失败 | 各家服务没有跨服务事务。控制器幂等。再跑，每次变更先核对当前状态。不重建已接受的字节 | 恢复从不就地覆盖 | 无 |

## Hermes

下一次语义版本取已发布家族里较新的那个：受保护的 R2 稳定头，和最新的、带 `vX.Y.Z` 标签的非预发布 GitHub 发布。跳过了包的发布只移动第二个。尝试不移动版本线。下一次版本已经有最终标签时，拒绝开切，直到那次发布结束。

原子推送带注释的 `rc.<N>-vX.Y.Z` 尝试引用，在上面建一个非预发布的 GitHub 草稿，并对那一个精确引用分发稳定发布。认领消息绑提交、尝试号、自动发布政策、是否跳过包和测试，以及一个单调分配的纪元。这个纪元是每个矩阵腿和重试的发布日期和原生打包时钟。

准入核对远端带注释的标签对象、剥出来的提交、`GITHUB_REF`、`GITHUB_SHA`、检出的 `HEAD`，以及在 `origin/main` 上的祖先。然后跑源码、Docker、Nix、PM 包、安装和更新、Termux、Windows、签名包和原生升级的验收图。

从测过的字节推送不可变的、带版本的 Docker 和 R2 制品。Docker 镜像在它自己的测试通过后就推，标签是尝试引用。此时不要移动 `stable` 或 `latest`，也不要为了发布再构建一次。

带注释的最终 `vMAJOR.MINOR.PATCH` 回执在发布时创建，不在变绿时创建。它绑获胜尝试的引用、对象、提交、档案前缀、候选清单的 SHA256（认领跳过包时为 `null`）、Docker 清单摘要和自动发布政策。

稳定发布控制器按最旧的先解析。它创建 `vX.Y.Z`，把仍是草稿的发布改指向它，去掉警告块，最后一次调用才把发布公开，然后核对并提升回执绑住的 Docker 摘要，再推进应用安装器、macOS、APT、下载页和受保护的 R2 头。

只有一份变绿的草稿会等着，除非认领选了自动发布。后来一份变绿的认领，按顺序冲掉所有紧挨着的、更早的、已变绿的草稿。更旧的、还在跑的认领挡住更新的发布。烧掉的尝试跳过。放弃之后那个版本再切一次。失败、取消、缺失和意外跳过的要求保持红。

Docker Hub、R2、APT、GitHub 和商店不支持一次跨服务事务。控制器因此幂等。部分失败之后再跑，让每一次变更在继续之前核对自己的当前状态。最终标签是保管回执。不要重建或替换已经接受的字节。

## OpenClaw

四个通道。扩展稳定失败关闭，缺数据不退回 `latest`。构建拒绝打开比自己新的库。更新拒绝模式支持比磁盘库更旧的目标。那是状态库和通道的合同。Hermes 这一页是发布门：尝试是锁，最终标签是回执，主干版本文件不动。

## Claude Code

客户端按自己的版本发布。没有「主干版本恒为 0.0.0、变绿不等于发布、部分失败再跑且不重建已接受字节」这一道门。
