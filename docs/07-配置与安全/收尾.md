# 收尾

更新命令进程拥有准入、更新锁和输出寿命、更新前清单、全部 profile 的快照、网关暂停、Git 的选择和暂存与恢复、语法和 HEAD 守卫，以及 ZIP 的下载、暂存、脏树复查、保留嫁接和交换。它在交换代码之前导入完成传输。最终的树选定之后，包括上游合并，Git、已经是最新的重试和 ZIP，都从那棵树向 `update_completion.py` 发一次带版本的 JSON 请求。命令进程里不驱逐、不重载任何缓存的应用模块。

| 历史名字 | 已发布更新器历史上能到达的名字保持可解析。未冻结的、只在分支上的重试组合删掉，不做垫片 | 无这道冻结表面 | 无 |

## Hermes

请求带规范的源和家目录、桌面产品选择、是否交互和网关模式、更新前版本、活动和兄弟快照标识、序列化的运行时计划、打开的回执身份和数据，以及暂停的 Windows 令牌。里面是数据，没有可调用对象，也没有 pickle。标准输入仍继承，给交互配置提示用。网关模式保持非交互。子进程输出保持可见，并由父进程的更新输出流镜像。

只含标准库的入口用可用的 Python 以 `-I -S` 启动。私人的字节码缓存前缀在任何新检出导入之前围住过期缓存。显式导入路径指向新检出。它调用新的 PM 接口准备记下的依赖并集，再用新的激活环境启动选定的 Python。那个解释器也先关掉站点初始化，然后运行时主人租用并激活选中的代，之后才有应用导入。只有那个解释器导入应用完成代码。同一份回执和关联身份穿过这道准备边界，包括 PM 的结果。选定 Python 的完成拥有启动器发布、构建器、缓存失效、全部 profile 的配置和状态和技能维护、进程扫描、舰队重启、Windows 恢复、仪表盘去重和核对。

按种类的重启和中止恢复算法还在。瞬时的监督者或进程失败，即使没有混代导入，也是真的。消失的是清除再重载的权宜，以及独立的重试和 ZIP 尾巴组合。网关退出状态在重启能终止更新器的 cgroup 之前写下，后来的失败会降级它。核对发布最终回执。

父进程等待，并传播子进程精确的非零结果。信号映射成 shell 风格的 128 加信号。子进程不能靠仅仅退出 0 就算成功。必须有匹配回执身份的终态响应。响应交还变更过的 Windows 令牌，这样父进程登记的紧急恢复不会重复已经完成的工作。正常的父进程完成不做维护。

父进程保留原来的回执，直到被确认的子进程收尾。缺失或失败的子进程输出把它留给已有的命令边界失败收尾器。标准库引导即使应用导入不可用，也返回关联的 PM 失败数据，并在每个进程边界把负的信号退出规范化。POSIX 完成拥有新的会话和进程组。取消在释放锁之前杀掉那个组。Windows 用保留的子进程的 `taskkill /T` 树。父进程在启动完成进程之前记下待定的舰队义务，包括准备无法开始的时候。父进程的 Windows 紧急恢复是最后手段，用在子进程无法执行或被杀掉时。失败的子进程从不清除待定的舰队义务。维护一开始之后没有自动的代码回滚。SQLite 快照仍是文件丢失恢复，不是回滚。

从已发布更新器完整可达历史上冻结的名字都保持可解析。历史依赖钩子保留只含标准库的接管桥。旧父进程等待，带着回执和恢复状态，从不恢复一个已退役的安装器。新退役的、明确标成未完成的准备和模块重载钩子以非零停止，并要求再跑一次 `hermes update`。它们不能制造一份缺失的完成请求。当前的 Git、已最新和 ZIP 调用者只用规范的完成传输，不用历史的接管入口。未冻结的、只在分支上的重试组合被删除，不做垫片。ACP 的便利发布用启动器主人的 `expose_cli`。历史的 ACP 入口只是适配器，从不是第二个写入者。冻结集合从不裁掉，也不换成只靠标签的覆盖。新的当前路径导入和那段历史取并集。

## OpenClaw

更新先构建候选再停 Gateway。扩展稳定不退回 `latest`。医生是文件到 SQLite 迁移的唯一主人。没有「命令进程不重载缓存模块、完成代码只在新解释器里导入、退出 0 不算成功」这一页交接。

## Claude Code

安装器替换客户端。没有舰队义务，也没有「失败的子进程不清掉待定义务、维护开始后不自动回滚代码」。
