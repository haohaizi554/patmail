# 静默

后台维护用精确的静默记号开头，投递层把它拿掉，用户看不见中间输出。记号必须是整段载荷。草稿或打字流里，一段以这个记号开头时，流也被压住，免得静默操作在回合中途漏出半句。这只给真正不投递的后台回合。它不是普通、该办事的用户请求的捷径。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 记号 | 整段是 `NO_REPLY` 或 `no_reply`，大小写不敏感 | 空的终稿可以不发渠道气泡。没有这个精确记号 | 无静默记号 |
| 刷写 | 压缩前的静默回合对着会话的私有、脱离视图。内部提示和回复不进原转录，即使用户消息打断了它 | 记忆在会话结束时抽取。压缩是主转录上的摘要 | 压缩前没有单独的记忆刷写回合 |
| 模型 | 刷写模型若写明，不继承会话的回退链 | 压缩走辅助任务，有自己的回退 | 压缩模型跟这次请求 |
| 谁跳过 | 只有嵌入的 OpenClaw 会话做刷写。CLI 后端和心跳跳过 | 定时任务默认跳过记忆 | 无嵌入会话之分 |

## OpenClaw

自动压缩之前，可以先跑一轮静默的 agent 回合，把耐久状态交给选中的记忆提供者，免得压缩擦掉关键上下文。记忆核心把 `memory/YYYY-MM-DD.md` 写在 agent 工作区。别的提供者可以露出自己的持久化工具。上下文用量越过压缩阈值下方的软边时，宿主发出「现在写记忆」的指示，并带上精确静默记号。

刷写对着一份私有、脱离的对话视图。它的内部提示和回复从不进入原转录，包括新的用户消息打断它的时候。记忆文件的写入仍然耐久。必需的预检排除已经准入、正在等待的用户。回复之后的刷写包含这一轮已完成的回合。刷写内部的压缩只影响那份私有视图。原对话有自己的压缩步骤。

默认打开。软边距默认 4000 token，是压缩阈值下方触发刷写的间隙。活跃转录历史达到估计的 2 MiB 时强制刷写，即使 token 计数过期。写成 `0` 则关掉这道字节守卫。默认 20000 token 的保留被帽在窗口的四分之一。默认 4000 的软边距被帽在扣除保留之后剩余窗口的一半。32768 token 的窗口因此用 8192 的保留和 4000 的软边距。提前刷写从投影的 20576 token 开始。阻塞式的 token 压缩从 24576 开始，若适用的服务器阈值更高则更晚。两道阈值之间，记忆刷写可以跑，而不必要求压缩。字节守卫默认 2 MiB，并且独立。非正的阈值压住自己的触发。

刷写刷新过期用量时，计入最近一次有效提供商用量报告之后追加的投影消息，再把合计存成新鲜的。随后的压缩检查因此算上后来的转录增长。

刷写模型若写明，这一轮用那个模型，不继承活动会话的回退链。本地家务失败时，不会悄悄退到付费的对话模型。每个压缩周期刷一次，记在会话行上。只对嵌入的 OpenClaw 会话。CLI 后端和心跳跳过。工作区只读或无权时，记忆核心的文件刷写跳过。靠工具武装的提供者不要求可写的工作区。

扩展 API 有 `session_before_compact` 钩子。上面的刷写逻辑在 Gateway 侧，不在那个钩子上。

## Hermes

压缩前先把旧工具结果换成占位，再调用辅助模型做摘要。记忆抽取在会话结束，默认不在定时任务里跑。没有「整段静默记号压住草稿、刷写对着私有视图、写明的刷写模型不继承回退链」这一套。

## Claude Code

压缩在请求前分层做。没有给用户隐藏的精确静默记号，也没有压缩前单独写每日笔记的私有回合。
