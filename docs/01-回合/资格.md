# 资格

认证 profile 能不能用，在真正打到模型之前就有稳定的原因码。排序、运行时取钥匙、`models status --probe` 和 doctor 的认证检查共用同一套。令牌过期不能靠只写 `tokenRef` 绕过。过期字段若存在，必须是大于 0 的有限 Unix 毫秒，并且不超过 JavaScript 日期的上限。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 还没打到模型 | `missing_credential`、`expired`、`invalid_expires`、`unresolved_ref`、`excluded_by_auth_order`、`ineligible_profile`、`no_model` | 秘密源解析失败不挡启动。更新进程不解析保险库 | 客户端在请求时才发现钥匙无效 |
| 令牌 | `token` 和 `tokenRef` 都没有就不合格。`expires` 可选，有了就必须合法且未过期 | 凭据池里的钥匙按池的规则轮换 | 登录过期由客户端处理 |
| 探测 | 原因码和真正的模型调用失败分开。可用时原因码是 `ok` | 建会话时拒绝明显属于别家的模型名 | 无这组原因码 |
| 顺序 | 显式认证顺序里被省略的 profile 是 `excluded_by_auth_order` | 池先于跨提供商备用 | 无 |

## OpenClaw

检查结果有状态桶：`ok`、`auth`、`rate_limit`、`billing`、`timeout`、`format`、`unknown`、`no_model`。从未到达模型调用时，再带稳定的 `reasonCode`。

令牌 profile：

1. `token` 和 `tokenRef` 都缺，是 `missing_credential`。
2. `expires` 可以不写。写了就必须是有限的 Unix 纪元毫秒，大于 0，并且不大于 `8640000000000000`。
3. 类型不对、`NaN`、`0`、负数、非有限或超过上限，是 `invalid_expires`，profile 不合格。
4. 在过去，是 `expired`。
5. 只配 `tokenRef` 仍然要过 `expires`。

SecretRef 解析不了是 `unresolved_ref`。和提供商配置不兼容，包括畸形的钥匙输入，是 `ineligible_profile`。有凭据但没有能测的模型候选，是 `no_model`。

这些码让「没配钥匙」和「提供商拒绝了这一轮」分开。失败转移里，用户显式选中的模型不用无关备用顶上。资格不合格是还没进入那条转移。

## Hermes

钥匙在 `.env`、认证存储或凭据池。外部源在插件发现之后再拉一次，幂等，失败不挡启动。更新不解析外部源。多 profile 时按秘密范围读，不从进程环境借。没有把 `expires` 收成同一组原因码再给 doctor 和探测共用的这一页。池里的 402 会立刻换钥匙。

## Claude Code

认证是客户端的登录或 API 钥匙。请求失败才表面化。没有 Gateway 在模型调用前用同一套原因码过滤 profile 顺序。
