# 缓存

提示缓存复用没变过的前缀：系统或开发者说明、工具定义和其它稳定上下文。换模型一定是另一条缓存谱系。改思考或推理档也可以让复用失效，即使提示和模型没变。失效指下一次请求打不中那份缓存状态。它不一定在提供商正常过期之前删掉旧条目。用量里活的非零缓存计数永远压过转录里的回退。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 计数 | 归一成 `cacheRead` 和 `cacheWrite`。活的非零优先 | 前缀在对话内字节稳定。压缩才改已发送的上下文 | 提供商自己的缓存 |
| 换档 | 思考变化可以让复用失效。支持的 OpenAI Responses 保留原来的努力，并追加这一轮的配置 | 辅助任务的推理努力单独指定，不改主提示字节 | 新请求按新参数 |
| 工人 | 缓存键来自会话 id 加上权威转录的重置和压缩边界次数。不接受工人自己报的键 | 子代理是另一段上下文。换钥匙会让提供商侧缓存作废 | 子代理侧链 |
| 技能 | 已投递的工人技能用会话范围的、按内容寻址的路径和确定的目录顺序 | 技能索引在易变层。钉住的技能在稳定层 | 索引常驻，正文另注入 |

## OpenClaw

`/status` 一类用量在活会话快照没有缓存计数时，退回转录里最后一条用量。活的值只要非零就赢。

选模型和思考档放在创建会话时，并且保持两者稳定。计划中的改变开新会话。

经 Gateway 代理的工人推理，和本地回合用同一套 OpenAI 缓存键推导。显式的 Gateway 键优先。否则键把会话 id 和权威转录的重置次数、压缩边界次数合在一起。Gateway 把这些事实和已准入的回合留在一起，不接受工人提供的缓存键，也不从裁过的重放历史推导。

投递给工人的技能用稳定的、会话范围的、按内容寻址的路径，目录顺序确定。技能没变，系统提示前缀在回合之间就稳定。刷新仍投递当前校验过的字节。内容一变，那条技能的路径就故意变。工人和本地提示的范围不同：工人装入有界的工作区 `AGENTS.md`、Gateway 给的说明，以及收窄的工具集。会话在运行时或工作区之间搬动，仍可能让缓存前缀失效。

这和裁剪投影不同。裁剪是等缓存 TTL 之后软裁或硬清工具结果，原文不改写。缓存键是让提供商能复用前缀。两者都怕中途改掉已经发出去的稳定部分。

## Hermes

系统提示分稳定、上下文和易变。当天的日期行字节稳定。换表面是一条一次性的用户消息说明，系统字节不动。换提供商钥匙会让提供商侧的前缀缓存作废。压缩是唯一允许的上下文变更。微压缩默认关，开了会每回合打断缓存。

## Claude Code

请求前的分层裁剪会改送出去的历史。自动压缩是缓存断开的一种。没有「工人缓存键必须来自重置和压缩边界次数、拒绝工人自报」这一条 Gateway 合同。
