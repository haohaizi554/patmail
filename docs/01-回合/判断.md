# 判断

聊天模型负责对话和工具。效用模型做短的语言活，例如标题和摘要。判断模型对着证据和量规返回有类型的结果：一个选项、一个分数，或一个布尔概率。选了判断模型不会把它换成聊天模型，也不会因此启动后台工作。不同提供商的概率不能互相替代。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 聊天 | 主模型。工具循环 | 选中的提供商和模型。混合代理的聚合器才算在跑 | 当前模型 |
| 短任务 | `utilityModel`：标题、摘要 | 辅助客户端：压缩、标题、视觉、嵌入、会话搜索 | 压缩和标题若有，走客户端自己的调用 |
| 有类型的判断 | `decisionModel`。`decision_evaluate` 跟随选择和工具策略 | `/goal` 的判断是完成、继续或堵住。不是单独的概率 API | 计划是否接受由人决定 |
| 计费 | 判断不替换聊天，也不在后台自己跑 | 辅助调用不触发主循环的请求钩子 | 同一次查询里的模型调用 |

## OpenClaw

判断模型根据提供的证据和量规给出有类型的答案，用来做有界的判断：把请求路由到哪、紧急程度打几分、条件满不满足。`decisionModel` 是一个模型角色，提供商可以有不同的架构和推理后端。接口相同，不表示推理能力或概率可以互换。

这个角色和适配器是 2026.9.5 之后的开发检出和包含它的后续版本才有。控制界面里有单独的判断选择器。选择决定显式评估和受支持的消费者用哪个提供商。核心工具 `decision_evaluate` 跟随这个选择，再加上普通的工具策略。选择不启动后台工作，也不替换聊天模型。

主模型的产出是消息和工具调用。效用模型的产出是生成的文本。判断模型的产出是类型化的答案和概率估计。把判断模型的分数当成主模型的下一句回答，或者把两个提供商的 0.7 当成同一个置信度，都越出了这个角色。

效用模型和判断模型都不进入「用户选了严格的主模型、失败就不准换」那条链。它们是旁边的角色。主模型的备用链仍然只活在当前这一轮。

未设置的 agent 覆盖继承全局默认。空字符串关掉那个 agent 的判定。未设置或空的全局默认让整个角色关闭。自动的实验消费者还要显式打开判定辅助。显式的 `decision_evaluate` 不依赖那个实验开关。

每次请求带共享的 `state` 和一张 `questions`。选择题的答案是选中的标签和同一组标签的概率。打分的答案是分数和按索引对齐的概率。布尔的答案是 0 到 1 的 `probabilityTrue`。量表跟着这一次请求走。本地 ONNX 分类器在持久子进程里跑，不需要托管 API 凭据。当前这些插件在文档里是尚未发布的候选。模型表写的是插件声明的引用，不是这台机器上已经备好的制品。

## Hermes

辅助任务有自己的提供商、模型和推理力度，写在配置的 `auxiliary` 下。压缩、策展、视觉、嵌入、标题、会话搜索走这条解析。自动路由在没有专门指定时决定用谁。

每一次物理的辅助调用经过中继。那里发出辅助专用的调用前和调用后钩子，并带上任务名。主循环的 API 请求钩子不为主辅调用触发。这样插件不会把一次标题生成当成用户回合的模型请求。

辅助失败有自己的回退。压缩摘要停滞时，先在压缩的回退链上再试一次。再停滞则用确定性的后备摘要，仍走同一条管道。这不是把聊天模型换成判断模型。

`/goal` 的判断返回完成、继续或堵住，用来决定还跑不跑下一轮。它不是带概率的打分 API，也不创建看板卡片。混合代理的参考模型给分析，聚合器才写回答和工具调用。参考模型不带工具 schema。

标题生成是辅助调用，结果写进会话标题。它不改系统提示的稳定前缀。

## Claude Code

当前模型跑查询循环。压缩和摘要若发生，是这次客户端里的另一次模型调用，没有独立的判断角色和类型化概率合同。计划是否执行由人在计划模式里接受。停止钩子可以要求再跑一轮，那是钩子的决定，不是量规打分。
