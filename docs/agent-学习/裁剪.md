# 裁剪

旧的工具结果可以先从模型看见的上下文里拿掉，对话原文不动。这和摘要压缩不同：不调用模型，不改写用户和助手的话。完整历史仍在。裁剪只是一份投影，重启后还能按同一份投影重放。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 对象 | 旧工具结果。对话正文不改 | 成批压缩先裁旧工具结果，再摘要 | 请求前按条、按轮裁工具结果 |
| 原文 | 不改写。投影记在隐藏的缓存标记里 | 超长结果可换成占位。行仍在库里 | 超出的落到 `tool-results/` |
| 何时 | `cache-ttl`。直连 Anthropic 钥匙走服务端清除 | 压缩阈值，或打开微压缩后每回合 | 每次组请求之前 |
| 缓存 | 清除从第一条被清的结果起让前缀失效。清得太少就不清 | 裁剪和摘要都会断开缓存 | 裁剪改变这一次请求的前缀 |

## OpenClaw

`agents.defaults.contextPruning.mode` 设为 `cache-ttl` 才启用。请求的提供商、端点和认证决定跑在哪一侧。

直连 Anthropic、Messages API、API 钥匙、默认端点或 `api.anthropic.com` 时，清除交给 Anthropic 的服务端。OpenClaw 不再开新的客户端裁剪轮。服务端在模型看见之前清掉旧结果。同一会话里更早在代理路线上做出的投影，或从转录标记恢复的投影，仍按原样重放。本地完整历史保留。这条路径不受 `ttl` 开关约束。

服务端参数由 OpenClaw 推导，不另加配置项。触发大约是 `max(50000, 窗口的 30%)` 输入 token。保留最近 3 次工具使用和它们的结果。至少要清掉 `max(12500, 窗口的 5%)` 才值得做，免得为了很少的 token 重写缓存。`tools.deny` 或允许名单之外的工具名排除在外。工具调用的参数保留，不一起清掉。若同时开了服务端压缩，清除编辑排在压缩编辑前面。调用方已经提供的 `context_management` 不改。客户端的软裁和硬清设置不改变服务端政策。

其它合格路线走客户端：Bedrock、Google、Foundry、OAuth、代理、Vertex。新的一轮裁剪要同时过时间和体积。没写 `ttl` 时默认 5 分钟。内置 Anthropic 插件把种子写成 1 小时。每次成功的模型请求把内存里的钟拨到请求开始时间，包括回合落定前的工具循环。失败的请求不拨钟。TTL 没到，不开新一轮，已有投影照旧重放。

TTL 到了之后，上下文大约低于窗口的 30% 就跳过，钟继续走。软裁：超过 4000 字符的结果留头尾各 1500，中间是省略号。若仍大约在 50% 以上，并且至少还有 50000 字符可裁的工具内容，就硬清成占位，默认 `[Old tool result content cleared]`。可以关掉硬清。每次改变记成会话投影，并重置裁剪钟。后续请求复用同一批投影字节。

投影活过 Gateway 重启和空闲会话卸载，因为标记写在转录里。原始工具结果条目不改写。

## Hermes

压缩的第一刀是丢掉旧工具结果，不调用模型。大约超过 200 字符的旧结果可以换成占位。这发生在阈值上，不是每 5 分钟按缓存 TTL。微压缩打开后，每回合把最老的一个交换折进摘要，用户原文不动。那是摘要，不是这份投影。

会话库里的旧行在大压缩后标成不活跃，查询活历史时滤掉。那是存储代际，不是发给模型前的临时投影。

## Claude Code

组请求之前按大约每条 50000 字符、每轮 200000 字符裁工具结果。超出的正文在 `tool-results/`。缺了配对结果会补一条，否则下一请求失败。没有「等缓存 TTL 过期再投影、原文一行不改」的标记。自动压缩若再摘要一段历史，那是另一层。
