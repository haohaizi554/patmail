# 图像后端

`image_generate` 只是门面。真正画画的是当前选中的图像提供商插件。没有注册任何提供商时，工具返回指向 `hermes tools` 的错误，而不是假装画出来。内置提供商也是插件。用户目录里的同名后端要显式启用。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 工具 | `image_generate`。聊天里异步，完成再投递 | 同一工具名。活动提供商来自 `image_gen.provider` | 若有，是客户端工具 |
| 发现 | 媒体工具在至少一个提供商配置后才出现 | 发行目录、用户目录、pip 入口。发行的随后端种类自动加载 | 无插件登记 |
| 覆盖 | 插件可以替换能力 | 用户目录需要 `plugins.enabled`。登记进 `image_gen_registry` | 无 |
| 结果 | 路径受任务工作目录和批准的根约束 | 提供商返回图像。再被视觉读回时进入嵌入预算 | 内容块 |

## Hermes

扫描三处：仓库里的 `plugins/image_gen/<name>/`，带 `kind: backend`，始终可加载；用户家目录下的同名路径，要放进 `plugins.enabled`；以及声明了 `hermes_agent.plugins` 入口的 pip 包。

`register` 调用 `ctx.register_image_gen_provider`，进入 `agent/image_gen_registry.py`。`config.yaml` 的 `image_gen.provider` 选出活动的一个。`hermes tools` 带人去选。

工具包装向登记处要活动提供商再分发。一个都没有时，错误指向 `hermes tools`，不返回一张假图。

提供商实现 `ImageGenProvider`。必填的是名字和 `generate`。其余有默认。内置的 OpenAI、Codex、xAI、FAL、Krea、DeepInfra、OpenRouter、Meta 都是这种插件，不是核心里的一串分支。

视频生成是另一条提供商 ABC。不要把图像插件的 `generate` 当成视频。浏览器和电脑使用也不走这个登记处。

生成的文件若出现在网关回复的路径里，交付物扫描可以把它收成附件。模型不必写媒体标记。图像若再交给视觉分析，嵌入进工具结果的次数和体积受 `vision` 预算。委派子进程里默认有每张图的次数帽。

## OpenClaw

图像工具在至少一个后端配置后才出现在目录里。聊天会话里异步跑，好了再发。相对路径相对任务工作目录。根外和符号链接拒绝。出生仪式在 `image_generate` 可用时生成四张头像，选中的裁下来放进工作区的 `avatars/`。生成失败就用表情继续，不因此结束出生。

## Claude Code

没有图像提供商登记处。图片是内容块或工具结果，受字符预算。没有「未配置就指向一条工具安装命令」的统一错误合同。
