# 终端后端

shell、代码执行和建立在 shell 上的文件工具都通过 `create_environment()` 进当前终端后端。第三方沙箱做成插件，用配置里的 `terminal.backend` 选择，和内置的本机、Docker、SSH 一样。核心在每个分类点问登记处，不维护一份后端名字的硬编码清单。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 内置 | 沙箱后端：Docker、Podman、SSH、OpenShell 等 | 本机、Docker、Singularity、Modal、Daytona、SSH 等在核心里 | 本机 shell，外加 worktree |
| 扩展 | 插件声明能力 | 用户插件登记 `TerminalEnvironmentProvider` | 无后端插件 |
| 秘密 | 出口代理按命令收回 | `strip_env_keys` 决定子进程剥哪些钥匙 | 子进程环境由客户端给 |
| 批准 | 提权才离开这个 agent 的沙箱 | `skip_container_guards` 表示危险命令批准可以按容器政策跳过 | `canUseTool` |

## Hermes

内置后端在 `tools/environments/`。第三方放在 `~/.hermes/plugins/`，注册之后用 `terminal.backend` 选择。登记的后端自动出现在这些面上：命令分发，包括终端、代码执行和文件工具；安装向导的选择器；仪表盘的探测状态；`hermes status` 和 `hermes doctor` 的检查；系统提示里的环境说明；危险命令是否跳过容器护栏；容器路径和工作目录；同步缓存路径的翻译；子进程剥秘密；非持久容器时的按会话隔离。

这些旗标写在提供商上。核心在每个点问登记处。新后端漏掉某一个 `if 名字 == docker` 的老问题，靠的是不再写那种分支。

`is_remote` 和 `env_description` 进提示的环境说明，放在易变层的运行环境块里，不把「现在在哪台机器」写进稳定身份。`is_container` 决定路径怎么解释。`session_isolated_when_nonpersistent` 在 `container_persistent: false` 时按会话隔离。`cache_path_base` 翻译要同步的缓存路径，免得容器里的路径被主机当成主机路径。

`strip_env_keys` 和全局的子进程环境剥除一起工作。提供商钥匙默认不进 shell。插件自己不该用 `os.environ.copy()` 去生孩子。为被服务的 profile 干活的孩子用那份家的环境构造器，丢掉启动 profile 的残留。

危险命令的批准是启发式。`skip_container_guards` 只表示这个后端已经把命令放在容器里，核心可以按这个旗标决定还要不要再套一层容器护栏。它不使容器变成对抗恶意模型的全部边界。代码执行的内核、MCP 和插件仍可能在主机 Python 里，除非整个进程树都在这个后端里。

## OpenClaw

沙箱模式和范围决定哪些会话进容器。提权只在已经沙箱时有意义，并且必须沙箱的创建者角色不能逃。后端包括 Docker、Podman、SSH 和 OpenShell。工作树的私有检出是另一层：执行在私有副本，已接受的变更归托管工作树。依赖准备不在主机上跑仓库代码。

## Claude Code

命令在客户端允许的工作区里跑。worktree 换的是检出，不是可插的终端后端。没有 `strip_env_keys` 这种由提供商声明的剥秘密旗标。权限在每次调用前决定。
