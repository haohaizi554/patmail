# 提权

沙箱里的 `exec` 默认出不了沙箱。提权让它改在配置的主机路径上跑，批准仍可保留。只有 agent 真的在沙箱里时，提权才改变行为。没沙箱的 agent，命令本来就在主机上。创建者角色要求必须沙箱的会话，不能用提权逃出去。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 开关 | `/elevated on`、`ask`、`full`、`off`。`ask` 是 `on` 的别名 | 终端后端和批准门。无同名斜杠档 | 计划模式和 `canUseTool` |
| 完全 | 主机路径上跑，并且在模式已经宽松时跳过批准 | `full` 不是跳过批准的同义词。批准门仍是启发式 | 允许规则可以不询问 |
| 谁不能 | 创建者角色要求沙箱的会话 | 容器若包住整个进程，提权斜杠不存在 | 拒绝停在工具结果 |
| 和权限模式 | 权限模式的完全访问仍受已要求的根和沙箱约束 | 文件工具和执行设置独立 | worktree 不自动提权 |

## OpenClaw

`/elevated on` 在配置的主机路径上、沙箱外执行，批准保留。`ask` 与 `on` 相同。`full` 也在沙箱外，并且当模式和主机的批准政策已经宽松时跳过批准。`off` 回到沙箱内。不带参数则显示当前级别。短名是 `/elev`。

提权不创造一台新机器。它只是不再使用这个 agent 配置的普通沙箱。主机上的执行批准、允许名单和操作者范围仍然可以问人。`full` 跳过批准的前提是那些政策已经允许跳过，不是斜杠本身废掉所有门。

会话权限模式是另一道。只读拒绝执行。守卫在允许名单之后问人。工作区模式先由模型审。完全模式要 `operator.admin`。要求必须沙箱的创建者角色打不开展提权。把 `/elevated full` 打在这种会话上，不能变成主机命令。

委托的配置变更仍要批准卡或 `/approve`。自由文本的「好」不授权。提权级别是会话指令，不是那次配置写入的批准。

## Hermes

终端后端决定 shell 和建立在 shell 上的文件工具跑在本机、容器还是远程。批准门在合作模式下拦常见的破坏性模式。它不是对抗模型的边界。代码执行、MCP 和插件仍在 agent 进程里，除非整棵进程树进了容器。

没有 `/elevated` 这四档。要离开容器，换的是后端或明确的主机执行政策，不是一条斜杠把沙箱关掉。中间件可以在批准前改写命令。批准看见的是改写后的参数。

## Claude Code

计划模式在接受前限制写和执行。`canUseTool` 每次给出允许、询问或拒绝。没有「沙箱内的命令用一条斜杠改到主机上」的档位。worktree 把检出分开，不把命令提到宿主机的另一个路径。
