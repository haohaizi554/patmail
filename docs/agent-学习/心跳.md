# 心跳

心跳是系统自己发起的一轮，用来看有没有要告诉主人的事。它和用户刚发来的消息、和 cron 任务不是同一条会话账。空转的确认不该刷屏。完成通知要回到拥有那份工作的会话，而不是借道当前主会话。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 是什么 | 主会话上的周期 agent 回合，调度器里有一条系统自动化 | 进程级心跳是存活信号。到点的 agent 工作是 cron | 没有渠道心跳。定时工具挂在编码会话上 |
| 默认间隔 | 30 分钟；Anthropic OAuth 或令牌时 1 小时 | cron 扫描大约 60 秒，那是调度不是心跳回合 | 无 |
| 不想说话时 | 投递目标可以是 `none`；静默确认留在隐藏对里 | 后台完成要被承认才注入；拒绝则退回 | 工具结果照写，没有「不发私聊」 |
| 不进记忆 | 心跳会话不产生可提升的长期候选 | cron 默认不写记忆 | 不适用 |

## OpenClaw

心跳是系统拥有的自动化：在主会话里定期跑一轮，让模型把需要注意的事浮出来，而不是每次都发一条消息。ACP、子代理和隔离的自动化任务有自己的执行主人，不借用这次心跳。

节奏归自动化调度器。每个开了心跳的 agent 在 cron 列表里有一条系统任务，名字像 `Heartbeat (agent-id)`。配置 `agents.*.heartbeat` 是期望状态。真正的 tick 和冷却在持久化的监视日程上。Gateway 在启动和配置重载时把配置写进去。改的是心跳配置，不是那条自动化任务本身。保存监视行失败时，已接受的配置留着，并报告需要恢复。被拒绝的修改不会变成重试目标。

`cron.enabled: false` 或 `OPENCLAW_SKIP_CRON=1` 时，不定时心跳，启动时警告。手动和事件唤醒仍可用。没有第二条心跳定时器。`every: "0m"` 只关掉周期。事件仍可以跑一轮，例如后台 exec 完成。它不会把周期日程重新打开。若连完成回合和它的模型调用都不要，把 `tools.exec.notifyOnExit` 设为假，用 `process poll` 自己取结果。

事件唤醒即使没有周期，仍受每 agent 的限速：两次事件回合至少隔 30 秒，60 秒内开始五次之后进入洪水保护。保护到期再继续。配置重载保住这份计数，不会因此把 agent 编进周期或广播心跳。

transcript 里用标记区分心跳轮询、exec 完成、cron 唤醒和会话事件。定时轮询用配置的心跳会话，默认是该 agent 的主会话。指向某份工作的完成事件回到拥有那份工作的会话。标记保留来源，不把内部说明抄进聊天历史。成对的静默确认保持隐藏。

默认投到操作者的私聊。`target: "owner"` 从 `commands.ownerAllowFrom` 再从渠道 `allowFrom` 找第一个能解析的私聊，绝不落到群。`last` 才跟随上次的外部对话，包括群。`none` 只跑内部状态，不对外送。`directPolicy: "block"` 抑制私聊投递。`to` 在目标是 `owner` 或未设置时被忽略。Telegram 话题写成 `<chatId>:topic:<id>`。`target` 不接受 `telegram:123` 这种拼在一起的值。

`lightContext` 为真时跳过工作区引导文件。监视便签仍由心跳运行器注入。某次对话自己的后台命令完成仍用那次对话的完整上下文。`isolatedSession` 为真时每次心跳是一份没有历史的新会话，和隔离自动化同一套模式，用来省 token。投递仍按选中的对话、账号和话题走。后台命令完成不因为对话后来换了房间就借用新房间的说明。对话自己的后台完成不隔离。

活跃时段用本地或指定时区。窗口外跳过，下一拍在窗口内照常跑。`start` 和 `end` 设成同一时刻是零宽度窗口，心跳永远跳过。省略 `activeHours` 就是全天。

心跳、cron 和 exec 可以写会话元数据，但不延长每日或空闲重置所看的新鲜度。它们不产生可提升的长期记忆候选。

## Hermes

网关事件里的 heartbeat 是进程还活着，不是一轮让模型看便签的主会话。到点要让模型干活，用 cron：每次新建没有历史的 AIAgent，技能作为用户消息注入，跑完再投递。投递失败记 `delivery_failed`，和运行失败分开。漏掉的周期按宽限补一次或收成一次追赶，见定时笔记。

后台命令 `terminal(background=True, notify_on_complete=True)` 在完成时武装网关观察者，再开一轮。verbosity 看 `display.background_process_notifications`。注入要拿到 `admit_internal_event` 的回执。处理函数返回空不算接受。拒绝时，同批已经占用的名额退回，不消耗尝试。这和 OpenClaw 的「完成事件回到拥有工作的会话」是同一类约束：通知不是旁路成功。

子代理的后台进程在孩子拆卸时杀掉，完成通知不进父会话。交给父任务的进程才跟父主人走。心跳租约是 cron 领取的 300 秒续期，不是主会话轮询。

## Claude Code

没有「每 30 分钟在主聊天里问一句有没有事」的系统回合。`ScheduleCronTool` 把以后再跑留在编码会话的工具面上。后台任务导航和计划任务钩子是界面状态，用来看任务还在不在，不另开一条会刷屏的私聊。

工具若失败，结果保持失败。没有一条隐藏的 `HEARTBEAT_OK` 协议。要安静，就不要发那次工具调用。
