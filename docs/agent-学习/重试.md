# 重试

重试的是当前这一次 HTTP，不是整段多步流程。非幂等的操作不自动再放一遍。模型的临时故障有单独的预算。账单、认证和拒绝不占用这份预算，它们走换钥匙或换模型。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 模型临时故障 | 限流最多 10 次尝试。其它临时故障在 90 秒窗口里 8 次重试。成功的完整响应清空窗口 | 凭据池内先重试再轮换。跨提供商备用在池用尽之后 | 同一 `query` 里的恢复和空响应修补 |
| 长的 Retry-After | SDK 内部等待默认帽在 60 秒，然后把控制交回，好走转移 | 响应里的重置时间让主模型停到那个时刻。没有时间则从约 60 秒退避到约 4 小时 | 客户端的请求超时 |
| 渠道发送 | 默认 3 次，抖动 10%。Telegram 下限 400 毫秒，Discord 发送 500 毫秒 | 投递和模型运行分开记 | 无渠道发送环 |
| 不重试 | 账单、认证、拒绝、空的 400 和 422、git 的 push 和 pull | 内容策略。用量封顶不对同一把钥匙再试 | 用户拒绝可以停整轮 |

## OpenClaw

目标是按 HTTP 请求重试，保持顺序，避免重复非幂等操作。渠道发送的默认尝试次数是 3，抖动 0.1。共享下限 400 毫秒，上限 30 秒。Discord REST 上限 300 秒。Discord 的 WebSocket 重连是另一条环，最多 50 次，从 2 秒指数到 30 秒，没有抖动。

模型运行在展示终局错误之前，自动从临时限流、过载和提供商故障里恢复。限流最多 10 次尝试。其它临时故障允许在 90 秒窗口里 8 次重试。一次完整成功的模型响应清空中断窗口。有用的模型和工具工作夹在失败之间，不消耗这个窗口。半截流、失败响应和单独的工具活动不清空它。整个运行的重试次数仍有界。退避从大约一秒起，指数增加并加抖动。提供商的 `retry-after` 和「请在若干秒后重试」设定最低等待，可以超过 30 秒的退避帽。取消和运行期限仍能停掉恢复。

恢复沿现有 transcript 继续，并要求保留已完成的工作、先检查被打断的动作再决定要不要重复。限流发生在工具活动或半截输出之后，也可以恢复，不必重交原来的用户请求。等待时只显示一个临时重试指示，可取消。恢复了的尝试不留下持久的助手错误。只有终局失败保留一条错误。

空的错误体不会让确定的 HTTP 客户端错误变得可重试。没有正文的 400 和 422 直接表面化。带有已知临时证据的客户端错误仍走恢复。空的成功响应有单独的修补重试。

嵌入运行时里，工具活动之后的模型空闲超时，在最新一批工具都有记录的结果、执行也都落定之后，才用这份恢复。下一次尝试仍带着工具把任务做完。待批准、异步工具、有意终止、取消和运行期限阻止这次继续。已完成的动作不重交。

Responses 流在终局事件之前结束，包括工具调用还没写完，也算临时恢复。半截的工具参数从不执行。完成了的响应若工具调用身份不一致，不算断流。输出 token 用尽时若正在生成工具调用，嵌入运行器在已承认的工具落定后自动继续，同一模型和账号，共享重试次数和运行期限，但不共享那 90 秒中断窗口。拒绝和未知的未完成原因不合格。

用尽的日、周、月额度直接走合格的认证 profile 或模型备用。单独一个 `Retry-After` 不构成额度用尽。临时限流尊重提供商的最低等待，直到保存的 `retry.provider.maxRetryDelayMs`（默认 60 秒）。比这更长的限流下限，在配置了备用时直接转移。没配备用则完整等待。设成 0 关掉这顶帽。

模型转移控制器拥有这份恢复预算。用尽之后才走 profile 或模型备用，或表面化终局失败。原生 harness 在返回终局失败之前可以自己重试单次请求，那不算 OpenClaw 的继续预算。

基于 Stainless 的 SDK 在 408、409、429 和 5xx 上可能内部睡眠。等待长于 60 秒时，OpenClaw 注入 `x-should-retry: false`，让 SDK 尽快把控制交回来。`OPENCLAW_SDK_RETRY_MAX_WAIT_SECONDS` 可调，0 或 off 表示让 SDK 自己睡满。

托管的 git `fetch` 和 `ls-remote` 对瞬时失败再试一次，延迟一秒，仍在原命令超时里。失败的半截克隆先删掉。`push` 和 `pull` 不由这个运行器重放，因为失败的连接可能发生在写入已被接受之后。认证失败、仓库或引用缺失、本地存储失败不重试。这套政策不包住 agent 自己跑的任意 git 命令。

Discord 对 429、超时、5xx 和瞬时传输失败重试，有 `retry_after` 就用它。Telegram 用共享信封。

## Hermes

同一提供商内，普通 429 对当前钥匙再试一次，第二次再轮换。用量封顶不重试当前钥匙。402 立刻轮换并冷却一小时。401 先刷新。内容策略不轮换。

跨提供商的备用在池用尽之后。限流若带重置时间，主模型停到那个时刻。没有时间则从大约 60 秒退避到大约 4 小时。很快就会恢复时，可以用 `fallback.min_switch_reset_seconds` 选择等待而不是换模型。

回合循环里的错误相位处理空响应、溢出和提供商错误。压缩的摘要流若停滞，在辅助回退链上再试一次。再停滞则走确定性的后备摘要，仍经同一条管道。不在租约之外提交裁剪。

渠道投递失败不把模型运行改判成失败。`delivery_failed` 表示跑完了但人没收到。

## Claude Code

临时的模型失败留在这一次查询循环里修补。空响应和断流有自己的重试。工具失败写成配对的失败结果，不把整次用户请求无声重放。用户拒绝可以停整轮。停止钩子还可以要求再跑一轮，那是新的一轮，不是 HTTP 重试。

没有渠道发送的三次尝试信封。MCP 刷新发生在两轮之间。刷新失败留下上一份工具面，直到下一次成功的刷新。
