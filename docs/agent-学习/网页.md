# 网页

搜索和抓取是轻量 HTTP。浏览器是另一块屏幕，用来点、登录和跑 JavaScript。把搜索结果当成已经核实的页面，或者把抓取当成沙箱浏览器，都会把不可信正文送进上下文，同时还绕过标签页上的对话框和跨域限制。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 搜索 | `web_search`，按查询缓存约 15 分钟 | 网页工具门面，后端可换 | `WebSearch` |
| 抓取 | `web_fetch` 总在本地跑 | 抓取工具返回正文，作为工具结果 | `WebFetch` |
| 和浏览器 | JS 重的站和登录用管理浏览器 | CDP 监督器只在有调试端口的后端上 | 抓取不持有标签页 |
| 不可信 | 声明为网络来源的工具结果污点这一轮记忆 | 工具结果进上下文，秘密和批准仍在进程策略里 | 结果受每条、每轮字符预算 |

## OpenClaw

`web_search` 用配置的提供商，返回归一化结果。同一查询默认缓存 15 分钟。`x_search` 搜 X 的帖子，始终走 xAI Responses。`web_fetch` 抓一个 URL，始终在本地跑。Grok 当搜索提供商时，`web_search` 走 xAI Responses。其余提供商走各自的 HTTP API。

设置里把「搜索开着」和「提供商已配置且能用」分开。选一个 agent 和模型，才能看见有效路线：原生搜索、托管提供商、禁用或不可用。控制界面或 `openclaw configure --section web` 写入提供商。API 密钥在浏览器里打码。终端对话把输入交给打码向导。也可以只设提供商自己的环境变量，例如 `BRAVE_API_KEY`。

自动模式在还没选定提供商时，按优先级试密钥，直到有一个能解析。选定之后，没被选中的提供商密钥变成未激活表面，解析失败不挡 Gateway 启动。

搜索不是浏览器自动化。要执行页面脚本或使用登录态，用管理浏览器。要读一个已知 URL，用抓取，而不是再搜一次。

抓取和搜索的正文是外部内容。工具若声明结果来自网络，这一轮剩下的助手消息在记忆分类里变成 `untrusted`。下一条用户消息才清除污点。本地读文件不走这道污点。所以把网页贴进工作区再读，和当场抓取，在记忆提升上不是同一条路。

SSRF 策略在浏览器配置里，避免用浏览器打内网。抓取工具自己的 URL 策略要和这道一起看。搜索缓存只省重复查询，不把结果变成可信记忆。

## Hermes

网页工具和浏览器工具是两套门面。搜索和抓取把正文放进工具结果。浏览器在有 CDP 的后端上维持标签、对话框和跨域 iframe。Camofox 只有 REST，监督器帮不上抓取替代不了的点击。

工具结果会进入之后的模型上下文。旧的、超过大约 200 字符的结果可以在压缩时被换成占位。网页正文因此既贵，也会在摘要里丢掉，除非它还在保护尾里，或已经被写进记忆或技能。

网络来的正文属于不可信输入面。安全政策认为：批准门和打红挡不住对抗性字符串。默认本机后端加上开放网页，不在「整个进程都在沙箱里」的支持姿态中。终端沙箱只困住 shell 和基于 shell 的文件工具，困不住已经进了 Python 进程的抓取结果。

出口代理可以让离开进程的 HTTP 走密钥注入，而不是把 API 密钥放进抓取命令。那是凭据路径。页面正文仍会回到工具结果里。

子代理若保留网页工具，父会话只看见摘要，除非结果被写进文件或评论。看板上的抓取留在那张卡的评论和附件里，压缩父对话不会把板清掉。

## Claude Code

`WebFetch` 和 `WebSearch` 是普通工具。结果按大约每条 50000 字符、每轮 200000 字符裁，超出的落到 `tool-results/`。缺了配对的 `tool_result` 会补一条，否则下一请求失败。

它们不打开标签，不回答 `alert`，不进入跨域 iframe。登录墙就是一块抓下来的 HTML 或一条错误。要看渲染后的页面，得另有视觉或截图路径，那仍是工具结果，不是 CDP 会话。

SSRF 防护在钩子里。抓取不是工作区读文件。`file://` 和工作区外的路径走读文件和权限，不走网页工具绕过。

搜索结果和抓取正文一样，是这一轮的工具输出。它们不自动写成 `MEMORY.md`，也没有 15 分钟的查询缓存合同写在这棵还原树的循环里。下一轮要再看到，就靠还留在上下文里的那条结果，或模型再次调用工具。
