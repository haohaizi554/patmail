# 客户

第三方操作者或 WebChat 客户端用发布的 Gateway 包，不从仓库里抄协议。包版本跟着 OpenClaw 的发布列车，和线路协议版本不是同一个数。要钉死确切版本，并和要连的 Gateway 一起测。保留的 `0.0.0` 包没有可运行入口，也没有 TypeScript 声明。设备令牌的存放和签名归宿主，不归传输库。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 包 | `@openclaw/gateway-protocol` 与 `gateway-client`。示例列车 `2026.8.1` 导出线路版本 4 | `tui_gateway` 的契约在 Python 里生成 TypeScript | 无 Gateway 客户包 |
| 浏览器 | 浏览器入口另给 WebSocket 适配器、持久存储和签名回调 | 桌面用共享的 JSON-RPC 客户端。令牌在查询里因为升级带不了 Authorization | 无 |
| 重连 | 客户端自己的恢复。事件不重放 | 再挂一个订阅者，不换掉原连接。主人重启不保证提示还在 | 打开同一份 JSONL |
| 范围 | 会画批准的交互客户端请求操作者角色和相应范围 | 会话令牌。方法再绑 profile | 本机用户 |

## OpenClaw

协议包提供 schema、运行时校验、类型、客户端身份和能力登记、结构化错误读取，以及协议版本常量。npm 包里还有生成的 `protocol.schema.json`，当作文件下，不是包的导出子路径。客户端包的根是 Node。`/browser` 是浏览器安全的协议、设备认证和重连助手。这些发布声明 Node.js `>=22.19.0`。Node 入口带 `ws`。设备身份、签名和设备令牌存储通过宿主依赖留下，由宿主实现。

锁文件里若还钉着 `0.0.0`，换上确切的稳定版。那个保留构件跑不起来。

线路版本和包版本分开。某个包导出线路 4，不保证配得上每一台 Gateway。根 CLI 有自己的包版本和 dist-tag。升级前看线路版本规则。

握手仍是 Gateway 先挑战，客户端再 `connect`。角色和范围在认证之后决定能调什么。会话 id 选路由。发现信标里的 TXT 无认证，不代替已存的 TLS 指纹。

## Hermes

契约是 Pydantic 模型，生成给 TypeScript。未声明的方法在导入时拒绝。未知参数键拒绝。测试隔离下，结果对不上模型会违反合同。桌面、TUI 和仪表盘共用这套。旧客户端没声明能回答服务端请求时，提问快速失败。没有把 `0.0.0` 保留包和线路版本拆开的 npm 列车。远程连接每次 OAuth 拨号领新票。

## Claude Code

没有这套 Gateway 客户包。IDE 若走别的协议，版本跟着那个客户端。
