# 语音频道

Discord 有两套语音。实时语音频道是持续对话。语音消息附件是波形预览那种格式。Gateway 两者都支持。实时语音默认不随纯文本配置打开。要设 `channels.discord.voice.enabled`，或保留已有的 `voice` 块，才会有 `/vc`、语音运行时和 `GuildVoiceStates` 意图。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 房间 | 每个说话人一条提供商连接。房间共用一个 OpenClaw 会话和一条播放队列。最多八条说话人连接 | 语音模式按句播放。Discord 语音回复另计 | 无 |
| 模式 | 默认 `agent-proxy`。另有 `stt-tts` 和 `bidi` | 流式合成或按句同步 | 无 |
| GPT-Live | 不支持宿主强制的唤醒名。显式打开会在启动时报配置错误 | 唤醒词在设备上，针对文本语音管道 | 无 |
| 转向 | 语音里转向正在跑的 agent，后端要能在分发时再查说话人权限。Copilot 目前没有这道 | `/steer` 在工具结果之后 | 无 |

## OpenClaw

`/vc join`、`leave`、`status` 用账号的默认 agent，并遵守和其它 Discord 命令相同的允许名单和群策略。在 Discord 消息框里当斜杠命令打，不是在 shell 里。

`voice.mode` 默认 `agent-proxy`。实时语音前端负责回合时机、打断和播放，把实质工作经 `openclaw_agent_consult` 交给路由到的 OpenClaw agent，并把结果当成那个说话人的一条打出来的 Discord 提示。`stt-tts` 是较旧的批量识别加合成。`bidi` 让实时模型直接对话，同时暴露咨询工具给 OpenClaw。

每个说话人的音频在单独的提供商连接里，延迟的转录和工具调用仍带着那个人的 Discord 身份。大家仍用同一条路由到的 OpenClaw 会话和一条房间播放队列。直接的 `bidi` 历史属于每个说话人自己的实时连接。共享的房间历史走 OpenClaw 咨询。房间最多留八条说话人连接。捕获、请求和播放都结束后，收回空闲连接。

`voice.agentSession` 不设时，语音回合进这个语音频道自己的会话。设成目标文本频道时，语音频道变成那条已有文本会话的麦克风和扬声器，例如 `#maintainers`。

`voice.model` 覆盖 Discord 语音回复和实时咨询用的 OpenClaw 脑子。不设就继承路由到的 agent 模型。它和 `voice.realtime.model` 分开。

`agent-proxy` 经 `discord-voice` 走。它保留说话人和目标会话正常的主人和工具授权，但藏起 agent 的 `tts` 工具，因为播放归 Discord 语音。默认给主人说话人的咨询以相当于主人的完整工具访问。有宿主控制回合的模型强烈偏好在实质回答前咨询 OpenClaw。GPT-Live 用提供商拥有的委派，咨询策略是 `auto`。`always` 时，实时层不在咨询答案之前自动说填充语。它捕获并转写，然后说出路由到的 OpenClaw 答案。多份强制咨询的答案在 Discord 还在放第一份时完成，后来的精确语音答案排队，直到播放空闲，不在句子中间替换。

GPT-Live 拥有响应时机和打断。Discord 播放连续音频，不等完成事件，也不在本地加说话人开始的打断。播放期间麦克风仍准入，让 GPT-Live 自己听见并处理打断。委派的任务用路由到的 OpenClaw agent，带着发起说话人的 Discord 身份和工具权限。房间控制在请求口播结果之前清掉缓冲的本地播放，并保持连续的提供商流开着。Gateway 持续给麦克风输入打拍，包括说话人捕获之间的静音。播放保留活动流里的安静 PCM，包括前面的语音已经放过之后送来的停顿。播放器两秒空闲宽限里没有未听的语音时，接受的音频排空，然后才释放房间播放器。宽限退休期间到达的语音排到新的资源下，不跟旧流一起丢掉。连续播放建 120 毫秒的启动缓冲，吸收短暂的投递空隙。120 毫秒的启动期限让短回复不必等完成事件。

GPT-Live 不支持宿主强制的唤醒名门，也不支持每次回复前强制咨询。默认把这些策略留关。显式 `requireWakeName: true` 或 `consultPolicy: "always"` 在启动时配置错误。要宿主控制的回合，去掉这些设置，或改用 `gpt-realtime-2.1`。每个说话人仍有单独的语音模型连接。OpenClaw 的 agent 对话提供共享的房间上下文。

模型和嗓音必须属于同一条路线。`cove` 是 Codex GPT-Live 的嗓音。把它和 `gpt-live-1` 一起选，会退回 `marin`。Codex 路线优先 ChatGPT OAuth，再回退平台 API 钥匙。公开 API 选 `gpt-live-1` 时，Discord 用 Gateway 直连的平台钥匙 WebSocket 桥。

实时语音在 Discord 播放暂时落后时缓冲生成的音频，并容忍短暂的提供商或网络空隙。每一次提供商响应保留自己的缓冲音频，包括原生工具的延续。正常的背压不取消响应。排队的答案等到 Discord 放完上一条，即使提供商响应或音频编码器已经结束。

从 Discord 语音转向正在跑的 agent，后端要能在分发时再查说话人的权限。Copilot 目前没有这道受守卫的输入能力。状态和取消仍可用，也可以新开一次请求。

## Hermes

语音按句播放，思考块先剥掉。Discord 可以有语音回复。没有「每个说话人一条提供商连接、房间最多八条、GPT-Live 拒绝宿主唤醒名、咨询答案不在句子中间替换」这一页 Discord 语音频道合同。唤醒词在设备上，针对的是开口之前音频不离开机器的那条管道。

## Claude Code

没有 Discord 语音频道，也没有房间播放队列。
