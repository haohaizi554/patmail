# 反代

可信反代把认证交给前面的身份代理。Gateway 只在源地址落在 `gateway.trustedProxies` 里时，才读身份头。环回要显式同意。Gateway 自己其它网卡上的地址一律拒绝。任何能绕过代理直达 Gateway 的路径，都不该开这个模式。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 谁证明身份 | 反代写身份头。Gateway 先核对源 IP | 会话令牌。RPC 再绑 profile 的家目录 | 本机用户 |
| 环回 | 默认拒绝。`allowLoopback` 且该地址也在可信列表里才过 | 本机 `serve` 用会话令牌，不把 `X-Forwarded-User` 当登录 | 无 |
| 本机网卡 | 非环回但属于 Gateway 自己接口的源，当伪造拒绝。接口发现失败也拒绝 | 无这道源地址阶梯 | 无 |
| 绕过 | 有任何不经代理的路径就不要用这个模式 | 令牌不在查询里发给浏览器升级以外的设计。WebSocket 用同一枚会话令牌 | 无反代模式 |

## OpenClaw

代理先认证用户，再加身份头，例如 `x-forwarded-user`。Gateway 确认请求来自可信代理 IP。环回来源要 `allowLoopback`。其它属于 Gateway 本机接口的地址被拒绝。然后读必填头和配置的用户头。设了 `allowUsers` 时，抽出的用户必须在名单里。

模式是 `gateway.auth.mode: "trusted-proxy"`。默认期望代理的源 IP 不是环回，绑定常用 `lan`。只把代理自己的地址放进 `trustedProxies`。支持 CIDR。IPv4 映射的 IPv6 写法与纯 IPv4 等价。`::ffff:0:0/96` 表示全部 IPv4，其中的环回仍要 `allowLoopback`。原生 IPv6 对端不匹配映射范围。

判定顺序：

1. 像代理的流量在 Gateway 认证之前就归属。源 IP 必须匹配可信列表，客户地址头必须解析成非环回客户。否则要 Gateway 认证的路由以 `proxy_attribution_required` 拒绝，还不接受身份头。插件认证的 webhook 仍可处理，但忽略不可信的转发地址，用套接字源做自己的限额。
2. 代理必须用安全的链覆盖 `X-Forwarded-For`。只有在转发头缺失、且打开了 `allowRealIpFallback` 时，才接受被覆盖过的 `X-Real-IP`。代理若没有去掉客户端自带的 `X-Real-IP`，不要开这个后备。
3. 环回在头检查之前就拒绝，除非显式允许且环回地址也在可信列表里。必填头缺失改变不了这个结果。
4. 撞上 Gateway 自己非环回接口地址的源，以伪造防护拒绝。接口发现失败同样拒绝。
5. 必填头和用户头必须存在且非空。
6. `allowUsers` 非空时必须包含抽出的用户。

环回上若带着 `Forwarded`、任何 `X-Forwarded-*` 或 `X-Real-IP`，这份转发证据使它不能再走本机直连的口令后备和设备身份门。它作为环回，可信反代认证仍然失败。

`allowLoopback` 把 Gateway 主机上的本机进程信任到和反代同一程度。只有 Gateway 仍然被防火墙挡住远端直连、且本机代理会去掉或覆盖客户端自带的身份头时才开。

不走反代的内部客户端用 Gateway 口令，不用身份头。`openclaw gateway status` 在没有 `--url` 时自动选这个本机口令。更新和重启的健康检查在没有共享凭据时，可以复用本机 CLI 已经配对的设备凭据。这些检查只读已有身份和令牌，不创建身份，也不保存替换凭据。

`identityScopes` 把连接期的操作者范围授给核对过的反代或 Tailscale 身份。邮箱键不区分大小写。未知的范围名通不过配置校验。

只做 TLS 终结或负载均衡、却不认证用户的代理，不要开这个模式。个人单用户更适合 Tailscale Serve 加环回。

## Hermes

仪表盘和桌面的 WebSocket 用同一枚会话令牌。方法在会话所属的家目录上执行。多 profile 时，秘密不从进程环境里借。没有「源 IP 在名单里才相信 `x-forwarded-user`」这一档。API 服务用 `.env` 里的 `API_SERVER_KEY`，示例绑定在环回。

## Claude Code

认证是跑客户端的用户。没有 Gateway，也没有把反向代理的身份头变成操作者范围的模式。
