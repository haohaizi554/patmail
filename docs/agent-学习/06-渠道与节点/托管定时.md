# 托管定时

Chronos 让托管的 Hermes 网关在空闲时可以缩到零，定时任务仍会触发。它不在进程里转 60 秒的滴答。agent 请 NAS 为每个任务、在那个任务真正的下一次触发时刻，武装恰好一次外部的一次性触发。到点 NAS 用已认证的回调打回来。agent 跑完任务，再武装下一次。两次触发之间进程可以完全停着。它只在真的触发时醒来。

## 对照

| | OpenClaw | Hermes Chronos | Claude Code |
|---|---|---|---|
| 谁守钟 | Gateway 里的调度器。停了就停 | NAS 武装一次性触发。agent 可以不在 | 无托管 cron |
| 一次几个 | 每个任务自己的下次运行 | 每个任务恰好一个外部一次性，对准真实的下次触发 | 无 |
| agent 看见什么 | 任务存储在本机 | 三个 NAS 端点。不接触调度器，不拿它的凭据，不叫它的名字 | 无 |
| 认领 | 槽在分发前推进 | 核对 NAS 签发的短时 JWT，存储做比较并交换的认领，再跑，再武装下一次 | 无 |

## Hermes

创建、更新、暂停、恢复或删除在 agent 侧。`reconcile` 算出 `next_run_at`，用 agent 的 Nous 访问令牌 `POST` 到门户的 provision。NAS 为 `fire_at` 武装一次性触发。NAS 拥有调度器和它的凭据。到点，调度器用自己的签名打到 NAS 的 relay。NAS 铸造短时的、听众是这个 agent 实例、用途是 `cron_fire` 的 JWT，再 `POST` 到 agent 的 `/api/cron/fire`。agent 用 NAS 的 JWKS 核对这个 JWT，存储做比较并交换的认领，跑这一个任务，再武装下一次一次性触发。

第一跳的令牌是 agent 已有的门户访问令牌。托管 agent 用的是启动时种进 `auth.json` 的引导会话令牌，客户端是 `hermes-cli-vps`，不是 `agent:*` 客户端令牌。浏览器用户的交互授权才会铸出 `agent:{instance_id}` 那种客户端凭据。NAS 要从令牌认出实例：要么是 `agent:{id}` 客户端，要么是引导令牌的会话 id 对上 `AgentInstance.bootstrapSessionId`，并且限在组织内。第三跳的触发 JWT 仍然带 `aud=agent:{instance_id}`。只认 `agent:*` 客户端会让真正的托管 agent 在 provision 上全部 403。

第二跳的调度器签名由 NAS 核对。agent 从不拿这把签名。第三跳的短时 JWT 由 agent 核对。三跳的秘密不混用。

本机的 Hermes cron 仍是进程内的滴答，按家目录加锁，发生槽在分发前推进。Chronos 是托管、可缩到零的那一条。两条不要当成同一个调度器。

## OpenClaw

定时任务在 Gateway 里。没有 NAS 替它武装一次性触发，也没有缩到零之后靠短时 JWT 叫醒。Gateway 停了，这一台主机上的调度就停了，除非另有进程在跑。

## Claude Code

没有托管的一次性触发合同。定时若存在，是用户自己的环境，不是 NAS 回调。
