# 尾网

Tailscale 的 Serve 让 Gateway 继续绑在环回上，由 Tailscale 提供 HTTPS、路由，以及 Serve 的身份头。Funnel 把仪表盘公开到公网，并且要求共享口令。默认 `off` 表示 OpenClaw 不在管理 Serve 或 Funnel。它不表示本机的 Tailscale 守护进程已停止或已登出。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 环回加 HTTPS | `tailscale.mode: serve`。Gateway 仍在 `127.0.0.1` | 远程用 SSH、URL 加令牌或云。无这条自动 Serve | 无 |
| 公网 | `funnel` 必须配口令。tailnet 里的对端走 Serve 身份路径，公网请求仍要这份口令 | 不要把兼容补全或 API 放到公网当默认 | 无 |
| 直接听 tailnet | `bind: tailnet` 是另一条，不经过 Serve | 无 | 无 |
| 设备身份 | 共享秘密不代替浏览器的设备身份 | 会话令牌。OAuth 每次拨号领新票 | 本机用户 |

## OpenClaw

`serve` 经 `tailscale serve` 只对 tailnet。`funnel` 是公网 HTTPS。状态和审计里的「Tailscale 暴露」指的是 OpenClaw 的这档模式。

直接绑到 tailnet 地址时，不经过 Serve 或 Funnel。另一台 tailnet 设备用 `ws://<tailscale-ip>:18789`。浏览器控制界面可以在直接的明文 HTTP 地址上用纯 JavaScript 的 Ed25519 创建并签名设备身份。令牌或口令认证下，共享秘密仍然不代替浏览器设备身份。明文 HTTP 是降级的传输：签名不加密页面、共享秘密或 Gateway 流量。更合适的是 Serve 的 HTTPS。

从 tailnet 地址本身加载控制界面，是私有的同源请求，不需要 `allowedOrigins` 里的一条。公网或跨源的浏览器部署需要允许的源。

启动时若有可绑定的 tailnet IPv4，Gateway 还为已认证的同主机客户端要求 `http://127.0.0.1:18789`。启动时没有 tailnet 地址，就只落回环。Tailscale 之后才可用时，重启才加上直接的 tailnet 访问。两条路径都不增加局域网或公网暴露。

Funnel 把 Gateway 留在环回，模式 `funnel`，认证用口令。口令优先放在 `OPENCLAW_GATEWAY_PASSWORD`，不要写进磁盘上的配置。Funnel 的 URL 在 tailnet 内部也能用。Tailscale 把公网请求标成 Funnel 流量，但把 tailnet 对端送进 Serve 的身份路径。OpenClaw 在专用监听器上认出两条路径，并且仍然要求配置的 Funnel 口令。

Serve 不能和 `gateway.auth.mode: "none"` 叠在一起。Gateway 事先要有令牌、口令或可信反代。稳定的 HTTPS 名是 `https://<主机>.<tailnet>.ts.net`，配套 WebSocket 是 `wss://` 同一主机。它从允许的 tailnet 设备可达，不从公网可达。要公网用 Funnel。MagicDNS 和 Tailscale 管理台里的 HTTPS 证书要开着。OpenClaw 自己找 `tailscale`：PATH、macOS 应用包里的二进制，以及系统的 locate 库。不必把应用包里的二进制加进 PATH。

身份头只有在可信反代或这条 Serve 路径上、源被核对之后才算数。Funnel 的公网入口不是「没有口令的身份头」。发现信标里的 tailnet DNS 只是提示，路由仍以解析到的端点为准。Tailscale 的身份头只认证控制界面的 WebSocket 这一面，不认证其它认证路径。个人使用优先环回加 SSH 隧道。公网暴露要身份感知的代理、TLS、限流、严格允许名单，以及非主会话的沙箱。说不清谁能到达、怎么认证、能触发哪个 agent、那些 agent 能用哪些工具时，回到只听环回并重跑审计。

## Hermes

远程桌面连接用操作者给出的地址和令牌。本机 `serve` 示例绑在环回。没有 OpenClaw 这种由应用去调用 `tailscale serve` 或 `funnel`、并在 Funnel 上强制共享口令的模式开关。

## Claude Code

没有要暴露的 Gateway 仪表盘。客户端在本机。
