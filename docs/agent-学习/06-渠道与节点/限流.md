# 限流

Gateway 上有多道彼此独立的限流。它们保护的边界不同，键不同，错误形状也不同。未认证的 WebSocket 是同时挂起的握手预算，不是每分钟请求数，也不封顶已经认证的客户端。环回不豁免。认证失败另有锁。重启之间有冷却。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 握手 | 每个客户端 IP 最多 128 个未认证连接。超了 HTTP 503。认证成功或连接关闭就放槽 | 会话令牌。没有这道预认证套接字预算 | 无 |
| 认证失败 | 10 次 / 60 秒，锁 5 分钟。键是 IP 加凭据范围。浏览器来源的失败同样，环回不豁免 | 确认的 401 或 403 才重新认证 | 客户端自己的错误 |
| Webhook | `/hooks` 认证失败 20 次 / 60 秒，锁 60 秒。按 IP。不可配置 | 入站平台有自己的限制 | 无 |
| 写 | 控制面写 RPC 每个方法 30 次 / 60 秒。键含方法、设备和 IP | 配置写是原子的。无限流表 | 无 |
| 其它 | ACP 建会话 120 次 / 10 秒，按翻译器实例。Gateway 重启冷却 30 秒 | 更新先排水。无 30 秒重启冷却写在同一张表 | 无 |

## OpenClaw

未认证连接的槽在认证成功或连接关闭时释放。失败的升级也释放。超过预算的升级得到 503，正文说明限流。这不是把已登录的操作者算进 128。

令牌、口令或设备认证失败走 `gateway.auth.rateLimit`。浏览器来源的 WebSocket 认证失败用同一套，环回不豁免。环回上若能从页面源站认出，键可以用源站。

控制面写的背压不可配置。ACP 的会话创建上限是内部的。重启冷却按进程，30 秒内不再起一轮重启。这和请求的重启先排水最多约五分钟不是同一道。冷却挡住重启风暴。排水等的是已经在跑的活。

非环回绑定若没有有效的 Gateway 认证路径，拒绝启动。有效路径是共享秘密的令牌或口令，或正确配置的、非环回的可信反代。画布和 A2UI 资源在 Gateway 同一端口上。绑出环回之后，它们受 Gateway 认证保护。

这些数字是默认。预认证并发和认证失败锁可以改。Webhook、控制面写、ACP 和重启冷却在这页上不可配置。

## Hermes

认证失败不会按这张表锁 IP。多 profile 的错误是范围读不到秘密，不是 5 分钟锁。API 的 429 是提供商的，和 Gateway 的预认证 503 不是同一层。桌面重试有界，并以恢复手段结束。

## Claude Code

没有 Gateway 握手预算。提供商的速率限制出现在这一次请求的错误里。客户端可以重试或换模型，没有 128 个未认证套接字这道门。
