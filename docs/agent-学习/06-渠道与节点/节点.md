# 节点

配对过的节点是能力宿主：摄像头、屏幕、位置、通知，以及 macOS 上的部件面板。`openclaw nodes` 经 Gateway 看状态和调用。数字旗标省略就用默认。显式的空字符串或纯空白在查找节点或请求 Gateway 之前就失败。连接时间用 Gateway 记下的上次连接，包括刚重连的，也包括已经断开但有历史的。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 角色 | `node`。命令经 `node.invoke`。不是操作者 | 桌面是渲染器。电脑使用走本机无障碍 | 无节点 |
| 在场 | 已连接的 macOS 节点报告和 OpenClaw 的交互，不另要权限。全系统在场要辅助功能 | 无这套节点在场 | 无 |
| 列表 | `list` 把待配对和已配对分成两表。`status` 合成一张，带能力和版本 | 设备配对不在这条 CLI | 无 |
| 统计 | 有主机统计时带负载、内存和磁盘。负载是一分钟平均加上 CPU 数 | 无 | 无 |

## OpenClaw

`status` 和 `list` 都可以只要当前连着的，或只要上次连接在某段时间以内的，例如 24 小时或 7 天。`list` 的已配对行带最近一次连接的年龄。`status` 里最新的一行标成 `active`。`describe` 打出一个节点的能力、权限、活动和有效的以及挂起的调用命令。

已连接的 macOS 节点报告与 OpenClaw 交互的活动，不需要额外权限。可选的全系统在场还报告其它应用里的身体活动，要辅助功能。这是在场，不是把节点提升成能改配置的操作者。

节点执行命令前仍查目标上的策略。调用方要 `full` 或关掉询问，挡不住目标上的 `ask: always`。范围页里，节点角色和操作者角色是两种连接。发现可以帮节点找到 Gateway。配对和挑战仍在连上之后。

空的 `--location-timeout`、`--max-age` 或 `--quality` 不算「用默认」。省略旗标才是默认。

## Hermes

电脑使用在网关或本机上读无障碍树，不把系统光标拽走。有头屏幕是 Linux 上按 profile 的一块 Xfce，租约只挡工具。没有「配对节点、用上次连接时间筛 24 小时、macOS 全系统在场要辅助功能」这一套 `nodes` 命令。

## Claude Code

没有配对节点。屏幕和文件在打开客户端的那台机器上。
