# 钩子

钩子是循环旁边的回调。有的只观察，有的能挡住工具或改写结果。三家都要求：观察者抛错不能吃掉这一轮；能改行为的返回值要有明确的终态语义，不能用「返回假」把已经挡住的调用悄悄放开。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 观察 | 插件 `api.on`，压缩前后只能看 | `pre_api_request`、`post_tool_call` 等，失败打开 | 独立事件总线，给界面和日志 |
| 能改行为 | `before_tool_call` 的 `block`、`message_sending` 的 `cancel` | `pre_tool_call` 可挡或改参数；`transform_*` 可替换文本 | 停止钩子可硬停或再提示；工具前钩子参与权限 |
| 批准 | 人在审批层，不由观察钩子代答 | 批准钩子只记录选择，不能预先答应 | `canUseTool` 是执行前的门，不是遥测 |
| 关联 | 运行 id、会话键 | `turn_id`、`api_request_id`、父子会话 | `hookId` 加上钩子名和事件名 |

## OpenClaw

进程里有两套，和对外的 HTTP webhook 不是一回事。`HOOK.md` 跟命令走：`command:new`、`command:reset`、`command:stop`。`agent:bootstrap` 在系统提示定稿前增删引导文件。其它命令名不会自动变成钩子事件。

插件钩子是类型化的 `api.on`。和循环相关的时机已经写在运行时笔记里。这里补决定规则：`before_tool_call` 的 `{ block: true }` 停掉更低优先级的处理器。`{ block: false }` 不撤销已经有的拦截。`message_sending` 的 `cancel` 同样。安装允许还是拦截走 `security.installPolicy`，这样命令行安装和更新也盖得住，不靠 `before_install`。

`before_compaction` 和 `after_compaction` 只观察，不能改写或否决。`tool_result_persist` 在写入 transcript 之前同步改结果。`before_prompt_build` 可以前置上下文，或在支持的运行时上用 `toolsAllow` 收窄这一轮的工具面。空的 `toolsAllow` 表示不提交可选工具。不支持收窄的运行时拒绝这个值，而不是假装没看见。

只登记钩子、不登记能力的插件形状是 hook-only。这仍然受支持，也是外部插件最不容易被打断的接法。新的内置插件更倾向显式登记能力。失败的登记会留在诊断里，贡献回滚，不进入执行范围，也不挡住别的插件。

## Hermes

观察合同和会改行为的返回值写在同一套 `register_hook` 上，但语义不同。回调一律收关键字参数，应当接受 `**kwargs`，这样以后加字段不会把旧插件调用爆掉。每个载荷带 `telemetry_schema_version = "hermes.observer.v1"`。回调抛错被接住，记一条警告，循环继续。

多数返回值被忽略。四个旧钩子例外：

| 钩子 | 返回值 |
|---|---|
| `pre_llm_call` | 字符串或 `{context}`，注进当前用户消息，一次性 |
| `pre_tool_call` | `{action: block}` 挡住；`{action: modify, args}` 改参数 |
| `transform_tool_result` | 替换即将进入模型上下文的工具结果 |
| `transform_llm_output` | 替换最终助手文本 |

遥测插件把这四项当兼容能力，不当成必须实现的观察接口。批准钩子 `pre_approval_request` 和 `post_approval_response` 只观察。选择可以是 `once`、`session`、`always`、`deny`、`timeout`、`cancelled`。插件不能用它们预先答应或否决。要让工具到不了批准框，用 `pre_tool_call` 的拦截。

人在回路另有一对：`on_human_input_request` 和 `on_human_input_resolved`。种类是 `sudo`、`clarify`、`approval`。提示文案强制打红。密码和答案不进载荷。辅助模型做的智能批准不发这对钩子。

关联用显式字段，不解析拼出来的字符串。`session_id` 是对话。`turn_id` 是这一次用户回合，同一回合里的 API 尝试和工具调用共享它。`api_request_id` 是不透明的一次提供商尝试。`task_id` 用于子代理和隔离执行。父子会话和父子子代理 id 把委派连回父回合。

会话钩子要分清范围。`on_session_end` 是一次 `run_conversation` 结束，包括被打断的。它不一定是这个聊天身份的最后边界。身份拆掉用 `on_session_finalize`，换成新身份用 `on_session_reset`。`pre_llm_call` 包的是用户回合，不是每一次重试。每一次提供商尝试用 `pre_api_request`、`post_api_request`、`api_request_error`。辅助模型用 `pre_auxiliary_call` 和 `post_auxiliary_call`，带 `aux_task`，不进主循环那三个 API 钩子。

工具的 `post_tool_call` 在成功、错误、被挡、被取消时都发，方便把 span 关上。`status` 就是这四者。`transform_tool_result` 发生在 `post_tool_call` 之后、结果写入模型上下文之前。

子代理开始时带父回合、孩子角色和目标。结束时带摘要、耗时，以及一份只有元数据的工具历史：工具名、参数名、有界的副作用目标、输入输出字节数、结果类别。原始参数、提示词、命令、正文和 URL 查询串不在里面。

消毒过的 `request`、`response`、`error` 才是新消费者该读的。大载荷有上限，敏感键打红。没有插件登记相应钩子时，不构造这份载荷，避免空手跑也付消毒成本。

这些钩子在所属 profile 的 scope 里被调用。驱逐、关闭和 cron 结束由调用方先绑 home。提供者不要把 `initialize` 时看到的家目录当成唯一的家。

## Claude Code

钩子可以是提示词、HTTP 或子代理进程，对应 `execPromptHook`、`execHttpHook`、`execAgentHook`。执行进度不进主消息流。事件是 `started`、`progress`、`response`。`response` 带退出码和 `success`、`error`、`cancelled`。订阅者还没挂上时，事件先进一个最多 100 条的队列，超出丢掉最旧的。

`SessionStart` 和 `Setup` 无论界面是否打开「包含全部钩子事件」都会发出。其余事件可以按选项过滤。

停止钩子的行为写在审批笔记里：`continue: false` 硬停；exit 2 或 `decision: block` 把反馈塞成用户消息再跑一轮；`stop_hook_active` 防止钩子把自己再触发一次。子代理的停止不跑主线程的记忆抽取。

工具权限在 `canUseTool`，发生在执行前。钩子事件总线报告钩子跑得怎么样，不代替这次允许或拒绝。技能 frontmatter 可以登记自己的钩子，加载时走 `registerFrontmatterHooks` 和 `registerSkillHooks`。配置有快照，避免一轮中途目录变化把已经开始的钩子名单换掉。
