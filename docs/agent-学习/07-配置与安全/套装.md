# 套装

带标签的 macOS 套装用 `electron-updater`。捆绑和 Light 的戳标明这个主人。稳定和金丝雀是分开的应用身份。各自在烤进去的通道里更新。开发和引导安装保持检出更新。一次性构建带 `source: commit-build`，没有更新器。它们的包身份含短提交。不同提交的构建可以并存。检查和申请说明要由开发者提供新构建。这适用于桌面和它捆绑的 CLI，不适用于桌面连上的、无关的远程后端。

## 对照

| | Hermes 桌面 | OpenClaw | Claude Code |
|---|---|---|---|
| 检查 | 检查从不自动下载。应用要等签名应用被接受，才停自己拥有的后端 | 更新先构建候选再停 Gateway | 客户端安装器 |
| 失败 | 下载或原生校验失败时，后端继续跑。无关的退出不触发安装 | 停不下来可以拒绝停止 | 无这道 |
| 字节 | 同一标签的 macOS 制品不能用不同字节覆盖。读不了的源阻止修剪 | npm 发布不可变。扩展稳定不退回 latest | 无 |
| 检出 | 已有的检出更新器从不改写封好的应用套装 | 安装方式按渠道对齐 | 无 |

## Hermes

通道登记在 R2 的 `releases/channels/NAME.json`，不在检入的通道表里。通道套装先解析那条记录和摘要绑住的构建清单，再选不可变的原生源。被准入的请求让应用身份在各次构建之间稳定，并把源提交和递增的原生包版本分开记下。

已有的带标签客户端保留自己的原生源 URL。通用适配器计算这些遗留路径。它不登记通道。构建器把遗留 URL 写进 `app-update.yml`。`updates.desktop_feed_base_url` 可以给显式的桶基址。稳定和金丝雀各有 darwin 下的 yml。Light 在 `darwin` 和通道之间多一层 `light/`。制品在 `releases/tag/TAG/`，下载链接和源共用。通道构建的制品和原生元数据在 `releases/channel-builds/BUILD_ID/`。

退役和原生更新不是同一操作。旧通道指向合格的官方目的地，不是指向自己原生源里一个改了名的包。显式迁移必须在去掉预览应用之前保留用户状态并核对目的地就绪。合格接收者的清单保持不可变，这样目的地通道已经前进之后，离线的预览仍能迁移。之后由目的地拥有更新。

当前工作流构建捆绑变体，在 ARM64 和 Intel 运行器上。Light 有分开的客户端和源路由，这一变更里没有发布矩阵的腿。定稿要求每个架构一份元数据，名字是 `arm64-CHANNEL-mac.yml` 和 `x64-CHANNEL-mac.yml`。它拒绝错误的版本、变体、架构、哈希和不一致的遗留路径字段。每个被引用的 ZIP 或 DMG 被流回来，对照 SHA-512 和大小。发布核对活版本，有条件地替换 ETag，再读回结果源。同一标签的 macOS 制品不能用不同字节覆盖。可变源用 `Cache-Control: no-store`。金丝雀保留保护活源引用的制品和块图。读不了的源阻止修剪。

检查从不自动下载。应用重新核对发布、下载，并等 Squirrel.Mac 接受签名应用。然后 Hermes 才停掉它拥有的后端，并请求安装和重新启动。无关的退出不触发安装。下载和原生校验失败让后端继续跑。并发的检查不能替换一次应用操作的目标。已有的检出更新器从不改写封好的应用套装。

## OpenClaw

更新按渠道。扩展稳定失败关闭。没有 electron-updater 的稳定和金丝雀两套应用身份，也没有「检查不下载、签名被接受才停后端」。

## Claude Code

桌面若有，按那一家的安装器更新。没有「一次性构建没有更新器、同一标签不能换字节、读不了的源就不修剪」这一页。
