# 秘密引用

SecretRef 到处是同一个对象：`source`、`provider`、`id`。恰好这三个字段。`source` 是 `env`、`file`、`exec` 或 `store`。`env` 和 `store` 有隐含的提供商，取这个来源的有效默认别名，没设就用 `default`。同来源的 `secrets.providers` 条目优先。否则用内建读取器，不需要提供商条目。`file` 和 `exec`，以及其它别名，必须有同来源的已登记提供商。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 形状 | 三个字段。多出来的字段由 doctor 报告删除，并先备份原行 | 秘密源插件。行为不进 `.env` | 设置里的钥匙 |
| 改默认 | 不改写已经写明的引用。仍叫 `default` 的引用必须对得上同来源的已登记提供商，否则解析失败 | 配置默认和 profile 的 `.env` 分开 | 无 |
| 环境名 | `id` 是大写字母开头的环境名语法 | 秘密名在可选环境变量表里 | 无 |
| 执行 | `id` 不能含有作为路径段的 `.` 或 `..` | 秘密源不由插件写进进程环境 | 无 |

## OpenClaw

结构化引用总是带 `provider`。旧对象只有 `source` 和 `id` 时，跑 `openclaw doctor --fix`。doctor 给已登记的配置凭据补上这个来源配置的默认提供商。存着的认证 profile 引用保持历史上的 `default` 提供商，独立于配置默认。doctor 在改写之前备份配置和认证库。更新走同一套修复。插件 SDK 的输入强制仍兼容。SDK 的认证写入持久化规范引用。

已登记的配置凭据或认证 profile 里，旧的、没有提供商、还带了别的字段的引用，doctor 报告这些字段会被去掉，并在写成规范引用之前把原来的配置或认证行留在备份或来源档案里。已登记凭据路径以外的不透明值不动。新的 SDK 认证写入在改变已存或已发布状态之前拒绝扩展输入。那些元数据另存，并显式调用强制函数来选定规范引用。

改一个来源的默认，不改写显式引用。

`env` 的 `provider` 是小写字母开头、最长 64 个字符的标识。`id` 是大写字母开头的环境名，最长 128 个字符。简写 `${NAME}` 和 `$NAME` 在 SecretInput 字段上也可接受。

`file` 的 `id` 是绝对 JSON 指针，或以字面 `value` 给单值提供商。指针段里 `~` 写成 `~0`，`/` 写成 `~1`。

`exec` 的 `id` 可以带选择器，例如 `secret#json_key`。它不能把 `.` 或 `..` 当成斜杠分隔的路径段。`a/../b` 拒绝。

`store` 的 `id` 用环境名语法。只解析 Gateway 范围的团队作用域。

这些语法是引用能不能解析。它不把秘密移出进程内存。解析成功之后，值在激活快照里。能读那个进程或能读未迁走的明文文件的人，仍然看得到秘密。

## Hermes

秘密在 `.env`、认证存储或秘密源。插件不自己写 `os.environ`。多 profile 按范围读，不从进程环境借。没有「恰好三字段、doctor 补提供商、认证 profile 的 default 独立于配置默认、执行 id 拒绝 `..` 段」这一页 SecretRef 语法。

## Claude Code

钥匙在客户端登录或设置。没有这四种来源的引用语法，也没有 doctor 在改写前备份认证库再补 `provider`。
