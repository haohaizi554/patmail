# 证明

`openclaw policy check` 把一次干净的检查收成耐久的审计证据。`policy.hash` 标识写下的规则制品。`evidence` 记录检查用到的观察到的 OpenClaw 状态。`workspace.hash` 标识那份证据载荷。`findingsHash` 标识精确的发现集合。`checkedAt` 记录检查何时跑的。`attestationHash` 标识稳定的声称：政策哈希、证据哈希、发现哈希，以及干净或脏。它故意不含 `checkedAt`。同一份政策状态永远得到同一个证明哈希。这四个值是一次政策检查的审计元组。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 稳定哈希 | 不含检查时间。同一状态同一哈希 | 更新回执绑尝试和字节。不是政策证据哈希 | 无 |
| 时间 | `checkedAt` 留在 JSON 里给审计日志，不进稳定哈希 | 发布纪元是打包时钟 | 无 |
| 漂移 | `policy watch` 在当前证据对不上已接受的证明哈希时报出 | 医生再检测。发现还在就是警告 | 无 |
| 改什么 | 规则变了，两个已接受哈希都从一次干净检查更新。只改工作区设置时，通常只变证明哈希 | 配置写是原子的 | 无 |

## OpenClaw

网关或监督者若用政策去挡住、批准或标注一次运行时动作，应记下上次干净检查的证明哈希。

接受政策状态的顺序是：写下或审阅 `policy.jsonc`，跑 `openclaw policy check --json`，干净则把 `policy.hash` 记成期望的政策哈希，把 `attestationHash` 记成期望的证明哈希，在 CI 或发布门里再跑 `openclaw doctor --lint`。

故意改了政策规则，从一次干净检查更新两个已接受哈希。只有工作区设置变了、政策没变，通常只有期望的证明哈希变。启用或升级 `agents.workspace` 规则，会把 `agentWorkspace` 证据加进工作区哈希和证明哈希。审新证据，启用之后刷新已接受的证明哈希。工具姿态规则同样会加上 `toolPosture` 证据。

`openclaw policy watch` 重跑检查。当前证据不再匹配期望的证明哈希时报告。这是漂移，不是把一次脏检查说成干净。证明哈希对得上，也不证明运行时没有别的配置路径绕过这份政策。它证明的是这次检查看见的证据和上次接受的那份相同。

## Hermes

发布的最终标签绑获胜尝试的字节。医生把检测和修复分开。没有「证明哈希故意去掉检查时间、监视只比对那一个哈希」这一页政策证据。配置注释和键顺序靠原子写保住。那是文件形状，不是政策状态的哈希元组。

## Claude Code

权限是这一次工具调用的决定。没有把干净检查收成不含时间戳的证明哈希、再用监视看漂移。
