# 库检

Gateway 对 agent 库的检查，前台等五秒。没做完的库在启动准入的主人做完检查、以及监听器就绪之后的会话和模型准备之前，保持不可用。其它 agent 和控制界面可以先起来。检查在前台就绪期间开始，不插入空闲重试延迟。可写准入延后到 Gateway 的旁路进程就绪之后，同时最多打开两个库。慢的打开和索引修复因此不会占住共享的 SQLite 工人，挡在插件服务启动前面。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 前台等待 | 五秒。等完了也不因此把延后的库放行去写 | 打开 `state.db`。损坏则隔离句柄 | 打开 JSONL |
| 并发 | 可写准入最多两个库。会话准备最多四个 agent。凭据和模型发布串行 | 一个家目录一个库。多 profile 是多个家 | 无这道门 |
| 就绪 | 待处理的必需库记在 `agentDatabases`，不因此让 Gateway 检查失败。确认的库失败仍让就绪失败 | 医生报告发现。修复后要再检测 | 无 |
| 刷新 | agent 完成准入后刷新聊天元数据和模型列表，带上刚恢复的库 | 会话列表读库 | 无 |

## OpenClaw

按 agent 的会话准备最多四个 agent 同时跑。只有凭据和模型的发布，以及最终准入是串行的，顺序是会话准备做完的先后。慢的打开或迁移不占住那一轮发布。就绪报告把待处理的必需库放在 `agentDatabases` 里，不因此让 Gateway 检查失败。确认的数据库失败仍然让就绪失败。校验期限、脏关闭检查和干净关闭回执的要求不变。延后的库绝不会仅仅因为前台等待到期就被准入去写。

聊天元数据和模型列表在某个 agent 完成准入时刷新，所以包含刚恢复的库。更新金丝雀保留前台检查和严格的数据库就绪，因为那条路径要证明库能开。

这和「模式比构建新就拒绝打开」是前后两步。库检是这一次启动里谁可以写。版本合同是这份构建认不认这个模式。

## Hermes

`SQLITE_CORRUPT` 隔离句柄，并跳过 WAL 检查点。拷贝库要连同 WAL 和共享内存。FTS 坏了卸下索引，退回 LIKE。没有「前台五秒、同时最多两个库打开、等完了也不放行写」这一道 Gateway 准入。一个进程可以服务多个家目录，每个家自己的库。

## Claude Code

没有多 agent 的 SQLite 准入队列。转录是文件。打不开就是这一次读失败。
