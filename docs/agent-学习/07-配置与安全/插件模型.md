# 插件模型

插件要单独打一次模型，走 `ctx.llm`。聊天、结构化抽取、同步、异步、带不带图像，都是这一面。认证由宿主持有。插件看不到钥匙。信任门默认失败关闭。没有 `plugins.entries` 配置时，插件只能打用户当前的提供商和模型，并设置温度、长度、超时、提示和模式这类请求形状。`provider`、`model`、`agent_id`、`profile` 会抛出信任错误，直到操作者打开。

## 对照

| | Hermes | OpenClaw | Claude Code |
|---|---|---|---|
| 谁拿钥匙 | 宿主从认证存储、环境或凭据池取。插件看不到 | 插件在 Gateway 进程里。秘密经秘密源，插件不写进程环境 | 客户端 |
| 换模型 | 默认拒绝。允许之后，模型名单是字面匹配，宿主不再查找 | 会话模型有自己的故障转移 | 无 `ctx.llm` |
| 各门独立 | 允许换模型不附带允许换提供商 | 工具策略按名字。拒绝优先 | 无 |
| 校验 | 装了 `jsonschema` 才按模式严格校验。没装就记调试并跳过严格校验 | 工具参数在执行前校验 | 客户端 |

## Hermes

`purpose` 是自由的审计字符串，出现在 `agent.log` 和结果的审计里，用来看哪一个插件打了哪一次。建议常触发的调用带上。

结构化车道用说明、输入和 JSON Schema。宿主在用户的主提供商返回 5xx 或 429 时，走 Hermes 通常的、知道聚合器的备用链，然后才把错误还给插件。带了图像而当前文本模型只做文本时，宿主自动改用配置的视觉模型。超时用调用参数，否则用辅助任务的超时或全局辅助默认。要 JSON 时宿主发送响应格式，提供商若用代码围栏返回，宿主再在本地解析。每次调用在 `agent.log` 写一行信息：插件 id、提供商和模型、用途、令牌合计。

内置的 `task` 只能用插件注册的辅助任务，除非操作者授予 `allow_task_override`。允许名单里的模型按插件送来的字符串原样匹配。授予换模型并不授予换提供商。插件仍钉在用户当前的提供商上，除非提供商那一扇门也开了。

请求形状不挑选凭据或路线，所以始终允许。未配置的插件仍能做事，只是打在当前的提供商和模型上。操作者只在插件要更细的路线时才写 `plugins.entries`。

这和回合里的主模型调用分开。插件的一次调用不应改写正在缓存的系统提示。主循环的请求前和请求后事件不该为辅助调用触发。`ctx.llm` 是插件侧的入口。宿主仍走它自己的解析、备用和审计。

## OpenClaw

插件可以注册工具和钩子。模型调用若由插件发起，不经过 Hermes 的 `ctx.llm` 信任门。秘密解析失败不挡启动。插件不把解析结果写进进程环境。

## Claude Code

没有宿主持有的 `ctx.llm`，也没有「未授权的模型覆盖直接抛信任错误」。模型是这一次客户端会话的模型。
