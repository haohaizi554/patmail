# 认证

OAuth 和 API 钥匙都进认证 profile，按提供商存在每个 agent 的库里。配置只记顺序和元数据，不记秘密。加一次登录不替换已经选好的主模型。遗留的文件要 doctor 才导入，在此之前运行时失败关闭。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 存放 | 每 agent 的 SQLite。OAuth 带访问、刷新和过期 | `.env`、认证存储、凭据池。外部保险库经秘密源 | 客户端登录和设置 |
| 多账号 | profile id。有邮箱时是 `提供商:邮箱` | `hermes auth add` 往池里加钥匙或 OAuth | 一个客户端登录 |
| 登录 | `openclaw models auth login --provider <id>`。PKCE | `hermes model`、`hermes auth`、门户登录 | 客户端自己的浏览器登录 |
| 不改模型 | 加认证或重新认证保留已有主模型。`--set-default` 才换 | 保存的模型高于残留环境变量 | 登录可能带默认模型 |

## OpenClaw

支持提供商的订阅认证，尤其是 OpenAI Codex 的 ChatGPT OAuth，以及复用 Anthropic Claude CLI。API 钥匙走普通的 API 计费。Claude CLI 的复用按 OpenClaw 的集成政策处理。生产环境仍把 API 钥匙当成更稳妥的推荐路径。

OpenAI 的 API 钥匙和 ChatGPT 或 Codex 的 OAuth 都放在规范提供商 id `openai` 下。旧的 `openai-codex:*` profile 和 `auth.order.openai-codex` 由 `openclaw doctor --fix` 修。新配置用 `openai:*` 和 `auth.order.openai`。

令牌交换走 PKCE。令牌在库里，不在配置的 `auth.profiles` 里。配置那一段只有元数据和路由顺序。多个账号并存：没有邮箱时默认 `provider:default`，OAuth 有邮箱时是 `provider:邮箱`。

提供商插件自己的 OAuth 或 API 钥匙流程走同一个入口：`openclaw models auth login --provider <id>`。控制界面的连接提供商只保存账号，不请求一次模型回复。要验证并选中模型，用测试并使用。只支持完整安装的插件保留自己的安装动作。

`openclaw configure` 在添加或重新认证提供商时保留已有的 `agents.defaults.model.primary`。`models auth login` 同样保留，除非带了 `--set-default`。插件可以在认证补丁里返回推荐的默认模型。已有主模型时，那只表示这个模型变得可用，不表示替换当前主模型。

退役的 `credentials/oauth.json`、`auth-profiles.json`、`auth-state.json` 和每 agent 的 `auth.json` 只由 doctor 导入。更老的共享 `credentials/oauth.json` 导入器已经退役。doctor 留下那个文件不动，并报告需要先经指定旧版本导入，再装最新发布。运行时不从这些退役文件取凭据。库里已经有 profile 时，退役文件是剩余字节。运行时记一次警告并继续工作。下一次 `--fix` 把它归档。doctor 从不用导入值覆盖一份还能用的存储凭据，所以文件不能把过期令牌救活。库是空的时，运行时只读 `auth-profiles.json` 里的提供商元数据，用来圈定必须迁移的提供商。那里点名的提供商不能落到环境或配置认证。无关的提供商照常解析。范围定不下来时，包括坏掉的 JSON 或其它退役格式，拒绝仍是整个 agent。Gateway 启动把凭据主人降级，而不是拒绝启动。凭据写入和快照发布保持围住，直到迁移清掉。

认证 profile 存储被当成令牌汇。运行时每个 agent 从一个地方读凭据。多个 profile 可以并存并确定地路由。某个提供商一旦由 OpenClaw 拥有本地 OAuth profile，本地刷新令牌就是规范的。那份本地刷新被拒绝时，报告这个 profile 需要重新认证，而不退回外部 CLI 的令牌材料。Codex CLI 的引导更窄：它只能在 OpenClaw 拥有该提供商的 OAuth 之前，给空的 `openai:default` 一类 profile 做种子。之后 OpenClaw 拥有的刷新保持规范。状态和启动路径把外部 CLI 发现限制在已经配置的提供商集合里。

共享凭据在状态目录的 SQLite。agent 本地的凭据和状态在该 agent 的库里。个人账号用所选 Gateway 共享状态库里、按身份限定的私有记录。一次运行只加载被选中的个人 profile。普通的共享账号读取从不枚举这些记录。个人 OAuth 刷新写回那个人的账号记录，而不是共享的或 agent 本地的凭据。agent 没有本地 profile 时，读共享存储，不把共享凭据克隆进 agent 库。普通拷贝默认跳过 OAuth 刷新令牌，因为有的提供商在使用后会轮换或作废它们。需要独立账号时，另做一次 OAuth 登录。

自动选中的 profile 按会话钉住，好让提供商缓存保持热。用户钉住的跨重置和压缩仍在。冷却时先试同提供商的下一个，不改存着的钉。静态令牌不刷新，用于不走刷新的凭据链。OAuth 会在访问令牌过期且没有可用同伴时刷新。

cell 的状态挂载里，当前 OAuth 的访问、刷新和 ID 令牌以明文在 SQLite 中。那份备份是凭据。

## Hermes

钥匙放在 `.env` 或认证存储。同一提供商的多把钥匙组成凭据池。OAuth 过期先尝试刷新，失败再轮换。Anthropic 在原生路径上优先使用可刷新的 Claude Code 凭据，而不是抄进来的环境令牌。

外部保险库由秘密源插件在读 dotenv 之后拉取。插件的 `fetch` 不提问、不写环境。编排器拥有顺序、先认领者赢、超时和写环境。插件只取自己配置允许的值，没有接口把别的插件或整库秘密倒出来。dotenv 常常在插件登记之前就加载。发现之后，若有已启用的秘密源，Hermes 再拉一次。再拉是幂等的，失败打开，不挡住启动。`hermes update` 不解析这些外部源，更新进程和它生成的导入健康探测都不解析。慢的助手否则会被误报成导入失败。启用插件仍以 agent 的权限在进程内运行。读已经装进环境的值，对进程内代码是可能的。

多路复用打开后，没有 scope 的 `get_secret` 失败关闭。次要 profile 不借用启动进程的环境。

门户登录和普通的设备码登录是两条渲染。免费层的状态从服务端拉，不在界面里闩住。

## Claude Code

登录在客户端。OpenClaw 复用 Claude CLI 的认证是 OpenClaw 侧的 profile，不是 Claude Code 把钥匙写进 OpenClaw 的库。Claude Code 的设置里可以有 API 钥匙。那些钥匙对能读设置文件的工具可见。

没有 doctor 迁移 `openai-codex` profile 这一步。换账号就是换客户端会话所用的凭据。前缀缓存跟这把钥匙走。
