# 重启

请求的重启先停收新活，再等正在跑的回合和后台任务结束。默认排水预算五分钟。大多数这样的重启什么都不打断。崩溃或杀进程是另一条：磁盘上的会话、转录、子代理记录、投递队列和 cron 还在。终端 PTY 跟旧进程一起结束，不恢复。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 有序重启 | 停收新活，排水最多约 5 分钟 | 更新按种类重启，先排水，范围是每个家目录自己的单元 | 客户端退出即停 |
| 崩溃后 | 合格的被打断回合自动续上。恢复一直开着 | `resume_pending` 保住会话 id。连续失败后 `suspended` 换新 id | JSONL 还在就可以 resume |
| 投递 | 队列在重启后排空。重试花完仍留下结算信息，不再发送 | 网关投递走适配器。桌面退出不杀掉消息网关 | 无出站队列 |
| 终端 | Gateway 的 PTY 在进程内存里，不恢复 | 终端会话跟环境后端走。更新不把另一个安装的运行时拉起来重启 | 本机 shell 随客户端 |
| 浏览器未确认输入 | 发件箱保留到 Gateway 确认转录已消费。重连不复用旧的队列权威 | 桌面重连重铸界面会话 id，谱系仍指压缩尖端 | 无 Gateway 发件箱 |

## OpenClaw

对话历史在每个 agent 的 SQLite 里，重启不改。被打断的主会话回合在启动后几秒自动续上或对账。子代理 run 在共享状态库里。被打断的 run 先落定，由父级决定怎么继续。出站队列排空，没送到的回复重试。cron 存储还在，调度器启动时重新武装。有人请求过重启续跑时，重启哨兵对那个会话发一次后续，只一次。

控制界面把已接受的正文和附件留在发件箱，直到 Gateway 确认转录已经消费。重连后先对保存的回执，再经正常认证和会话准入重交被打断的输入。旧的队列和执行权威不复用。不同浏览器可以按不同顺序重连。已取消的输入不重放。更老版本接受、但没有可恢复保管的输入，要显式重发。结果还不确定的提交，一直不确认，直到能对账或人选择重试。已经在转录里的回合，恢复不依赖浏览器再回来。

已接受的控制界面输入，在 ACP 执行或问题消费之前就提交到准入的源会话。对话若路由到绑定的 ACP 会话，源会话保留原始请求，绑定会话拥有 ACP 转录和回复。输出持久化失败，不让已经消费的输入再自动重交。

基础设施重试花完，或缺少耐久的消息动作权威声明，可以把一个会话做成墓碑，直到人检查或替换。

原生 Codex 的恢复在当前附件策略和上下文限制下重建已存文档。故意钉住的旧插件不会从只更新了核心的那次里得到修复。已经带着出站渠道路由进入父回合的、脱离的运行时完成，可以留下精确的源完成、终态和请求者会话声明。崩溃后，主会话恢复继续那次已准入的回合，不把孩子再启动一次。原来的完成身份和恢复 run 仍是两个东西。留着的终稿回执可以结算已准入的完成，即使旧的原生监视器已经不在。挂起的恢复声明不是已投递的结果。取消、会话替换、缺失或矛盾的源身份，不授权重放。

待投递的行在重启后排空或重试。投递花完重试预算后，恢复收回过期的生产者保管。活着的生产者保持所有权。失败的投递不能再发，但留着结算所属会话所需的信息。那次更新若失败或网关崩溃，恢复继续做更新，不把消息再发一遍。结算之后，失败行丢掉载荷。只有可复用或崩溃时含糊的主人留下一份有界的回执，用来挡住重复投递。同一意图的不确定通知不会再通知第二次。

降级前先做完挂起的结算。更老的构建在修库或重写会话记录时，可能丢掉这些元数据，即使 schema 版本没变。

启动迁移的警告不阻止 Gateway 起来。它记一次警告，以降级模式启动。把状态读到不安全的错误仍然阻止启动。`doctor --fix` 对着同一份状态和配置做完，再重启。没做完的迁移留到下一次启动。

只读的等待（`agent.wait`、批准决定、`question.waitAnswer`、`device.scopes.waitUpgrade`）在客户端断开时停止观察。排水开始后，还连着的等待者收到可重试的 `UNAVAILABLE`。

CLI 关闭排的是整个进程的活。关掉单独一台 Gateway，排的是它自己的活动聊天 run 和排队回合，并等待进程范围的待回复计数。两边都按具名计数报告剩余工作。类别可以重叠，不要把它们加成「多少个不同回合」。

## Hermes

桌面拉起的 `hermes serve` 随应用退出。消息网关是分开拉起的，应用退出到不了它。不要为了「重启桌面」把网关重新挂到 serve 下面。

更新的重启按运行单元的家目录排水，不把另一个安装的运行时重启掉。能证明已经过期的网关让这次更新失败。

会话库还好、回合被打断时，`resume_pending` 保住原来的会话 id。`/stop` 或连续重启失败之后是 `suspended`，下次换新 id。库页已经坏了时，这两面旗不修复页。Gateway 开着时不要跑 `hermes doctor --fix`。

## Claude Code

进程退出后，内存里的流式工具执行和未写入的钩子状态都停。项目 JSONL 和子代理侧链还在，下一次 resume 从文件继续。没有五分钟排水，也没有出站投递队列在重启后排空。
