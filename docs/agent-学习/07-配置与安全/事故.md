# 事故

怀疑自己的 Gateway 或渠道账号被闯了，先收口，再轮换，再核对，再收集。先停掉监督 Gateway 的 macOS 应用，或结束 `openclaw gateway` 进程。把绑定收回收环回，或关掉 Tailscale Funnel 和 Serve，直到弄清发生了什么。有风险的私聊和群改成私聊禁用或要求点名，并去掉任何 `"*"` 全放行。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 收口 | 停进程，绑定回环，私聊改禁用，去掉星号 | 停网关或收窄允许名单。秘密按 profile | 停客户端 |
| 轮换 | 认证令牌或口令在有效认证模式不变时热应用。改模式或改进程环境里的口令要重启 | 更新和秘密源分开。更新进程不解析外部保险库 | 客户端重新登录 |
| 日志 | 默认在 `/tmp/openclaw/` 按日。具名 profile 带 profile 名。`logging.file` 可以改 | 家目录里的日志 | 客户端日志 |
| 证据 | 时间、主机系统、版本、打红后的转录和日志尾巴、攻击者发了什么、agent 做了什么、是否露出环回之外 | 监控不含内容。转录在库里 | JSONL |

## OpenClaw

轮换 Gateway 认证。只有有效认证模式保持不变时，轮换才热应用。SecretRef 要显式设置 `gateway.auth.mode`。改认证模式，或更新了进程环境里的凭据，例如 `OPENCLAW_GATEWAY_PASSWORD`，要重启。能调用 Gateway 的机器上，远程客户端的令牌和口令也轮换。提供商和 API 凭据一起轮换：WhatsApp、Slack、Discord、SQLite 认证库里的模型和 API 钥匙，以及用到的加密秘密载荷。

日志用 `openclaw logs`。具名 profile 加上 `--profile`。默认路径是 `/tmp/openclaw/openclaw-YYYY-MM-DD.log`。具名 profile 是 `openclaw-<profile>-YYYY-MM-DD.log`，除非 `logging.file` 覆盖。转录在每个 agent 的会话目录。看最近有没有把访问放宽的配置：绑定、认证、私聊和群政策、提权、插件。再跑深度安全审计，确认严重发现已经解决。

报告里留时间、Gateway 主机系统和 OpenClaw 版本、打红之后的会话转录和一小段日志、攻击者发了什么、agent 做了什么、Gateway 是否超出环回，包括局域网、Tailscale Funnel 或 Serve。

这是操作者对自己的 Gateway 的收口顺序。它不代替分开的信任边界。互不信任的人本来就该用分开的 Gateway。

## Hermes

秘密在 `.env` 和认证存储。多 profile 按范围读。怀疑泄漏时轮换那一家的钥匙，并看那个家目录的日志。没有「认证模式不变才热应用令牌、日志默认在 /tmp 按日」这一页 OpenClaw 事故顺序。更新先排水。医生的修复和检测分开。

## Claude Code

停掉客户端，轮换那一家的登录或 API 钥匙，看项目里的 JSONL。没有 Gateway 绑定和 Funnel 要收回。
