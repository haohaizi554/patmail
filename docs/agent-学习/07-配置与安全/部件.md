# 部件

`show_widget` 在当前表面上显示一份自包含的 HTML。核心先解析每一段内联脚本。语法错误带着行和列拒绝，坏脚本不会被托管。控制界面经已认证的 Gateway 连接读取，放在专用源站的双层 iframe 里。部件脚本不能直接碰到控制界面或 Gateway。内联预览不继承钉到仪表盘之后的能力授予。浏览器不在不可信的框里解析数据绑定。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 渲染 | 控制界面和若干原生快聊。Discord 在活动打开时发一颗按钮 | 桌面的工件 iframe 不自己打开系统浏览器 | 无这套 HTML 部件工具 |
| 源站 | 不透明源站加收紧的内容安全策略 | 访客分区。空白目标只经受信任点击、且仅 http 或 https | 无 |
| 露出 | 客户端声明 `inline-widgets`，或恰好一个当前频道展示器匹配 | 渲染器能力，不是模型工具的默认核心 | 无 |
| 出错 | 十分钟内的部件才唤醒 agent。更旧的历史只显示通知 | 预览失败不拆掉旁边的终端 | 无 |

## OpenClaw

核心工具在控制界面，以及 iOS、Android、macOS 和 Linux 快聊的转录里内联渲染。Linux 仪表盘用的是浏览器里的控制界面。Discord 会话开了活动时，插件发一颗「打开部件」按钮，作为活动启动。模型仍只调用一次 `show_widget`。没有按传输拆开的第二种部件工具。

HTML 路径：解析每个内联 JavaScript，经典脚本和模块都包括。带 `src` 或非 JavaScript 类型的脚本跳过。然后包进规范的 HTML 文档一次。内联客户端把这份文档存成画布文档，返回预览句柄。部件框不需要自己的登录会话。原生快聊用隔离的网页视图。完整聊天客户端在历史重载后恢复部件。快聊只在当前这条回复里留着。

钉到会话仪表盘：调用里 `pin: true`，或在已有转录部件上钉。钉选给仪表盘那一份自己的身份和能力授予。内联预览从不继承这些授予。结构化的 `report` 加 `pin: true` 用控制界面自己的排版直接画在仪表盘上，没有文档框。一次性的图留在转录里。钉选留给明确的仪表盘请求，或多张属于一起的非代码可视化。

嵌入用的包装注入几座小桥，其余留在框内。高度报告被钳在 48 到 8000 像素。`sendPrompt` 是把提示送回聊天的助手。内联聊天提示走私有消息通道。仪表盘 API 走绑定观看票的请求通道。错误报告每个文档加载最多三条不同的消息，消息截到 500 个 UTF-16 单位。控制界面每个文档、每个聊天会话、每次页面加载向 Gateway 转发一份，作为会话唤醒。另有每键 60 秒 10 份、最多跟踪 100 个键。只有在消息之后十分钟内渲染的部件，报告才转给 agent。更旧的历史只显示通知，不唤醒。会话已有活动运行时，事件排队，立即唤醒会重试到会话车道空出来，模型在下一个可用回合看见。这次唤醒不带原来客户端的能力，所以 `show_widget` 在那一轮可能不可用。报告让模型用改正的代码在下一轮再显示。原生应用目前还不报运行时错误。

文档在不透明源站上，内容安全策略收紧。公开 CDN 资源按页内规则允许。API 连接和静态资源加载分开。

工具只在发起的 Gateway 客户端声明了 `inline-widgets`，或恰好一个已登记的当前频道展示器同步匹配受信任的运行上下文时才露出。控制界面和支持的原生应用自动声明。Linux 快聊在 Gateway 连接要求自定义 TLS 叶子指纹时保持纯文本，因为它的网页视图绑不上那个指纹。Discord 只在当前账号配置了活动且有具体频道时匹配。没有内联客户端、也没有匹配展示器的其它频道运行，拿不到这个工具。

绑在持久会话上、带服务器撰写的排程工具政策的自动化，可以在没有内联客户端时显式允许 `show_widget`。那个表面只钉选：每次调用都要 `pin: true`，写到绑定会话的仪表盘，不能设 `presentation.target`。脱离的 cron 会话、普通的无帽频道运行、没有显式工具帽的排程任务，仍然排除。内联展示仍强制要求发起客户端的能力。

Gateway 在重启后续上被打断的控制界面回合时，恢复的回合也可以在没有连着的浏览器时创建或更新已钉的仪表盘部件。同样只钉选，省略 `presentation.target`。内联预览仍要一次由声明了 `inline-widgets` 的客户端发起的新回合。恢复的回合不继承浏览器连接或设备展示权。

`status: "pinned"` 表示部件在会话仪表盘上。托管 URL 是内部渲染资源，不要在浏览器面板里打开它来代替部件展示。

能力传输覆盖嵌入式、Codex 应用服务器和 CLI 支撑的模型后端。没有 `inline-widgets` 的、靠授予认证的 MCP 调用者失败关闭，除非受信任的运行上下文匹配一个展示器。已认证的直接 HTTP `tools/invoke` 不能请求内联渲染。带着合格的当前频道上下文的请求可以用匹配的展示器。认证本身不绕过展示器或路由资格。

## Hermes

桌面里的工件 iframe 和预览网页视图不自己驱动系统浏览器。窗口打开一律拒绝。网页视图没有弹出许可。访客里的空白目标链接，只经受信任点击的桥，并且只允许 http 和 https。这是渲染器的客人内容规则，不是模型可调用的 `show_widget`。仪表盘的主聊天是嵌入的 TUI，不在 React 里再做一套聊天。

## Claude Code

没有把 HTML 放进双层 iframe、用能力位决定工具是否出现的核心工具。界面是终端或 IDE。
