# 钩子入站

Gateway 的 HTTP 钩子让外部服务叫醒一个 agent，或提交一轮。默认关闭。它们和内部事件钩子不是同一条。内部钩子是 Gateway 进程里的处理函数。这里是外部服务来调 OpenClaw。也和出站的自动化投递不同：方向是外面打进来。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 默认 | 关闭。专用令牌，不用 Gateway 的认证令牌或口令 | Chronos 的触发是 NAS 签发的短时 JWT | 无 |
| 200 | 表示这次运行拿到了会话或全局的位置准入。不表示模型做完、工具成功或消息已送达 | 触发核对 JWT 之后才跑 | 无 |
| 等完成 | `waitForCompletion: true` 才把终态放在同一次响应里。响应不含模型输出 | 回调是跑任务 | 无 |
| 重放 | 幂等键让丢失的响应重放同一次已准入的运行和完成结果，不再分发一次 | 认领是比较并交换 | 无 |

## OpenClaw

一次 agent 请求最多等 15 秒准入。响应到达时，模型运行时可能还在准备。需要同一次请求里的终态执行和投递事实时，在直接的 `/hooks/agent` 载荷里加 `waitForCompletion: true`。准入之后响应保持打开，运行落定才返回 200。

`replyDisposition` 只记终局回复是可见、沉默还是空，不露出文字。准入之后的执行或投递失败，是 `completion` 里的终态数据，不是可重试的 HTTP 失败。`deliveryError` 若出现，是固定的分类值 `delivery-failed`。提供商、运行时、模型、目标、会话和诊断细节保持私有。响应从不包含模型输出或摘要。

配置里可以限制允许的 agent id，并关掉请求自己带会话键。钩子令牌要长、随机、专用。改配置要校验并重启已安装的服务，前台跑的进程则停掉再起。认证失败的速率限制按 IP，20 次每 60 秒，锁 60 秒，这道不可配置。

## Hermes

托管定时的叫醒是 NAS 到 agent 的 `/api/cron/fire`，用短时 JWT，用途是 `cron_fire`。那不是一条默认关闭的、用共享钩子令牌提交任意回合的 HTTP 钩子。内部钩子和 HTTP 钩子在 OpenClaw 里分开。Hermes 的观察者钩子在进程内，失败打开，除了工具前的拦截。

## Claude Code

没有 Gateway 的 `/hooks/agent`。外部叫醒若存在，是用户自己的环境，不是这道准入 200 与完成分开的合同。
