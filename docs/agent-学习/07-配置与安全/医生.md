# 医生

检查和修复分开。`detect` 只报告。`repair` 只在明确要求修复时跑。修复之后再检测一次，问题还在就报告修复警告，不把这次改动当成已经完成。Gateway 还开着时不要对会话库做修复。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 检查 | 结构化的 `detect`。`--lint` 只检测 | `hermes doctor`。网关开着时不要 `--fix` | 无对等的状态库医生 |
| 修复 | 可选的 `repair`。`--fix` 或 `--repair` | `sessions recover`、`sessions repair`。先停网关 | 损坏的 JSONL 靠还完整的行 |
| 成功标准 | 修复后再跑 `detect`。发现还在就是警告 | 核对健康、FTS 标记、触发器和行数，再启动 | 文件能被 resume 打开 |
| 遗留 | 退役的认证 JSON 和 JSONL 只由 doctor 导入。启动发现遗留库就拒绝就绪 | 不在损坏文件上做一次性的 FTS 重建 | 无导入器 |

## OpenClaw

面向检查作者的合同是：`detect` 返回发现列表，可选的 `repair` 在修复模式下处理这些发现。只有 `run()`、没有健康检查声明的贡献，不走这套合同。操作者跑 doctor 不必读这份合同。

`detect` 驱动 `doctor --lint`。`repair` 只在 `--fix` 或 `--repair` 下运行。修复上下文可以带着干跑和差异请求。结果可以返回结构化的差异和副作用，例如服务、进程、包、状态。这样检查可以长成干跑修复，而不必把变更计划塞进 `detect`。

修复状态是已修复、跳过或失败。省略状态当成已修复。跳过或失败时，doctor 报告原因，并跳过那项检查的校验。成功之后，doctor 按已修复的发现再跑一次 `detect`。发现仍在，就报告修复警告，而不是当成完成。

读不了的仓库克隆产生跳过检查的警告，不中止其余检查。修复指导是去掉所有半克隆过滤、从源重新拉取、只在需要时取消浅克隆、按 id 取缺失对象、清掉 promisor 和部分克隆扩展，然后重新打包。这些网络和磁盘操作不要凭记忆手跑，先看修复顺序。

doctor 还负责把退役的认证文件和热的 JSONL 导入 SQLite。Gateway 要先停，并先备份。运行时在导入完成前对受影响的 agent 失败关闭，不悄悄读旧文件。配置重载不迁移工作区状态。选中带退役安装状态的工作区会被拒绝，并提示 doctor。

旧的重载模式 `hot` 和 `restart` 由 doctor 收成 `hybrid`。旧的 `openai-codex` 认证 id 由 doctor 收成 `openai`。

## Hermes

Gateway 还在跑时不要 `hermes doctor --fix`。会话库的修复先停网关。`sessions recover --inspect-only` 先看。能恢复再写出新库，或从 `state-snapshots/` 取快照。`sessions repair` 默认先做 SQLite 备份。

FTS 坏了： durable 的 `fts_stale`，拆掉同步触发器，正文继续写，搜索走 `LIKE`。失败的那次操作不跑整库重建。整库结构损坏：隔离句柄，停止检查点，待写进 JSONL 缓冲。不要把 `state.db`、`-wal`、`-shm` 分开拷。

doctor 对 FTS 拆开的情况给出明确的修复命令。修完后核对健康探测、`fts_stale`、三个 FTS 触发器是否还在，以及会话和消息的行数，然后才启动网关。

配置写入的守卫拒绝把读不出来的文件覆盖掉。doctor 不是第二套随便 `yaml.dump` 的写入器。

## Claude Code

没有 detect 和 repair 的注册表。转录坏了，能用的是还完整的 JSONL 行。工具结果文件丢了，消息里的指针还在。没有「启动时发现遗留库就拒绝就绪」的守护进程。客户端打开损坏文件时，失败停在这一次读取。
