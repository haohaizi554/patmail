# 迁入

`openclaw migrate` 经插件拥有的提供商，把另一套 agent 的状态导入 OpenClaw。捆绑的提供商覆盖 Claude、Codex CLI 和 Hermes。干跑只做计划并退出，不改状态。`apply` 拒绝干跑，因为它总是改状态。凭据要单独点头。非交互的 `--yes` 若不带 `--include-secrets`，不导入认证凭据。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 入口 | `migrate list`、`plan`、`apply`。入职也可以 `--flow import` | 家目录就是状态。没有把 OpenClaw 再导入的对等命令写在这条 CLI 里 | 项目目录里的 JSONL |
| 预览 | 无其它旗标时在终端里先计划、预览、再问。`plan` 与 `apply` 拆开 | 配置写入走原子写，不经这份迁移计划 | 无 |
| 秘密 | 交互默认会问，是选中。非交互必须显式 `--include-secrets`。`--no-auth-credentials` 整个跳过 | `.env` 是秘密。更新进程不解析外部保险库 | 客户端自己的登录 |
| 冲突 | 默认不盖。`--overwrite` 才允许替换计划里报告冲突的目标 | profile 是岛。克隆在发布前先剥离 | 无 |

## OpenClaw

不带其它旗标运行某个提供商时，做计划、预览，并在 TTY 上询问后再应用。`plan` 和 `apply` 用同一套旗标把预览和应用拆开。共享旗标放在子命令前或后都可以。放在子命令上的同名旗标盖过放在前面的。`--dry-run` 是例外：`apply` 拒绝它，不应用。要预览用 `plan`。

来源目录可用 `--from` 覆盖。Hermes 跟随 `HERMES_HOME` 和活动 profile，再落到平台默认。Codex 默认 `~/.codex` 或 `CODEX_HOME`。Claude 默认 `~/.claude`。导入进已配置的 agent。只有默认 agent 就是想要的主人时才省略 `--agent`。无效或未知的 agent id 拒绝。

`--include-secrets` 导入支持的凭据，不再要 OpenClaw 的确认。Codex 仍可能请求操作系统的凭据库，例如 macOS 钥匙串。交互式应用在检查和导入认证凭据之前询问，默认选是。非交互的 `--yes` 要导入它们就必须带 `--include-secrets`。`--no-auth-credentials` 跳过认证凭据导入，包括交互提问。

`--overwrite` 允许在计划报告冲突时替换已有目标。非交互必须 `--yes`。技能、插件和单条计划项可以用重复的旗标挑选。省略时，交互式 Codex 迁移给出选择器，非交互保留计划中的全部技能或插件。插件旗标只适用于 Codex 应用服务器清单里发现的、源安装的 `openai-curated` 插件。

未知的提供商不在这份 CLI 里硬编码分支。插件登记自己的迁移提供商。`migrate list` 看已安装的。

导入的是状态计划，不是把来源的 Gateway 或进程接进来。干跑之后磁盘上的 OpenClaw 状态应与跑之前相同。应用才会写。秘密不因为跑了 `migrate hermes` 就自动进来。

## Hermes

Hermes 的家目录用 `get_hermes_home()`。profile 各自一份配置和秘密。克隆在暂存目录里建好，剥离频道所有权之后一次改名发布。这是 Hermes 自己的 profile 复制，不是 OpenClaw 的迁移提供商。被 OpenClaw 读取时，秘密是否进入新家目录由那边的 `--include-secrets` 决定。

## Claude Code

项目里的 JSONL、设置和技能目录可以被另一套系统读取。OpenClaw 的 Claude 提供商走同一条计划再应用。客户端自己不把这些文件收成带干跑的迁移计划。
