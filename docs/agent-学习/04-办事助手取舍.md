# 办事助手该拿走的部分

对照对象是 `patmail-extension/src/agent/`。`loop.ts` 先做原文摘录，再最多 6 步：有工具就执行，没有工具就把正文当最终答复。`tools.ts` 把未知工具、坏 JSON 和抛错收成工具文本。长期记忆只接收用户亲口说过的，或这次工具返回的文号、客户和日期。

下面按现在就能做、和不必搬来分。

## 现在就能做

**文本收尾先看工具记录。** Hermes 的看板闸门和 Claude Code 的停止钩子是同一形状：模型说做完了，并不等于办成了。用户要建工作流或发文任务时，扫这一轮的工具记录。对应工具没出现，或返回的是失败，就把这段正文留成候补，再给有限的一轮。次数用尽时用候补收尾，不要再要一轮。纯说明、纯查询，没有必调工具，不拦。

**同一工具、同一参数出现第二次就停。** OpenClaw 的空转检测有六种，阈值在 10 到 30 之间，压缩后还有一个 3 次窗口。6 步循环用不上那套。同一轮里相同工具加相同参数出现第二次，就停下来说明卡在哪一次查询。

**步数用尽时做一次不带工具的收尾。** Hermes 在上限之后注入「总结现状，不要再调工具」，摘要失败才用固定句子。现在的固定句「这轮工具调用已经到上限」可以留作摘要请求失败时的兜底。

**大块工具结果先裁再摘录。** Hermes 压缩的第一步不调模型，只裁旧工具结果。Claude Code 的 snip 和 microcompact 同样不调模型，并且按 `tool_use_id` 冻结替换文本。原文摘录继续保留，不要改成让模型写摘要。摘录之前，先把旧的案件列表和长叙述收成短摘要加稳定 ID。

**发文和提交审核放在执行层拒绝。** Claude Code 把「不能做」放在权限结论上：不放行就不执行，并回一条带同一 `tool_use_id` 的错误结果。提示词里的「不能代点」只降低误触。`create_task` 若只记计划、不提交，这个边界应写在工具实现里，失败也回工具文本。

**外部抓取和读失败不要进记忆。** OpenClaw 的回合污点不是「工具失败」，而是网络来源的结果，以及转录读失败。读失败时宁可不记。专利流程已有的规则更严，继续保持：推断出来的文号、客户、日期不写进长期记忆。

## 对话变长再做

系统提示词每一轮都拼进记忆和摘录。没有提示词缓存时这样最直接。Hermes 要求一次对话里 system 字节不变，中途补充走用户消息或工具结果，只有压缩可以改历史。要做前缀缓存时，再把记忆改成会话开始写一次。

记忆若从固定的近 12 条变成可检索文件，可以学 Claude Code 的预取：回合入口就异步检索，没完成不挡第一个 token，完成后再注入，并去掉本轮已经读过的条目。

查询类工具若要并行，只给没有副作用的查询开并行，结果仍按调用顺序交回。建工作流和改字段保持独占。一个查询失败不要取消其他查询。

## 不必搬

会话车道、认证 profile 轮换、可插拔上下文引擎、子代理蜂群、流式工具执行器、MCP 连接库、技能策展器和辅助模型路由，都是为长会话、多渠道、多提供商准备的。浏览器里这一次 6 步办一件事，用不到。

子代理在三家里都是短生命周期的侧链：独立预算、独立转录、父会话只看摘要。查询、建档、改一栏，留在主循环里。

技能索引可以学 Hermes 的长度：系统提示里只放一句不超过 60 字的 description，全文在用户点名 `/技能名` 时再注入。不必做 `/learn` 自动写技能，以免把一次对话里的推断写成长期技能。
