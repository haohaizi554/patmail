# 小龙虾 OpenClaw

用户消息从 `agentCommand` 进入，经 `runEmbeddedAgentAttempt` 调到 `runEmbeddedAgent`。`run.ts` 只做转发，实现在 `run-orchestrator.ts`：会话准入、车道排队、准备模型之后，进入 `run-loop.ts` 的 `runPreparedEmbeddedLoop`。

## 一次运行怎么转

1. `prepareEmbeddedRunRuntime` 准备模型、认证 profile、思考档位。
2. `admitEmbeddedContextEngine` 接上上下文引擎。
3. `while (true)` 里先 `beginRunAttempt`，再用会话写锁包住 `prepareAndDispatchEmbeddedRunAttempt`。
4. `normalizeEmbeddedRunAttempt` 给出完成、重试或继续恢复。完成就结束。否则 `recoverEmbeddedRunAttempt`，再不行走失败收尾。
5. 重试预算看 `attemptsCounted`，上限大约在 32 到 160 之间，随 profile 数量增加。认证失败、限流、空回复算重试。`progress_continuation` 会把这一次从计数里减回去，权限续跑和已经有进展的截断续写不烧失败额度。预算用尽走 `handleRetryLimitExhaustion`，配置了备用模型才换模型。

失败先分类，再决定动作。限流和过载可以同模型退避，profile 轮换各大约 1 次。认证优先换 profile。上下文溢出先压缩，本轮最多 3 次，不把这次失败写进 profile 健康。超时多数不记 profile 故障。单模型插件至少要能分出限流、过载、认证、溢出、超时，不必自建凭据轮换。

会话车道在 `lanes.ts`。`resolveSessionLane` 得到 `session:<key>`，默认并发是 1。编排固定先占会话车道，再占全局车道。同一会话的第二条消息在车道层排队，不并行，也不自动取消。定时任务和子代理用嵌套车道，避免子任务占着父任务正在等的名额。单面板连发两条时：固定同一个 `sessionKey`，第二条排队，并带上中止信号。

## 上下文引擎

契约在 `src/context-engine/types.ts` 的 `ContextEngine`。

| 方法 | 作用 |
|---|---|
| `ingest` / `ingestBatch` | 把消息写进引擎自己的库 |
| `assemble` | 在 token 预算内拼出真正送给模型的消息 |
| `compact` | 摘要、裁旧回合，带中止信号和超时 |
| `afterTurn` | 回合结束后决定要不要后台再压 |
| `maintain` | 引导、成功回合或压缩之后整理转录 |
| `bootstrap` | 会话开始时导入历史 |

`assemble` 可以声明 `promptAuthority`。`"assembled"` 表示预检只看拼好的提示。`"preassembly_may_overflow"` 表示拼好的视图可能藏住溢出，预检要同时看未开窗的会话历史。`contextProjection.mode = "thread_bootstrap"` 让有持久线程的后端按 epoch 注入一次。嵌入式宿主不宣称这个能力。

默认引擎 id 是 `legacy`。它的 `ingest` 是空操作，`assemble` 原样返回，`compact` 再委托给运行时。真正的裁剪仍在 attempt 管线里。换引擎走 `plugins.slots.contextEngine`。token 预算由宿主算好再传进去。

发请求前，`shouldPreemptivelyCompactBeforePrompt` 先估压力，路由可以是放下、只截工具结果、只压缩、或先压缩再截断。模型已经因溢出失败后，走 `recoverEmbeddedRunOverflow`。压缩成功若轮转会话，`acceptCompactionSuccessor` 在同一个 `sessionKey` 下换新的 `sessionId`，旧转录归档。摘要超时可以退到不调用模型的确定性裁剪。本轮溢出压缩最多 3 次。

办事助手用不上可插拔引擎。值得留下的是：能只截工具结果就不要改历史；减负之后要能续跑；压缩没有打断空转就停。

## 工具空转

检测在 `src/agents/tool-loop-detection.ts`。历史保留最近 30 次。`hashToolCall` 对参数做稳定序列化再哈希；`exec` 会去掉只用于展示的 `title`，避免标题不同被当成两次不同调用。

警告阈值是 10（`TOOL_LOOP_WARNING_THRESHOLD`），严重阈值是 20，全局熔断是 30，未知工具名重复是 10。

| 检测器 | 何时算卡住 |
|---|---|
| `generic_repeat` | 同一工具、同一参数达到 10 次先警告；结果也没有进展并达到 20 次则阻断 |
| `argument_churn` | 参数在几套稳定值之间抖，达到 10 次 |
| `ping_pong` | 两个工具对打，10 次警告，有「没有进展」证据且达到 20 次则严重 |
| `known_poll_no_progress` | 已知轮询工具连续没有新结果 |
| `unknown_tool_repeat` | 工具名不存在仍反复调用 |
| `global_circuit_breaker` | 单次运行调用次数到顶 |

警告仍会执行这次调用，再把一条系统说明塞进结果，并按每 10 次分桶去重。严重级别直接否决，结果是 `blocked`，`deniedReason` 为 `tool-loop`，并给一次换思路的机会。同一次运行里再次严重则终止。`argument_churn` 只警告，不升到严重。`wait` 的严重阈值也是 10，其他轮询工具是 20。

工具真正执行前，`runBeforeToolCallHook` 还可以改参数或否决。否决留下 `status: "blocked"` 的结果，不把这次调用当成成功。钩子自己抛错则失败关闭。允许名单在调用前就把工具从目录里滤掉。结果进模型前按上下文截断，优先留头和诊断尾。发送给模型的视图和会话里的原文可以分开，恢复时仍能指回完整输出。

压缩成功后，`post-compaction-loop-guard.ts` 武装一个 3 次窗口，并记住压缩前最近 16 次调用的签名。窗口里若同一工具、同一参数、同一结果出现 3 次，说明压缩没有打断循环，直接中止。只看参数相同不算，因为轮询可以合法地重复参数。

6 步的办事助手用不到这套阈值。最小规则是：同一轮里，相同工具加相同参数出现第二次就停，并说明卡在哪一次查询。

## 记忆与回合污点

长期记忆的原文是工作区里的 `MEMORY.md`、`USER.md` 和 `memory/**/*.md`。每个 agent 另有一份 SQLite 索引，带全文检索和可选向量。默认检索是向量 0.7 加文本 0.3，再做时间衰减和去重，大约最多 6 条。引用形如 `path#L起止行`。配置解析在 `src/agents/memory-search.ts`。压缩前可以有一次静默的 memory flush，把要留下的内容追加到记忆文件。这次 flush 的转录不进入后面的用户回合。会话摘要和长期记忆是两套东西。

写入经过 `memory-write-provenance.ts`，出处分成 `owner`、`agent`、`untrusted`、`system`。主人发送记为 `owner`，同一轮助手写的内容可以记为 `agent`。自动注入只用前两类。网络工具结果会把整回合标成 `untrusted`。这里没有「只能记用户原话或工具返回」的硬规则，助手在主人回合里写下的内容仍可能进记忆。

`turn-taint-state.ts` 的污点也不是「工具失败」。非展示用途、且 `resultContentSource === "network"` 的结果会把当前回合标脏，并在重试之间保持。记忆写入因此标成不可信，避免网页内容被当成主人权威落库。发件人不是主人时，记忆刷写同样带上 `initialTurnTainted`。读转录失败时，记账代码把污点设为真，宁可不记。没有可见回复时，另有失败警告，要求把失败说出来。

办事助手已有的规则更严，也更适合专利流程：只有用户亲口说过的，或这次工具返回的文号、客户、日期，才能写进长期记忆。OpenClaw 补上的一点是，外部抓取内容、助手自己的转述、读失败的转录，都不要自动进记忆。

## 技能与子代理

技能是目录里的 `SKILL.md`，必填 `name` 和 `description`。发现顺序从工作区 `skills`、`.agents/skills` 到用户目录和内置技能。`prepareEmbeddedSkills` 做快照，系统提示里只放名字、短描述和可读路径，正文靠模型再读。没有读权限，或这次只是在结算已完成的工具时，技能提示为空。技能环境变量在回合结束后回滚。

用户用 `/技能名` 或 `$技能名` 会写成「先读这些 SKILL.md」。`disable-model-invocation` 只把它从模型可见的索引里拿掉，显式点名仍然有效。`command-dispatch: tool` 可以不经过模型，直接调工具。

子代理由持有 `sessions_spawn` 的 main 或 orchestrator 派生，叶子代理没有这个工具。默认深度 5，每个控制会话最多 5 个活跃子代理，全局子并发默认 8。子会话默认是空的独立转录，可选复制父转录。子代理再收紧工具，固定拒绝对外发消息和网关操作，也不直接对用户说话。结果默认 announce 回父会话，也可以只收集、不通知。车道名按父会话加前缀，父代理等待时不占子代理自己的名额。查询和建档都在同一次 6 步里能做完，不必再派生子代理。
