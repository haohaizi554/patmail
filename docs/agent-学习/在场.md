# 在场

在场是尽力而为的花名册：这台 Gateway，以及连上来的、人看得见的客户端。它不是进程锁，也不是租户授权。问 agent 用 `presence` 工具读快照，不必开 shell。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 看什么 | Gateway 和已连接的客户端：Mac 应用、WebChat、节点 | 网关状态、桌面连接、profile 花名册 | 本机这一次客户端 |
| 怎么问 | `presence` 的 list、person、device。RPC 是 `presence.query` | 状态命令和桌面的连接原子 | 无花名册工具 |
| 新鲜度 | 尽力而为。重复或过期的实例行要靠合并规则 | 连接断开后界面进入重连，不把旧连接当成还活着 | 进程在就不在 |
| 和锁 | 在场不证明自己拥有状态目录 | pid 加启动时间才是活性 | 无 |

## OpenClaw

在场覆盖 Gateway 自己，以及用户可见的、连到 Gateway 的客户端。控制界面的设备页和 macOS 的实例标签画的是这份实时连接元数据。最近用过的 Mac、以及把节点告警送到那台机器，是另一页的活动电脑在场，不是这份客户端花名册。

核心工具 `presence` 读取人、他们连着的客户端和设备、以及观察到的活动。个人 Gateway 和共享 Gateway 都可以用，不需要 shell。同一读模型的 RPC 是 `presence.query`。

`list` 是默认。`person` 要 `me`、返回的人或 profile id，或不会歧义的显示名。`device` 要在场返回的设备 id。`include` 可以加设备、网络和位置。网络和位置的细节也会带上设备行。列表里的人默认最多 50，可从 1 到 100。截断的结果会被标明。

在场用来回答「谁连着」。它不决定消息进哪个 agent，那是绑定。它不决定谁可以批准，那是操作者范围。它也不代替 Gateway 锁：锁看的是状态目录的主人和端口，在场看的是连接元数据。一边显示有客户端、一边锁被别人持有，两件事可以同时为真。

## Hermes

桌面的连接、当前 profile 和后端是三件要一致的事。切换连接是软的重新安家：壳还在，绑在网关上的存储清掉再连。运行时的家目录变化是硬的重新加载。活的 profile 切换时合并列表，后台 profile 可以继续流式输出。换完之后，活动套接字、profile 和连接原子必须一致。

网关是否活着看 pid 和启动时间，或规范的匹配器，不看「进程号还在不在」。在场式的「设备页上有一行」不能代替这个。

## Claude Code

没有 Gateway 设备花名册。IDE 和终端是同一个用户的两个界面时，它们共享或各自打开转录，不向一台中心 Gateway 报在场。子代理不是设备行。
