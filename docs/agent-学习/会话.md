# 会话

会话是「这串对话算不算同一次」的边界。三家都把边界做成显式的键或文件，而不是靠空闲时间偷偷换一份历史。压缩管的是模型看见的窗口，不负责把两个人的私聊并到一起。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 谁拥有 | Gateway。界面只查询 | 网关的 `session_key` 指到 `state.db` 里的一次 `session_id` | 项目目录里的 JSONL |
| 私聊默认 | 所有私聊共用主会话 | 每条私聊按 `chat_id` 分开 | 没有渠道键 |
| 群默认 | 每个群一份 | 群默认按人再切开；话题线程默认共享 | 无 |
| 定时任务 | 每次运行一份新会话 | 每次运行一个没有历史的 AIAgent | `ScheduleCronTool` 挂在编码会话上 |
| 自动换会话 | 默认不换。可开每日或空闲 | 空闲和墙钟都不换。只有 `/new`、`/reset`、挂起 | 用户新开或 resume |
| 重启 | 打断的回合最多三次拉起后端；真开始后预算刷新 | `suspended` 强制新 id；`resume_pending` 保住原 id | 转录还在磁盘上 |

## OpenClaw

入站按来源进会话：私聊默认共享，群和房间默认隔离，cron 每次新会话，webhook 按钩子隔离。原生目录 id、Matrix 房间和线程、Signal 群 id 区分大小写。`session.scope: "global"` 仍由选中的 agent 拥有，不会把两个 agent 的对话并成一份。停掉、删除、重置或归档只取消这个 agent 在这条对话上的工作。

私聊范围：

| `dmScope` | 行为 |
|---|---|
| `main` | 全部私聊进主会话 |
| `per-peer` | 按发送者，跨渠道 |
| `per-channel-peer` | 按渠道加发送者 |
| `per-account-channel-peer` | 再加账号 |

多人能发消息时要用隔离，否则后一个人看得到前一个人的上下文。同一个人的多个渠道可以用 `identityLinks` 收成一个 peer。Slack 的 Agent View 私聊在此之外再加 `:thread:<rootTs>`。跨渠道把回复目的地改到另一边的 docking 已经去掉。

群和房间用 `groupScope`：默认 `per-group`，`main` 则把它们送进该 agent 的主会话。单条 binding 可以覆盖全局值，而且只改会话键，不改提及门槛和回复目的地。

`memory.search.rememberAcrossConversations` 只增加一次跨私聊检索，不合并 transcript。默认按群隔离时，群和频道既不是私聊召回的来源，也不接收私聊摘录。当前对话自己的历史已经在上下文里，不再检索一遍。

隐身线程只从控制界面的新线程打开。会话行、transcript 和压缩状态留在内存里，24 小时或 Gateway 重启先到者为准，活动不续命。到期删掉，不归档，不做自动记忆刷写。工具写文件仍可以在会话库之外留下数据。提供商仍会处理发出去的消息。多用户网关上，隐身线程只对管理员范围的连接可见。`incognito-` 这段键前缀保留给面板、子代理和内部隐藏会话。

重置默认 `mode: "none"`，同一 `sessionId` 一直用，变长靠压缩。`daily` 在 Gateway 主机的本地钟点换新，默认 4 点，看的是这个 `sessionId` 何时开始，不是后来的元数据写入。`idle` 看最后一次真实的用户或渠道交互。心跳、cron 和 exec 系统事件可以写元数据，但不延长这两份新鲜度。每日和空闲同时配置时，先到期的生效。换会话时，旧会话排着的系统事件通知丢掉，避免贴到新会话的第一条提示前面。`resetByType` 认 `direct`、`group`、`thread`。`resetByChannel` 可以按渠道覆盖。

三个时间戳分开：`sessionStartedAt` 给定时重置，`lastInteractionAt` 给空闲，`updatedAt` 只给列表和清理。

Gateway 重启打断回合时会自动接着原会话。三次没能开始一次后端回合，恢复预算用尽。真正开始一次后端回合后预算刷新；只是接受、排队或准备恢复请求不算。不报告接受的 CLI 后端，要看到助手输出或工具活动才刷新。重放保留已记录的工具调用和结果，复用原来的用户消息。已经有完整回复或更晚的用户消息，这一轮就不再重放。恢复在等容量时新来的消息先挂起，开始之后按该会话的队列策略走。预算用尽后 transcript 还在，用新会话或 `/new`、`/reset` 换一份。

状态在每个 agent 的 `openclaw-agent.sqlite`。旧的 `sessions.json` 只由 `openclaw doctor --fix` 导入。启动若发现遗留库，拒绝就绪，不悄悄用空历史开工。

维护默认 `enforce`：30 天修剪，面板会话 7 天归档，最多 5000 条。启动和孤立的 cron 会话不在读库时做全量清理。生产上的上限用高水位缓冲，分批收回到配置的帽。

## Hermes

会话键是确定的车道名：

```text
agent:main:{platform}:{chat_type}[:{chat_id}][:{thread_id}][:{participant_id}]
```

私聊有 `chat_id` 就按对话切开。没有 `chat_id` 时退到 `user_id_alt` 或 `user_id`。什么标识都没有，该平台的私聊合成一条。WhatsApp 号码收成 E.164，避免同一号码的不同别名拆成两份会话。

群和频道默认 `group_sessions_per_user` 为真，键上再挂参与者。线程默认 `thread_sessions_per_user` 为假，一个话题里的人共享上下文。私聊永远不共享。共享会话的系统提示不写死某一个用户名，只说明这是多人会话；发送者名字加在每条用户消息上，这样系统提示不必每人改一次。

`sessions.json` 只存键到 `session_id` 的映射和元数据。消息在 SQLite。`session_id` 形如 `YYYYMMDD_HHMMSS_` 加 8 位十六进制，表示这一次化身。`/new` 和 `/reset` 结束旧的 SQLite 会话，新建 id，并设 `is_fresh_reset`，以便下一条消息重新注入话题技能。这和历史自动重置分开，避免提示「会话过期」。

`/stop` 或连续三次重启失败把 `suspended` 设上。下次 `get_or_create_session` 无论 `resume_pending` 与否都换新 id。崩溃恢复或排空超时设 `resume_pending`，下次仍用原来的 id，成功一轮后清除。挂起优先于恢复标记。

`switch_session` 可以带 `expected_session_id`。对不上就返回空，不切换。这样在一次 await 之间别人已经 `/new` 或 `/resume` 时，旧快照不能把键指走。

不活动时间和墙钟不轮换对话。旧的定时重置配置被忽略。资源驱逐和 WebSocket 孤儿回收让对话仍可恢复，不制造新边界。

## Claude Code

一次编码会话的转录写在项目目录的 JSONL 里。子代理写在旁边的 `subagents/agent-<id>.jsonl`，带元数据，可以 resume。主会话和侧链不共用一把渠道键，因为没有消息平台要路由。

压缩、工具结果落盘和权限都作用在这一份转录上。计划模式和 worktree 改变的是改哪些文件，不改变「这是哪一次对话」。
