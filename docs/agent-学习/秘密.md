# 秘密

密钥可以不写在配置明文里，但只要还在同一个进程的内存里，agent 就能读到。三家都把「配置里不落明文」和「进程隔离」分成两件事。审批、打红和允许名单是启发式，不是对抗模型的边界。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 明文 | 仍可用。SecretRef 按凭据选开 | `.env` 只放秘密。行为进 `config.yaml` | 客户端设置和登录 |
| 运行时 | 启动时解析进内存快照。模型密钥在出网前是哨兵 | 启动后由秘密源写入环境。多 profile 时按 scope 读 | 进程内的密钥 |
| 出了进程 | 哨兵在最后一次出网前换回真值 | 子进程默认剥掉提供商密钥。出口代理可在外面注入 | 工具子进程继承客户端环境的方式由权限和启动决定 |
| 审计 | `secrets audit --check` 看还有没有明文残留 | 秘密源失败不挡启动。更新进程不解析外部保险库 | 无对等的 SecretRef 审计 |

## OpenClaw

SecretRef 是加在凭据上的引用，这样支持的密钥不必以明文坐在配置里。没迁的明文仍然有效。只要明文还在 agent 能读的文件里，包括 `openclaw.json`、`.env`、退役的认证 JSON、生成的 `models.json`，文件工具和 shell 就能读到。API 层打红绕不过磁盘。

秘密在激活时急切解析进内存快照，不在每次请求上懒解析。冷启动时，可隔离的主人若 SecretRef 暂时失败，Gateway 仍起来，把那个主人记成已配置但不可用，并发出打红的降级警告。可隔离的主人包括模型提供商、技能、媒体和语音、cron、合格的认证 profile、按 agent 的记忆、沙箱 SSH、渠道账号，以及清单声明的插件路由。Gateway 入站认证、结构上无效的引用、失败必须关闭的主人、运行时主人对不上的引用，仍会让启动失败。

重载按主人独立校验，再发布一份原子快照。健康的主人刷新。失败但资格还在、引用身份和合同都没变的主人，保留上次已知良好的值，并标成陈旧。变了或新的失败主人变成冷的。严格失败拒绝这次重载，活跃快照不动。渠道凭据变了就按插件策略只重启受影响的账号。冷账号停下。手动停止在恢复时保留。

运行时只读这份活跃快照。模型提供商的 SecretRef 在认证存储、流选项和日志里是进程本地哨兵，形如 `oc-sent-v2.` 加上密文。真正的值在请求离开进程前，由受守卫的 fetch 换上。认不出的哨兵形状在出网前失败关闭，不把未解析的哨兵发给提供商。没有自定义 fetch 的 SDK 在构造客户端前解开。哨兵减少调用链上的明文，但不是进程隔离。真值仍在同一进程的内存里，出现在最后一道适配器边界。没走 SecretRef 的环境变量密钥仍是明文。`OPENCLAW_SECRET_SENTINELS=off` 只停掉铸造哨兵，不停打红，也不停对子进程的存储密封。

未激活的表面不挡住启动。禁用的渠道、没被选中的搜索密钥、沙箱不是 SSH 时的 SSH 材料，只记一条非致命诊断。自动搜索在选定提供商之后，其它提供商的密钥变成未激活。`gateway.auth` 上的 SecretRef 若是有效认证面，必须解析成功。环境变量里的 Gateway 令牌只在配置没有对应输入时当后备。

策略违规，例如 OAuth 认证 profile 又混上 SecretRef，在切换运行时之前失败。孤立的主人失败时不退到更低优先级的凭据来源。

迁移算完成，要同时满足：支持的凭据都用 SecretRef、旧明文从配置和生成的模型文件里清掉、审计干净、剩下的轮换密钥放在操作系统隔离、容器或外部凭据代理后面。`secrets apply` 不改写 doctor 负责的退役认证 JSON。备份和旧目录里的拷贝仍是生产秘密，直到删掉或移出 agent 能读的范围。

出网代理和流量允许名单是另一页。它和哨兵一样，管的是密钥何时离开进程，不管 agent 在进程里能不能把已经解开的值写进文件。

## Hermes

`.env` 只放密钥、令牌和密码。非秘密的行为写在 `config.yaml`。`hermes config` 遇到登记过的环境变量名，写入 `.env`，不写进配置顶层。

内置秘密源在读 `~/.hermes/.env` 之后、Hermes 读凭据之前，把外部保险库的值放进环境变量。Bitwarden、1Password 和通用命令助手在树内。新的保险库后端做成独立插件，不往 `agent/secret_sources/` 里加。插件发现往往晚于第一次 dotenv 加载。只要有启用的插件秘密源，发现之后会再拉一次。再拉是幂等的，失败不挡启动。`hermes update` 不解析外部源，避免慢的助手被当成导入失败。

编排器拥有顺序、先声明者获胜、`override_existing` 不跨源、受保护的启动令牌、每个源的墙钟超时，以及写 `os.environ`。插件的 `fetch` 不能抛、不能交互提问。插件自己不写环境变量。没有 API 去倒出其它插件或用户的整个秘密库。

多路复用打开后，`get_secret` 在没有 scope 时失败关闭。次要 profile 的 `.env` 只在它自己的 scope 里。scope 已装上且多路复用开着时，没有的项返回默认，不回退到进程环境。那份环境是启动 profile 的。`hermes serve` 在启动的最后一步，若机器上有多于一个可服务的家目录，就打开这道守卫，并冻结当时的环境作为没有 `.env` 可重建的启动密钥来源。之后再注入的密钥，这个进程看不见。

交给 shell、MCP、cron 脚本和代码执行孩子的环境，默认剥掉提供商 API 密钥和网关令牌。操作者或已加载技能显式声明的变量会通过。这减少随手外泄。它不是隔离。进程里的技能、插件和钩子能读 agent 自己能读的一切，包括内存里的密钥。对抗被攻破的进程内组件，靠的是安装前的审阅，不是剥环境变量。

安全政策把边界说死：对抗恶意模型的唯一边界是操作系统。批准门、输出打红、技能扫描和工具允许名单都是启发式。终端后端只困住走 shell 和建立在 shell 上的文件工具的操作。代码执行、MCP、插件加载和技能导入仍在 agent 自己的 Python 进程里，除非把整个进程树放进容器或 OpenShell。默认本机后端加上不可信输入（开放网页、入站邮件、多用户频道、不可信 MCP）不在支持的安全姿态里。

技能在 import 时就能跑任意 Python。审阅要读代码和脚本，不只读 `SKILL.md` 的描述。

## Claude Code

密钥在客户端的登录和设置里。工具调用前的 `canUseTool` 决定这次命令或写文件能不能发生，不决定密钥是否只在出网时才变成明文。MCP 服务器若带了环境变量，那些变量在服务器进程里。钩子可以是外部进程或 HTTP，它们看见的是钩子载荷，不是一份 SecretRef 快照。

没有「未选中的提供商密钥不算激活面」这种 Gateway 诊断。还原树里的 OAuth 和设置同步是客户端服务。把密钥写进仓库文件，和写进 OpenClaw 的 `openclaw.json` 一样，读文件工具就能看见。
