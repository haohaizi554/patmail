# 保管

保管技能是随版本发布的操作剧本，只给配置成系统 agent 的那一个。其它 agent 在发现、快照、斜杠目录、沙箱同步和面对模型的技能提示里都看不到它们。没指定系统 agent、又有多个 agent、也没有留下的旧主人时，谁都得不到这份库。剧本用验证过的配置写入，不直接改文件。没有现场证明就不宣称成功。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 谁看得见 | `agents.defaults.systemAgent.agentId` 解析到的那个 agent | 技能按家目录和允许名单。没有只给一个系统 agent 的保管库 | 项目和用户技能目录 |
| 五段 | 收集、变更、修复、证明、报告。秘密不进提示、日志和文件 | 技能是说明。策展归档闲置的 agent 技能 | 技能正文在被点名时进入 |
| 写入 | `config set` 或 `config patch`，或会话内允许的保管工具 | 配置经原子写。不靠模型直接改 YAML 当唯一路径 | 人改设置 |
| 医生 | 只读诊断不做 `--fix`。普通 `doctor` 即使用了非交互，也可以拷旧配置和迁移状态 | Gateway 开着时不要 `--fix` | 无对等医生 |

## OpenClaw

文件在安装包的 `custodian-skills/`。加载优先级在捆绑技能那一层，但只对系统 agent。设置缺失时，退回留下的旧默认主人、唯一配置的那个 agent，或在没有显式花名册时的旧 `main`。多个 agent 且没有系统 agent、也没有留下的旧主人，则没有任何 agent 收到这份库。

普通技能开关仍然有效。某一条可以 `enabled: false`。agent 的技能允许名单可以再收窄最终集合。

每一份发布的保管技能按这个顺序：

1. 收集：读打过红的当前配置，检查活的状态。
2. 变更：用验证过的非交互写入，从不直接改文件。可信 shell 里的 `openclaw config set` 或 `config patch`，或政策允许的会话内保管工具。
3. 修复：用 `openclaw doctor --lint` 诊断。只有显式批准的修复才用 `doctor --fix --non-interactive`。只读的 `diagnose-gateway` 可以建议这一步，自己从不跑它。
4. 证明：做一次活的端到端结果。
5. 报告：记下改了什么、观察到什么、还剩什么。

五段剧本把秘密值留在提示、日志和文件之外。凭据用 SecretRef 或凭据库。现场证明不可用时，报告确切的阻塞，不把缺少证明说成成功。

lint 退出码 `1` 表示有发现，不是诊断命令本身失败。读报告，继续其余检查。普通 `doctor`，包括 `--non-interactive`，可以在没有 `--fix` 时复制旧配置并迁移状态。它不是只读替代。只读诊断排除的是配置和服务修复以及状态迁移，不是顺便的日志或缓存记账。

第一批剧本包括：配置频道并送出一条确认过的测试消息，加入模型提供商并做一次活的 Gateway 推理，只读地分诊 Gateway、配置、SecretRef、频道认证、日志和端口，以及烘焙云工人镜像、用计时的分发证明、再安全退役被取代的快照。

## Hermes

技能对加载它们的 profile 可见。工作区优先于内置。没有「系统 agent 才发现、其它 agent 的快照里根本没有」这一档保管库。医生在网关开着时不要修复。修复默认先备份。这和 OpenClaw 的「普通 doctor 可能迁移状态、所以不是只读」是同一类警告：诊断和修复要分开看。

## Claude Code

技能在客户端能扫到的目录里。没有按一个系统 agent 隐藏整库操作剧本，也没有「没有证明就不许说成功」写进每份技能的五段合同。
