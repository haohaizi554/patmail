# 专线

并行专线是一个 Gateway 把不同聊天或房间分给不同 agent，同时把用户感受到的速度保住。并行是稀缺资源的设计问题。会话锁、全局模型容量、工具容量、上下文预算和所有权含糊，才是真正的瓶颈。OpenClaw 已经按会话串行，并用命令队列给全局并行加帽。专线是加在上面的政策：谁拥有哪件工作，什么留在聊天里，什么变成后台。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 合同 | 每条专线的 `AGENTS.md` 写目的、非目标、聊天预算、交接和工具风险 | profile 是岛。没有专线合同模板 | 子代理按工具调用。没有房间到专线的路由 |
| 并发 | `maxConcurrent` 帽住共享主车道。子代理的上限给每个发起会话自己的孩子预算 | 委派有并发孩子上限。看板工人是操作系统进程 | 子代理有侧写的转录 |
| 委派模式 | `delegationMode` 只是提示指导 | 叶子和编排者是运行时角色 | 子代理工具有深度 |
| 起步 | 先写合同和把重活放后台。协调者没有合同，只是在协调混乱 | 多 profile 不靠一份协调者提示 | 计划模式等人批准 |

## OpenClaw

现成起点是 `openclaw agents team create`。它把专线合同做成协调者、研究者、写作者和审阅者。每个角色把范围、交付物交接、批准门和升级规则放进 `AGENTS.md`。预设把协调者接到专线，并指示专线把结果交回，不再继续委派。

第一阶段给每条专线一份书面合同，会话开始时装进系统提示。目的是这条线拥有的工作。非目标是它应该交出去、而不是自己做的工作。聊天预算：快的回答留在聊天里。长任务先短短确认，再放到后台子代理或任务里。交接规则：另一条线拥有工作时，说明该去哪，并给一份紧凑的交接摘要。工具风险：用能完成工作的最小工具面。

第二阶段按每条线的业务价值调队列和模型容量。主车道并发和子代理并发是两道帽。直接的、个人的聊天和生产运维 agent 做高优先级。系统忙时，研究、起草和批量编码挪到后台任务。委派模式只是给模型的指导，不改运行时的队列帽。

第三阶段才加一个小协调者：跟踪活动任务和主人，发现跨群的重复请求，在专线之间送交接摘要，只把阻塞、完成结果和必须由人做的决定露出来。不要从这里开始。

## Hermes

多 profile 各自有家目录和秘密范围。委派把孩子的上下文和终端隔开。看板把任务分给指定 profile 的工人进程。没有「先写专线合同、委派模式只是提示、协调者没有合同就不要上」这一页推出顺序。

## Claude Code

并行来自子代理工具和可选的工作树。没有按房间把聊天分到研究者和写作者，也没有一份装进每次会话的专线合同。
