# 让出

子代理登记处拥有跨 `sessions_yield` 的完成。让出的那次执行结束。被委派的任务和它的完成听众还在。登记处的请求者结算批次在孩子落定之后启动后继回合。Gateway 准入在必要时把那个后继挂到暂停的子代理上，保留原来的请求者。

交互会话里生出的编排者和隔离 cron 里生出的编排者适用同一套。Cron 拥有排程结果的投递。登记处拥有嵌套编排者的延续。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 让出之后 | 执行结束，任务和完成听众留下。后继通过正常准入，拿到新的执行权威 | 后台委派在进程里。停手不自动把所有权交给下一次回合 | 子代理跑完把摘要交回 |
| 所有权 | 让出在关掉旧执行之前转移完成所有权。已履行的义务不再重新武装 | 孩子的完成回到发起会话 | 无登记处批次 |
| 重启 | 替换的 Gateway 通过同一行主人取得新的运行时化身。已关闭 Gateway 的回调不能结算恢复后的唤醒 | 进程死了，后台委派不耐久 | 侧写的 JSONL 还在 |
| 自动化 | 让出可以转移已核实请求者延续上的自动化管理。不转移创建权、旧授权或直接用户身份 | 定时任务的主人是 profile | 无 |

## OpenClaw

执行中的请求者是已准入的 agent 回合。孩子用 `requesterTurnRunId` 认出发起回合。进度回调用这一回合的活权威。显式让出由登记处的请求者让出结算拥有：持久化让出意图，冻住孩子运行 id，推进批次世代，并清掉旧的请求者回合绑定。等孩子时，登记处保留捕获的完成结果并排程欠下的批次。个别通告不得启动竞争的延续。结算派发校验当前批次和 Gateway 主人，给嵌套请求者派一次幂等的内部延续，并记下结果。后继准入在新准入的运行 id 下继续暂停的任务，保留请求者谱系和未完成的结算义务。后继完成把编排者的结果交给原来的请求者。

收养暂停的运行用已有的登记处替换。它不制造第二个被委派的任务。收养清掉只给孩子的暂停通知，不把它带进完成。显式的 `waitFor: "message"` 在登记处接受等待之后，算作延续证据。已登记的消息等待不会产生「缺少延续」的警告。被拒绝或未登记的等待不提供这份证据。

私有孩子的结果要等发起回合落定，才准入个别通告。正常结算在兄弟还在跑的时候，也会恢复每个已经结束的私有孩子。显式让出先指派冻住的批次，再在那个主人下恢复孩子清理。迟到的通告失败不能替换批次的投递状态。已经提交的投递证据仍然有效。重启激活在恢复孩子完成之前，先对上保留的请求者回合绑定。

嵌套请求者的结算在排程延续之前，把暂停的运行和孩子唤醒批次一起持久化。孩子在请求者让出之前就结束时也一样。后继准入不得依赖后来的生命周期结束通知。后继保持同一个任务。前任迟到的通知不能把它重新打开。

请求者正在执行结算唤醒的延续时，它自己的完成批次仍可以被标成派发中。让出工具把那一个精确批次排除在更老的待定孩子之外。它不得再为已经在处理的结果承诺另一次唤醒。无关的待定批次和新生成的工作保持已有的完成所有权。

结算派发用 `subagent_settle` 的输入出处。个别通告和更老的后代唤醒路径保留 `subagent_announce`。后者在派发之后已经拥有自己的运行替换，不得在准入时触发暂停运行的收养。出处给交接分类。活的 Gateway 准入和登记处所有权仍然授权它。

显式让出批次在任何请求者深度都必须合格。没有让出批次的嵌套运行仍走已有的后代结算路径。顶层 cron 的排除仍在。为 cron 会话再开一个独立的请求者结算回合，会和调度器拥有的延续竞争。

登记处的持久化主人按每次运行串行变更，多运行批次按排序后的顺序准入。同步计划在准入之后读当前不可变的已发布行，返回替换行或删除。异步准备先发生。计划在提交前再查执行、取消、请求者和同批所有权。回调在等待期间保留观察到的所有权和唤醒进度。它们只从自己已确认的发布推进这些观察。

SQLite 工人在写入前比较行版本摘要。外来变更通过读工人刷新受影响的行并重跑计划，最多三次。只有已确认的提交才发布常驻行并通知读者。未知的写入结果把那些行围住，直到规范恢复。终态行和它们合格的会话状态事件一起提交。等价的重复终态回调保留进行中的清理权威。进程本地的回调所有权在元数据发布之后仍然在。恢复到替换的 Gateway 时，通过同一行主人取得新的运行时化身。已关闭 Gateway 的回调不能结算恢复后的唤醒。

一个完成主人。让出在关掉旧执行之前转移所有权。精确回合和孩子批次上已有的可见终稿回执，阻止把已经履行的义务重新武装。成功的批次结算退役那个世代。重复的回调不能再把它收尾一次。存储的运行 id 和出处都不能复活已关闭的执行。后继通过正常的 Gateway 准入，拿到新的执行权威。收养保留任务谱系，不保留旧的工具、批准、渠道或工人回调。

经过认证的控制界面管理员的显式让出，可以把自动化管理转给已核实的请求者延续。登记处在让出前捕获活权威，在整批持久化之后提升它，并把新的管理授权绑到已准入的后继。它从不转移自动化创建、旧授权或直接用户身份。交接留在进程本地。新的直接用户回合、取消、会话重置或归档、以及 Gateway 重启都会撤销。后继绑上自己的运行范围之后，那个范围拥有资格直到关闭。退役已经投递的孩子批次，不能撤销仍在跑的后继上的资格。

## Hermes

后台委派在发出时从这一轮拆开。停手要另外打断那些单元。没有「让出冻住孩子 id、后继通过新准入、已关闭 Gateway 的回调不能结算恢复后的唤醒」这一页登记处。看板的所有权是任务认领，不是同一次委派的让出批次。

## Claude Code

子代理跑完把结果交回父回合。没有跨让出的完成登记处，也没有「个别通告不得启动竞争延续」的结算批次。
