# 工人边界

云工人的转录在 Gateway。工人能打到的面，和哪些凭据会离开 Gateway，是另外的合同。工人回合模式下，已登记的节点拉起工人子进程。子进程拨 Gateway 已认证的公共工人路线，说一套方法允许名单封闭的专用协议。工人不能调用操作者 RPC。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 工具面 | Gateway 在准入响应里给出精确的工具定义和已解析的文件系统策略。空结果就是没有工具 | 子代理的工具集在生成时定 | 子代理工具面由客户端定 |
| 凭据 | 每次分发铸造工人凭据。Gateway 只存哈希。过期的工人重连被围住，不合并 | 子进程环境是允许名单。不复制启动 profile 的秘密 | 客户端环境 |
| 模型钥匙 | 默认按提供商和模型引用代理推理。钥匙留在 Gateway | 远程后端不因此拿到主进程的全部钥匙 | 钥匙在客户端 |
| 一次 | 转录批次对会话叶子做比较并交换。陈旧的基座让运行失败停止，不复制、不改基已付费的输出 | 完成队列。无这道叶子交换 | 侧链追加 |

## OpenClaw

Gateway 套用和本地相同的工具组装策略。安装节点的启动信封给放置本地的实现封顶。Gateway 拥有的工具使用发出的面，不跟监督者的工具词汇走。明确封顶的定时回合复用受信任的所有者组上下文，不把那个身份送到盒子上。发出的面以外的工具不可用。

准备好的面上，每一个 Gateway 拥有的工具走一条封闭的调用传输，由同一构建的 `worker-gateway-tools-v1` 把守。句柄属于这一次准入的运行、认领、环境纪元和放置代。每一次调用重新核对当前权威。工人不能另选来源会话或操作者 RPC。工具效果和前后钩子留在 Gateway 主人和保留的插件代上。取消和更新走同一条工人连接，不挡住心跳或转录确认。取消还在队列里的 Gateway 工具调用，使它不会开始。已经在跑的保留协作式取消和结算。在场查询保留自己的超时，工人连接关闭时结束。生成和发送保留耐久的重放选举、拓扑限制和不确定结局的处理。重连从不制造一份新的操作身份。

节点专用的设置凭据绑在耐久环境上，只能在登记还活着时登记它的第一台设备。关闭或超时未完成的登记会收回凭据。重放为同一设置身份签发新凭据。Gateway 重启之后，只有活着的替代登记可以收养还留着的待定凭据。第一台认证的 Ed25519 设备身份和设置完成一起原子记下。同一设备的投递重试仍然有效。重放不能换成无关的节点。

云节点和已配对设备上的远程执行，需要明确允许的 `codex.exec-server.stdio.v1` 命令、获准的配对面，以及关键的节点调用批准。允许一次绝不授予后来的启动。总是允许造的是当前 Gateway 进程拥有的内存常设授予，最长 30 天。Gateway 重启就清掉。每一次启动在分发前立刻重新核对精确的活动放置、节点配对、环境主人、命令批准范围和工作区。托管的执行服务器以全新的私人家目录和消毒过的环境启动。它的托管工作区不是操作系统沙箱。获准的执行可以碰到节点账户被允许的进程和文件。需要隔离时用单独的最小权限账户。

工人回合默认按 `{provider, model}` 引用代理推理，模型凭据不放到工人上。显式配置的配对设备 profile 上的工人本地推理，用节点准备的模型配置和不透明的外部代理认证。Gateway 仍只发送模型引用和获准的放置选择。受信任的 Gateway 和凭据保管留在不可信工作负载外面。不要把真正的提供商钥匙放进去。启动传输和打红不是同一用户的隔离。Codex 远程执行把 app-server 加上 ChatGPT 订阅或 API 钥匙留在 Gateway，只把沙箱操作送到盒子。远程执行要求准备好的认证，拒绝环境里碰巧有的认证回退。Crabbox 的 AWS 租约元数据在设置前权威核对实例角色。设置命令也保持无凭据。

工人回合经私人启动信封收到 Gateway 有效的共享 GitHub 访问令牌，每一轮刷新。工人把它物化成一次性状态目录里的私人 profile。每一轮自己的 profile 目录。下一轮绑定之前去掉更早轮次的 profile。更早一轮留下的进程只保留它启动时的那把令牌。这限制的是继承路径，不是同一用户的访问。以工人的操作系统用户跑的进程，包括 agent 自己更早一轮的后台命令，仍能读工人状态，和在 Gateway 主机上一样。云工人是单会话的一次性机器。要和 agent 更早的命令隔离，把配对的会话宿主放在专用的最小权限账户下。密封的工人启动器为每次 `exec` 读那个 profile，只把令牌暴露给子进程。不写进日志或日记。配对设备自己的 `gh` 登录不用。

控制界面和 Codex 远程执行的发布走 Gateway 经纪，凭据来自 Gateway 上选中的 GitHub profile。仓库会话经 GitHub 的树、提交和比较并交换引用 API 发布已接受的、Git 规范化的检查点。Gateway worktree 会话用临时索引、`git commit-tree` 和命令本地的凭据助手。两条路径都关掉仓库钩子，并拒绝不安全的 Git 配置。都不把持有者令牌写进参数、远端 URL、`.git/config`、发布请求或转录。

Gateway 代理的推理去掉了 OpenClaw 对直接模型访问的需要。OpenClaw 不改写提供商的防火墙。任务要求时，在工人提供商侧限制出站。

工人回合模式下，工人用比较并交换把转录批次提交到会话叶子。陈旧的基座让运行失败停止，而不是复制或改基已经付费的输出。远程执行经 Gateway 正常的本地运行时路径写。

## Hermes

子进程环境按被服务的 profile 建，剥掉启动 profile 的残留。看板工人是操作系统进程，板是硬边界。没有「工人不能打操作者 RPC、凭据只存哈希、陈旧重连围住不合并、转录叶子比较并交换失败即停」这一页云工人合同。

## Claude Code

工作在客户端。没有一次性云盒子上的封闭方法名单，也没有 Gateway 持有模型钥匙、只把沙箱操作送出去这一划分。
