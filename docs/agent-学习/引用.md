# 引用

在消息里写 `@` 加一种引用，会把内容展开进这条用户消息，放在附带上下文一节下面。这是用户消息，不是系统提示。网页引用和抓取一样，是外部正文。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 语法 | 工作区文件由引导和读工具进入 | `@file`、`@folder`、`@diff`、`@staged`、`@git`、`@url` | 客户端可以附加文件 |
| 位置 | 引导在会话开始。工具结果在回合中 | 展开后附在当条消息 | 附件是内容块 |
| 范围 | 会话根和沙箱 | 行范围从 1 起、含两端。提交数量有上限 | 权限内的路径 |
| 网页 | `web_fetch` 是工具 | `@url` 抓取后注入同一条消息 | `WebFetch` 是工具 |

## Hermes

`@file:路径` 注入文件内容。后面加 `:10-25` 注入从第 10 行到第 25 行，含两端，行号从 1 开始。`@folder` 注入目录树和文件元数据，不是每个文件的全文。`@diff` 是未暂存的工作区差异。`@staged` 是已暂存的差异。`@git:5` 注入最近若干次提交和补丁，最多 10。`@url` 抓取网页并注入。

展开是内联的，内容放在 `--- Attached Context ---` 下面。因为附在用户消息上，它不改系统提示的缓存前缀。下一条消息若不带同样的引用，那段内容不会自动再出现，除非它还留在历史里。

文件引用受读取政策。家目录里受保护的库和秘密文件不应通过 `@file` 绕过 `read_file` 的拒绝名单。目录引用是清单，不是把整棵树读进上下文。差异和提交可能含秘密。它们和普通文件一样会进入模型。

`@url` 的正文是网络来源。在 OpenClaw 的记忆污点规则里，网络工具结果会把这一轮剩余的助手输出标成不可信。Hermes 没有同一句污点合同，但正文同样不可信，也不该写进每条会话都加载的记忆，除非人明确要记住。

子目录的 `AGENTS.md` 提示是另一条路：附在工具结果上，并拒绝工作目录以外的路径。`@file` 是人在这条消息里点名要带上的内容。

## OpenClaw

引导文件在会话开始注入，有预算。之后读文件是工具，受会话根约束。没有这套 `@` 语法写进渠道消息里再展开的合同。渠道入站的是 `BodyForAgent`。人如果把路径打在消息里，模型再用工具去读。

## Claude Code

附加文件成为内容块或工具能读的路径。`@` 若由客户端展开，效果同样是把内容放进这一条用户消息。`WebFetch` 是工具调用，有结果预算，不是消息语法。计划模式可以限制随后的写，不限制人已经附上的只读内容。
