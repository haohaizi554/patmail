# 中继

网关向外拨号连接器，不在进程里实现每一种平台的套接字。握手时连接器交回能力描述：字数上限、长度单位、能不能草稿、编辑、线程和 Markdown。网关不知道对面具体是哪一个平台。合同在实验期只做加法，破坏性变更要两个仓库一起改。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 平台 | 渠道插件在 Gateway 进程里 | 中继适配器向外拨。连接器拥有平台身份和套接字 | 无消息中继 |
| 握手 | WebSocket 先挑战再 `connect` | 网关 `connect`，再 `handshake()`，拿到 `CapabilityDescriptor` | 无 |
| 未知字段 | 协议有版本下界 | 忽略不认识的描述字段。缺的可选项用默认 | 无 |
| 状态 | 渠道是正式的 | 实验。至少两个一类平台验证之前可以无弃用窗地演进 | 无 |

## Hermes

Gateway 跑一个通用的 `RelayAdapter`，向外拨到连接器。连接器在握手时给出能力描述。之后在每回合的双向 WebSocket 上交换规范化的入站消息和出站动作。平台专用的套接字和身份留在连接器里。网关配置字数上限、草稿、编辑、线程和 Markdown，并登记入站处理。然后连接器推入站事件，并接受出站动作。

`contract_version` 目前是 1，放在描述里。网关忽略未知字段，以便向前兼容，并把缺失的可选项填上默认。实验阶段的演进只做加法，由版本把住。破坏性变更要网关和连接器仓库一起改。在 Discord 和 Telegram 这两类平台都验证过之前，可以没有弃用周期。

这和进程内的渠道适配器不同。适配器读的是该 profile 的秘密，并在忙碌时把普通消息排队、让批准命令插队。中继把平台差异推到连接器。投递仍要遵守：终稿由消费方交出，临时发送要标明，已封上的流用编辑而不是再发一条。

多路复用时，出站帧要带回被路由的 profile。后续的跟随从会话钥匙的命名空间得出 profile，让连接器在下一次转发时盖上它。连接器不能假设进程环境就是那个 profile 的 `.env`。

## OpenClaw

渠道是加载进 Gateway 的插件。绑定在消息已被接受之后选择 agent。回复回到来源渠道。没有「向外拨一个连接器、自己不认识平台」的实验合同。多租户用的是每户一个 cell，不是一条中继。

## Claude Code

没有消息平台中继。编辑器协议是本地的。工具事件留在这次查询里。
