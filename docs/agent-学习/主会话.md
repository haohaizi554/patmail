# 主会话

个人 agent 默认把所有渠道的私聊收成一条滚动对话。手机上问的，笔记本上接着说，上下文是同一份。这条会话的钥匙后缀是固定的 `main`。自定义的主钥匙被忽略。心跳叫醒它，后台工作向它汇报。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 私聊 | 默认 `agent:<id>:main`。可改成按人、按渠道分开 | 每条私聊一条会话。群默认按人切开 | 当前项目的一条转录 |
| 群 | 默认不并进主会话 | 共享线程才合成一条 | 无 |
| 谁叫醒 | 心跳叫醒主会话。后台完成回到把命令启动的那条聊天 | 心跳和完成通知各有主人 | 无心跳 |
| 钥匙 | 后缀固定。`session.mainKey` 忽略 | 会话 id 和标题。Bot 的规范聊天按标题「Bot Chat」 | 文件路径 |

## OpenClaw

开箱之后，Telegram、WhatsApp、iMessage、Slack 私聊、网页，任何地方的私聊都进主会话。它是普通会话，规范钥匙是 `agent:<agentId>:main`。后缀固定。配置里的 `session.mainKey` 被忽略。特殊的是默认的私聊范围把所有私聊塌进它，并且系统其余部分把它当根：心跳叫醒它，别处的活动向上汇入。

网页里它是首页。从主对话分出去的在线程下，群在群组下，编码和 CLI 在编码下。可以在别的页面旁边打开首页来接着说。

群默认仍按群隔离。把群并进主会话要改 `groupScope` 或由绑定覆盖。即便私聊历史在主会话里，外部私聊的沙箱和工具策略仍用派生的按账号运行时钥匙，不把渠道消息当成本地主会话运行。

多个私聊共享主会话时，若允许名单里恰好一个具体发送者，非主人的私聊不改 `lastRoute`，避免最后一条回复路被别人盖掉。

隐身会话不进这份滚动历史。重启或到期就删。主会话的转录在 agent 的库里，重启后还在。被打断的回合按恢复预算再拉起。

广播和绑定可以把一部分流量送到别的 agent。那些 agent 有自己的主会话。绑定不把两个 agent 的主会话合成一条。

## Hermes

没有「所有渠道的私聊合成一把固定的 main 钥匙」。每条会话有自己的 id。群默认按人分。共享会话才把多个人放进同一车道，发送者前缀加在用户消息上。

Bot 模式的规范聊天是标题恰好为 `Bot Chat` 的那一行，隐藏，每次点击都按标题再解析。不用存下来的会话 id 当身份。这和 OpenClaw 的主会话相似的地方只在于：身份要稳定、不能被最新一条可见会话偷换。实现是标题唯一，不是 `agent:main:main`。

心跳若启用，叫醒的是它配置的目标，不自动是「所有私聊的那一条」。后台命令完成回到启动它的那条会话。

## Claude Code

一条项目转录就是当前对话。换项目就是另一份文件。没有跨 Telegram 和网页的主会话。远程和 IDE 若打开同一份转录，那是同一个文件，不是渠道塌缩规则。
