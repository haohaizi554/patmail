# 上下文文件

项目说明在会话开始时装进提示，一条会话只加载一种项目文件。更深目录的文件出现得更晚，所以更具体的说明压过仓库根上的说明。`SOUL.md` 单独从家目录加载，不参与这场挑选。安装树里的说明不当成项目上下文。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 人格 | `SOUL.md` 等工作区引导，有预算 | `HERMES_HOME/SOUL.md`。子代理跳过上下文文件时用内置身份 | 无 SOUL 注入 |
| 项目 | `AGENTS.md` 等引导文件每次会话注入 | 一种：`.hermes.md`、覆盖、`AGENTS.md`、`CLAUDE.md`、`.cursorrules`，先匹配先生效 | `CLAUDE.md` |
| 链 | 引导名单是固定的。子目录任意文件不自动注入 | git 根到当前目录合并。相同副本去掉 | 从项目目录读 |
| 中途 | 改文件不自动重写已缓存的前缀 | 子目录提示附在工具结果上，并拒绝工作目录以外的路径 | 新会话或压缩才重新装入 |

## Hermes

家目录里的 `SOUL.md` 是这套 Hermes 的身份，每次都加载，不和项目文件争一个槽。项目文件从工作目录发现，一条会话只取一种，先匹配的生效：`.hermes.md` 或 `HERMES.md`，然后 `AGENTS.override.md`，然后 `AGENTS.md`，然后 `CLAUDE.md`，然后 `.cursorrules`。覆盖文件和正式的 `AGENTS.md` 挨着时，加载覆盖，不加载已提交的那份。个人说明可以放进通常被 git 忽略的覆盖文件，而不必改仓库里的 `AGENTS.md`。

`.cursorrules` 和 `.cursor/rules/*.mdc` 只看当前目录。`SOUL.md` 只看家目录。

当前目录在 git 仓库里时，`AGENTS.md` 从仓库根合并到当前目录。根上的文件先出现，越深的越晚，更具体的说明因此压过仓库级说明。每个文件带上来源标题。链上内容相同的副本去掉。

这些文件在会话开始时装入，并受上下文长度上限。中途改磁盘上的文件，不改已经进缓存前缀的那一份。要让新说明进入系统提示，开始新会话，或走会重建提示的压缩，或对明确支持的命令使用立刻生效。

回合进行中，子目录里的 `AGENTS.md` 提示附在工具结果后面，头尾截断，有单独的长度上限。截断写进日志，不排成一条聊天警告。路径必须在工作目录之内。家目录里的 `~/.codex/AGENTS.md` 或 `~/.claude/CLAUDE.md` 不会混进来。安装树里的 `AGENTS.md` 也不当成项目上下文。

子代理可以跳过上下文文件。这时不加载 `SOUL.md`，用内置身份。

提示里的项目说明指导模型。它不授予文件系统权限，也不跳过批准。

## OpenClaw

工作区引导注入固定的一组：`AGENTS.md`、`SOUL.md`、`IDENTITY.md`、`USER.md`、`BOOTSTRAP.md`、`MEMORY.md`。子目录里的任意文件不会仅仅因为在工作区就被注入。常设命令要写进 `AGENTS.md` 或由它引用，才会每次都在上下文里。

`openclaw agent exec` 跳过引导，一次性运行不受这些文件管辖。节点会话仍由 Gateway 选择引导文件。节点只提供自己的路径和主机事实，不把节点上没被选中的引导文件送进上下文。

大段稳定的项目上下文放在提示缓存边界之上。易变的项目记忆事实在边界之下。

## Claude Code

`CLAUDE.md` 是项目说明，会话开始时进入上下文。Hermes 会读到同一份文件，如果没有更优先的 `.hermes.md` 或 `AGENTS.md`。Claude Code 自己不读 Hermes 的家目录 `SOUL.md`。

权限和计划模式不因为说明文件里写了「可以写」就放行。说明是提示。工具是否执行仍由 `canUseTool` 决定。
