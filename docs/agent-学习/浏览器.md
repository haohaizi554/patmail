# 浏览器

浏览器是 agent 的另一块屏幕。它和用户每天用的那个配置文件分开，除非明确去附着。对话框和跨域 iframe 会把「页面看起来能点」变成「工具调用挂死」。三家里，OpenClaw 和 Hermes 把这件事做成长期会话；Claude Code 更常抓 URL 或截图，而不是养一个带标签页所有权的浏览器进程。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 默认配置 | 名叫 `openclaw` 的独立 Chromium 配置，不碰个人浏览器 | 本地 Chrome 的远程调试端口，或托管后端 | `WebFetch` / `WebSearch`。没有对等的标签页主人 |
| 控制面 | Gateway 里的回环控制服务 | 每个 `task_id` 一条持久 CDP WebSocket | 无 CDP 监督器 |
| 登录态 | `user` 配置通过 Chrome DevTools MCP 附着已登录的 Chrome | `/browser connect` 接已有端点 | 抓取公开页面。登录页是另一件事 |
| 对话框 | 在浏览器安全页里按后端处理 | 监督器看见 `alert` / `confirm` / `prompt`，并用 `browser_dialog` 回答 | 无 |

## OpenClaw

管理浏览器是单独的 Chrome、Brave、Edge 或 Chromium 配置。Gateway 里有一个只听回环的小控制服务。橙色外观的 `openclaw` 配置不写入个人浏览器的用户数据。agent 在这条隔离通道里开标签、读页面、点击和输入。

`user` 配置走 Chrome DevTools MCP，附着真正已登录的 Chrome。这是显式选择。macOS 上可以把 Chrome 家族系统配置里的 cookie 拷进另一个托管配置。托管浏览器仍用自己的用户数据目录。只拷选中的 cookie。local storage 和 IndexedDB 留下。

标签控制是确定的：列出、打开、聚焦、关闭。动作包括点击、输入、拖拽、选择、快照、截图、PDF。也可以只对可读文本提问，而不把整页快照塞回模型。Playwright 配置把直接附着导航产生的下载存到托管下载目录，校验最终 URL 之后返回 `url`、`suggestedFilename` 和 `path`。动作若立刻开始下载，结果里带 `downloads` 数组。

启用浏览器插件时，随包的 `browser-automation` 技能教快照、稳定标签、过期引用和人工阻塞之后怎么恢复。可以有多个命名配置，例如 `openclaw`、`work`、`remote`。

远程浏览器和托管 CDP 是另一条文档：浏览器可以在别的机器上。控制 API 的认证和远程 CDP 令牌在安全页。SSRF 策略在配置页，避免 agent 用浏览器去打内网。沙箱里的浏览器是 Docker 后端的可选项，和主机上的管理浏览器不是自动的同一个进程。把 docker 套接字挂进沙箱等于把主机交出去，见沙箱笔记。

工具策略里 `group:ui` 包含 `browser`。策略拿掉这个名字，沙箱开着也不会把浏览器变回来。

## Hermes

CDP 监督器补两件事。原生 `alert`、`confirm`、`prompt`、`beforeunload` 会堵住页面的 JS 线程。没有监督时，agent 不知道对话框开着，后续工具会挂起或抛出看不懂的错误。跨域 iframe 对顶层 `Runtime.evaluate` 不可见。快照里能看见 iframe 节点，但点不了、打不了字，除非有连到子 target 的 CDP 会话。

每个 Hermes `task_id` 有一个后台线程里的 asyncio 任务，握着到后端 CDP 的持久 WebSocket。它维护对话框队列、带父子关系的 frame 树、会话映射，以及最近 50 条控制台错误。附着时订阅页面、运行时，并用 `Target.setAutoAttach` 把跨域子 target 摊平，再在每个子会话上打开页面和运行时。工具处理函数读加锁后的快照，不在同步路径上等待。

`browser_navigate`、Browserbase 会话创建和 `/browser connect` 会 `get_or_start`。同一任务重复调用是幂等的。会话拆掉或 `/browser disconnect` 时取消任务、关掉 WebSocket、丢掉状态。附着成功之后若端点掉了，按退避重连，上限大约 10 秒，连续失败达到上限就警告并退出，登记项删除。本地 Chrome 已死时不会留下永远重试的线程。下一次浏览器调用再起一个新的监督器。

本地带远程调试端口的 Chrome，以及 Browserbase，能发现对话框、回答对话框、看到 frame 树，并能按 `frame_id` 在跨域 iframe 里求值。Camofox 只有 REST，没有 CDP，监督器不支持。对话框回答不了，iframe 求值也不行。

Browserbase 的 CDP 代理内部用 Playwright，大约 10 毫秒内会自己关掉原生对话框，来不及用 `Page.handleJavaScriptDialog`。监督器改注入脚本，把 `alert`、`confirm`、`prompt` 换成发往 `hermes-dialog-bridge.invalid` 的同步 XHR。`Fetch.enable` 在请求出网前截住。回答通过 `Fetch.fulfillRequest` 交回一段 JSON，页面上的 `prompt()` 仍得到 agent 给的字符串。agent 侧仍是 `browser_dialog`。

快照把待处理对话框和 frame 结构露出来。agent 用 `browser_dialog` 明确回答，而不是假装点击能关掉 `alert`。

视觉截图会进工具结果，并在之后的每次 API 调用里重放。体积和重复次数在 `vision` 配置里：目标字节数、每张图最多嵌几次。计数按会话和解析后的源，同一文件的区域裁剪共享这个计数。子进程里的默认帽只在委派孩子的上下文中生效。新的嵌图成本规则放在这一处，不在浏览器工具里再做一个计数器。

## Claude Code

`WebFetchTool` 和 `WebSearchTool` 取页面或搜索结果，作为工具结果回到循环。它们不持有标签页，不附着个人 Chrome，也没有对话框队列。登录墙、按钮和跨域 iframe 不会变成一次 CDP 操作。

需要看图像时走模型的视觉能力，图片进工具结果，受结果预算约束。这和 Hermes 把截图嵌进历史再重放是同类成本问题，但没有 per-task 的浏览器监督器。

SSRF 防护在钩子层。抓取不是沙箱浏览器。工作区里的文件用读文件工具，不绕到 `file://` 抓取。
