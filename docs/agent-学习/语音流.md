# 语音流

语音可以按句播放，不必等整段音频合成完。模型的文本增量先被收成句子，去掉思考块，哪怕思考标记被拆在两个增量里。没有分块 API 的提供商仍按句走同步合成。所有要说出口的文本用同一套清洗。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 实时 | Talk 的 realtime、语音识别加合成、只转写 | 语音模式、仪表盘的说话流、适配器可选的流式音频 | 无 |
| 切句 | TTS 工具可以是同步的 | 句子块。思考块剥掉后再合成 | 无 |
| 格式 | 渠道附件 | 原始 PCM，16 位整型，单声道，采样率由提供商声明 | 无 |
| 唤醒 | 无这份设备端热词合同 | 热词在设备上。没开口之前音频不离开机器 | 无 |

## Hermes

管道有四段。模型产出文本增量。句子收集器累加增量，剥掉 `<think>` 块，凑成完整句子再冲刷。注册的流式语音提供商把每个句子变成 PCM 块。本地播放用扬声器输出流。网关适配器若加入，走 `write_streaming_tts`。语音回复在第一个子句之后就开始说，而不是等整段生成和合成结束。

没有分块接口的提供商仍能按句播放，走已经验证过的同步 `text_to_speech` 路径。因此默认的边缘提供商也能对话式地出声。所有口语文本经 `prepare_spoken_text` 清洗，一条清洗，所有路径。

语音模式覆盖 CLI 的录音、Telegram 和 Discord 的语音回复，以及 Discord 语音频道。唤醒词是另一条：`wake_word.enabled` 或 `/wake on` 之后，轻量检测器在配置的输入设备上听。听到短语就暂停自己，把麦克风让出来，开一条新会话，再走普通语音管道。检测完全在设备上。常开的监听只找唤醒短语。在你真正对 agent 说出命令之前，音频不离开这台机器。

站点口令和 API 钥匙不进语音文本。清洗去掉的是不该读出来的标记，不是秘密扫描的边界。思考内容被剥掉，是为了不把推理读出来。

## OpenClaw

Talk 有三种模式，和电话、会议、浏览器实时、按住说话共用事件信封和取消。一次性的 `tts` 工具是同步的。媒体在 `NO_REPLY` 时仍可送达。日志不记录转录正文、音频载荷和通话 id。打字指示在心跳开始时可以出现，若目标聊天支持打字且没有关掉。

## Claude Code

没有句子级的流式语音，也没有设备端唤醒词。文本增量画在客户端。若要出声，得另接一条合成，不在这棵查询循环的合同里。
