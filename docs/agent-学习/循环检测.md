# 循环检测

重复的工具调用有两道闸。模式检测默认关。压缩重试之后的守卫默认开：同一个工具、同一组参数、同一个结果在窗口里再出现，就中止这次运行。把总开关设成 false，两道一起关掉。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 模式 | `tools.loopDetection.enabled` 默认关。看滚动的工具历史和未知工具的重试 | 停手闸门和重复调用检测在回合循环里 | 停止钩子和迭代上限 |
| 压缩之后 | 只要没有显式关掉，每次压缩重试后武装。重复三元组就中止 | 压缩是唯一允许的缓存断开。空转另有闸门 | 三次压缩失败有断路器 |
| 轮询 | 已知的轮询工具有专门的重复模式。输出没变的 poll 计入检测 | 后台完成不靠反复 poll。用通知 | 任务列表 |
| 总开关 | `enabled: false` 两道都静音 | 各闸门单独有预算 | 无这一对守卫 |

## OpenClaw

两道都在 `tools.loopDetection` 下。循环检测看着滚动的工具调用历史，找重复模式和未知工具的重试。它默认关闭。压缩后守卫在 `enabled` 没有显式写成 false 时开启。每次压缩重试之后武装。agent 若在窗口里重复同一个 `(工具, 参数, 结果)` 三元组，运行中止。溢出然后压缩然后原样再循环，靠这道打断，而不是让它一直跑。

要抓的是没有进展的重复序列、同一工具同一输入反复出错的高频空转，以及已知轮询工具的特定重复。后台命令上，输出没变的反复 `process poll` 或 `log` 计入循环检测。单纯的空闲时间不是进展。

设 `enabled: false` 会同时关掉模式检测和压缩后守卫。不是只关其中一道。

这和迭代预算不同。预算是次数上限。循环检测是形状：同样的调用没有新信息。取消和运行期限仍能停。恢复沿 transcript 继续时，要求先检查被打断的动作，避免把这道闸门当成「再原样调用一次」。

## Hermes

回合里有停手闸门和重复调用检测，避免同一工具同一参数空转。迭代有硬上限。压缩失败有冷却，不在每次溢出时立刻再摘要。微压缩若打开，每回合改写历史，那是另一条缓存成本，不是这道三元组中止。

后台工作用完成通知，不用睡眠循环或反复轮询来模拟提醒。提醒用 cron 或会话内的 `/loop`。`/loop` 在回复不再变化时自己放慢，不把相同的 poll 当成进展。

## Claude Code

查询有迭代上限。停止钩子可以要求再跑一轮，那是钩子认为还没做完，不是发现三元组重复而中止。工具结果预算和压缩断路器限制上下文，不专门武装在「压缩重试之后」。未知工具返回错误结果，模型可以再试，没有默认关闭的滚动模式检测写在这棵还原树的合同里。
