# 本地

本机模型可以装成 Gateway 管理的服务，也可以接已经在跑的服务器。托管安装会先显示主机、模型、下载体积和执行后端，下载之后用一次真实的工具调用验证，通过了才改默认模型。本机模型没有托管提供商的安全过滤。工具权限和提示注入防护仍要按这个模型和任务来设。能答一句短提示，不表示扛得住一次带工具和历史的 agent 回合。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 托管 | llama.cpp 插件。入职时选托管本机服务器 | 提供商配置里的 `base_url`。不在这里替人下载权重再改默认 | 客户端指向的端点 |
| 验证 | 真实工具调用通过之后才把默认模型改过去 | 模型组合在建会话时做离线拒绝。不把「一次工具调用成功」当成切换默认的门 | 第一次请求失败就失败 |
| 接口 | 支持就用 `openai-responses`。自定义提供商省略 `api` 时默认 `openai-completions` | 三种 API 模式由配置决定 | 客户端的提供商 |
| 过滤 | 没有托管方的安全过滤 | 同样是你自己的端点。批准和工具策略仍在 | 本机策略 |

## OpenClaw

硬件感知的推荐：安装 llama.cpp 插件，`openclaw onboard`，选托管本机服务器。策划好的配方用 64K 上下文。最小的一份有 8 GiB 主机内存下限，更大的要更多。下限不保证装得下或跑得快。检查的是可用内存、支持的 GPU 显存和磁盘，而不是假设某一种机器。

LM Studio 和 Ollama 留给想自己管模型的人。自定义服务器要给完整的 OpenClaw 提示、工具、历史和模型输出留地方。先用真实任务试，再把它设成默认。

后端按用途选：macOS Metal 上的本地 DeepSeek 用 ds4。前面还有另一套模型 API 时用 LiteLLM 或 OpenAI 兼容代理。要硬件感知的选择、校验过的下载和 OpenClaw 管理的服务，用 llama.cpp。OCI 仓库拉取和混合路由用 llmman。第一次本机、图形界面和原生 Responses 用 LM Studio。高吞吐自建用带 OpenAI 兼容 HTTP 的 MLX、vLLM 或 SGLang。命令行和 systemd 用 Ollama。

后端支持 Responses 时用 `api: "openai-responses"`（LM Studio 支持），推理和最终文本分开。否则用 `openai-completions`。自定义提供商有 `baseUrl` 但省略了 `api`，默认补全接口。

WSL2 上官方 Ollama 的 Linux 安装会开 `Restart=always` 的 systemd。GPU 场景下开机自动加载上次的模型可能钉住主机内存，虚拟机反复重启。那是安装器的服务政策，不是 Gateway 的模型回退。

只在选中的模型需要时才启动的本机服务，是另一页。这里的托管路径会改默认模型，所以验证放在改默认之前。

## Hermes

本地或自建端点写在提供商的基址和 API 模式里。钥匙进 `.env`。建会话时，明显属于别的提供商的名字当场拒绝。自定义端点接受。没有「下载配方、跑一次工具调用、再改默认模型」这一条入职门。工具是否露出仍由工具集和 `check_fn` 决定。

## Claude Code

本机端点是客户端配置。没有 Gateway 在改默认之前强制一次工具调用。权限仍是每次工具的允许、询问或拒绝。
