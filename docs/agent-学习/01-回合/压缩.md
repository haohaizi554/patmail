# 压缩

三家都把「上下文变长」拆成好几步，并且都规定：工具调用和它的结果不能被切成两半；磁盘上的完整历史还在，变的是下一轮模型看见的窗口。循环笔记里只有阈值。这篇写切分、摘要失败和缓存。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 谁决定压 | 上下文引擎的 `compact`；默认 `legacy` | 网关卫生 85%，循环内压缩器默认 50% | 请求前一串收缩，报错后再反应式压一次 |
| 先做什么 | 压缩前提醒写入记忆文件 | 先把旧工具结果换成占位，不调用模型 | 先按条、按轮裁工具结果 |
| 摘要失败 | 超时则提交一次无摘要压缩，会话继续 | 冷却 60 秒、300 秒、900 秒；可落到确定性摘要 | 自动压缩连续失败有熔断；反应式只试一次 |
| 切分 | 工具块整组移动边界 | 尾部按 token 预算回走，工具组对齐 | 压缩边界单独成一种续跑原因 |
| 历史 | transcript 全留 | 旧行 `active=0`，不删 | 项目目录里的 JSONL 仍在 |

## OpenClaw

默认 `agents.defaults.compaction.mode` 是 `safeguard`。摘要先套预算再校验：规定的标题必须留在正文里，未完成的请求和精确标识必须出现在即将写入的文本里。校验失败只重试配置允许的次数。全部失败则不写 transcript，原历史保留。

自动压缩在接近窗口时发生，也在模型返回上下文溢出时发生。溢出恢复会裁当前窗口里的工具结果，已完成的动作不重放，模型和账号不变。取消会停掉尚未开始的恢复，但已经写进 transcript 的压缩不算回滚。

摘要超时（截止时间到了，或 HTTP 408 / 504）是例外：这次压缩照样提交，只是没有新摘要。最近的消息、完整的工具对、挂起的请求和上一份摘要都留着，并注明删掉了多少更早的消息。下一轮不再为同一份摘要空等。日志记 `reason=timeout summary=deterministic`，聊天里不通知。超时不进入模型回退链，因为每多一个模型就可能再等一整段超时。`safeguard` 在这次例外里放弃「标识必须保留」。更早、从未进过摘要的事实离开模型上下文，以后的压缩从新边界开始，不会把它们找回来。磁盘上的 transcript 仍可检索。

其它摘要错误可以走会话已有的模型回退链，回退不写回会话状态。显式配置的 `compaction.model` 不继承这条链。摘要模型更大，也不会把前台模型的窗口变大。

手动 `/compact` 可以带焦点，焦点限 800 个 Unicode 码位，并当作数据转义后再放进请求。内置运行时用 `keepRecentTokens`（默认 20000）决定留下的尾巴。Codex 原生会话在 ChatGPT 登录下可以自动压缩，但不能手动 `/compact`；有 API key 时手动命令不接收焦点说明。

内置摘要器只收文本。图片记成省略标记，不声称模型看过像素。前八条受影响消息最多各两个固定标记，其余合成一句。这些标记加上角色标签，每次摘要请求最多 847 字节，计入 token 估计。工具调用和结果即使超出分块目标也留在一起。CJK 字符参与分块估计。

`compaction.enabled: false` 只关掉阈值触发和可选维护。溢出恢复和手动压缩仍在。持久 Gateway 会话里，可选的记忆刷写和压缩要等回复送达、前台主人关闭之后才跑，用单独的会话主人和这一轮剩余的时间。新消息会取消这些可选工作。一次性 `openclaw agent --local` 跳过回合后的可选工作，下一条命令在推理前做必需维护。

压缩前的记忆刷写是静默回合，把还没写下的事实写进每日笔记。这段维护记录不进入后续用户轮。

上下文引擎把这件事收成四个点：`ingest`（新消息入库）、`assemble`（按预算返回消息，可附加一段系统提示）、`compact`（摘要旧历史）、回合结束后的持久化。可选的 `maintain()` 可以安全改写 transcript。`legacy` 是默认，插件引擎要显式选中，不会自动接管。子代理可选 `prepareSubagentSpawn` 和 `onSubagentEnded`。请求 `lightContext` 且解析成隔离模式时，故意跳过 spawn 前的引擎状态。

## Hermes

两层独立。网关卫生在 agent 开工前，阈值固定 85%，防止隔夜会话把下一轮直接打爆。token 优先用上一轮接口回报，其次用会话行上的用量锚，最后才用按字符的粗估。历史短于 4 条或压缩关闭时不跑。它比循环内的 50% 更高，是因为两边设成一样时，长会话每一轮都会被提前压缩。

循环内的 `ContextCompressor` 用真实用量。用量锚是提供商上次的 prompt 与 completion，再加上锚之后新消息的粗估。锚按内容指纹认出那份计价过的 transcript，网关每轮从数据库重读历史也不会对错。压缩、会话重置和 Codex 原生压缩会清掉锚。没有锚时，回合开始和请求前的阈值门会等一次真实用量，粗估再大也不当成已经溢出。模型切换后旧用量作废，新提供商裁决第一次请求。

失败或卡住的摘要会给这个会话装上冷却：60 秒、300 秒、900 秒，且不会短于 `compression.context_timeout_seconds`，写在 `state.db`。冷却期间普通阈值压缩让路，避免坏掉的摘要后端每轮重试。`finish_reason=length` 走另一条同样升级的计数，transcript 保留。

算法四步：

1. 保护尾之外、超过 200 字符的旧工具结果换成占位，不调用模型。模型还没回答的那一轮工具结果留原文，图片也留。单轮超过输入预算 20% 时，这一轮可以被摘要，更老的图片退役。
2. 头部保护系统消息和第一轮往来。尾部从末尾按 token 回走。尾部预算封顶在窗口的 20%，`protect_last_n` 只是小下限。最后一条用户消息、最后一条助手消息和原子工具组可以超出这个帽。边界对齐到工具组的父助手消息。
3. 中间段交给辅助模型，任务名 `compression`，产出固定骨架：目标、约束、进展、关键决定、相关文件、下一步、关键上下文。摘要预算是被压内容的 20%，至少 2000 token，至多取窗口的 5% 和 12000 的较小值。摘要模型的窗口必须不小于主模型，否则这次调用失败，中间段会被丢掉且没有摘要。
4. 拼回头、摘要、未改的尾。摘要的 role 选成不会和相邻消息同角色。对不上的工具结果删掉，对不上的工具调用补一条占位结果。

再次压缩时把上一份摘要交给模型去更新，而不是从头重写。确定性兜底摘要也会存进 `_previous_summary`，因为它已经是 transcript 上的交接文本。

插件引擎通过 `context.engine` 显式选择，不会自动启用。默认 `compressor` 就是内置有损摘要。

Anthropic 缓存用 `system_and_3`：系统提示一个断点，再加上倒数三条非系统消息。每请求最多四个 `cache_control`。标记打在副本上，不改写缓存前缀本身。

微压缩默认关闭。打开后，每个正常结束的回合只吸收一份最老的交换，用户原文不进摘要，并且每一轮都打断前缀缓存。细则在 [微压缩](微压缩.md)。

Bedrock 的窗口长度以显式配置和提供商确认过的值为准，确认结果写在该 Hermes home 的 `context_length_cache.yaml`。探测失败有五分钟冷却，不把静态表写成已确认。

## Claude Code

请求发出前按固定顺序收缩：压缩边界、工具结果预算、snip、微压缩、折叠、自动压缩。工具结果大约每条 50000 字符、每轮 200000 字符，超出的落到 `tool-results/`，消息里留指针。缺了 `tool_result` 会补一条，否则接口返回 400。

自动压缩留大约 13000 token 的缓冲。连续失败有熔断，大约三次后不再在同一路径上空转。反应式压缩在模型已经报上下文过长时再试一次，用 `hasAttemptedReactiveCompact` 挡住第二次。

续跑原因和结束原因分开。结束可以是完成、达到回合上限、流或工具被中止、钩子停止、模型错误、提示过长、图片错误、触及限制。续跑包括下一轮、反应式压缩重试、折叠排空重试、输出 token 恢复、停止钩子拦截后的再提示、token 预算续跑。

这棵 2.1.88 还原树里，snip、折叠和部分反应式实现是占位，顺序和熔断写在 `query.ts` 的注释里。笔记只记这个顺序，不把占位函数当成可运行的压缩器。
