# 失败转移

模型失败先分类，再决定原地重试、换账号，还是换模型。三家都不把「这一轮临时用了备用模型」写成会话的新选择。用户明确点过的模型失败了，就报告这次失败，不用一份无关的备用模型把回合圆过去。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 先做什么 | 同一模型上的有界恢复，续写已有 transcript | 按入口、配置、环境的顺序解析提供商 | 流里换模型时丢掉旧的工具执行器 |
| 再做什么 | 同一提供商内轮换认证 profile | 提供商档案上的 `fallback_models` | 回退不把已经发出的 `tool_use` id 带进新请求 |
| 最后 | 配置的模型链，只对这一轮 | 辅助任务走自己的路由，不进主循环钩子 | 主循环看到回退后的新响应 |
| 不重试的 | 账单、认证、拒绝、格式错误、本地 transcript 冲突 | 凭据解析失败就停在这一层 | 用户中止、权限拒绝 |
| 会话里记下的 | 选中的模型不变。`/status` 能区分谁答的 | 保存的模型选择压过壳里的旧环境变量 | 回退不改系统提示 |

## OpenClaw

两阶段：当前提供商里轮换认证 profile，然后才走到 `agents.defaults.model.fallbacks`。在这之前，对临时限流和提供商故障做有界的同模型恢复。恢复续写现有 transcript，保留已有输出和已完成的工作，并让 agent 先检查被打断的动作再决定要不要重做。取消仍然有效。

限流最多 10 次尝试。其它瞬时故障在 90 秒窗口里最多再试 8 次。一次完整成功的模型响应清掉这扇窗口。半截流、失败响应和单独的工具活动不清。退避从大约一秒指数增长，加抖动。`retry-after` 和正文里的等待提示抬高下限，可以超过 30 秒的退避帽。账单、认证和拒绝不占用这份瞬时预算。

空的 400 和 422 不静默重交。带瞬时证据的客户端错误仍走恢复。限流类的等待若长于保存的 `retry.provider.maxRetryDelayMs`（默认 60 秒），且配置了备用模型，就直接换，不再握着这次运行干等。没有备用时，等待照单全收。`maxRetryDelayMs: 0` 关掉这个帽。用尽的日、周、月额度直接进入认证或模型备用，单独一个 `Retry-After` 不等于额度用尽。

输出 token 用尽且工具调用还没生成完时，已准入的工具跑完，半截参数不执行，然后从已有结果继续。这次续跑共享重试次数和运行期限，不共享那 90 秒故障窗口。拒绝和未知的不完整原因不走这条。

本地 transcript 写冲突不重试模型、不轮换账号、不换模型。主人重读当前修订，合格的追加再试一次。再冲突就是本地错误。旧回复不能盖过更新的用户回合。思考级别只有在提供商明确拒绝思考参数时才回收。无关的不支持选项保持原来的失败类别，不会改成关掉思考再试。

候选链看选择从哪来：

- 配置的默认主模型使用配置的备用链。
- agent 自己的 `model` 默认严格，除非它自己带 `fallbacks`。空列表表示明确不要备用。
- 用户用 `/model`、选择器、`session_status` 或 `sessions.patch` 点的模型是精确选择。回复产生之前就失败，就报告失败，不拿无关备用来答。
- 选「默认」不写入提供商覆盖，孩子也不会继承父会话的模型钉死，同时保留配置默认的备用策略。
- v2026.4.26 之前只有 `modelOverride`、没有来源字段的旧行，当成用户选择。
- cron 的 `payload.model` 是任务的主模型，不是用户会话覆盖。它用配置备用，除非任务自己给了 `fallbacks`。

备用只活在这一轮。下一轮从选中的主模型再开始。运行到达最终超时或空闲熔断时，备用链停止。这是终态，不是再试下一个模型的信号。

认证存在每个 agent 的 SQLite 里。配置里的 `auth.profiles` 和 `auth.order` 只有元数据和顺序，没有秘密。遗留的凭据文件只由 doctor 导入，运行时不悄悄回退。轮换顺序是：该 agent 存的顺序、配置的 `auth.order`、配置里的 profile、库存的 profile。没有显式顺序时轮询：OAuth，然后静态 token，然后 API key。OAuth 里能用的 access token 排在过期的前面。过期的仍可尝试刷新。冷却中的排到末尾，按最快到期排序。

自动选中的 profile 按会话钉住，为的是提供商缓存。不每次请求轮换。压缩不换钉。`/new`、`/reset`，或 profile 进入冷却，自动钉可以转或清。用户用 `/model …@<profileId>` 钉的账号在重置、压缩和冷却之后仍是第一偏好。它冷却时先试同一提供商的下一个，存储的钉不换。用户点死的提供商和模型在同一提供商的 profile 用尽后就失败，备用模型链不因此打开。

普通冷却按这个 profile 最近的错误次数：第一次 30 秒，第二次 1 分钟，第三次起 5 分钟封顶。账单和整段禁用挡住该 profile 的所有模型。限流冷却可以只针对失败的那个模型，同一提供商的其它模型仍可试。格式错误通常终态，因为同一份载荷再送还会失败。OpenAI 兼容的 `finish_reason: error` 归成服务器错误，可以换 profile 或模型，但诊断保留原文，不改写成超时。408、504、522、524、499 归超时。529 归过载。

成功的一次运行清掉过期的失败状态。transcript、格式、上下文、提供商之前的超时，以及没有选中 profile 的环境故障，不改共享的 profile 健康。

嵌入式运行时对带结构化 `cyber` 类别的 OpenAI 拒绝，可以在这一轮改试 Daybreak，默认 `openai/gpt-daybreak-blue-latest`。条件是重放元数据证明不会重复工具或投递副作用，目标模型和被拒的不同，选择不是严格的，并且功能开着。这次失败若还没提交工作，保留原来的拒绝，不再走无关备用。已经执行过工具或投出内容，就保留重试自己的结果。授权失败会把该目标冷却，默认 10 分钟。普通提供商故障不因此送去 Daybreak。

## Hermes

CLI、网关、cron、ACP 和辅助模型共用 `hermes_cli/runtime_provider.py`。解析顺序是：这次调用的显式参数，然后 `config.yaml` 里保存的模型，然后环境变量，然后提供商默认或自动。保存的选择压过壳里残留的导出变量，避免上次在 `hermes model` 里点的端点被旧环境悄悄换掉。

提供商是插件。`plugins/model-providers/<name>/` 在首次访问时注册 `api_mode`、`base_url`、环境变量和 `fallback_models`。用户家目录里的同名插件覆盖内置。解析器按 id 取档案，不为每个提供商写分支。

内部消息保持 OpenAI 形态。`api_mode` 决定发出去的形状：`chat_completions`、`codex_responses`、`anthropic_messages`。推理字段在进字符串处理前摊平。`reasoning_details` 按到达顺序原样收集，写进助手消息，重放时还在。可见回答和推理分开。

多个密钥同时存在时，自定义端点不会拿到另一个提供商的 key。OpenRouter、AI Gateway 和自建兼容地址各自用自己的密钥来源。

辅助任务（压缩、标题、记忆策展、视觉）走 `auxiliary_client`，配置在 `auxiliary.<task>`。它们发出 `pre_auxiliary_call` 和 `post_auxiliary_call`，不发主循环的 `pre_api_request`。所以插件看到的主循环钩子不会把一次摘要调用当成用户回合。

压缩摘要若换模型，那个模型的窗口必须不小于主模型，否则中间段会在没有摘要的情况下被丢掉。这和 OpenClaw「备用模型不扩大前台窗口」是同一类约束。失败冷却写在会话上，见压缩笔记，不写成下一次的默认模型。

## Claude Code

流式执行中若回退到另一个模型，当前 `StreamingToolExecutor` 被丢弃。已经发出的 `tool_use` id 不能出现在下一次请求里，否则接口把它们当成没有结果的调用。回退前未完成的参数不执行。

权限拒绝和用户中止不是模型故障。它们停在审批那一层，不进入换模型。反应式压缩是上下文过长之后的另一次请求，也不是认证轮换。

这棵还原树没有 OpenClaw 那种按 profile 冷却的账本。模型名单和密钥在客户端设置里，回退行为以 `services/api` 把失败变成下一次请求为准。
