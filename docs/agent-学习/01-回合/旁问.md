# 旁问

`/btw` 对当前会话问一句旁的问题。问题和回答不写入会话历史，也不进 `chat.history`。主运行若还在，保持不动。回答走单独的 `chat.side_result`，客户端不会把它当成普通助手消息。用量若由运行时提供，走诊断管道，不加进由会话推导的费用合计。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 旁问 | `/btw` 或 `/side`。一次快照加一次单独查询 | 普通消息进会话。回绕才剪历史 | 同名的旁问不进主转录 |
| 历史 | 不写。脱离的结果重载后消失 | 提交先落用户行 | 旁问不进主历史 |
| 思考 | 以关闭运行 | 跟随该会话的模型参数 | 旁问自己的参数 |
| 控制界面 | 另一条只读的 Side chat，要 RPC。频道没有这条 | 桌面是自己的转录 | 客户端内 |

## OpenClaw

两套合同分开。BTW 是在会话实际模型上的一次提问，保留运行时行为。频道入站、TUI 和嵌入的本地 TUI 走 BTW。TUI 按设计留在 BTW。Side chat 是控制界面一类客户端上持久的、只读的 RPC 线程。第一个问题才懒惰地从选中会话准备有界的可见上下文。临时的历史失败可以重试，不会当成空会话跑起来。频道没有 RPC 连接，不能用 Side chat。

步骤是：把当前会话拍成背景，包括进行中的主运行提示。再跑一次单独的一次性查询，让模型只答旁问，不恢复、不转向主任务。答案作为活的旁结果交付。主运行不碰。

附在 `/btw` 上的图像，在直接提供商运行时和 Codex 运行时上随旁问送出。包括带 `/btw` 说明的照片，以及频道把被回复消息的媒体当成回复上下文时的那份。其它运行时把图像当可选输入，可以忽略。CLI 运行时收到一条文本，说明省略了几张图。媒体理解已经描述过的图像不再附上，因为描述在主对话提示里，不在旁问里。

完成的直接提供商和运行时旁问，若运行时给出用量，经配置的诊断管道报告。这不把这次交换写进会话历史，也不加进 `/usage cost` 从会话推出的合计。

Codex 会话上，BTW 把活动的 Codex 应用服务器线程分叉成一个短暂的子线程，而不是另打一次提供商调用。OAuth 和原生工具、线程行为留着。分叉线程保持父线程当前的批准政策、沙箱和原生工具面。边界提示说明：边界之前是继承的参考，不是活动指令。只有边界之后的消息是活的。`/btw` 需要已经存在的 Codex 线程，先发一条普通消息。合格的 Codex 旁问可以用和主线程相同的 Gateway shell 工具。取消旁问或超时，会在释放之前停掉旁线程拥有的原生后台终端。主线程终端和 OpenClaw 管理的后台任务保持它们原有的寿命。

CLI 别名在一次性旁问模式里调用所属的 CLI 后端：把打过红的对话上下文种进一次新的 CLI 调用，关掉工具捆绑和可复用会话状态，并加上该后端支持的不恢复、不用工具的旗标。非 CLI 的直接运行时则是一次直接的提供商调用。

它不创建耐久会话，不继续没做完的主任务，不把问答持久化进转录。脱离的 BTW 结果熬不过重载。控制界面的 Side chat 可以在重载后从 Gateway 内存把线程再注水，但会话重置、Gateway 重启、空闲过期或栏上的清除会清掉它。

外部频道把答案当成标清楚的一次性回复，因为 Telegram、WhatsApp、Discord 没有本地的短暂浮层。TUI 画在聊天记录里，和普通回复看得出区别，Enter 或 Esc 关掉。

## Hermes

一条用户消息写入会话，再进入这一轮。没有「拍下当前上下文、另问一句、两边都不落盘」的斜杠。忙碌时的普通正文进队列或转向。回绕要当场确认才会剪已落盘的行。辅助模型做的是标题、压缩和视觉，不是对当前会话的无历史旁问。

## Claude Code

旁问的形状是：不把问答写进主转录，主任务继续。OpenClaw 的频道投递和 Codex 线程分叉是 Gateway 上的适配。客户端里的 `/btw` 没有 `chat.side_result` 和 Side chat 这两条线。
