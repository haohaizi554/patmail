# 修剪

会话修剪从模型上下文里裁掉旧的工具结果。普通对话正文不改写。完整历史还在。客户端修剪在内存里保持一份稳定的投影视图，并记在隐藏的 `openclaw.cache-ttl` 转录标记里，Gateway 重启后可以恢复同一份视图。原来的工具结果条目不改写。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 开关 | `contextPruning.mode` 设成 `cache-ttl` 才做新的修剪轮 | 压缩前把超长旧工具结果换成占位。那是压缩，不是 TTL 修剪 | 工具结果按条、按轮有预算 |
| 直接 Anthropic | API 钥匙走服务端清理。`ttl` 不闸这道路径。更早的投影仍原样重放 | 缓存标记打在副本上 | 请求前收缩 |
| 其它路线 | TTL 到期且用量够高才软裁、再硬清。默认 TTL 5 分钟。失败的请求不刷新时钟 | 占位不按缓存 TTL | 无这道投影标记 |
| 历史 | 投影变了才记增量。最多约 31 个增量或 64 KiB 之前做一次完整检查点 | 旧行标成不活跃，不删原文 | JSONL 仍在 |

## OpenClaw

直接的 Anthropic API 钥匙请求，提供商是 anthropic、API 是 anthropic-messages、端点是默认或 `api.anthropic.com` 时，修剪交给服务端的工具结果清理。OpenClaw 不再开新的客户端修剪轮。服务器在模型看见之前清掉旧结果。同一会话里更早做出的投影，例如代理路线上的，或从转录标记恢复的，仍然原样重放。`ttl` 不闸这道路径。

服务端参数由请求推导，不另加配置项。触发是输入 token 里 `max(50000, 窗口的 30%)`。保留最近 3 次工具使用和它们的结果。至少清掉 `max(12500, 窗口的 5%)`。排除当前和历史上被 `tools.deny` 排除、或不在已配置的 `tools.allow` 里的工具名。工具调用参数保留，不随结果清掉。清理编辑排在压缩编辑之前。调用者已经提供的上下文管理保持不变。客户端的软裁和硬清设置不改变服务器的清理政策。清理从第一个被清的结果起使提示缓存失效。至少清掉那么多，是为了避免一次清得太少、却不值得重写缓存。

Bedrock、Google、Foundry、OAuth、代理、Vertex 和其它按缓存 TTL 合格的路线保持客户端修剪。新的修剪轮要同时过时间和上下文大小。打开 `cache-ttl` 且没设 `ttl` 时，TTL 是 5 分钟。捆绑的 Anthropic 插件另种 `1h`。每次成功的模型请求把内存里的时钟刷新到这次请求的开始时间，包括回合落定之前的工具循环请求。失败的请求不刷新。TTL 没到之前，不做新的修剪。已有投影仍原样重放。

TTL 到了之后，按模型窗口估计总上下文。大约低于 30% 就跳过修剪，TTL 时钟继续走。软裁过大的工具结果：超过 4000 字符的，保留头尾各 1500 字符，中间是省略号。用量仍大约在 50% 或以上，并且至少还有 50000 字符可修剪的工具内容时，硬清那些结果。硬清把每条结果的内容换成占位，默认是 `[Old tool result content cleared]`。可以关掉硬清。然后把每个改过的结果记成会话投影，并重置修剪 TTL 时钟。后续请求复用同一份投影字节，包括工具循环的延续和后来的回合。

TTL 闸的是新的修剪轮，不是先前投影的重放。投影经过 Gateway 重启和空闲会话卸载仍然在，靠转录标记。上一次活动尝试在清理之后释放提示投影。下一次尝试从活动转录恢复。普通的工具结果裁切和已经发送的边界，在投影变化时也会在模型请求前存下，即使 TTL 修剪关着。变化的投影只记增加、更新和删除的条目。最多 31 个增量，或累计增量载荷到达 64 KiB 之前，做一次完整检查点。没变化的投影不加新标记。重启恢复活动分支上最新的检查点和随后的增量，停在一次重置。更老的完整快照标记仍可作为检查点读。已有转录行不需要迁移，也不删除。

## Hermes

压缩的第一步把保护尾之外、超过 200 字符的旧工具结果换成占位，不调用模型。那一步服务的是压缩，不按缓存 TTL 分轮，也不把投影记进隐藏的转录标记。Anthropic 缓存用系统提示加倒数三条非系统消息。

## Claude Code

工具结果在请求前按条和按轮裁。没有「TTL 到期且低于大约 30% 就跳过、硬清占位、投影增量最多 31 或 64 KiB」这一套。完整 JSONL 仍在磁盘上。
