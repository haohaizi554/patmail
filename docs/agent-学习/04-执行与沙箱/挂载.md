# 挂载

一个沙箱 agent 需要主工作区以外的目录时，用 Docker 绑定挂载。每一条是主机目录、容器路径和显式的 `ro` 或 `rw`。容器路径才是 agent 用的路径。主机路径不会自动露出来。`workspaceAccess` 和额外挂载的模式彼此独立。改工作区访问不会把一条额外挂载从只读改成可写，反过来也一样。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 额外目录 | `host:container:ro` 或 `:rw`。全局和按 agent 合并 | 终端后端的挂载。远程可见性在挂载上修 | 工作区就是客户端目录 |
| 共享范围 | `scope: "shared"` 忽略全部按 agent 的 Docker 覆盖，只用全局挂载 | 无这档沙箱范围 | 无 |
| 同一目标 | 最后一条赢，包括来源和只读模式。按 agent 的条目跟在全局后面 | 无 | 无 |
| 危险来源 | 默认挡住系统路径、Docker 套接字、常见凭据根、符号链接父目录和保留目标 | 出口代理和文件权限另计 | 无这道绑定检查 |

## OpenClaw

`scope` 用 `agent` 或 `session` 才能让按 agent 的挂载生效。多个挂载指向同一容器目标时，最后一条赢。托管的只读技能挂载在它们的目标上仍然权威。相对路径和主机路径别名通过选中的容器挂载解析，包括嵌套覆盖。只针对工作区的写、编辑、列举和补丁，仍用容器工作区边界，即使一条显式挂载换掉了它的主机文件夹。额外挂载的读取例外不授予那条边界之外的写。

绑定挂载是支持的多文件夹边界，因为 Docker 用挂载隔离构造容器的文件系统视图，`ro` 和 `rw` 作用于沙箱里的每个进程。这覆盖执行、文件系统工具、子进程和库，不必在每条 OpenClaw 路径上重复路径授权。主机侧的路径允许名单做不到同样完整的边界，因为被允许的 shell 或依赖可以直接碰文件。

`dangerouslyAllowExternalBindSources` 只放行工作区根以外的来源。它不关掉对系统路径、凭据根、Docker 套接字、符号链接父目录和保留目标的检查。校验先规范化来源，再沿着最深的已存在祖先再解析一次，然后重新检查被挡路径和允许根。最终叶子还不存在时，符号链接父目录的逃逸仍然失败关闭。例如 `run-link` 指向 `/var/run` 时，`/workspace/run-link/new-file` 仍按那条路径拒绝。

默认挡住的来源包括 `/etc`、`/proc`、`/sys`、`/dev`、`/root`、`/boot`，Docker 套接字目录 `/run`、`/var/run` 及其 `docker.sock`，以及家目录里常见的凭据根，如 `~/.ssh`、`~/.aws`、`~/.gnupg`。挡住的还有阴影掉保留容器挂载点 `/workspace` 和 `/agent` 的目标。覆盖保留目标要用单独的 `dangerouslyAllowReservedContainerTargets`。允许根用同样的方式规范化。一条在解析符号链接之前看起来在允许名单里的路径，解析之后在外面，仍然拒绝。

敏感挂载除非必须写，用 `:ro`。改完挂载要重建沙箱。沙箱浏览器有自己的 `browser.binds`。设了，包括空数组，就替换浏览器容器的 `docker.binds`。省略时浏览器容器退回 `docker.binds`。

## Hermes

远程后端的文件可见性在挂载上修。没有这一页「额外绑定默认挡住凭据根和符号链接父目录、共享范围忽略按 agent 覆盖」。终端在 docker 或 ssh 里时，屏幕和命令都在那个后端里。

## Claude Code

没有 Gateway 沙箱的绑定挂载表。工作区外的路径取决于这一次权限决定。
