# 工作区访问

沙箱能看见多少工作区，由 `workspaceAccess` 决定。默认 `none`：工具读写的是 `~/.openclaw/sandboxes` 下的隔离工作区，agent 的工作区不暴露。`ro` 把 agent 工作区只读挂到 `/agent`，并关掉写、编辑和补丁。`rw` 可读写挂到 `/workspace`。角色要求必须沙箱时，配置里的 `rw` 被压成 `ro` 并记一条警告。客人仍有自己的沙箱工作区。共享的 agent 工作区只读。这样客人不能共享一块可写的 agent 工作区。`none` 和 `ro` 不变。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 默认 | 不把 agent 工作区暴露给沙箱 | 终端工作目录。沙箱后端是 docker、ssh 等 | 工作区就是这次会话的目录 |
| 只读 | `/agent`。写工具关掉 | 后端自己的挂载 | 计划模式限制写 |
| 角色要求 | `rw` 降为 `ro`。没有角色要求的会话保持配置 | 必须沙箱不是 Hermes 的角色字段 | 无 |
| 托管 worktree | Docker 和 Podman 上是私人 Git 检出。`worktree: true` 授权的是准备源，不是直接碰那个主机目录 | 工作树是会话侧的检出 | 客户端 worktree |

## OpenClaw

没有角色要求沙箱的会话，保持自己配置的工作区访问。角色要求在会话创建时定死。后端起不来就失败关闭，不退回主机。提权绕不过「必须沙箱」。

沙箱会话若拥有托管 worktree，在 Docker 和 Podman 上用私人 Git 检出。注册的项目可以在 agent 配置的工作区之外，当它以 `worktree: true` 被选中。这授权准备源，不授权直接访问那台主机上的目录。任意的外部 `cwd` 和直接的项目绑定仍然受限。

可见的孩子会话在以后的回合里，把托管 worktree 当作沙箱工作区，包括更新之前创建的会话。

技能进沙箱的是同步过去的副本，不读主机上的原路径。工作区访问决定挂载。技能镜像是另一份拷贝，不把 `none` 变成能读主机技能目录。

## Hermes

终端后端决定命令在哪跑。相对路径落在工作目录。绝对路径在没沙箱时可以碰到主机别处。远程文件可见性在挂载上修。没有 `none` / `ro` / `rw` 这三档把 agent 工作区挂进客人，也没有「角色要求时把可读写降成只读」这一条。

## Claude Code

工作区和 worktree 在客户端。计划模式可以在接受前不写。没有 Gateway 沙箱里的 `/agent` 只读挂载。
