# 策略

只读、工具策略和执行批准是代码里的门，不是写在提示里的请求。对 OpenClaw 管理的工具，只读会话去掉 `edit`、`write` 和 `apply_patch`。它的执行工具在调用边界上解析成拒绝。原生运行时可以保留自己的工具面，并另外用原生权限。`full` 需要 `operator.admin`。范围在分发前从请求参数推导。带特权参数的方法仍要特权范围。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 只读 | 变更工具不在目录里。执行在调用边界拒绝 | 工具集决定暴露什么 | 只读或计划模式限制写 |
| 拒绝优先 | 工具策略里拒绝永远赢。提权不能压过拒绝 | 禁用的工具集不出现 | 拒绝是一次决定 |
| 批准绑什么 | 规范命令、工作目录、环境哈希、按内容哈希的文件操作数。漂移就拒绝 | 批准看的是这一次调用 | 允许、询问或拒绝 |
| 没有界面 | 默认拒绝。内联求值和 heredoc 不能被任何回退设置放软 | 没有批准界面时那一次不执行 | 询问若没人答就停 |

## OpenClaw

三道控制管三件不同的事。沙箱决定工具在哪跑。工具策略决定哪些工具存在。拒绝永远赢。日常的策略过滤诊断在调试级别写出配置层和命中的拒绝项。耐久审计账本另记被挡住的结果，不记命中的规则。`tools.elevated` 只给执行留的逃逸口，不能压过拒绝。

执行批准把一次获准的运行绑到规范命令、工作目录、环境哈希，以及按内容哈希的文件操作数。批准之后任何漂移都拒绝。支持的管道和命令链可以用强制的执行计划。OpenClaw 建不起所需执行和文件绑定的 shell 形式或解释器调用，直接拒绝。没有批准界面可达时，默认拒绝。严格情形，内联求值和 heredoc，不能被任何回退设置放软。

工具策略按名字过滤，不按副作用。允许执行同时拒绝写，不会让 shell 命令变成只读。限制副作用是沙箱的事。

## Hermes

中间件可以在批准之前改工具参数。观察者钩子失败打开，除了工具前的拦截和修改，以及变换钩子。危险命令走批准。没有把获准命令绑到环境哈希和文件内容哈希、漂移即拒绝这一页执行计划。操作系统隔离才是对抗模型的边界。策略减少意外，不证明模型不会试。

## Claude Code

`canUseTool` 在执行前给出允许、询问或拒绝。计划模式可以在接受前不写。原生权限和 OpenClaw 管理的工具目录是两套。只读去掉变更工具，是 OpenClaw 对它自己管理的工具的形状。
