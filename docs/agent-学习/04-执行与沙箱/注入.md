# 注入

提示注入不需要公开私聊。只有你能给机器人发消息时，它读到的网页、邮件、附件、粘贴的日志和代码仍可以带对抗性指示。内容本身是威胁面。模型选择是便宜的一层。爆炸半径不能接受的动作，仍靠工具策略、执行批准、沙箱和频道允许名单。提示注入不是认证绕过。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 谁带进来 | 发送者，以及工具读到的不可信正文 | 声明来自网络的工具结果把这一轮剩余助手输出标成不可信 | 工具结果是当时的输出 |
| 沙箱关着 | 隐含的 `host=auto` 落到 Gateway 主机。显式 `host=sandbox` 失败关闭 | 终端默认本机。出口代理另计 | 命令在用户机器上 |
| 解释器 | 允许名单里的解释器若开了严格内联求值，`-c`、`-e` 仍要显式批准。允许名单模式下任何 heredoc 段都要审 | 危险命令走批准 | `canUseTool` |
| 转述 | 只读的读者 agent 交出的摘要仍然不可信 | 叶子可以去掉再委派。摘要不因此变成可信 | 子代理摘要仍是工具输出 |

## OpenClaw

群是支持的部署。用点名门和上下文可见性，让 agent 只读它需要的。真正公开的房间里谁都能贴不可信内容，要额外小心。链接、附件和粘贴的指示默认当敌对。敏感工具放进沙箱。秘密不要放在 agent 够得着的文件里。沙箱默认关。

高风险工具 `exec`、`browser`、`web_fetch`、`web_search` 留给受信任的 agent 或显式允许名单。允许名单里若有 `python`、`node`、`ruby`、`perl`、`php`、`lua`、`osascript`，打开 `tools.exec.strictInlineEval`，内联求值形式仍要显式批准。允许名单模式下，任何 heredoc 段无论引号如何，都要审阅者或显式批准。允许名单上的命令不能靠 heredoc 正文绕过审查。

缩小爆炸半径时，用只读或关掉工具的读者 agent 概括不可信内容，再把摘要交给主 agent。不给跨 agent 历史时，把窄的会话可见性和读者的只发送名单配在一起。全局政策和沙箱的生成会话夹紧仍在。摘要仍不可信。只发送不阻止有权限的接收者泄露数据或执行注入进来的请求。

Gmail 钩子按消息隔离会话上下文，不拿掉目标 agent 的工具或工作区权限。不可信邮件路由到专用读者，并套上按 agent 的沙箱和工具限制。agent 之间默认开着。省略或空的 `allow` 允许每一对。把交接收成显式允许列表，或关掉跨 agent。

OpenResponses 的 URL 输入要收紧文件和图像的 URL 允许名单，并把 `maxUrlParts` 保持低。空的允许名单算未设置。`allowUrl: false` 整个关掉 URL 拉取。秘密不要放进提示。在 Gateway 主机上用环境或配置传递。

自适应的人仍能打破静态基准上分数好看的模型。更小或更旧的模型更容易被带着走。推荐的模型是缓解，不是做完了的问题。

## Hermes

网络来源的工具结果把这一轮剩余的助手消息标成不可信，记忆分类当 `untrusted`。下一条用户消息清除污点。本地读文件不污点。审批和允许名单是启发式。对抗有敌意的模型，边界是操作系统隔离。中间件可以在批准前改工具参数。那不是把不可信网页洗成主人指示。

## Claude Code

工具结果进预算。权限在执行前允许、询问或拒绝。计划模式可以挡住写。没有「沙箱关着时隐含主机、显式沙箱失败关闭」这一对 exec 主机。网页和文件内容同样不要当成用户的新指令。
