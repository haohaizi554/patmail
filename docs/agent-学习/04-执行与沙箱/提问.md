# 提问

结构化提问只在主会话里。子代理没有这个工具。它用来问真正属于人的决定，不用来确认模型自己可以从代码或合理默认里推出来的事。自由文本的「好」不授权配置变更。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 工具 | `ask_user`，一到三个问题。仅主会话 | `clarify`。网关在忙碌时仍要能当场批准 | 客户端的询问对话框 |
| 表面 | 控制界面、TUI、Telegram 按钮、Discord、Slack、Mattermost | 桌面和 TUI 的服务端请求：澄清、提权、秘密 | 权限询问和计划审批 |
| 跳过 | 跳过或过期的问题保留原文和结局 | 拒绝或超时留在工具结果里 | 拒绝可以停整轮 |
| 和批准 | 提问不是 `/approve`。批准用卡片或明确的 allow-once | 批准命令绕过两道忙碌守卫 | `canUseTool` 的询问 |

## OpenClaw

`ask_user` 让 agent 问人一到三个结构化问题并等待。主会话才有这个工具。子代理和其它非主运行拿不到它。

控制界面把问题面板停在作曲家上方。多题一次显示一题。答完后面板关闭，聊天里留下问题和答案的紧凑摘要。跳过或过期的问题保留措辞和结局。在待定问题之间切换时，已选的选项和打的字都保留，即使打的字和一个选项的标签相同。

TUI 在网关模式和本地模式都显示问题。方向键或数字选择，其它用来打字，可以跳过。多选先切换再确认。多题逐题前进。Esc 回到作曲家而不回答，之后用 `/question` 重新打开。

Telegram 对单题单选把每个选项画成通栏按钮。其它切换到回复输入，不立刻结束问题。Discord、Slack 和 Mattermost 对单题单选使用原生按钮。Mattermost 在接受的那一次点击上收回提示。问题在别处结束时，按钮留着，直到有人点了才被告知已经答过。

这和执行批准分开。委托的配置变更要批准卡或 `/approve <id> allow-once|deny`。一句「好」不授权。提问工具返回的是人对那几个问题的答案，成为工具结果，然后主会话继续。

OpenClaw 总是提供自由文本的「其它」。agent 不要自己在选项列表里再加一个 Other。跳过在所有表面上都有，并且拒绝整份提示。不要用提问回答凭据。agent 要 API 钥匙时用秘密工具。打码提示把值存下来，不进聊天、转录或模型上下文。

单独附着的 MCP 客户端提出的问题，不带 OpenClaw 运行的创建者绑定。那些要用控制界面、TUI 或原生应用里的问题控件回答，不用普通的频道消息。带 `operator.sessions.write` 的客人可以回答自己创建的会话里、自己获准的 agent 运行提出的普通问题。控制界面在重连后恢复那些待定问题。能进另一个人的会话，并不因此看见或能够回答他们的问题。秘密、管理和无会话的问题保持原有的特权要求。回答一个问题不给 agent 额外权限。

iOS、macOS 和 Android 用内联卡片。多题堆在一起。TUI 在聊天里留一条紧凑的解决通知。其它平台保留问题到答案的摘要，不按时间清掉。

## Hermes

澄清是模型工具，在需要人补充时发出。桌面和 TUI 通过服务端请求把它画成对话框：澄清、提权、秘密、保险库。请求挡住 agent 线程，直到同一 id 的响应回来，或被取消。重连的客户端用仍开着的请求列表把问题再画出来。

网关忙碌时，`/approve` 和 `/deny` 必须同时绕过适配器队列和运行器拦截，当场处理。普通正文进队列。澄清若被排进普通正文，人的答案会晚于工具正在等的那一轮。

秘密请求走打码输入，不把钥匙回显进转录。保险库助手不能在插件的 `fetch` 里交互提问。提问属于回合，不属于启动时的秘密源。

## Claude Code

权限询问是 `canUseTool` 的询问分支。计划模式在执行写之前要人接受计划。这些是客户端对话框，不是主会话专有的三题工具。子代理有自己的工具权限。用户拒绝可以中止整轮。

没有「只有主会话能问人、子代理必须自己假设」这条 OpenClaw 规则写在还原树的工具目录里。子代理的问题若要回到人，走父会话的工具结果和后续回合。
