# 审批

三家都把「工具在不在名单里」和「这一次调用能不能执行」分成两道门。名单决定模型看不看得到。审批决定看见了之后，这一次 argv、路径或副作用过不过。审批只能把策略收紧。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 第一道门 | 工具策略、沙箱、提权 | toolset 和 `check_fn` | 工具是否暴露给这一轮 |
| 第二道门 | 主机 exec：策略、允许名单、可选的人 | `tools/approval.py`，危险命令等用户 | `canUseTool`：allow、ask、deny |
| 收紧方向 | 审批默认不能松于 `tools.exec` | 插件 `pre_tool_call` 可以挡住，不能把危险命令改成已批准 | 模式改变默认倾向，取消不了必须询问的工具 |
| 人没在时 | 该问的请求按 ask 回退，默认拒绝 | 网关把问题送回渠道 | `dontAsk` 把要问的改成拒绝 |
| 拒绝之后 | 拒绝的执行仍是失败 | 工具错误写回，模型可以换路 | 用户拒绝可中止整轮；策略拒绝是工具错误 |

## OpenClaw

`tools.exec.host` 选命令在哪跑。`tools.exec.mode` 选怎么批。模式和底层的 security / ask 是一对：

| 模式 | 行为 |
|---|---|
| `deny` | 不跑主机命令 |
| `allowlist` | 只跑名单内的，名单外静默拒绝 |
| `ask` | 名单内直接跑，名单外问人 |
| `auto` | 和 `ask` 同一对设置，名单外先交给审查者：允许、拒绝或再问人 |
| `full` | 跳过普通策略提示 |

`auto` 里审查者允许一次低或中风险执行。拒绝把理由还给 agent，让它换一条更安全的路或去问用户。审查失败也问人。网关上连续三次审查拒绝会升级到人。`ask` 和 `auto` 的差别是有没有这个审查者。

审批叠在工具策略和提权之上。有效策略取 `tools.exec` 和审批默认值里更严的一边。审批字段缺省时用 `tools.exec` 的值。执行主机本地若写了 `ask: "always"`，即使会话要求 `on-miss` 也继续问。节点未配置时用和 Gateway 一样的 `full` / `off` 基线，但派出前仍查目标策略：调用方的 allowlist 或 off 挡不住目标上的 `ask: always`。

Gateway 上要靠批准才执行的命令，在审查前绑定每个已解析命令段的可执行文件，启动前再查一次。受保护的可执行文件只认真实路径。可写的再加内容哈希。等待期间解析变了，包括 `PATH` 上出现了更早的新文件，就拒绝。shell 脚本和解释器直接跑的那个本地文件若在批准后、执行前变了，也拒绝。认不出恰好一个具体本地文件时，不发这次批准，而不是假装覆盖了所有加载路径。远程等人批准时，这套绑定盖不住壳里面的可执行文件。

POSIX 登录壳或交互壳在 `auto` 模式下跳过审查者，绑定成功后改问人。它们的启动文件不在操作数绑定里。`python -c`、`node -e`、`sed` 程序这类内联求值，只有打开 `strictInlineEval` 才强制审查或明示批准，默认关。`mode: full` 本身不绕过这道检查。全权限会话且 security 为 full、ask 为 off 时，可以跳过主机批准路径。把 full 会话收紧成要问，路径就回来。

伴侣应用不在时，本来要弹窗的请求走 ask 回退，默认拒绝。审批降低的是误执行，不是按用户划分的认证边界，也不是文件系统只读。批准之后，命令按所选主机或沙箱的文件权限去改文件。

节点上的批准绑定当时的工作目录、精确 argv、存在时的环境绑定，以及可固定的可执行路径。macOS 上节点服务把 `system.run` 经本地 IPC 交给应用，由应用在界面上下文里执行。

工具在不在和命令批不批是两件事。`messaging` 配置可以拿掉 `exec`，即使批准文件允许命令。`openclaw exec-policy show` 能看本地排除和策略来源；带 `--session` 只预览已存会话设置。预览里有，不保证这次能执行。

Codex app-server 上 `mode: auto` 把批准政策推向按请求审查、审查者自动、沙箱为工作区可写，并压过会变成「永不询问加完全访问」的旧组合。`deny` 和 `allowlist` 直接挡住 Codex 在本机的执行。

排队中的 Gateway 输入保持原来的操作者和权限上限。转向和收集不能借用更宽的发送者。

## Hermes

模型看见的工具来自本轮 toolset 减去 `check_fn` 失败的项。`check_fn` 回答的是密钥或功能是否够得着，结果按 Hermes home 做短时缓存。一个进程服务多个 profile 时，探针必须走 `get_secret`，不能读进程环境，否则次要 profile 会拿到启动 profile 的答案。

真正执行前还有插件 `pre_tool_call`，然后是 `tools/approval.py`。危险命令等用户。执行后是 `post_tool_call`。多个工具调用默认线程池并发，结果按原顺序写回。会和人交互的工具改回串行，避免两个澄清同时挂起。

未知工具三次之后停。调用前的拦截是终态。调用后的钩子可以要求停轮。失败的工具结果保持失败，收尾文案不能把它说成成功。

网关在 agent 忙碌时还有两道消息守卫：适配器把这个会话的新消息放进待处理队列；运行器在送到 `interrupt` 之前先认 `/stop`、`/new`、`/queue`、`/status`、`/approve`、`/deny`。新的、必须在批准对话框挂起时仍能到达的命令，要同时绕过这两道，并且当场分发。放进后台处理会和会话生命周期赛跑。

profile 之间的秘密不借用 `os.environ`。多路复用打开后，环境变量里是启动 profile 的值。次要 profile 的 `.env` 只在它自己的 secret scope 里。范围已安装且多路复用开着时，scope 里没有的项返回默认值，不回退到环境变量。

## Claude Code

`canUseTool` 对每次调用给出 allow、ask 或 deny。模式是默认倾向：

| 模式 | 倾向 |
|---|---|
| `default` | 多数写操作和命令要问 |
| `plan` | 先计划。退出计划模式本身可以要求人在场 |
| `acceptEdits` | 工作区内的安全编辑可以自动过。工作区外和命令仍常问 |
| `bypassPermissions` | 多数自动过。标成必须人参与的工具、内容级规则和安全检查仍问 |
| `dontAsk` | 本来要问的改成拒绝 |

用户拒绝常用会要求停下的文案，并可能中止整轮，后续工具不再跑。策略拒绝写成工具错误，模型可以换一条路，不能绕过这道拒绝。子代理用另一套拒绝文案，因为它不能替主会话做主。

Bash 的兄弟调用在一个失败时可以中止其余兄弟，这一轮不因此结束。模型回退时丢掉旧执行器上的 `tool_use` id，避免新请求带上已经作废的调用。

只读工具标了可并发才并行。写文件、改笔记本和有副作用的命令独占。权限判断发生在执行前，不依赖工具自己记得先问。

停止钩子是第三道，发生在模型想结束的时候。`continue: false` 硬停，不再请求模型。exit 2 或 `decision: block` 把反馈塞成用户消息再跑一轮。`stop_hook_active` 防止钩子触发的那一轮再进钩子。子代理的停止钩子不跑主线程的记忆抽取。
