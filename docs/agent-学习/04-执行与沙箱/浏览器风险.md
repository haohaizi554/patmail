# 浏览器风险

打开浏览器控制，就是给模型一个真浏览器。那个配置里若已有登录会话，模型就能碰到那些账户和数据。浏览器配置按敏感状态对待。默认用名为 `openclaw` 的专用配置，不用每天开车的个人配置。沙箱 agent 除非信任，否则关掉主机上的浏览器控制。远程 Gateway 上的浏览器控制，等于对那个配置能到达的一切的操作者访问。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 环回 API | 只认共享秘密。不消费可信反代或 Tailscale Serve 的身份头 | CDP 监督器按任务一条连接 | 无浏览器控制端口 |
| 中继 | v2 从不发送持久的扩展中继钥匙。证明绑协议、角色、传输、方法、资源和实例。同一或另一套接字上的重放失败 | 无这道扩展中继 | 无 |
| 私网 | 默认挡住。`*.example.com` 不挡住顶点 `example.com` | 出口代理和允许名单另计 | 抓取有自己的网络守卫 |
| 拦截 | 页面路由是请求级拦截，不是网络防火墙。完整挡住要主人侧的出站隔离或执行政策的代理 | 子进程环境是允许名单 | 无 |

## OpenClaw

下载当不可信输入。能隔离就用单独的下载目录。agent 配置里尽量关掉浏览器同步和密码管理器。Gateway 和节点主机留在 tailnet。不要把浏览器控制端口暴露到局域网或公网。不需要时代理路由设成 `off`。Chrome MCP 的已有会话模式并不更安全。它能以你的身份做那个主机 Chrome 配置能到达的事。

浏览器中继认证 v2 从不发送持久的扩展中继钥匙。扩展和外部 CDP 客户端在返回短时、一次性、绑连接的 HMAC 证明之前，核对签过名的服务器挑战。证明绑协议版本、角色、传输、方法、资源、流、配置和中继实例。在同一或另一套接字上重放都失败。`allowLegacyAuth` 默认真，只给一个迁移窗口，暂时接受旧的 Bearer、Basic 和令牌子协议客户端。更新全部中继客户端之后设成假。v2 客户端在证明失败或不支持的响应之后从不降级。独立的环回浏览器 HTTP API 只用共享秘密：Gateway 令牌、`x-openclaw-password`，或用配置口令的 HTTP Basic。Tailscale Serve 身份头和可信反代模式不认证这道独立 API。浏览器控制开着却没有共享秘密时，启动会自动生成并持久化一份凭据。认证模式是 `none` 时生成令牌。是可信反代时生成口令，经 `gateway.auth.password` 持久化，让进程外的环回客户端能解析。该模式已经有显式字符串凭据，或模式是 `password` 时，跳过自动生成。要自己掌握的稳定秘密，就显式配置令牌或口令。远程 CDP 优先短时令牌和加密端点。长寿命令牌不要直接写进配置文件。URL 和令牌当秘密。

Chrome 扩展配对把访问模式存在扩展自己的 Chrome 存储里，不在 Gateway 配置里。全部标签暴露那个 Chrome 配置里每一个合格的普通标签，除了会话暂停的标签。选定标签用 OpenClaw 标签组当访问控制。已有配对迁到选定标签。新的个人浏览器配对推荐全部标签。隐身和 Chrome 内部页在两种模式下都排除。

自动的 Chrome 扩展设置用源站锁定的原生消息清单，从 Chrome 配置元数据里精确的未打包扩展路径发现。一次性宿主只接受带新鲜随机数的带版本请求，输入上限 4 KiB，校验 Chrome 提供的源站，只返回本地拥有的配对。它从不转移远程 Gateway 钥匙。原生宿主的清单、启动器和状态输出不含配对钥匙。OpenClaw 拒绝符号链接、不安全的所有权或模式、通配源站，以及用同一宿主名的外来登记。Windows 在可执行的原生宿主路径得到支持之前，用手动配对回退。

Gateway 离浏览器很远时，在浏览器那台机器上跑节点宿主，让 Gateway 代理浏览器动作。节点配对按管理员访问对待。Gateway 和节点宿主放在同一 tailnet。不要把中继或控制端口暴露到局域网、公网或 Tailscale Funnel。

私网和内部目的地默认挡住，除非显式打开 `dangerouslyAllowPrivateNetwork`。旧别名 `allowPrivateNetwork` 仍接受。`blockedHostnames` 在 DNS 和任何允许规则之前拒绝精确主机和通配子域，包括私网例外。`*.example.com` 不挡住顶点 `example.com`。要挡整域，两个都写。空的或缺失的列表不增加拒绝。守卫的抓取，包括重定向，用同一套策略。严格模式下，通配感知的 `allowedHostnames` 用于 `*.example.com` 这类模式，以及精确主机例外，包括本来会被挡住的 `localhost`。

直接导航请求做预检。动作期间和有界的动作后宽限里，受守卫的 Playwright 交互在 HTTP 请求字节之前拦截政策拒绝的顶层和子帧文档加载，然后尽力再查最终的 `http(s)` URL。每次新启动托管 Chrome 之前，OpenClaw 尽力关掉网络预测，压住 Chromium 对那些被拒加载的推测性预连接。这是纵深，不是政策边界。跨控制服务重启复用的浏览器，以及其它浏览器后端，可能没有这份加固。页面路由仍是请求级拦截，不是网络防火墙。重定向跳、弹出窗口的第一个请求、Service Worker 流量、有界守卫窗口之后才跑的页面代码，以及一些后台或子资源路径，可以绕过它。最终 URL 检查仍是检测和隔离。完整阻止要主人侧的出站隔离，或执行政策的代理。

## Hermes

浏览器监督器处理对话框和跨源 iframe。默认配置和每天的浏览器分开，除非去附着。没有「环回控制 API 不吃 Tailscale 身份头、中继证明绑实例且重放失败、通配不挡顶点域名」这一页。访客 iframe 不自己打开系统浏览器。

## Claude Code

抓取和搜索不是带登录配置的浏览器控制。没有扩展中继的一次性证明，也没有默认挡住私网的浏览器 SSRF 表。
