# 权限模式

一个会话可以收紧文件系统边界，并决定命令升级由谁审。这和沙箱、工具允许名单是三道不同的门。`full` 仍受已要求的工作区根和沙箱约束。自由文本的「好」不构成批准。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 模式 | 只读、守卫、工作区、完全。边界是记录的 `sessionRoot` | 终端后端、批准门、工具策略。无同名四档 | 计划模式限制写。`canUseTool` 允许、询问、拒绝 |
| 谁审命令 | 只读直接拒绝。守卫在允许名单之后问人。工作区先由模型审，再可问人 | 危险模式检测是启发式。合作失误，不是对抗边界 | 每次调用前询问或按规则放行 |
| 工作树 | 检出是根。嵌套目录仍是运行时的当前目录 | 终端的 cwd 是配置或进程的当前目录 | worktree 是隔离检出 |
| 中途切换 | 原生运行时刷新工具策略，不重启对话。Codex 打断当前轮并停后台终端 | 改变系统提示的命令默认下一会话 | 计划模式在会话内切换 |

## OpenClaw

四种模式。只读：只能读 `sessionRoot` 之下，托管的变更工具不出现，执行拒绝。守卫：根内可读写，允许名单的快路径之后由人审执行升级。工作区：根内可读写，由模型审执行，结论是允许、拒绝或问人。完全：文件系统不设这道限制，执行升级不再审。完全要 `operator.admin`。其余要 `operator.write`。

没有记录根时，边界是所选 agent 的规范工作区。显式工作目录和托管工作树各自钉住会话根。工作树会话用检出作为根。嵌套的工作目录仍是运行时当前目录，相对路径从那里起，文件系统收纳覆盖整棵检出。

文件工具认识受信任根和工作目录的别名，包括用这些别名写成的绝对路径。这不扩大边界。无关的外部符号链接指进来仍拒绝。逃出根的符号链接和 `symlink/..` 拒绝。只读模式下托管的变更工具仍然不出现。

新会话在没指定模式时继承全局或该 agent 的工具和执行策略。执行设置和文件工具独立。`apply_patch` 默认仍收在工作区内，即使执行模式是完全。创建工作树只钉工作目录，不选权限模式。已保存的显式模式保持不变。

控制界面的「默认」标签在能对应到一种会话模式时写成默认加括号，例如执行模式是询问、又没有更严的主机批准政策时显示守卫。允许名单专用、不等价的安全与询问组合、以及沙箱可能作用到会话上的 agent，保持朴素的「默认」，因为有效政策不能在 agent 范围说死。这是展示，不是授权决定。选默认会清掉会话覆盖，不把展示出来的模式写进会话。

工作区模式里，模型审拒绝会把理由还给 agent，不建人的批准卡。agent 必须换一条实质更安全的路或去问人，不能绕过拒绝。审的结论是问、或审失败，才请求人。网关审连续拒绝三次也升级到人。已有的命令绑定和显式的人批要求仍然有效。

靠批准的命令在审之前绑定每一个解析后的可执行段，启动前再查一次。受保护的可执行文件只用解析后的真实路径。可写的还用内容哈希。POSIX 的登录或交互 shell 包装在绑定成功时跳过自动审，改问人。它们隐式的启动文件在操作数绑定之外。

记忆刷写只暴露读和追加写。控制界面的文件预览遵守这道文件系统边界。打开根以外的文件还要求当前有权在该会话里开一轮。

普通 agent 经 `openclaw` 工具委托持久变更时，主机把请求这一轮的有效权限用到那一次提议上。完全访问自动应用，包括完全来自配置默认而不是显式会话模式。消息渠道上的受限运行向请求的那个聊天要批准：渠道有原生卡就用卡，否则用 `/approve <id> allow-once|deny`。自由文本的「好」从不授权。工具一直等到人的决定和应用结果。停掉这一轮会取消待定批准。过后的批准不能复活这一轮。

独立的文件系统和沙箱边界、工具策略、系统 agent 的操作限制仍然适用。主机还检查请求这一轮和已核对的推理路线仍然有效。交互式安装向导和 agent 交接仍要直接的操作者会话。

聊天里改模式时，选择器先显示图标并暂时挡住同会话的另一次选择。别的客户端在 Gateway 发布更新后看见。失败则和权威会话状态对齐。Codex：打断当前原生轮，停掉它的后台终端，同一条对话用新权限继续，并留一条内部的权限变更说明。不重置对话，不重放原来的请求。OpenClaw 原生运行时：刷新活动工具策略，不重启对话。之后的工具调用用新权限。

原生 harness 可以在自己的权限控制下保留自己的工具面。上面的可见性和执行规则描述的是 OpenClaw 托管的工具。

## Hermes

批准门、终端后端和工具允许名单分开。批准门抓常见的破坏性 shell 模式，在合作模式下拦失误。shell 是图灵完备的，拒绝名单在结构上不完整。终端后端困住 shell 和建立在 shell 上的文件工具。代码执行、MCP、插件和技能导入仍在进程里，除非整棵进程树进了容器。

危险命令的检测不是这四种会话模式。没有「工作区模式由模型先审三次再升级给人」的会话档。人的批准是明确的允许或拒绝，不是闲聊里的一句肯定。

## Claude Code

`canUseTool` 对每次工具调用给出允许、询问或拒绝。计划模式在计划被接受前限制写和执行。worktree 把工作放进隔离检出。拒绝写进配对的工具结果，用户拒绝可以停整轮。没有 OpenClaw 的四档会话根，也没有「连续三次模型拒绝再升级」这道计数。
