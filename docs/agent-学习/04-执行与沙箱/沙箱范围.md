# 沙箱范围

沙箱包住工具执行：`exec`、`ls`、读、写、编辑、补丁、进程，以及可选的沙箱浏览器。Gateway 进程本身不进沙箱。提权只影响执行，而且绕不过「创建者角色要求必须沙箱」。沙箱关着时，提权什么都不改变，因为执行本来就在主机上。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 列目录 | `ls` 不授予 shell。整名、JSON 引用。还有下一页时给文件名游标。不返回半个文件名 | `search_files` 或终端。分页不是工具合同 | 客户端列目录 |
| 自定义后端 | 没有 `readDirectory` 就藏起 `ls`。不退回读主机文件系统 | 后端缺失是工具不可用 | 无这层桥 |
| 留在主机 | Gateway 进程。显式提权的执行，且角色不要求沙箱 | 网关和代理进程 | 客户端进程 |
| 策略和地点 | 工具策略决定工具在不在。沙箱决定在哪跑。两者分开 | 工具集和终端后端分开 | 权限模式 |

## OpenClaw

目录发现用 `ls`，不因此获得 shell 执行。它返回完整的、JSON 引用的名字。还有一页时带文件名游标。继续时用同一目录和返回的 `after`。每一页装进所选模型的工具结果预算。不返回半截文件名。

自定义后端可以提供 `SandboxFsBridge.readDirectory`，从它允许的文件系统根返回名字和是否目录。对旧插件这个方法可选。没有它，`ls` 隐藏。OpenClaw 不退回去读主机文件系统。

不进沙箱的是 Gateway 进程，以及经 `tools.elevated` 明确允许跑在普通沙箱之外的工具。提权执行走配置的逃逸路径，默认是 Gateway，执行目标是节点时是节点。创建者角色要求沙箱的会话，提权逃不出去。沙箱关着时，执行已经在主机上，提权不改变这件事。

工具策略按名字过滤，不按副作用。允许 `exec` 同时拒绝 `write`，不会让 shell 变成只读。限制副作用是沙箱的责任。

## Hermes

终端后端决定命令在哪执行。文件工具在工作目录里。远程可见性在挂载上修，不靠多一个列目录工具去读主机。没有「列目录不授予 shell、缺桥就隐藏而不是读主机」这一条沙箱文件系统桥。提权在 Hermes 里不是 OpenClaw 的 `tools.elevated` 逃逸路径。

## Claude Code

工具在客户端执行。权限决定这一次能不能跑。没有 Gateway 留在沙箱外面、工具进沙箱这一划分。
