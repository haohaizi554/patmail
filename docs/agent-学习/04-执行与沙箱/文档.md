# 文档

`read_file` 把常见文档转成 Markdown 再按偏移阅读。笔记本、Word 和 Excel 用标准库，始终可用。PDF 和旧版 Office 靠可选转换器，允许懒安装时才在第一次使用时装上。超过 50 MB 的文档拒绝。SQLite 只给结构预览，并且只读打开。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 阅读 | `pdf` 和媒体工具走任务工作目录和批准的根 | `read_file` 转换后走普通的偏移窗口 | 读文件工具。PDF 未必内置转换 |
| 数据库 | 不把任意 `.db` preview 成五张表 | 只读、不可变打开。每表的建表语句、行数和前五行 | 无这条预览 |
| 远程 | 沙箱文件系统里读 | 字节传到主机侧再转换。沙箱里的文档和本地读起来一样 | 在工作区里读 |
| 失败 | 越界和符号链接拒绝 | 不是 SQLite 的 `.db` 按真实原因拒绝。懒安装关掉时，可选格式退回二进制守卫 | 权限拒绝是工具结果 |

## Hermes

笔记本用标准库。docx 和 xlsx 用标准库。SQLite 的 `.db`、`.sqlite`、`.sqlite3` 用标准库。PDF、旧版 Office、OpenDocument、RTF 和 epub 用可选的 `firecrawl-anydoc`，在 `security.allow_lazy_installs` 允许时第一次使用才装。没有它，三种标准库格式仍可用，其余退回二进制文件守卫。

SQLite 渲染的是结构，不是整库转储：每张表的 `CREATE`、行数和前五行，加上索引、视图和触发器列表。打开方式是只读并且不可变，所以另一个进程正打开的活库也能读，不加锁。再往下查用终端里的 `sqlite3`。魔数不像 SQLite 的 `.db` 按真实原因拒绝。Hermes 自己的读取拒绝名单在提取之前生效，家目录下受保护的存储仍然读不了。

返回的范围里若有成对的合并冲突标记，结果带上 `conflict_blocks` 计数，并提示先解决再在旁边编辑。字符串或测试夹具里单独一个标记不算。

转换结果是 Markdown，走 `read_file` 平常的偏移和限长。东亚读音指南不是提取出来的值。单元格里是「東京」、读音是「トウキョウ」时，读到的是「東京」。超过 50 MB 的文档拒绝，免得一次工具回合没有上界。

笔记本单元格输出超过 20000 字符就截断。截断标记里带一条 `jq` 命令，点出笔记本经过 shell 引用的完整路径，以便从原文件把省略的输出取回来。

远程终端后端把文件字节传过边界，在主机侧转换。Docker、Modal 或 SSH 里的文档和本地读到的是同一种文本。转换不在沙箱里执行文档里的宏。

这条阅读路径不绕过路径策略。受保护的库、秘密文件和会话库仍被拒绝名单挡住。把 `state.db` 当成普通 SQLite 来预览，不该发生。

## OpenClaw

`pdf` 和生成工具的参考文件使用任务工作目录。工作区根和沙箱决定能不能读。符号链接逃出根会被拒绝。没有「所有文档都走 read_file、SQLite 只预览五行、50 MB 一刀切」这份同一合同。媒体理解是另一条工具。

## Claude Code

读文件把路径内容放进工具结果，并受每条、每轮的字符预算。PDF 若没有转换，模型看见的是二进制拒绝或另一工具的输出。没有只读不可变打开活 SQLite 的预览合同。大结果落到 `tool-results/`。
