# 代码执行

模型要跑一段程序时，三家给的表面不一样。OpenClaw 的代码模式把几十个工具 schema 收成一段 JavaScript。Hermes 的代码执行是会话里的内核。Claude Code 的 Bash 就是用户机器上的命令，由权限门逐次决定。名字里的 `exec` 在代码模式里不是 shell。

## 对照

| | OpenClaw 代码模式 | Hermes `execute_code` | Claude Code Bash |
|---|---|---|---|
| 模型写什么 | JSON 里的 JavaScript，不是 shell | 在代码执行工具里写程序 | 命令行 |
| 工具 schema | 多数收成 guest 里的异步函数。模型只看见 `exec` 和 `wait` | 代码执行是工具集里的一项，和终端并列 | Bash、PowerShell、REPL 各是工具 |
| 安全边界 | Node 的 `vm` 不是边界。QuickJS 才是加固的 guest。批准仍在 Gateway | 内核按会话隔离。子代理的内核单独钉住 | `canUseTool` 在执行前 |
| 失败时 | 执行器不可用就失败，不退回把全部工具 schema 摊开 | 结果是工具错误，不写成成功 | 拒绝可中止整轮，或写成工具错误 |

## OpenClaw

代码模式开着时，模型不再看见每一个已启用工具的 schema。它看见 `exec`、`wait`，以及结果过不了 JSON guest 桥的少数直接工具，例如 `computer` 或原生视觉的 `view_image`。其余合格的非 MCP 工具收成 guest 程序里的异步全局函数。MCP 留在 `MCP` 命名空间，用 `catalog.search` 按任务找。

`exec` 的载荷是 `{ title, code }`。`command` 是 `code` 的别名，不是 shell 命令。认得出的 shell 命令在进 guest 之前就拒绝，并给出 `invalid_input`。TypeScript 风格的签名只用来描述工具。真正执行的格子是不带类型标注的 JavaScript。

`exec` 说明里有一份有界的速查：最终可调用的名字、紧凑的输入提示、受信任工具声明的输出提示。不放描述、完整 schema、MCP 条目和溢出的条目。输入提示可以保留整数和数值范围的注释。这些注释不改变真正的校验。完整 schema 在 `describe()` 里。句柄不暴露内部目录 id。调用走和普通回合相同的策略、批准、钩子和遥测。

`wait` 只在外层结果是 `status: "waiting"` 时使用，用顶层的 `runId`。格子里返回的后台 shell 有自己的 `sessionId`，那不是代码模式的 run id。要用进程工具再开一次 `exec` 去看它。

JavaScript 不在 Gateway 主事件循环里跑。Node 是默认执行器，在 worker 线程里用 `node:vm`，适合受信任执行，不是安全边界。随包的 QuickJS 提供加固的 guest 隔离。两边用同一座工具桥，权限、批准和会话所有权留在 Gateway。

未写 `tools.codeMode` 时用 `auto`，只对标记为偏好代码模式的模型开启。写成对象但没有 `enabled`、或显式 `false`，都是关。agent 和模型上的覆盖优先。执行器不可用时这次运行失败，不静默退回「把所有工具 schema 都给模型」。

这和 Codex 里同名的代码模式不是一个实现。Codex 的 `exec` 是自由语法，可带 `// @exec:` 一行，跑在进程内的 V8。OpenClaw 的 `exec` 是 JSON 载荷，跑在 Node 或 QuickJS。两者都不是 shell。

代码模式只改模型看见的编排面。它不替换工具、插件、MCP、认证、批准、渠道和模型选择。文件工具的规划 worker 只做匹配和 diff。真正改文件仍由调用方在规划之后再核对权限和取消。算力池的排队和内存帽见运行时笔记。

## Hermes

终端和代码执行是两套工具。终端跑命令，后端可以是本机、Docker、SSH、Daytona、Modal、Singularity 或 Vercel Sandbox。代码执行有自己的内核，按会话记。一个回合里的多个代码调用可以留在同一个内核里，所以变量还在。

子代理的内核键是 `<父主人>::child::<子会话 id>`。孩子在跑时这条内核钉在 LRU 上限之外，不会被别的会话挤掉。`cleanup` 时由 `shutdown_kernels_for_delegated_child` 释放。结束了的孩子不能继续占着名额。

`leaf` 子代理去掉再委派、澄清、记忆、发消息和 cron，代码执行保留。所以窄的孩子仍能算，但不能再派人或改记忆。

环境在拉起进程前就按目标 profile 拼好。不把启动 profile 的 `.env` 复制进孩子。后台进程的终止先打父进程，见沙箱笔记。

输出若声明了 schema 而对不上，委派路径重试一次后仍把原文留下并标 `schema_valid: false`。代码工具自己的失败同样是失败结果，收尾文案不能把它说成已经跑通。

## Claude Code

Bash、PowerShell 和 REPL 是三件工具。模型写的是命令或 REPL 输入，不是一份把其它工具收成函数的 JavaScript 目录。只读工具可以并行。Bash 有副作用时独占。一个兄弟失败可以停掉其余兄弟，这一轮还可以继续，用已经拿到的结果做下一轮决定。

工作区外的命令和写操作在默认权限下要问。`acceptEdits` 可以放过工作区内的安全编辑，命令仍常问。内联的 `python -c` 在 OpenClaw 里要额外打开严格求值才强制审查。Claude Code 里同一次调用直接进 `canUseTool`，没有第二套「这是代码模式所以 shell 被拒绝」的别名。

没有「执行器缺失就禁止暴露全部工具」的开关，因为工具表本来就是客户端编译进去的。MCP 工具在两轮之间刷新，不在一次 Bash 里面临时变成新的 schema。
