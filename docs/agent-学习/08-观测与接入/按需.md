# 按需

选中某个提供商的模型或嵌入请求时，OpenClaw 可以先看健康端点，没起来就拉起子进程，等到就绪再发请求。空闲够久再停。它不安装 launchd、systemd 或 Docker。服务器是第一个需要它的那个 OpenClaw 进程的普通子进程。另一个进程已经在同一健康地址上有健康服务时，这一进程复用，但不收养。每个进程只管理自己启动的孩子。只有 PID 消失，不等于可以换一台新的。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 何时启动 | 请求解析到带 `localService` 的提供商 | 进程起来时加载配置的端点。没有这页上的空闲停机 | 客户端去连配置的端点 |
| 重复启动 | 同一提供商、同一命令、参数和环境串行。并发的聊天和嵌入不各起一台 | 无 | 无 |
| 停机 | `idleStopMs` 从最后一条在途请求空闲之后算。关服务时会等已经在进行的空闲停机 | 终端后台按会话回收 | 随客户端 |
| 日志 | 子进程输出尾巴有界且打红。配置的环境值不打印 | 秘密不进普通日志的合同另计 | 本机 |

## OpenClaw

顺序是：请求解析到已配置的提供商。有 `localService` 就查 `healthUrl`。成功就用已经在跑的服务。失败就用 `command` 和 `args` 拉起。轮询健康端点直到 `readyTimeoutMs`。请求再走正常的模型或嵌入传输。若是 OpenClaw 自己拉起的，并且设了 `idleStopMs`，最后一条在途请求空闲那么久之后停进程。

每条请求持有自己的租约，直到响应处理完成。空闲停机等所有在途的模型和嵌入请求。配置的提供商别名保持区分：两个别名可以指向不同的 GPU 主机，不会塌成同一个 Ollama、LM Studio 或 OpenAI 兼容适配器 id。

关闭本机服务时，会等待已经在进行的空闲停机。同一服务的新请求先等那次停止，再取得替换。停机错误保持可见。之后的请求在启动替换之前，再检查自己拥有的进程。停机完成要求孩子和它的输出流关闭，并且挂起的树终止做完。

官方 llama.cpp 提供商自动生成这个形状。引导安装钉住并校验过的 `llama-server`，写下绝对命令和路由预设，选一个空闲的环回端口，存下 `baseUrl` 和 `localService`。聊天和本机嵌入经正常的 OpenAI 兼容传输租用同一个托管路由。生成的命令路径不要抄到另一台机器。在每台机器上跑 llama.cpp 的设置。

这和「入职时下载并在改默认模型前做一次真实工具调用」是前后两步。按需启动管的是选中之后、请求发出之前，服务在不在。

## Hermes

本地端点写在提供商基址里。进程不会因为一次嵌入或聊天才去拉起子进程、空闲再杀掉，除非操作者自己用系统服务这样做。子进程环境仍按被服务的 profile 建。不要把另一台机器上生成的绝对路径当成可移植配置。

## Claude Code

客户端在请求时连接已配置的端点。端点没起来就是这次请求失败。没有健康检查、租约和空闲停机这一层。
