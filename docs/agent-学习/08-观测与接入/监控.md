# 监控

Hermes 网关的监控平面按构造不含内容。它经 OTLP/HTTP 导出到操作者配置的端点。导出的是网关和 cron 的生命周期、平台连接器健康，以及不含内容的警告和错误诊断。它不导出提示、消息、工具参数或结果、任务名、目的地、时刻表、原始错误、会话历史、用量分析、审计日志或详细执行追踪。运行、模型和工具的轨迹是另一平面，走原生的 NeMo Relay，并且要显式配置订阅者或导出器。

## 对照

| | Hermes | OpenClaw | Claude Code |
|---|---|---|---|
| 内容 | 日志正文不导出。诊断是常量正文加有界属性 | 默认跨度不含提示。打开内容捕获仍排除系统提示和思考 | 转录在本机 |
| 实例 | 安装 id 的稳定单向哈希。不导出账户、profile 或原始安装标识 | 追踪按请求。会话键在低基数属性上变成 `unknown` | 无 |
| 活工作 | `active_agents` 是关机时要排干的。`background_work` 按任务计，扇出 N 个就是 N。`background_delegations` 按异步单元计，一批扇出是 1 | 车道和工人池另计 | 无 |
| cron | 任务键是不透明哈希。终态做失败打开的冲刷，最多耽误完成一秒 | 调度在 Gateway 里。无这道 OTLP | 无 |

## Hermes

网关仪表走指标。健康和生命周期走追踪，状态从启动到运行、排水、停止，另有启动失败和退出。诊断走日志。渲染出来的日志消息从不导出。

`active_agents` 数前台消息回合、在飞的 cron，以及 API 运行。这是关机时网关要排干的工作。`background_work` 数 `active_agents` 从不包括的脱离工作：后台的 `delegate_task`、后台终端进程和看板工人。它按任务计。一次扇出 N 个子代理计成 N，反映真实的并发子代理负载。`background_delegations` 只数异步委派单元。每次 `delegate_task` 分发是 1，一次扇出批也是 1，和异步池的容量记账一致。用它对照 `delegation.max_concurrent_children` 看槽压力。把 `active_agents` 和 `background_work` 相加，是这一实例上的全部活工作。池是否饱和看 `background_delegations`。

信号带服务名、版本、监督模式，以及安装 id 的稳定单向哈希。操作者能区分实例，而不导出账户、profile 身份或原始安装标识。

cron 仪表有滴答心跳和上次成功的年龄，不可用时省略。有调度器过期窗口分支上的单调追赶次数、启用和正在跑的任务数，以及从持久化的下次运行加上已有宽限规则得出的过期数。执行生命周期是耐久的认领、运行、完成、失败或未知。来源和错误类有界。任务键是不透明哈希。有时间戳时带经过的时长。调度器知道投递结局时带上。终态做一次失败打开的冲刷，最多把完成耽误一秒。

没配接收端就没有这平面。它不改变 agent 怎么回答。每日更新检查和匿名功能统计是别的管道。

## OpenClaw

诊断可以是 Prometheus 插件，要 `operator.read`，不要当成公开的未认证 `/metrics`。OpenTelemetry 可以继续上游追踪。默认不导出提示。打开内容捕获仍排除系统提示和思考。那和 Hermes 这张「按构造不含内容、安装 id 只出哈希、后台工作按任务而委派按单元」不是同一张表。

## Claude Code

没有网关 OTLP 平面。用量在这一次客户端请求里。
