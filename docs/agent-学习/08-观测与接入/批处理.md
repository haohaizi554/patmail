# 批处理

批处理把很多条提示各放进一次隔离的 agent 会话，产出带工具统计的轨迹。一条提示一个环境。中断之后按同一次运行的名字继续。它不是网关里的用户会话，也不是 cron。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 入口 | 无这条训练用的批跑器 | `batch_runner.py`。每条提示隔离环境 | 无批量轨迹跑器 |
| 产出 | 会话转录在各 agent 的库里 | 成功进 `trajectory_samples.jsonl`。失败或中断进 `failed_trajectories.jsonl` | 项目 JSONL 是对话，不是训练集 |
| 继续 | 重启恢复是把被打断的回合再拉起，最多三次 | `--resume` 用同一个 `run_name` | resume 打开一份转录 |
| 工具面 | 按 agent 的策略 | 可按分布选择工具集 | 当次客户端的工具 |

## Hermes

跑器读 JSONL 数据集。每条提示走一次完整的 agent 会话，带工具。输出是结构化轨迹：完整对话、工具调用统计、推理覆盖。主要用途是训练数据，ShareGPT 形状。

并行度和批大小由参数决定。同一次运行用 `run_name` 标识。中断后用 `--resume` 和同一个名字接着跑，而不是新开一份把已经完成的提示再跑一遍。

成功完成的对话写入当前工作目录的 `trajectory_samples.jsonl`。失败或被打断的写入 `failed_trajectories.jsonl`。批跑器可以写到每次运行自己的输出文件，并带额外元数据。文件名可以在保存时覆盖。

每条轨迹是一行自包含的 JSON。交互格式里有对话、时间、模型和是否完成。批跑格式在此之外还有这次运行的字段。

批跑会同时开很多会话，各自调用模型和工具。限流和凭据池的规则仍然适用。它不共享用户桌面上那一条会话的系统提示缓存。隔离环境意味着一条提示的文件副作用不要写进另一条的工作区。

这和 cron 不同。cron 按时刻表叫醒一份新会话，并记账以免漏跑或双发。批跑把一份数据集走完。这也和 `/loop` 不同。循环活在一条已经打开的会话里。

## OpenClaw

没有这个批跑器。大量会话来自信道、绑定和广播，每条仍是 Gateway 上的会话，写进该 agent 的库。重启恢复只重放还没完成的那一轮，有三次预算。轨迹若要导出，是从转录来的，不是批跑器的 ShareGPT 文件。

## Claude Code

一次查询写一份项目 JSONL。没有数据集、工人数和断点续跑的批处理入口。要批量产生轨迹，得在外面多次启动客户端，并自己避免写进同一个转录文件。
