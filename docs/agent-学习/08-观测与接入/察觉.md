# 察觉

几条会话同时做一件事时，人对着工人会话直接说话、或别人改了目标，父亲脑子里的假设就过时了。信号日志记下有类型的变化，不含消息正文。观察者得到一条合并过的过时通知，再用 `session_status` 的 `changesSince` 把增量拉回来。记录失败不让原来的那一轮失败。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 日志 | 共享库 `session_state_events`。一行摘要，无正文 | 会话行在 `state.db`。没有这套「别人插手了」的信号日志 | JSONL 是转录本身 |
| 谁被通知 | 人直接发话、上游消失、目标变化。孩子出生只播种光标。运行结束和压缩只记日志 | 完成队列把孩子结果送回父回合。不另发一条「去对账」 | 父回合收到摘要 |
| 通知形状 | 每一对观察者和目标只挂一条。二十次变化仍是一行 | 积压把已经就绪的完成收成一轮 | 无 |
| 多进程 | 多台 Gateway 共享耐久日志和 `changesSince`。v1 不把通知推过进程 | 一个家目录一把 tick 锁。不推跨进程的过时通知 | 单客户端 |

## OpenClaw

会通知观察者的种类：人直接向被观察会话发一轮，被收养会话的上游源消失，目标被创建、更新或清除。只写日志、不通知的：有可信创建归属的新会话，孩子运行成功，孩子失败、超时或取消，历史被压缩，目录会话被收养。`child_spawned` 不通知，它把父亲的光标种在孩子出生时的版本上。父亲不用手工订阅。

取消和超时记成失败，载荷里保留 `cancelled`、`timeout` 或 `error`。普通的孩子完成投递仍归子代理公告。信号日志不把公告再做一遍。

状态版本是这条日志里最高的序号。剪枝之后，每个会话的头仍单调。`sessions_list` 在有过变化时带上 `stateVersion`。`session_status` 总是报告它。版本是信号日志的头，不是事务性的变更捕获。追加失败只记日志，不让引发它的那一轮失败。

观察者还有两处。`session.groupScope` 为按组时，该 agent 的主会话在隔离的组、房间和频道会话发生第一次人的回合之后观察它们。这和私聊范围无关。房间已经路由进主会话时不必再观察，因为已经是同一段对话。协调者可以对非亲生目标显式 `sessions_send` 且 `watch: true`。仅有 agent 之间的发送规则，不授予去看本应隐藏的会话。发送成功之后，发送者注册为实际收到消息的那条会话的观察者。注册从目标当前版本开始，先前的历史不产生通知。

观察者身份必须是带 agent 限定的会话键。全局范围的共享 `global` 键在多个 agent 之间含糊，所以这些会话有耐久日志和 `changesSince`，没有主动通知。

观察还记下观察者的物理存储。改 `session.store` 不把排队的通知转到另一段同键对话。来源不明的旧观察留着历史，要重新注册才恢复主动通知。

没有取消观察的动词。光标随信号日志的保留期过期，观察者会话重置时去掉，任一边会话去掉时也去掉。重置已经提交之后，后来的清理步骤失败，观察仍会被清掉。

通知协议：挂起的通知文本在挂起期间字节稳定，系统事件队列按它去重。光标在通知入队时冻在已通知的位置。之后的实质事件只推进实质水位，不再通知。观察者的回合消化掉通知后光标前进。若入队和消化之间又有实质事件，对剩余部分再开恰好一条新通知。观察者不会收到自己造成的事件。挂起通知在内存队列里。Gateway 重启后，启动扫描从耐久光标把它们再具体化。

主会话的观察者经心跳立刻被唤醒。嵌套子代理观察者在自己的下一轮才看到通知。

`changesSince` 返回该版本之后的有类型事件，最多 200 条，不推进任何光标。`historyGap: true` 表示请求的版本早于保留的历史，来自每个会话的剪枝水位，不是用序号算术猜的。这时要刷新整份会话状态，不要把响应当成精确增量。

历史在共享库里，30 天或 5 万行。孩子运行的结果异步记录，等待共享库不挡住 Gateway 的事件处理。完成会接上记录工作。被替换或临时的 run 主人不能认领这次运行的第一个终态事件。写入准入之后会再核对会话所有权。对其它会话的并发写不会丢掉本应留下的事件。

多台 Gateway 共享耐久日志和 `changesSince`。v1 不把通知推到别的进程。压缩事件覆盖嵌入式运行时的压缩主人。只有原生运行时的压缩不会完全记上。取消载荷的细节目前来自 ACP 孩子。原生子代理的取消表面是笼统的失败。

从目录收养的 Claude、Codex、OpenCode 和 Pi 会话，按固定节拍检查上游的人是否直接活动。Pi 要等会话进入只追加的 v3 才开始监视。OpenCode 的 v1 表没有消息出处，含糊行不报，以免假警报。它不报告纯图片、只有 `@file` 提及、路由到子代理的斜杠，以及标了受众的 ACP 回合。它还压住与前面 50 条用户消息对得上的文本，用来认出压缩重放。人在这个窗口里故意发同样的字，可能被错过。上游源被外面删掉时，连续三次缺失检查产生一条 `upstream_missing`，并去掉上游链接。再继续目录会话会建一条新链接。

单行 Claude 或 Pi 的 JSONL 超过这一节拍 1 MiB 的扫描上限时，v1 停住该会话的光标。未分类的字节不跳过。配对节点上的 Claude 每次看最近 50 条。远端 Claude 的历史读不出确定的「线程不存在」，所以 v1 不把远端删除记成 `upstream_missing`。还没收养的目录会话在这层之外。一个被收养的会话键要有一个拥有它的 agent。同一条原生线程可以被不同的被观察键监视。同一键挂在多个 agent id 下的链接因为含糊而跳过。

## Hermes

孩子结束经完成队列回到父回合。桌面重连重铸界面会话 id，谱系仍指压缩后的尖端。没有「人跳进工人会话就给父亲一条不含正文的过时通知，再让它按版本拉取增量」。要知道孩子在做什么，用子代理列表和跟踪，那是活会话的快照，不是 30 天的信号日志。

## Claude Code

父回合和侧链 JSONL 是两份转录。没有观察者光标，也没有 `changesSince`。人在编辑器里改文件，agent 下一轮读文件才能看见。那不是会话状态信号。
