# 追踪

诊断导出默认不带模型原文。请求帧上的 `traceparent` 怎么接、畸形时怎么换一条新追踪，写在 [跨度](跨度.md)。跨度上是有界的标识：频道、提供商、模型、错误类别、只有哈希的请求 id、工具来源和主人、技能名和来源。没有提示、回复、工具输入输出、技能路径或会话键。看起来像 `agent:` 开头的会话键，在低基数属性上换成 `unknown`。要导出提示和工具文本，得显式打开 `captureContent`，并且收集器的保留政策已经批准。系统提示和提供商内部的思考载荷仍然不导出。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 默认 | 插件 `diagnostics-otel`，OTLP/HTTP。两边都开着导出器才挂上，进程内成本接近零 | 监控平面不含内容。不配接收端就没有 | 无 OTLP |
| 内容 | 默认不导出。`captureContent` 才带有界、打红的输入输出和工具定义 | 不导出提示和工具参数 | 转录在本机 |
| 仍排除 | 系统提示。思考和已打红的思考只留结构标记 | 原始错误和会话历史也不在监控平面 | 无 |
| 追踪 | 每条 RPC 自己的 `traceparent`。`connect` 帧上的被忽略 | 无这条 WebSocket 追踪头 | 无 |

## OpenClaw

已认证的 WebSocket 客户端可以在每条请求帧上带 W3C `traceparent`。Gateway 建一个子请求上下文，保留上游的追踪 id 和采样标志。这次请求里的 agent、运行时、模型调用、提供商、工具执行和 exec 跨度都留在这条追踪上，包括父运行已经结束后才记下的跨度。追踪上下文按请求，不按连接。长连接上的每一次 RPC 各自带合适的头。并发请求即使交错也隔离。

这个字段在现有认证握手之后才接受，不影响认证和方法授权。初始 `connect` 帧上的 `traceparent` 被忽略。在 128 字符以内缺失或语法不对的值，静默改成一条新的请求追踪。更长的值让这帧无效。协议不接受 `tracestate` 和 `baggage`。

导出器开着时，出站模型请求可以带上导出器自己拥有的模型调用跨度的 `traceparent`。诊断用的追踪 id 和跨度 id 只用来把事件关联到那个跨度，不拿去当出站的 OpenTelemetry 身份。解析不到真实跨度上下文时，省略这个头，不去命名一个没导出的父级。调用者自己带的 `traceparent` 会被去掉或替换，插件或自定义提供商选项不能伪造跨服务的追踪祖先。

`captureContent` 为真时，导出有界且打红的输入消息、输出消息、工具输入、工具输出、工具定义，以及 OTLP 日志正文。系统提示排除。`thinking` 和 `redacted_thinking` 排除：兼容属性只留打红的结构标记，GenAI 消息属性省略这些部分。

内容捕获关掉时，完成的助手旁白只有计时、序号、运行时和文本长度。打开时，每条事件最多 16384 个字符的可见旁白，走已有的打红输出属性。旁白正文不进普通诊断日志或公开诊断事件。

内建运行时的工具执行才会捕获工具输入输出。外部运行时（Codex、Claude CLI）的 `tool.execution` 跨度不带内容载荷。捕获的内容走受信任的、只给监听器的通道，不放到公开的诊断事件总线上。

语音指标只导出有界的事件元数据：模式、传输、提供商、事件类型。没有转录、音频、会话 id、回合 id、通话 id、房间 id 或交接令牌。

OTLP 日志默认保留严重性、记录器、代码位置、受信任的追踪上下文和打过红的属性。原始日志正文只在 `captureContent` 为真时导出。

Prometheus 文本端点是另一条抓取，要 `operator.read`。轨迹导出含提示，走批准。三条都不是默认把对话推到公网。

## Hermes

网关 OTLP 按构造不含提示、消息、工具参数和结果、会话历史。没有 `captureContent` 这种再打开正文、但仍排除系统提示和思考的开关写在同一份监控平面里。轨迹若要内容，是单独配置的 Relay 或人指定的批处理目录。

## Claude Code

没有 Gateway 上的 OTLP 插件。会话内容在项目 JSONL。外部运行时的工具跨度在 OpenClaw 里也不带内容载荷。
