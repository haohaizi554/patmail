# 遥测

更新检查默认每天问一次有没有新版本，带上版本、操作系统、Node 版本、CPU 架构和请求来自哪一面。匿名的功能统计默认关闭。打开之后搭在同一次每日请求上，不另开一条。它不统计插件被调用了几次、消息条数、模型请求或活跃用户。Hermes 的网关监控平面按构造就不含内容。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|

| 拒绝 | 不改变 OpenClaw 怎么工作 | 没配接收端就没有这平面 | 无 |

## OpenClaw

自动更新检查默认发送每日请求，问有没有更新的版本。载荷含 OpenClaw 版本、操作系统、Node.js 版本、CPU 架构和请求表面。这一页说的是更新检查，不是已配置的提供商、渠道或其它服务自己发出的请求。

匿名功能统计描述配置了哪些渠道和提供商、插件清单，以及保留的会话创建次数。默认关闭。启用后搭在同一次每日更新检查上，不增加第二次请求。它帮助决定维护优先级。不测量单次插件调用、消息、模型请求或活跃用户。拒绝是正常选择，不改变 OpenClaw 的行为。

用量页上的配额和费用来自提供商的用量端点和本地会话日志，不是这份匿名统计。两者不要混成「OpenClaw 把对话上传了」。

配置里的 `telemetry.enabled` 和同意时间属于热更新一类，下次检查才用，不必因此重启 Gateway。

## Hermes

网关监控把服务健康和结构化诊断经 OTLP/HTTP 送到操作者配置的接收端。这个平面按构造不含内容。导出的是网关和 cron 的生命周期、平台连接器健康，以及不含内容的警告和错误诊断。它从不导出提示、消息、工具参数或结果、任务名、目的地、时刻表、原始错误、会话历史、用量分析、审计日志或详细的执行轨迹。

轨迹采集是另一平面，由原生的 Relay SDK 集成和显式配置的订阅者或导出器负责。不配接收端，监控平面就不存在。铁代理的审计日志在本机，权限 0600，不是这份 OTLP。

批处理写下的轨迹在工作目录里，是人要的训练数据，不是后台统计。

## Claude Code

没有每日更新检查夹带架构和插件清单的合同写在这套笔记里。会话 JSONL 留在项目目录。客户端若有自己的使用统计，那是客户端的设置，不是 Gateway 的匿名功能计数。
