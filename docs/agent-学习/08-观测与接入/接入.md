# 接入

外部程序驱动 Hermes 有三条协议，底下是同一个 `AIAgent`。差别在线上格式和露出的功能。ACP 走 stdio JSON-RPC，给已经会说 Agent Client Protocol 的编辑器。TUI 网关走 stdio 或 WebSocket JSON-RPC，给要细控会话、斜杠、批准和流式事件的宿主。API 服务器走 HTTP 和服务器推送事件，给兼容 OpenAI 的网页前端。

## 对照

| | Hermes | OpenClaw | Claude Code |
|---|---|---|---|
| 编辑器 | `hermes acp`。stdout 只给协议帧 | ACP 运行时和 ACPX 会话按那条 harness | IDE 传选区和 diff |
| 自建界面 | TUI 网关。活会话的激活和关闭是进程本地的。已保存的转录用 `session.list` | 控制界面和 `tui` 投影 Gateway 会话 | 本机客户端 |
| 回绕 | 必须显式确认。忙碌时拒绝，不把剪切排成普通跟随。成功后旧行 id 作废 | 压缩和重置有自己的边界。不靠这组确认参数 | 编辑是客户端对转录的操作 |
| 多客户端 | 同一网关里恢复或激活是再挂一个事件订阅者。断开一个不结束别人正在看的会话 | 多个客户端投影同一条 Gateway 会话 | 各自打开文件 |

## Hermes

`session.active_list`、`session.activate` 和 `session.close` 管的是这个 TUI 网关进程里当前开着的会话。发现已保存的转录用 `session.list`。在同一个已认证的网关里，恢复或激活活会话是再挂一个事件订阅者，不替换先前的连接。流式和终端事件发给所有挂上的客户端。断开一个客户端不结束另一个正在看的会话。已有的提交独占和配置的忙碌输入政策仍然有效。挂上的客户端可以转向这条会话的子代理。浏览器控制器的结果仍要求登记了那个控制器的连接。这不让互相独立的网关进程去写同一条会话，也不表示主人重启之后提示准入还在。

`session.create` 接受这一会话的模型和提供商覆盖。提供商服务不了的一对，事先拒绝，JSON-RPC 码 `-32602`，而不是先造出会话、第一轮才在提供商处失败。错误数据带模型、提供商，以及该提供商目录里最多五条建议。检查是离线的，只拒绝 Hermes 知道属于别处的名字。自定义端点、聚合器、目录还没跟上的同族模型，以及任何目录都没有的名字，仍按以前接受。

回绕、编辑或重新生成是一次 `prompt.submit`，在跑新回合之前丢掉存储转录的一部分。因为这是对耐久行的破坏性改写，网关只在客户端声明意图时才做。从某个用户回合起切，该回合及之后都丢掉。只用于显示的时间线行不计。序数必须是真正的整数，JSON 布尔会被拒绝。行 id 是更耐久的地址。两者都给时，网关核对它们匹配，不配就拒绝。未知或过期的行 id 被拒绝，不退回序数。只要带了序数、消息 id 或行 id，就必须有 `confirm_truncate`。只确认、没有目标，也拒绝。切完会把转录清空时，还要 `confirm_empty_truncate`。带了截断参数却没确认，什么都不写。宿主必须在用户要求回绕的那一刻置上旗标，绝不能把截断参数留在普通提交的状态里。优先用行 id。序数只在还没有耐久 id 时作兼容。

截断提交不被忙碌输入政策吸收。回合还在跑时，普通提交可以被转向、改道或排队。回绕则拒绝，码 `4009`，会话忙。排进队列会丢掉历史剪切，把编辑当成未编辑回合之后的普通跟随。宿主调用 `session.interrupt` 再重试同一次提交，直到落地。对耐久会话成功的截断提交，结果里带幸存用户行的新 id。改写把保留的前缀重新插入成新行，所以宿主在回绕前缓存的每个行 id 之后都过期。要从这份列表重新绑定。空条目表示那一轮没有耐久 id，丢掉缓存的那个。否则下一次针对更老的幸存回合的回绕会被拒绝。

批准、澄清、sudo、保险库和桌面读写桥是网关发给客户端的 JSON-RPC 请求，不是事件。客户端用同一个 id 回答。

## OpenClaw

控制界面、终端和 `attach` 投影 Gateway 拥有的会话。短链和交接另有附着合同。没有「回绕必须确认、忙碌时拒绝而不是排成跟随、成功后全部行 id 作废」这一页 Hermes 网关参数。

## Claude Code

IDE 和终端打开同一份或各自的转录。没有三条对外协议共用一个 agent 核心，也没有用确认旗标保护的截断提交。
