# 接口

API 服务器把 Hermes 暴露成兼容 OpenAI 的 HTTP 端点。前端只说话，工具、记忆和技能仍在 Hermes 里执行。钥匙放在 `.env`。默认只听本机。流式时，工具进度出现在流里，让前端能显示正在做什么。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 形状 | Gateway 的 WebSocket 和若干 HTTP API | 网关里的 OpenAI 兼容 HTTP。示例监听 `127.0.0.1:8642` | 无这层对外的 agent API |
| 开关 | 网关随服务安装 | `API_SERVER_ENABLED` 和 `API_SERVER_KEY` 在 `.env` | 客户端本地 |
| 工具 | 渠道回合走 agent | 终端、文件、搜索、记忆、技能都在。返回的是最终回答 | 工具在这次查询里 |
| 浏览器 | 控制界面自己连 Gateway | 只有浏览器必须直连时才配 CORS 来源 | 无 |

## Hermes

任何说 OpenAI 格式的前端都可以把 Hermes 当后端。请求由 agent 用完整工具面处理，返回最终回答。流式时，工具进度指示嵌在流里。

启用写在家目录的 `.env`：打开开关，并设置钥匙。CORS 来源是可选的，只在浏览器必须直接调用 Hermes 时才设。然后启动网关。示例里 API 服务器听在 `127.0.0.1:8642`。

钥匙是秘密，不进 `config.yaml`。本机绑定避免把带工具的 agent 直接暴露到所有网卡。若前面加了反向代理，认证仍是这把钥匙，不另起一套。

这条 HTTP 和桌面用的 JSON-RPC 是两个入口，背后是同一个 agent。会话、提示缓存和工具批准的规则不变。前端把工具进度显示出来，不表示它可以跳过批准。需要人的澄清和批准仍要有地方接住，否则工具回合会停在等待。

多 profile 时，请求必须落在正确的家目录上。只听默认家、却用次要 profile 的模型，会读错秘密。网关的身份解析在消息渠道上更完整。API 服务器的调用方要自己带上它代表的是哪一个家。

## OpenClaw

Gateway 的控制面是 WebSocket，第一来回是挑战和 `connect`。另有 OpenAI HTTP 和工具调用 HTTP。那些是 Gateway 的端点，不是把整个 agent 伪装成一个聊天补全供任意前端使用的开关。渠道消息仍走适配器、绑定和会话钥匙。

健康检查可以问正在跑的 Gateway，不从 CLI 直接去拨渠道套接字。

## Claude Code

查询循环在客户端里。没有一把 `.env` 钥匙就把带工具的 agent 挂到 8642 上的模式。编辑器集成走自己的协议。工具进度画在客户端，不画成 OpenAI 流里的工具增量，除非某个包装器这么做。
