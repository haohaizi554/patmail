# 共享指标

NeMo Relay 是 Hermes 在有原生轮子的平台上的普通运行时依赖。共享指标做进 Hermes 里，不需要再开一个可观测性插件。没有轮子的平台用明确的、能力缩减的空宿主。Hermes 仍能执行。Relay 的范围、中间件、插件和订阅者不可用。`hermes-agent[nemo-relay]` 这个额外项仍是给旧安装命令的空兼容别名。

## 对照

| | Hermes | OpenClaw | Claude Code |
|---|---|---|---|
| 开关 | 共享指标默认关。只有这个 profile 自己的 `config.yaml` 能打开。机器管理的覆盖层不能替 profile 打开或关掉 | 每日更新检查和可选的内容捕获是别的管道 | 无 |
| 送出 | 要同时打开 `enabled` 和 `send`。送的是整包，不是活的跨度 | 追踪按请求。默认不含提示 | 无 |
| 旧插件 | `observability/nemo_relay` 去掉。导出配置挪到 Relay 的 `plugins.toml` | 诊断插件另装 | 无 |
| 版本 | 托管的提供商和工具调用要求 Relay 0.9，上界不到 0.10 | 无这道原生轮子 | 无 |

## Hermes

支持的平台上，Hermes 要求 NeMo Relay 0.9 来做托管的提供商和工具调用。依赖范围是 `>=0.9,<0.10`。不支持的平台用空运行时，不改去下载另一套实现。

Relay 托管执行开着时，提供商的请求和响应穿过 Hermes 进程里的那个原生模块，让配置的拦截器作用在真实调用上。这和共享指标的数据合同分开。共享指标模式不安装富可观测性的网络导出器。它的订阅者只接受下面那份带版本的、允许名单上的投影。可选的包发送器是唯一的出站路径。用户没有同时打开 `enabled` 和 `send` 就不传。它送整包，不送活的跨度。另外配置的富可观测性或动态插件可以走出另一条数据路径，要单独审政策。

收集保持关闭，除非 Hermes 政策打开 `telemetry.shared_metrics.enabled`。这个选择从 profile 自己的 `config.yaml` 读。机器管理的配置覆盖不能替这个 profile 打开或关掉共享指标。

旧的 `observability/nemo_relay` 插件去掉了。已有用户要从 `plugins.enabled` 里拿掉它或旧别名 `nemo_relay`，把导出配置挪进 Relay 的 `plugins.toml`。`HERMES_NEMO_RELAY_PLUGINS_TOML` 可以指定文件。`hermes update` 或 `hermes migrate relay` 在迁移旧的 `HERMES_NEMO_RELAY_ATOF_*` 和 `HERMES_NEMO_RELAY_ATIF_*` 时会建一份。那些旧变量自己不再配置 Relay 导出器。

这和网关监控平面不同。监控按构造不含内容，走操作者配置的 OTLP。共享指标是 Relay 的投影，默认关，而且不能被机器覆盖层替 profile 打开。

## OpenClaw

匿名功能统计默认关，打开后搭在每日更新检查上。轨迹导出要批准并打红。OpenTelemetry 默认不含提示。没有「机器覆盖层不能替 profile 打开共享指标、送出必须整包且要两道开关」这一页。

## Claude Code

没有 NeMo Relay 共享指标。用量在这一次请求里。
