# 账单

终端里的账单状态和类型化拒绝都有明确分支。未知错误码落到默认分支，用服务器带来的消息，不出现空白提示，也不把界面打崩。拉取 `billing.state` 失败时覆盖层不打开，不假设任何状态，更不会渲染成「没有卡」。没有保存的卡时走添加卡，不打开金额选择。金额选择会得到 `no_payment_method`。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 拉不到状态 | 无这张终端账单覆盖层 | 失败关闭。覆盖层不打开。用户重试 `/topup` | 客户端自己的账户 |
| 没有卡 | 无 | 添加卡路径。不给金额选择 | 无 |
| 权限 | 操作者范围 | 组织级开关是管理员且 CLI 账单开启。终端的 `billing:manage` 不预检，扣款 403 `insufficient_scope` 再进可恢复的提权 | 无 |
| 轮询 | 无 | 每 2 秒，上限 5 分钟。挂起和被限流的路径都算。持续的 429 或 503 不能让轮询一直活着 | 无 |

## Hermes

`full` 是 `is_admin` 并且 `cli_billing_enabled`。它管的是组织级开关，不是每个终端的 `billing:manage`。后者在扣款被拒时才发现，进入可恢复的提权画面，而不是事先检查。

自动充值的卡若是另一张，覆盖层写出它在扣的品牌和末四位，并说明不是档上的那张。没有自动充值配置时，那一行不出现。没有账单权限的角色，菜单收成门户管理和取消。组织关掉远程消费时，同样收起，并说明要账单管理员在门户打开。

拒绝码各自有文案。`remote_spending_revoked` 和 `session_revoked` 立刻清掉账单覆盖层，不等令牌刷新。`idempotency_conflict` 表示这把扣款键已经用于不同金额，要重新开始一次充值。`rate_limited` 和 `temporarily_unavailable` 说明现在扣款太多，这不是支付失败。有 `retry_after` 时按分钟显示，至少一分钟。未知码显示服务器的消息，有门户地址就附上。

扣款轮询每 2 秒一次，五分钟封顶。每一条非终态路径都用这个上限，包括挂起和被限流。这样持续的 429 或 503 不会让轮询永远继续。结算成功是终态。银行要求验证时，文案指向门户上的验证，不把这一次说成已经加上额度。

## OpenClaw

用量和计费禁用是模型调用上的状态桶，大约十分钟量级的计费禁用。没有终端覆盖层把每一种门户拒绝码画成固定文案，也没有「拉不到状态就绝不猜没有卡」这一条。

## Claude Code

账户和额度在客户端。没有这张「每种拒绝码一条恢复动作、轮询五分钟封顶」的终端合同。
