# 电脑

电脑使用在后台读无障碍树并投递合成输入。真实光标不动，键盘焦点不换，虚拟桌面不切换。人和 agent 在同一台机器上同时干活。任何能调工具的模型都可以用，不依赖某一家的原生电脑使用 schema。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 驱动 | 节点和浏览器是另一条控制面 | `computer_use` 经 stdio MCP 连接 cua-driver | 无这套后台桌面驱动 |
| 光标 | 浏览器在自己的标签里操作 | 不把系统光标拽走，不把窗口拉到前台 | 编辑器里的操作是 IDE |
| 平台 | 节点按设备配对 | macOS 用辅助功能，Windows 用 UIAutomation，Linux 用 AT-SPI | 本机 |
| 失败 | 批准和沙箱仍在 | 工具结果里没有密码和焦点偷取。写后的语言服务不覆盖点击 | 权限询问 |

## Hermes

内置工具集通过 MCP 的 stdio 和开源的 cua-driver 说话。各平台用自己的无障碍和输入栈。macOS 走辅助功能，输入按进程投递，不扭曲光标。Windows 用 UIAutomation，`SendInput` 加 `PostMessage`，不抢焦点。Linux 用 AT-SPI，X11 用 XTest，Wayland 用虚拟键盘。

结果在每个平台上相同：agent 能读任何可见窗口的无障碍树，并投递合成事件，而不把窗口带到前台、不切换虚拟桌面、不移动真实的系统光标。

这和浏览器工具不同。浏览器有标签、对话框和跨域 iframe。电脑使用看的是桌面窗口。两边都可以在同一台机器上开着。电脑使用不因为浏览器沙箱开着就自动被困进容器。它操作的是主机桌面。安全政策里，进程内的工具和主机输入是同一台机器上的能力。要把它和人的桌面隔开，需要别的会话或别的机器，而不是只靠提示词说「别点」。

工具搜索的策划延迟名单里可以包括 `computer_use`。延迟之后，模型经搜索、描述、调用才会看见完整 schema。调用仍走原来的批准和钩子。

模型看见的是无障碍树和动作结果，不是屏幕的每一帧，除非另有视觉工具把截图嵌进结果。截图若嵌入，受视觉的体积和重复次数预算。

## OpenClaw

节点是配对过的设备，可以在那台机器上执行。浏览器是管理过的标签。两者都不是「后台合成输入、系统光标不动」这一份桌面合同。权限模式和执行批准决定命令和文件。电脑使用若由插件提供，仍要经过工具策略。

## Claude Code

编辑器里的改动走工作区和权限。没有 cua-driver，也没有「不移动用户光标」的桌面输入合同。截图和读文件是工具结果。计划模式可以在接受前禁止写。
