# 投递

一条进来的消息要先变成会话键，再决定是并进当前轮、等当前轮结束，还是单独开一轮。出去的文本要经过渠道长度、前缀和静默记号。模型写了 `NO_REPLY`，不等于这次必须回答的回合可以结束。

队列模式和块流的细节在多代理笔记和流式笔记里。这篇写入站去重、给模型看的正文，以及什么时候必须有一条人看得见的回复。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 入站 | 路由、去重、防抖、队列、运行、出站 | 适配器、授权、会话键、两道忙碌守卫 | 没有渠道。用户消息直接进 `query` |
| 给模型的正文 | `BodyForAgent`。群里当前消息加发送者 | 共享会话给每条用户消息加发送者前缀 | 用户消息就是用户消息 |
| 静默 | 渠道上的 `NO_REPLY` 不展示。私聊不能靠它免答 | 终稿由消费方 `finish`。临时发送要标 interim | 空回复不是静默协议 |
| 失败 | 直接对话和被点名的对话要有一条紧凑错误。进度条不算结局 | 运行失败和投递失败分开记 | 工具失败留在配对的结果里 |

## OpenClaw

路径是：入站、按绑定路由到会话键、去重和防抖、若已有运行则进队列、agent 运行、再按渠道限制切块送出。

渠道重连会把同一条消息再交一次。去重缓存的键是 agent 范围、渠道路由（渠道、对端、账号、线程）和消息 id。条目 20 分钟或满 5000 条就丢，以先到者为准。所以短时间里的重投不会再开一轮。过期之后的重投会再跑。

同一发送者的连续文本可以收成一轮。防抖按渠道加对话，回复线程用这批里最新的一条。它是安静窗口，不保证长消息的每一段都进同一轮。只对纯文本。媒体和附件立刻冲刷。停止、中止、状态这类控制命令不防抖。Telegram 普通文本默认 300 毫秒安静窗口。其它渠道没有通用延迟，除非配了。设成 0 关掉普通连发合并。非转发的 Telegram 文本若至少 4000 字，可以再等最多 1500 毫秒的续写。长短消息可以在同一批，不要求消息 id 连续。这条长粘贴组装在普通合并关掉时仍有效。改防抖不用重连 Discord、飞书、iMessage、Mattermost、Teams、Signal、Slack、Telegram 或 WhatsApp。已经在等的那一批不会因为只改了配置就重排。后来的消息可以在原来的最晚期限里改它的空闲延迟。

给模型的字段按优先顺序是 `BodyForAgent`，然后才是命令正文、原始正文、带渠道信封的旧正文。命令解析用 `BodyForCommands`，避免把历史包装当斜杠命令。群和房间的当前消息前面加发送者，和历史行同一风格。剥指令只剥当前消息那一节，历史保持原样。

历史缓冲只放还没触发运行的群消息，例如没被提及、没进会话的那些。已经在 transcript 里的不再包进来。结构化的历史、回复、转发和渠道元数据在组装提示时是不可信的用户角色块。历史条数用 `messages.groupChat.historyLimit`，渠道可以覆盖，0 表示不要。

工具结果里，`content` 是模型要读的。`details` 给界面、诊断、媒体和插件。重放给提供商和送进压缩之前，`details` 被剥掉。transcript 里只留有界的 details，过大的换成带 `persistedDetailsTruncated` 的短摘要。模型必须看见的文字要放在 `content` 里。唯一的回复若是工具错误警告，WebChat 会留下它。这不把一次已完成的运行改判成运行时失败。失败的工具结果另行记录。

回合已经被耐久接受之后，若在答案出来之前失败，直接对话和明确点名的对话会收到一条紧凑错误。进度确认不能代替这个结局。这一轮保持失败，不会当成一条新的入站再放一遍。已经用消息工具发出去的仍然算数。助手在没有工具调用的情况下出错或中止，但已经有半截文字时，下一次模型请求里是一条短失败标记。没写完的文字不重放。存下来的失败回合不改。空的和只有占位的失败排除在外。

回复前缀按账号盖过渠道，空字符串可以关掉继承来的前缀。`auto` 用 agent 的身份名。`[{model}]` 这类模板用选中的模型。消息工具和 CLI 发出的文本也加解析后的前缀，已经有的不重复加。前缀里还有解析不了的模型、提供商或思考级别占位时，整段前缀省略，而不是把占位符发给人。

`NO_REPLY` 不区分大小写，只留给接了外部渠道的会话，不会当成人看得见的文本。子代理、控制界面和其它内部会话不能用它完成任务，必须给出结果或继续没做完的工作。这一轮若还有待送的工具媒体，例如语音，静默文字去掉，媒体仍送。

私聊的提示词里不教 `NO_REPLY`。没送达的必答仍要恢复。被接受的群和频道默认要回复，包括配置成不要求提及时放进来的消息。要让没被点名的请求可以沉默，必须显式把 `silentReply.group` 设为 `allow`。提及和已授权的命令仍要回复。环境房间事件可以沉默。在消息工具的可见回复模式里，可选回合靠不调用发送来沉默，而不是靠记号。

回复义务来自准入，不来自模型自己写的记号。已确认的送达，或仍有主人的送达，阻止再生成一条重复恢复。内部运行器的笼统失败，对还没展示过输出的可选回合保持安静。必答回合仍收到错误。缺认证、限流、过载这类分好类的恢复说明仍可送达。直接对话默认是短错误。原始运行器细节只在 `/verbose full` 时出现。

渠道插件可以在进会话队列之前做排序、防抖和传输背压。它们不该再包一层自己的回合超时。进了会话之后，慢回合由会话和运行时统一报告。

## Hermes

适配器收到消息后做授权，再按会话键找到或建会话。群默认按人切开，所以投递目标是那个人在这个群里的车道，不是整群一份共享回复，除非线程配置成共享。共享会话的系统提示不写死用户名。发送者加在用户消息上，系统提示保持稳定。

agent 忙碌时，新消息先停在适配器队列。`/stop`、`/approve`、`/deny` 等要当场处理的命令同时绕过适配器守卫和运行器守卫。普通正文不绕过。

出站在 `delivery.py`。流即消息的适配器要求草稿帧是前缀，终稿由消费方交给 `finish`。不是终稿的发送要标 interim，否则会把临时文字封成最终消息。终稿若必须改一条已经发出的消息，先编辑，没有可编辑 id 才新发。

cron 把运行成功和投递成功分开。`delivery_failed` 表示模型跑完了，人没收到。后台进程的完成通知要被 `admit_internal_event` 承认。返回空不算接住，同批占用退回。

触发消息的 id 可以注在送给 API 的那份文本上，便于回复和表情。写进会话的用户行仍是人写的原文，不把这条注释放进持久正文。

## Claude Code

没有渠道去重和 `NO_REPLY`。用户在作曲家里发送的就是这一轮的用户消息。斜杠命令等这一回合结束再展开。中途插话进队列，在工具轮之后变成附件。

失败的工具调用配一条失败的 `tool_result`。用户拒绝可以中止整轮。模型想结束时，停止钩子还可以要求再跑一轮。这些都发生在同一次本地会话里，不存在「私聊必答、群可沉默」的准入。

远程和 IDE 把同一套会话接到另一个界面。投递是界面事件，不是 Telegram 的编辑消息。终稿就是转录里的助手消息。
