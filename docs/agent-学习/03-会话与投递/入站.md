# 入站

进来的消息先路由到会话键，再去重和防抖，若已有运行就进队列，然后是 agent 运行，最后按渠道限制切块送出。去重挡住重连之后的重复投递。防抖把同一发送者的快速文本并成一轮。它是安静窗口的启发式，不保证一条长消息的每一段都会进同一轮。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 去重 | 内存缓存按 agent 范围、渠道路线和消息 id。20 分钟或 5000 条，先到为准 | 适配器有自己的更新和对账 | 无渠道重投 |
| 防抖 | 默认 2 秒。Discord 和 Slack 1.5 秒。WhatsApp 5 秒。媒体立刻冲掉。控制命令绕过 | 忙碌时进队列。转向是另一条 | 输入在这一轮 |
| Telegram | 普通文本默认 300 毫秒安静窗口。至少 4000 字的非转发文本最多再等 1500 毫秒拼续段 | 平台适配器自己的分块 | 无 |
| 热应用 | 改延迟不必重连列出的渠道。单独的配置变更不改期已在等的批次 | 多数键下次读取生效 | 下一轮看见新规则 |

## OpenClaw

渠道在重连后可能再次投递同一条消息。OpenClaw 用内存缓存，键是 agent 范围、渠道路线（渠道、对端、账号和线程）和消息 id。重复投递不会再触发一次 agent 运行。条目在 20 分钟后过期，或在跟踪到 5000 条时过期，哪个先到算哪个。

同一发送者的快速文本可以经 `messages.inbound` 并成一轮。防抖按渠道加对话。回复的串线和 id 用最近那条消息。只对纯文本。媒体和附件立刻冲掉当前批次。停止、中止、状态一类控制命令绕过防抖，马上派发。

Telegram 默认在 300 毫秒安静窗口之后把普通文本成批。其它渠道除非配置，没有通用的防抖延迟。`byChannel` 压过通用的 `debounceMs`。两者都压过渠道默认。设成 0 就关掉普通的突发成批。非转发的 Telegram 文本里，至少 4000 字符的消息最多再给 1500 毫秒等续段。短消息和长消息可以进同一批，不要求连续的消息 id。普通成批关掉时，这道自动的长粘贴组装仍然开着。iMessage 走同一套通用防抖。`imsg` 0.13.1 及更新版本在 OpenClaw 收到之前，就把 Apple 的 URL 预览拆开发送合并掉，所以不需要单独的 iMessage 防抖设置。

改 `debounceMs` 和 `byChannel` 不必重连 Discord、飞书、iMessage、Mattermost、Teams、Signal、Slack、Telegram 或 WhatsApp。新准入的入站工作用已提交的延迟。单独一次配置变更不把已在等的批次改期。后来的消息可以在原来的最大期限之内更新它的空闲延迟。显式的传输时序覆盖保持固定。Telegram 转发消息的收集窗口仍然分开。

会话归 Gateway，不归客户端。私聊收进这个 agent 的主会话键。群和频道有自己的会话键。存储和转录在 Gateway 主机上。多台设备可以映到同一条会话，历史不会完整同步回每一个客户端。长对话用一台主设备。控制界面和 TUI 显示的是 Gateway 上的那份转录。

## Hermes

网关在 agent 忙碌时把普通消息放进队列，并让停止、新建、批准和拒绝在两道守卫之前到达。没有「20 分钟或 5000 条的入站去重、媒体立刻冲掉防抖、4000 字的 Telegram 粘贴再等 1500 毫秒」这一页。渠道适配器自己处理平台的重投。

## Claude Code

没有渠道入站。用户消息进当前会话。没有重连去重缓存，也没有按渠道的安静窗口。
