# 群聊

群默认是允许名单，没点名的发送者进不来。进来之后，默认还要点名才跑一轮。没点名的话可以留下当上下文，不触发回复。私聊允许名单、群策略和点名是三道不同的门。机器人自己建的话题可以单独放宽或收紧点名。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 群准入 | `groupPolicy`：开放、关闭或允许名单。默认允许名单，没加发送者就挡住 | 平台允许名单和 `group_policy` 按该 profile 的范围读 | 无频道群 |
| 何时开口 | 默认要点名。`/activation` 可按群改 | 适配器自己的提及和策略 | 无 |
| 没点名的话 | 只存下来当上下文，不跑 | 不满足策略的消息不进这一轮 | 无 |
| 会话 | 按群一条键。个人私聊的指令状态不跟着变 | 会话键带平台和运行 profile | 无 |
| 机器人话题 | `requireMentionInBotThreads` 只改机器人建的话题 | 话题路由在适配器里 | 无 |

## OpenClaw

同一套群规则盖住 Discord、iMessage、Matrix、Microsoft Teams、QQBot、Signal、Slack、Telegram、WhatsApp 和 Zalo。私聊准入看 `allowFrom`。群准入看 `groupPolicy` 加上 `groups` 和 `groupAllowFrom`。回复触发看点名门和 `/activation`。最终回复默认自动发到房间。检查顺序是群策略和群允许名单先，然后才是点名或回复激活。回复机器人的一条消息是隐含点名，它不绕过 `groupAllowFrom`。你信任其成员的私密房间，把 `groupPolicy` 设成开放是正常部署。陌生人能加入或发帖的房间仍用发送者允许名单或点名。`dmPolicy` 设成开放是故意的选择，还要求允许名单里有 `"*"`。

一条群消息的去向：策略是关闭就丢掉。策略是允许名单而群不在名单里就丢掉。要求点名却没被点到，就只存为上下文。点名、回复、命令或私聊才成为用户请求。始终开启的群闲聊成为用户请求，或在配置了房间事件时成为房间事件。

机器人创建的话题可以用 `requireMentionInBotThreads` 只改那一层。`false` 接受已确认的、机器人所建话题里没被点名的后续。`true` 即使房间平常全收，话题里仍要点名。回复、引用和过去机器人说过话，本身不算点名。原生提及、配置的提及模式和已授权命令保持原样。省略则沿用该频道既有的提及和隐含回复。

WhatsApp 上的点名可以是真正的 @、配置的正则、正文里的机器人 E.164 号码，或引用机器人自己的一条消息。共享号码的自聊除外。`always` 对每条已准入的消息唤醒，并且默认必须回复。要允许对没被点名的消息选择性沉默，得显式把该表面的群静默回复设成允许，自动回复提示才接受精确的 `NO_REPLY`。群允许名单设了之后，没列出的群丢掉并记一条日志。`"*"` 表示全部群。群策略默认允许名单，发送者没加之前是挡住的。

群会话键形如 `agent:<agentId>:whatsapp:group:<jid>`。非默认账号再带线程段。`/verbose`、`/trace`、`/think` 作为独立消息时，范围是这个群，不碰个人私聊。

没触发运行的待处理群消息，默认最多 50 条，前缀放在「自从你上次回复以来的聊天，仅供上下文」。触发的那一行单独标成「当前消息，请回应这条」。这一轮之后清空待处理窗口。已经在会话里的消息不再注入一遍。每一行的信封里有发送者标签。发送者身份和群主题、成员在不可信的对话元数据块里。阅后即焚的包装先拆开再抽文本和提及，里面的点名仍能触发。群会话的第一轮，以及 `/activation` 改了模式之后的那一轮，把激活说明注入系统提示。持久的「你在群里」投递说明一直在。

提及模式可以按 agent 写，也可以用全局后备。都没写时，从该 agent 的身份名和表情推导。

## Hermes

群和私聊的允许名单、`group_policy`、是否允许全部用户，都从该 profile 的秘密范围读。范围装上且多路复用开着时，范围里没有的键返回默认，不借用进程环境里启动 profile 的名单。否则一个泄漏的允许名单会让次要 profile 的发送者全部被静默拒绝。

入站身份先规范化：哪个机器人收到、谁可以准入、在哪一份家目录里跑。未解析且多路复用开着时丢掉，不键进默认会话。群消息的投递走收到它的那个适配器。

## Claude Code

没有频道群、点名门和「没点名先存 50 条上下文」。协作是这次客户端里的人和子代理。
