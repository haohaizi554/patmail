# 打字

打字指示在运行还活跃时发给聊天渠道。`typingMode` 决定何时开始。`typingIntervalSeconds` 决定多久刷新一次，默认 6 秒。刷新节奏对每个 agent 都一样，它不决定开始时间。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 未设置时 | 私聊和带提及的群马上开始。没被提及的群要等到用户看得见的活动 | 渠道适配器自己的打字或草稿 | 本地界面没有渠道打字 |
| 静默 | `instant` 即使后来只返回静默记号也先开始。`message` 不把静默记号当成正文活动 | 空终稿可以不发气泡 | 无 |
| 心跳 | 目标是能打字的聊天时，心跳运行一开始就打字。`never` 关掉 | 心跳是主会话回合。没有这套打字模式 | 无心跳 |
| 覆盖 | 单个 agent 可以改模式。刷新间隔仍是默认那一道 | 按渠道 | 无 |

## OpenClaw

`typingMode` 没设置时：私聊在模型循环一开始就打字。带提及的群也马上开始。没有提及的群，要等已准入的运行出现用户看得见的活动，例如执行活动或消息正文。只用消息工具回复时，即使群里没有提及也马上打字，让成员看见 agent 在干活，因为不会自动贴出终稿。这压过上面的群规则。显式的 `typingMode` 仍然赢过它。心跳运行开始时打字，条件是解析出的心跳目标是能打字的聊天，并且打字没有被关掉。

模式有四档。`never` 永远不打字。`instant` 模型循环一开始就打字，即使这轮后来只返回静默记号。`thinking` 在第一段推理增量上开始，或在回合被接受之后的活动执行上开始。`message` 在第一段用户看得见的回复活动上开始，例如活动执行或非静默的正文增量。`NO_REPLY` 一类静默记号不算正文活动。从晚到早是 `never`，然后 `message` 和 `thinking`，然后 `instant`。

`message` 不从静默记号开始，但活动执行仍可以在任何助手正文出现之前显示打字。`thinking` 仍响应流式推理，也可以在推理增量到达之前从活动执行开始。心跳打字是给解析出的投递目标的存活信号。它在心跳运行开始时就打，不跟随 `message` 或 `thinking` 的流时间。目标是 `none`、目标解析不了、心跳的聊天投递关掉、或渠道不支持打字时，心跳不显示打字。

## Hermes

流即消息的渠道把草稿当成这一条消息。临时发送要标成 interim。没有「未提及的群等到看得见的活动、静默记号不算打字、心跳一开始就打字」这一套模式。

## Claude Code

打字和思考在本地界面里画。没有发给聊天渠道的打字指示，也没有 6 秒的保活刷新。
