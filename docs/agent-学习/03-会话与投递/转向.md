# 转向

默认的队列模式是转向。人在回合进行中又发来的普通消息，会试着送进正在跑的运行时，包括工具还在执行的时候。已经在跑的那一次工具调用不会被取消。还没开始的后续调用可以跳过，并配上一条说明它没跑的结果。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 默认 | `steer`。`followup` 和 `collect` 等到这轮结束 | 忙碌时普通消息进队列。`/steer` 是合法的用户行，放在工具结果之后 | 斜杠等这回合结束。中途的话进队列，工具轮之后变成附件 |
| 正在跑的工具 | 不打断 | 硬中断只到达这一轮的活动孩子。后台单元要另外打断 | 取消是客户端的中断 |
| 还没开始的 | 顺序模式在后续调用前检查。并行的一批一旦一起发出，转向不跳过 | 已发出的工具调用要配上结果 | 流式执行尽早配对 |
| 跳过 | 每个被跳过的调用有开始和结束事件，以及合成结果：为了处理新消息而跳过 | 不把转向涂进已经落盘的工具行 | 无这句合成结果 |

## OpenClaw

普通提示在会话运行还活跃、队列模式是转向时，送进活动运行时。OpenClaw 和 Codex 应用服务器的投递细节不同。跟随和收集模式不走这条，普通消息等到当前运行结束。显式的 `/steer` 命令另有一页。更早的一条跟随不会关掉后来输入的转向。每一次新的转向都在先前的转向尝试落定之后再试。运行时拒绝的消息按原来的顺序留在队列里。接受了的转向进入当前回合。

转向不打断已经在跑的工具。一条助手消息上的工具调用在其中一次开始执行之前，是已经提交的计划。顺序模式下，第一个可执行的调用在检查转向之前就发出。那条助手消息上有调用已经开始之后，后续每一次调用之前都会检查，包括异步解析、校验和执行前钩子之后。正在跑的调用结束后，若有转向在等，还没开始的顺序尾巴被跳过。并行模式下，调用一起准备、一起发出，中间没有转向检查点。等着的转向从不跳过一整批并行调用。

每一个被跳过的调用仍有成对的开始和结束事件，以及一条合成结果，说明为了处理进来的消息而跳过。结果按助手原文的顺序。模型因此知道工具没跑。控制界面标成已跳过。缺了这条结果，下一请求会因为工具调用没有配对而失败。

这和中断不同。中断停的是运行。转向是把新的用户意图插进还没执行的计划，已经开始的副作用留着。

## Hermes

`/steer` 作为独立的用户行，放在工具结果之后。助手带工具调用、然后工具、然后用户，在各提供商路径上都合法。不把转向涂进已经持久化的工具行，否则只追加的存储会和活的请求分叉。

忙碌时的普通正文先停在适配器队列。停止、批准和拒绝要当场处理，同时绕过两道守卫。转向若被当成普通正文，会晚于正在等的工具。

后台单元在分发时已经脱离。停止这一轮还要打断该会话的后台委派。深度大于零的委派是同步的，停止会递归到孩子自己的活动孩子。

## Claude Code

中途插入的话在工具轮之后变成附件。斜杠命令等这一回合结束再展开。已经开始的工具不会因为新的一句就配上「跳过」结果。用户拒绝可以停整轮。停止钩子还可以要求再跑。
