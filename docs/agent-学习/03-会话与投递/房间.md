# 房间

没被点名的群消息可以变成安静的房间事件。agent 可以更新记忆和会话状态。房间保持沉默，除非它显式调用 `message` 发送。最终助手文本是私人的。打字和生命周期反应在房间事件上保持压住。点名门若还开着，这些消息在路由前就被丢掉，永远不会变成房间事件。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 没点名 | `unmentionedInbound: "room_event"` 时成为安静事件。点名、命令、停止和私聊仍是用户请求 | 不满足群策略的消息不进回合 | 无房间 |
| 怎么说话 | 严格的可见投递。要 `message(action=send)` | 适配器按策略把回复发回房间 | 无 |
| 点名门 | `requireMention: true` 时，没点名的在变成房间事件之前就丢 | 提及由适配器决定 | 无 |
| 工具面 | `coding` 和 `minimal` 配置不含 `message`。听得见、说不出 | 消息工具集随平台会话 | 无 |
| 今天支持 | Discord 频道、Slack 频道和私有频道、Slack 多人私聊、Telegram 群 | 各平台自己的群 | 无 |

## OpenClaw

始终开着的群，把没点名的入站设成房间事件，把可见回复设成消息工具。房间仍要过普通的 `groupPolicy`、房间允许名单和发送者允许名单。然后关掉该房间的点名门，它才是始终开启。

两处会在配置已经写成房间事件时仍把它静默关掉。点名门开着：没点名的消息在路由前丢掉，agent 没有房间积压，只看见点到它的消息。它说看不到最近的房间历史时，先查点名门。另一处是没有 `message` 工具。`messaging` 配置里才自带它。`minimal` 和 `coding` 没有。这种 agent 能听房间事件，不能说话。要说话就显式把 `message` 加进允许。用 `openclaw agents list` 和一次试聊看有效表面，不要假设配置里已经有。

`messages` 设置在保存后由 Gateway 热应用。重载模式是 `off` 时要手动重启才生效。

房间事件上：没点名但已允许的群或频道消息变成安静事件。被点名的仍是用户请求。文本控制命令和原生命令仍是用户请求。中止或停止仍是用户请求。私聊仍是用户请求。

打字和生命周期状态反应保持压住。唯一的显式回执例外是确认反应范围设成 `all`，那时会发配置的确认反应。房间必须完全沉默时，用更窄的范围或关掉。

历史窗口默认 50，和群里待处理上下文同一数量级。其它群频道保持它们既有的群行为，除非该频道页写明支持房间事件。WhatsApp 上要选择性沉默，是另一条：显式允许群静默回复之后，才接受精确的 `NO_REPLY`。房间事件这条路不靠模型在正文里交出那个令牌。

## Hermes

群消息按该 profile 的允许名单和群策略准入。回复由收到消息的适配器发出。没有「最终文本私人、只有 message 工具才上墙」这一档房间事件。忙碌时的普通正文进队列。停止和批准要当场处理。

## Claude Code

没有群房间，也没有安静上下文和可见发送拆开的两档。人看见的就是这一次客户端里的回复。
