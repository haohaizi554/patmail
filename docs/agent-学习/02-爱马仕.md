# 爱马仕 Hermes Agent

源码在 `hermes-agent/`。一次对话是同步阶段机：租约放行后进入循环，有工具就再问一轮，没有工具就过停手闸门。系统提示词在这次对话里保持字节不变，只有压缩可以改已经写下去的历史。

## 一次对话怎么转

公开入口是 `agent/turn_facade.py` 的 `TurnFacadeMixin.run_conversation`。它拿到会话租约后，转到 `agent/conversation_loop.py` 的 `run_conversation`，再进 `_run_conversation_turn`。`build_turn_context` 先建 `_LoopState`。

循环条件是：`api_call_count < max_iterations` 且 `iteration_budget.remaining > 0`，或者还挂着一次 `_budget_grace_call`。`begin_iteration` 里先把 `api_call_count` 加一。grace 只清标志、不扣预算；否则 `consume()`，扣失败就跳出。中断和 review 输入预算也会提前停。出环之后统一 `finalize_turn`。

一轮里的阶段：

| 阶段 | 作用 |
|---|---|
| `begin_iteration` | 重定向、中断、预算或 grace 记账 |
| `prepare_iteration` | 步进回调、`/steer`、参数清洗、角色交替修复 |
| `assemble_api_request` | 组装待发消息和工具表 |
| `run_preflight_gate` | 发送前的压缩和压力门控 |
| `announce_api_call` | 日志和思考动画 |
| `_run_api_retry_loop` | 守卫、组请求、发请求、看响应或处理错误 |
| `apply_retry_restarts` | 处理压缩、重定向一类重启 |
| `normalize_model_response` | 归一化助手消息 |
| 分支 | 有 `tool_calls` 走 `run_tool_round`，否则走 `finish_text_response` |
| 出环 | `finalize_turn` |

有工具时，先校验，先把 `tool_calls` 落盘，再执行，再写工具结果，必要时压缩，然后通常 `continue`。纯文本时，空回复、截断和停手闸门都在 `finish_text_response` 里处理；通过才设 `final_response` 并 `break`。

6 步的办事助手值得学硬上限，以及用尽之后再给一轮收口。十余个 `turn_*.py`、租约和多提供商缓存约束不必拆成同样的文件。

## 迭代预算

`agent/iteration_budget.py` 的 `IterationBudget` 按代理各算各的。

- 父代理的 `agent.max_turns` 默认是空，表示不限（落到 `sys.maxsize`）。TUI 在配置为空时用 500 做回退。文件头里「默认 500」这句已经旧了。
- 子代理另算。`delegation.max_iterations` 默认 250。`delegate_task` 建子代理时传入 `iteration_budget=None`，子代理拿一份新计数，父子加起来可以超过父上限。

`consume` 发生在每轮入口 `begin_iteration`。`refund` 用于无效重试（重定向、压缩重启、备用模型重建），以及本轮工具调用恰好只有 `execute_code` 的情况：那被当成廉价的可编程调用，不占预算。

快用尽时可以按 `budget_warning_ratio` 提醒模型先落盘再继续，不要因为预警停工。墙钟 `run_budget` 到 80% 时，要求停掉探索，用已有状态交最终结果。迭代用尽后，循环退出，`_handle_max_iterations` 注入一条要求：总结现状，不要再调工具。Anthropic 和 Codex 这条收尾会去掉 tools。chat 为了保住缓存前缀仍可能带上 tools，但返回的 `tool_calls` 会被丢掉。

`_budget_grace_call` 只在一种窄情况置位：Codex 连续只吐出 reasoning、没有正文也没有工具，切到备用模型时预算已经用尽，于是多跑一拍。常规用尽的收口是循环外的那次摘要请求。摘要请求失败，才落到固定句子。

## 提示词缓存

提供商按前缀做缓存。根目录 `AGENTS.md` 写明：一次会话里改已有上下文、换工具集、重载记忆或重建系统提示词，都会打断缓存前缀。`agent/prompt_caching.py` 把静态系统前缀和整段 system 标成断点，所以 system 在这次对话里保持字节不变。

中途要加的内容走用户消息或工具结果。技能斜杠命令走用户消息（`agent/skill_commands.py`）。子目录 `AGENTS.md` 附在工具结果后面（`agent/subdirectory_hints.py`），超长时留头尾并写日志。项目上下文文件只在启动时从当前工作目录加载（`agent/prompt_builder.py`）。

禁止连续两条相同角色，也禁止在循环中途塞一条合成的 user。唯一例外是 `/steer`：它在工具结果之后单独放一条 user，顺序是 `assistant(tool_calls)`、`tool`、`user`。已经落盘的 tool 行不能改。定时任务因此用自己的会话。

`micro_compaction` 默认关闭，因为每轮改写前缀会打穿缓存。

`patmail-extension/src/agent/loop.ts` 现在每一轮都把长期记忆和更早摘录拼进 system。对话短、没有提示词缓存时这样读起来直接。一旦要缓存前缀，记忆应在会话开始时写进 system 一次，之后新记住的内容走用户消息或工具结果。

## 压缩

压缩有两层，顺序是先卫生、再主压缩。

| 层 | 阈值 | 时机 |
|---|---|---|
| Gateway 会话卫生 | 85%，固定 | 进入 agent 之前，兜住特别长的会话 |
| `ContextCompressor` | 默认 50%；上下文窗口小于 512K 时抬到 75% | 循环内，按真实 token |

主算法四步：先裁旧工具结果（这一步不调模型），再划定 head、middle、tail，然后只摘要 middle，最后组装。摘要走 `auxiliary.compression`，也就是 `call_llm(task="compression")`，provider 和 model 可单独配。流卡住时走 `fallback_chain` 再试一次；再卡住就写确定性 fallback 摘要，不再调模型。过载等多数中止保留原文，持续过载才降级写入。`abort_on_summary_failure: true` 时始终不丢消息。

入口：`compression_facade.py` 的 `_compress_context`，`conversation_compression.py` 的 `compress_context`，`context_compressor.py` 的 `should_compress` / `compress`，手动命令在 `conversation_compression_manual.py` 的 `compress_now`。说明见 `website/docs/developer-guide/context-compression-and-caching.md`。

只做原文摘录、不用模型改写的助手，值得学的是第一步：无模型地裁掉旧工具结果，对齐边界，保住头和尾里的用户原话。不必学那次结构化摘要。

## 停手闸门

模型给出文字、准备结束时，`agent/turn_stop_gates.py` 的 `apply_stop_gates` 按这个顺序看三个闸门：`verify-on-stop`、`pre_verify`、看板。命中任一个，就把这段答复当成中途稿，追加一条合成的 user nudge，把 `final_response` 清空，再 `continue` 一轮。

| 闸门 | 打回条件 |
|---|---|
| verify-on-stop | 开关打开（默认关）；本轮改过非散文代码；工作区验证账本不是 `passed`；nudge 少于 2 次 |
| pre_verify | 有文件改动，注册了钩子，次数少于默认 3 次，插件返回了继续文案 |
| 看板 | 有看板任务，本会话还没调过完成、阻塞、复查一类终态工具；nudge 少于 2 次。只写一段文字收尾算协议违反 |

闸门放行前，候补答复存在 `pending_verification_response`。若验证把迭代预算耗尽，`turn_finalizer` 直接复用这份候补，不再另要一轮摘要。

只改这些文件时，verify-on-stop 不触发：`.md`、`.markdown`、`.mdx`、`.rst`、`.txt`、`.text`、`.adoc`、`.asciidoc`、`.org`、`.log`、`.csv`、`.tsv`，以及无扩展名的 `license`、`notice`、`authors`、`changelog`、`codeowners`。

办事助手可以仿看板这一闸，不跑额外业务：文本收尾时看必调工具有没有出现。没有就再给有限的一轮，并留下候补答复；有了，或次数用尽，就放行。

## 工具执行和护栏

需要现场状态的工具走 `agent/inline_tool_executors.py` 的 `INLINE_TOOL_EXECUTORS`，不经注册表。这里有待办、记忆、会话搜索、委派等。普通工具走 `model_tools.handle_function_call`，再到 `tools/registry.py` 的 `dispatch`。异常收成 JSON 错误串，仍然是工具内容。

`agent/turn_tool_validation.py` 的 `validate_tool_calls` 在分发前就配对。工具名全无效时，写下带 `tool_calls` 的助手消息，再为每条调用写一条 `role:tool` 错误，然后 `continue`。混在一批里时，无效的回错误，有效的照常执行。非法 JSON 先重试请求，满 3 次后同样注入工具结果，不用用户消息去补。未知工具名满 3 次则走部分退出，并合上未闭合的工具序列。

`agent/tool_guardrails.py` 的 `ToolCallGuardrailController` 拦的是循环，不是命令黑名单：同一参数反复失败、同一工具多次失败、只读却没有进展、同一结果连打或周期性循环，以及每轮 `web_search` 和 `delegate_task` 的上限。`warn` 仍执行。`block` 和 `halt` 不执行，由合成的工具结果拒绝。

`patmail-extension/src/agent/tools.ts` 已经把执行期异常、未知工具和坏 JSON 收成工具文本。还缺的是护栏：同一参数连错、只读没有进展时，用同样的工具消息拒绝，而不是让模型把 6 步花完。

## 记忆

内置和外挂同时存在。`MEMORY.md` 和 `USER.md` 经 `MemoryStore` 写进系统提示，每轮可见。外部 provider 的静态说明走 `system_prompt_block()`；回忆内容走 `prefetch()`，在工具循环前注入，包在 `<memory-context>` 里，并标明这不是新的用户输入。寒暄和斜杠命令会跳过 prefetch。回合结束后 `queue_prefetch` 为下一轮预热。

`on_session_end(messages)` 只在真实会话边界触发，例如 `/new`，和每回合的 `sync_turn` 分开。内置 holographic 示例可以只从用户消息里用正则抓偏好，并跳过压缩摘要。外部 provider 同时只能有一个，避免工具 schema 膨胀和后端冲突。外部预取默认大约 8 秒，超时就跳过这一轮。文档里的 cron `skip_memory=True` 已经过时：现在会加载持久记忆，但 `agent_context="cron"` 让提供者跳过自动写入。

这里没有硬门禁去拒绝「模型推断出来的事实」。软约束在工具说明和提取侧。办事助手已有的规则更严：文号、客户、日期只有用户亲口说过，或这次工具返回了，才能记住。

## 技能

`/learn` 自己不写文件。它把 `build_learn_prompt` 当成普通的一轮用户消息注入，当前代理再用 `skill_manage` 落盘。新建路径是 `~/.hermes/skills/[category/]<name>/SKILL.md`。已有同类就修补，不另起一份重复技能。

`description` 必须是一句、不超过 60 个字符、以句号结尾，写能力和触发，不写营销词，不重复 `name`。新建时超过 60 字，`skill_manage` 直接拒绝。索引侧超长则截成 57 字加省略号。系统提示只放紧凑索引，不放全文。匹配之后用 `skill_view(name)` 拉全文。用户输入 `/技能名` 时，整份 `SKILL.md` 嵌进用户消息。

策展器只在闲时整理 `created_by: agent` 的本地技能：闲置的标成陈旧，或归档到 `.archive/`，不直接删。钉住的、内置的和外部来的不动。

「`/技能名` 只办这一件」时，路由靠 description 的前 57 个字，不靠长正文。正文再写步骤。

## 辅助模型

压缩、视觉、标题、审批、技能库、复查、策展、记忆查询改写等走 `agent/auxiliary_client.py`。`session_search` 和 `web_extract` 已经不再走辅助模型。配置在 `config.yaml` 的 `auxiliary.<task>` 下，各自可以钉 provider、model、base_url 和超时。`provider: auto` 时先跟主模型。

这些调用发 `pre_auxiliary_call` / `post_auxiliary_call`，不发主循环的 `pre_api_request` / `post_api_request`，避免旁路流量被记成主回合。失败默认不打断主对话。标题失败只保留瞬时标题。压缩失败一般用占位或确定性摘要，除非打开了 `abort_on_summary_failure`。

办事助手若要写标题或摘录，应单独走一次旁路调用。不要让主模型在同一回合里顺手把没查过的事写成已经查到。

## 子代理

子代理不花父代理的迭代预算，自己有一份默认 250 次的计数。工具继承父代理的启用集，再去掉 `delegate_task`、`clarify`、`memory`、`send_message` 和定时任务工具，并禁用看板。会话是新的，记下 `parent_session_id`，默认跳过上下文文件和记忆。工作目录从父目录种到子任务自己的目录。父代理只看见摘要，中间推理和工具调用不进父上下文。过长的摘要落盘。默认 `max_spawn_depth` 是 1，子代理不能再派子代理。

机械的多步用 `execute_code`，单次工具直接调，需要用户来回确认的不要委派。办事插件的查询和建档都在同一次循环里，不必做子代理。
