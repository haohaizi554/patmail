# 三家全景

`openclaw.md`、`hermes.md`、`claude-code.md` 只写了嵌入式循环里和「6 步办事」直接相关的机制。三个仓库的主体是运行时外壳：谁持有会话、工具如何注册、提示词如何分层、消息如何进出、失败如何分账。这篇把这些层对齐。细节分在三篇运行时笔记里。

## 它们不是同一种程序

OpenClaw 是一台主机上的长期 Gateway。WhatsApp、Telegram、Slack、Discord、Signal、iMessage、WebChat 都挂在这一个进程上。控制面客户端和手机节点走同一条 WebSocket。Agent 循环是 Gateway 收到 `agent` 请求之后的内层。

Hermes 是一个 Python 库加多种入口。CLI、消息网关、ACP（VS Code / Zed / JetBrains）、批跑、API 服务都创建同一个 `AIAgent`。平台差异留在入口，不进循环。状态在每个 profile 自己的 SQLite 里。

Claude Code 是编码客户端。没有「一台机器一个网关」这层。循环在 `queryLoop`，外壳是 Ink 终端、斜杠命令、权限弹窗、MCP、子代理和远程 bridge。工具面是为改仓库准备的，不是为收发聊天准备的。

## 对照

| 层 | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 进程 | 每台主机一个 Gateway，默认 `127.0.0.1:18789` | CLI 短进程，或 `hermes gateway` 长进程；profile 隔离 | 每次 `claude` 一个客户端进程 |
| 会话主键 | `sessionKey`，写入权用 `activeWriterRunId` 围栏 | `state.db` 里的 session，压缩后旧行 `active=0` | 项目目录下的 JSONL transcript |
| 循环位置 | `runPreparedEmbeddedLoop` | `conversation_loop._run_conversation_turn` | `query.ts` 的 `queryLoop` |
| 内部消息 | 自有 AgentMessage，可投影到各家协议 | 统一成 OpenAI 的 role/content/tool_calls | Anthropic content blocks |
| 提示词 | 纯函数渲染固定段落，缓存边界以上放稳的，以下放易变的 | `stable` → `context` → `volatile` 三层，会话内字节稳定 | 系统提示加附件；中途注入走附件或用户消息 |
| 工具从哪来 | agent 工具定义 + 插件 + MCP + 渠道能力 | `tools/*.py` 在 import 时 `registry.register`，AST 扫描发现 | `src/tools/*` 编译进客户端，MCP 在两轮之间刷新 |
| 工具执行 | 会话车道串行；事件走 `tool` 流 | 多个调用用线程池并发，交互工具改回串行 | 流式执行器：只读并行，写入独占 |
| 危险操作 | exec 审批、沙箱、权限模式 | `tools/approval.py` 在执行前等用户 | `canUseTool`：allow / ask / deny |
| 上下文变长 | 预检四档，溢出后压缩，最多 3 次 | 先剪工具结果，再辅助模型摘要；网关 85%、循环约 50% | snip、微压缩、折叠、自动压缩、报错后再反应式压一次 |
| 记忆 | 工作区 Markdown + 每 agent 一份 SQLite；带来源等级 | 内置 MEMORY.md，外加至多一个记忆插件 | 回合入口预取，最多 5 条，挂附件 |
| 技能 | 索引进提示词，正文按需读；`/名` 可直达工具 | 描述 ≤60 字的索引；`/learn` 让主循环自己写技能 | 索引约 1% 上下文；调用时整段变成用户消息 |
| 子代理 | `sessions_spawn`，深度 5，每控制器 5 个 | `delegate_task`，子预算默认 250，父只见摘要 | `Agent` 工具，侧链 JSONL，可 resume |
| 定时 | Gateway 调度器；持久工作的截止时间存在 store 里 | cron 每次新建一个没有历史的 AIAgent | `ScheduleCronTool`，挂在编码会话上 |
| 扩展 | 插件 SDK、harness id、两种钩子 | 工具、钩子、平台适配器；记忆和上下文引擎都是单选 | 插件、MCP、斜杠命令、钩子 |
| 模型失败 | 先分类再决定换 profile、换模型或压缩 | 三种 API 模式互转；辅助任务不进主循环钩子 | 流式中 fallback，丢掉旧 tool_use id |

## 读仓库时的顺序

OpenClaw 先读 `docs/concepts/architecture.md`（Gateway），再读 `docs/concepts/agent-loop.md`（一轮怎么跑），然后 `docs/concepts/system-prompt.md`。代码入口是 `src/gateway` 和 `src/agents/embedded-agent-runner`。

Hermes 先读 `website/docs/developer-guide/architecture.md`，再按它列的顺序读 agent loop、prompt assembly、tools runtime、session storage、gateway。代码入口是 `run_agent.py`、`gateway/run.py`、`tools/registry.py`。

Claude Code 没有同等的架构书。从 `src/query.ts` 进循环，从 `src/tools` 看工具面，从 `src/services` 看压缩、MCP、记忆和权限旁边的服务，从 `src/commands` 看 100 多个斜杠命令。

## 三家各自守住的不变量

OpenClaw：一个 Gateway 只握一条 WhatsApp 会话；握手的第一帧必须是 `connect`；事件不重放，客户端断了要自己刷新；transcript 写入必须带上仍然有效的 writer claim，被替换的 run 不能把旧内容提交进去。

Hermes：系统提示在一次对话里保持字节稳定，只有压缩可以改历史；角色严格交替，连续的 tool 消息可以，连续的 user 或 assistant 不行；一个 profile 一套 `HERMES_HOME`，子进程丢掉这个变量就会掉回默认 profile。

Claude Code：每个 `tool_use` 必须有配对的 `tool_result`，否则接口 400；系统提示不在循环中途改写；子代理有 `agentId` 时不碰主线程的进程级锁和主会话收尾。
