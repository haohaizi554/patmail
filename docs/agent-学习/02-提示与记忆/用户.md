# 用户

`USER.md` 放稳定的偏好、说话方式、关系和正在做的项目，作为以后会话的指示。它和 `MEMORY.md` 分开预算。共享 Gateway 上，个人说明写的是发起请求的那个人，不由会话主人、任务目录或模型提供的 profile id 来选。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 文件 | 工作区 `USER.md`。可选。没有就照常启动 | `USER.md` 快照在提示的易变层 | 无对等的用户模型文件 |
| 何时重读 | 长会话的后续回合会拾起编辑 | 快照在组装时冻进提示。中途改文件不改已缓存前缀 | 设置分层 |
| 多人 | 至少两个未合并的人 profile 才有个人文件。共享的 Owner 不算另一个人 | profile 是家目录，不是 Gateway 上的人 | 本机一个用户 |
| 谁可写 | 已认证的 profile 加 `operator.read` 就能改自己的。不能改别人的 | 每个家目录自己的文件 | 本机文件权限 |

## OpenClaw

`USER.md` 是 agent 工作区里可选的用户模型。稳定偏好、沟通风格、关系和活动项目上下文写成指示，引导以后的会话。会话开始时它和 `MEMORY.md` 并排加载，有单独的、较小的引导预算。长会话里后续回合会拾起对文件的编辑。文件不在，启动继续，不因此失败。

单用户 Gateway 只用工作区根上的 `USER.md`，在 Agent 的文件里编辑。不提供个人说明编辑器或聊天工具，不接受个人文件的 API，也不加载第二份按 profile 的 `USER.md`。磁盘上已经存在的按 profile 文件留在原地，不自动并进根文件。

个人文件只在 Gateway 至少有两个不同的、未合并的人 profile 时可用，沿用已有的多用户身份政策。共享的 Owner profile 不算另一个人。花名册变了之后，重连控制界面以刷新它宣传的能力。服务器在每次读和写时重新检查当前政策。

设置里的个人说明按已登录的人保存，不按当前打开的聊天的主人。已认证 profile 加上 `operator.read` 就可以创建或编辑自己的个人 `USER.md`。不要求管理员或一般的写权限。编辑器不能改另一个人的文件，也不能改共享默认。

在任何已认证的 Gateway 聊天里，包括工作树支撑的会话、或别人拥有的会话，都可以让 agent 更新你的个人说明。`personal_instructions` 工具读或更新的是请求者在所选 agent 的配置工作区里的那份文件。会话主人、任务目录和模型提供的 profile id 从不决定写哪一份。保存前先读当前文件，并带上内容哈希。没有活的已认证请求者的匿名或自主运行不能用这个例外。普通工具策略仍然适用。在多用户 Gateway 上，用令牌、口令或设备令牌登录的共享主人，改的是那个共享主人 profile 的文件。要让不同人的文件分开，就用各自的登录。

保存核对你加载时的版本。另一个编辑者改过文件时，留下草稿再重新加载。和个人工作区编辑器一样，对独立的宿主侧编辑器的冲突检测是尽力而为。个人说明必须放进 4000 字符的引导预算。更低的配置预算和已有的出处检查仍然适用。不要存秘密。编辑器支持本地 agent 工作区。远程托管的工作区报明确错误，而不是去写另一份 Gateway 本地文件。

工作区根上的 `USER.md` 留给共享默认。个人偏好在 agent 工作区里的 `users/<规范 profile id>/USER.md`，不在任务的 Git 工作树里。手工编辑时，从 Gateway 已认证的 profile 或人员数据取耐久的 profile id。不要用显示名、GitHub 登录、邮箱，或贴进消息里的 profile id。

每个会话只选一份个人 `USER.md`：先是指派的人类主人的文件，否则是已认证的人类创建者的文件。agent 或系统的指派不阻止这个创建者回退。合格的外部聊天回合先加载共享文件，再加载选中的个人文件。个人文件是补充，不是替换。它覆盖冲突的共享用户偏好，不覆盖项目规则或安全政策。工作区根上的文件无论工作区目录叫什么，仍是共享的。没有托管推理中继的 Codex 连接只用共享工作区偏好，省掉选中的个人覆盖，因为原生线程说明可以被孩子继承。托管中继连接保留只给父级的个人 profile 投递。

文件在后续回合刷新。重新指派会话在下一个新回合改变个人上下文，不改正在跑的回合。另一个参与者可以在正常的权限和队列规则下转向，而不切换个人上下文。排队和收集的、来自多个人的消息保持会话的选择。当前发送者不另选一份文件。profile 合并选存活的规范 id。把偏好自己挪到那个目录。OpenClaw 不合并文件，也不造一份档案。缺文件或缺合格的人类身份时只用共享默认。人类指派没有 profile id 时，不退回创建者。显示标签、渠道发送者 id、未知来源的创建者 id 和 agent 主人不能选个人文件。内部事件和委派任务不自动继承个人 profile。子代理引导仍只含它已有的、允许的项目说明。

符号链接别名不接受。个人文件必须整个放进 4000 字符的用户预算，或更低的按文件或剩余总预算。否则带警告省略，而不是部分注入。这是提示选择，不是文件系统保密。工作区工具、受信任的插件、共享转录和先前生成的回复仍可能露出别人的偏好。ACP、实时会话和远程工人执行不从这项得到按人的选择。

偏好进 `USER.md`。跨会话的事实和出处进记忆。把会变的任务步骤写进用户模型，会让以后每一次会话都带着过期指示。

## Hermes

`USER.md` 的快照在系统提示的易变层，和记忆、技能索引、时间放在一起。身份在稳定层的 `SOUL.md`。项目约定在上下文层的 `AGENTS.md` 一类文件。三者不要叠成一份。

易变层在对话生命期内仍尽量保持字节稳定。中途改 `USER.md` 不会自动重写已经发出的前缀。新会话或允许的重建才会把新快照装进去。

每个 profile 有自己的家目录，因此有自己的 `USER.md`。这不是 OpenClaw 那种「一台 Gateway 上两个人各写一份、工具按请求者选文件」。Hermes 的多 profile 在秘密和记忆上失败关闭，不提供跨家的个人说明工具。

## Claude Code

没有 `USER.md` 槽。用户偏好若写在 `CLAUDE.md` 或用户设置里，就和项目说明或客户端设置放在一起。没有「别人的会话里，工具仍只改请求者自己的文件」这道身份选择。本机文件权限决定谁能改那些设置。
