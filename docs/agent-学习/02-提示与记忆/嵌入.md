# 嵌入

记忆搜索把笔记切成小块，向量和关键词并行查，再加权合并。只有一条路可用时，另一条单独跑。排序是确定性的：混合相关度乘时间衰减乘重要度。重要度在写入时算一次。没有重要度就当中性，旧索引保持原来的相关信号。MMR 只重排，不改分数，不改是否过线，也不再叫一次模型。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 查什么 | 记忆文件。措辞不必和原文一样 | 会话搜索是用户和助手正文。FTS 坏了改 `LIKE` | 预取附件，不建这套混合索引 |
| 默认嵌入 | OpenAI。要换就显式写提供商 | 记忆提供者自己的存储。没有这页上的向量加 BM25 | 无 |
| 时间 | 每日笔记 30 天半衰期。`MEMORY.md` 和 `USER.md` 不过期 | 会话行按活跃标志。压缩不删正文 | 转录文件 |
| 查询时 | 排序不再叫模型 | 搜索是 SQL | 预取失败就少几条 |

## OpenClaw

查询同时走嵌入的向量搜索和分词后的 BM25。向量对上意思。BM25 对上原词：标识、错误字符串、配置键。文件名单独索引，和笔记正文分开。完整路径、基名和词干排在部分路径匹配前面。摘录和正文关键词分仍来自笔记内容。

内置引擎的排序是混合相关度、时间衰减和重要度乘数的乘积。重要度由已经有模型在环里的记忆工作流在写入时打一次分。缺了就是中性。带日期的每日笔记按 30 天半衰期衰减。策划过的 `MEMORY.md` 和 `USER.md` 当作常青。这是相关、新近和重要三者的结果，不在查询时再叫模型。

MMR 把已经打分的混合候选重排，减少重复摘录。分数、门槛和提供商调用都不变。

默认提供商是 OpenAI，可以用 API 钥匙或合格的 Codex OAuth。换成别的要显式设置，包括 Gemini、Voyage、Mistral、Bedrock、本机、Ollama、LM Studio、GitHub Copilot 或 OpenAI 兼容端点。`provider` 也可以指向自定义的 `models.providers` 条目，只要那条的 `api` 是 `ollama` 或另一个有记忆嵌入适配器的提供商 id。

本机、不要 API 钥匙时，安装官方 llama.cpp 提供商，设 `provider: "local"`。交互设置里选一次 llama.cpp。OpenClaw 安装校验过的 `llama-server`，下载嵌入用的 GGUF，并写下它管理的服务配置。这份嵌入模型大约 0.3 GB。

有的 OpenAI 兼容端点要求不对称的 `input_type`：搜索用 `query`，索引块用 `document` 或 `passage`。用 `queryInputType` 和 `documentInputType` 设置。不设的话，这类端点会把查询和文档标成同一种，检索变差。

这是记忆文件的召回。会话搜索是另一条：查的是过去会话里的用户和助手正文，默认可见性可以跨 agent。主动记忆在确定性触发没命中、且这句话像在问过去时，才阻塞去做深召回。深召回可以用这里的工具。它不取代写入时的出处门。`untrusted` 不会因为检索分高就进策划层。

## Hermes

会话全文在 `state.db`。FTS5 损坏时拆掉索引，搜索改 `LIKE`，正文继续写。记忆提供者可以有自己的向量或图。那是插件的实现，不是 Gateway 里固定的「向量并行 BM25、每日笔记 30 天半衰期、策划文件不过期」。cron 默认不做记忆。

## Claude Code

记忆预取把命中的片段当附件。没有查询时的 MMR，也没有按文件种类区分半衰期。预取失败只是少几条附件。
