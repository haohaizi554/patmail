# 语言

界面文案按层查找，命中即停。插件语言包最后加载的优先，然后是这个家目录里的覆盖，然后是随发行附带的，再对英语走同样三层，最后是裸键。每一层都可以只写自己改的键。agent 的回答、工具输出、日志和斜杠命令的名字不在这套翻译里。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 界面 | 文档和客户端有自己的语言流程 | `display.language`。层可插 | 客户端语言 |
| 谁覆盖 | 插件可以贡献文案 | 插件包、家目录 `locales/<lang>.yaml`、发行包 | 无这套层 |
| 部分 | 未知 | 每层可以缺键 | 未知 |
| 模型回答 | 不由界面包决定 | 要模型用另一种语言，写在提示里 | 提示和模型 |

## Hermes

查找顺序是：声明了 `provides_locales` 的已安装插件，两个包覆盖同一键时后加载的赢；然后是 `<家目录>/locales/<lang>.yaml`，每个 profile 自己的目录；然后是发行里的 `locales/<lang>.yaml`；然后对英语重复这三层；最后是裸键。

`hermes config set display.language` 接受任意一层提供的 id。不认识的 id 被拒绝，并列出可用语言，提示去装插件或放一份覆盖文件。

包翻译的是静态界面：CLI 的批准提示、网关回复、工具动词、提示、TUI 和桌面。agent 的回答、工具输出、日志和斜杠命令的名字保持原样。要回答本身换语言，在提示或 `SOUL.md` 里说。

改语言会丢掉按家目录和语言合并好的缓存。包注册和 `config set display.language` 都会重置这份缓存。TUI 用的 `.tui.yaml` 和桌面用的 `.desktop.yaml` 在 Python 侧只负责解析、展平和提供。TUI 的 TypeScript 本身只带英语，捆绑的 `locales/<lang>.tui.yaml` 是 TUI 表面目录的最底层。

内置语言的自称要和共享的语言表一致。未知的界面键显示裸键，而不是空白或崩溃。

## OpenClaw

界面和文档有自己的翻译流程。agent 看见的系统提示、时间信封和工具结果不走 Hermes 这种四层回退。用户时区和主机区域设置决定钟的写法，不决定界面语言包。

## Claude Code

客户端的界面语言是安装和设置的事。模型用哪种语言回答，由提示和模型决定。没有「插件包盖过家目录覆盖、再盖过发行包、最后裸键」这一份查找。
