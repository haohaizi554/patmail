# 上下文引擎

管理上下文的策略可以换成插件，但同时只能有一个。插件引擎不会自动激活。配置里的 `context.engine` 必须写成它的名字，默认仍是内置的压缩器。换引擎会改变历史怎么被裁和摘要，也就是改变前缀缓存何时断开。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 接口 | 上下文引擎：摄入、组装、压缩、回合之后。默认 `legacy` | `ContextEngine`。内置是 `ContextCompressor` | 请求前的分层裁剪和自动压缩 |
| 选择 | 引擎是 Gateway 的选择。节点不换一套提示 | `context.engine`。插件永不自动启用 | 无插件引擎名 |
| 数量 | 一条会话一条策略 | 同时一个 | 客户端一种 |
| 失败 | 压缩超时可以在没有摘要时提交 | 摘要停滞走回退链，再失败用确定性摘要 | 三次失败断路器 |

## Hermes

上下文管理建立在 `agent/context_engine.py` 的 ABC 上。插件要实现同一接口，用来替换内置压缩器。例如用知识图代替有损摘要。目录在 `plugins/context_engine/<name>/`。

配置写成 `context.engine: compressor` 用内置的。写成插件的名字才启用那个插件。没有「装上了就替换」的自动步骤。装错或没写名字，跑的仍是内置压缩器。

内置路径先裁旧工具结果，再按阈值摘要。微压缩是在这之上、默认关闭的按回合吸收，不是第二个引擎。辅助压缩模型可以单独指定。引擎若换成不摘要的实现，工具结果预算和提示缓存的假设都要按那个实现重新看。系统提示的字节稳定和「压缩是唯一允许的上下文变更」是 agent 的不变量。新引擎若在回合中途改系统提示或重载记忆，会打破缓存，也会让同一条对话的前缀对不上。

子代理可以跳过上下文文件。引擎仍是进程里配置的那一个，不是每个孩子一个引擎，除非孩子的配置自己指定。

## OpenClaw

上下文引擎负责摄入、组装、压缩和回合之后。默认是 `legacy`。压缩有 safeguard。超时可以提交而不带摘要。节点上的会话仍由 Gateway 做上下文引擎、历史准备和回合结算。节点只提供工作区路径和主机事实。

裁剪投影是另一条：等缓存 TTL，再软裁和硬清工具结果，原文不改写。那不是把压缩器换成知识图。

## Claude Code

没有可替换的上下文引擎名字。请求前按预算裁工具结果，再剪、折叠和自动压缩。还原树里有的步骤是桩。换一套策略意味着换客户端，不是改一个 `context.engine` 键。
