# 技能

技能是给模型看的操作说明，不是新的核心工具。三家都只把名字和短描述放进常驻上下文，正文在被点名时再送进去。这样几十个技能不会把系统提示撑满，也不会在一轮中途改掉已经缓存的前缀。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 载体 | 目录里的 `SKILL.md` | 同样是 `SKILL.md`，描述不超过 60 字 | `SKILL.md`，索引大约占上下文的 1% |
| 常驻的 | 快照里的索引 | stable 层里的索引 | 名字加描述 |
| 正文何时出现 | 模型按说明去读，或斜杠直接调用 | 作为用户消息注入 | `getPromptForCommand` 变成用户消息 |
| 谁写新技能 | 工坊提案，人批准后才进库 | 主循环 `/learn` 自己写；策展只归档 agent 写的 | 用户或插件提供 |
| 同名时 | 工作区优先于内置 | 用户技能覆盖同名内置的可见项 | 调用时解析到一份正文 |

## OpenClaw

文件技能按优先级加载，同名时高的赢：

1. `<workspace>/skills`
2. `<workspace>/.agents/skills`
3. `~/.agents/skills`（仅默认状态目录）
4. `<state-dir>/skills`
5. 该 agent 的 `workshop-skills`
6. 安装包自带，以及只给 Custodian agent 的保管技能
7. `skills.load.extraDirs` 和插件技能

执行工作区若和会话工作区不同，也会加载那边的 `skills/` 和 `.agents/skills/`，但排在整个 agent 目录之后。沙箱读的是同步过去的副本，不读主机原路径。托管 worktree 仍以记录的规范工作区为技能源，在 Gateway 上读和监视。节点不接收 Gateway 的源路径。模型侧用 `workspace-skill://` 读，避免一条相同的 Gateway 路径被指到节点上。选中的嵌套工作区不会往父仓库上爬。从仓库安装 OpenClaw，不会把那个仓库的 `.agents/skills` 变成全局内置源。

`SKILL.md` 在配置根下最多 6 层都会被发现。找到一份就不再往下走。目录只用于归类，名字来自 frontmatter 的 `name`，没有则用目录名。允许名单也按这个名字匹配。无效文件跳过，同级的有效技能仍加载。每次发现对每个根打一条摘要：数量和最多三个例子。工作区覆盖内置、worktree 覆盖检出，记成警告。内容相同则安静。

Codex CLI 自己的 `$CODEX_HOME/skills` 不是 OpenClaw 的根。要先 `openclaw migrate plan codex` 盘点，再复制进工作区。

节点可以发布它自己技能目录里的技能。连着就出现在名单里，断开就消失。和本地或 Gateway 撞名时，本地保留原名，节点技能得到确定的节点前缀。v1 要求目录名和 frontmatter 的 `name` 一致。文件在节点上，要用 `exec host=node` 去读和跑。

工坊技能只属于写出它的那个 agent。要给多个 agent 用，就发布到托管库。`OPENCLAW_STATE_DIR` 不是默认 `~/.openclaw` 时，会话索引排除 `~/.agents/skills` 这类家目录根。

共享 Gateway 上，个人库按已认证的 Gateway 配置文件选，不按扫盘。共享令牌认不出人。新技能属于创建者。分享给团队不给编辑权。转给团队改的是管理权，不挪文件，也不改稳定 id。同名可以共存，调用时用选择器或返回的命令身份，避免一份悄悄替换另一份。技能内容不是秘密仓库，也不因此多出工具或主机权限。

保存发布一份不可变修订：`SKILL.md` 和全部附属文件。哈希含可携带路径、内容、大小和可执行标记。只改一个辅助脚本也算新修订。分享、所有权、ZIP 时间戳和归档顺序不算。过期的编辑冲突失败，不覆盖较新修订。会话记住自己选中的 id 和修订。别人加入或接管会话不替换这份选择。已发布的变更给新会话；老会话要显式附加或刷新，下一轮才用上。从库里移除不删除已被会话选中的修订。禁用只影响新会话的默认项。

新会话最多选 64 个已启用的库技能，个人的在前，组内按稳定 id 排。启用绕不过 agent 允许名单、所需二进制和操作系统限制。一个包最多 256 个文件、单文件 1 MiB、合计 8 MiB。记录在 `state/openclaw.sqlite`，包在 `skill-library/<id>/revisions/<hash>/`。不要手改这些目录。

位置和可见性是两件事。`agents.defaults.skills` 是共享基线。`agents.entries.*.skills` 整份替换该 agent 的名单，不是合并。

一轮开始时技能收成快照，注入环境和提示。快照避免目录在这一轮中途变化。提示词只教模型如何按需加载正文，不把每份正文都放进去。

## Hermes

索引放在提示词的 stable 层，和身份、工具说明一起缓存。描述是一句话，不超过 60 个字符，以句号结束，不写营销词，也不重复技能名。正文在被调用时作为用户消息进入，不改系统提示。项目文件和技能索引因此可以在多次调用之间保持字节稳定。

内置技能在 `skills/`，按类别放。更重的在 `optional-skills/`，要 `hermes skills install` 才激活。frontmatter 里的 `platforms` 必须和脚本真实用到的系统接口一致。模型面对的是 Hermes 工具名，不是它已经包过的 shell 命令。

`/learn` 让当前循环自己写技能，写完仍走同一套索引。策展只碰 `created_by: "agent"` 的技能。内置和从中心安装的不进自动归档。固定的技能不参与自动转移。删除被拒绝时，修补和改文件仍可以。归档是上限，不删除。用量记在技能家目录的 `.usage.json`。

cron 把挂上的技能按顺序作为用户消息注入那次没有历史的新 agent。旧任务若只有单个 `skill` 字段，加载时收成 `skills` 数组。

表面从桌面切到 TUI 时，已存系统提示不动。当前表面的说明作为一次性用户消息送出，技能索引留在原来的前缀里。

## Claude Code

斜杠命令大约一百个，和技能不是同一张表。命令可以在本机执行、打开终端界面，或变成提示词。以 `/` 开头的输入不在模型思考中途展开，等这一回合结束再处理。中途插话进队列，在工具轮之后变成附件。

技能平时只占索引。用户点名或模型调用技能工具时，正文整段变成用户消息。`context: fork` 则改由子代理执行，主转录不承担那份正文。

技能搜索的部分目录在这棵 2.1.88 还原树里被裁过，调用点还在。笔记只记「索引常驻、正文按次注入」，不把缺失的搜索实现当成完整的技能中心。
