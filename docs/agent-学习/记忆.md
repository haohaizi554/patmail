# 记忆

三家都把「这一轮要用的上下文」和「以后还能找回来的事实」分开。写入比检索难，而且写入是安全边界：来源不可信的内容不能靠以后的扫描洗白。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 人能直接改的 | 工作区 Markdown | `MEMORY.md`、`USER.md` | 会话记忆目录，预取结果是附件 |
| 索引 | 每个 agent 一份 SQLite | 内置存储加至多一个外部提供者 | 预取不建第二套系统提示 |
| 谁写入长期层 | 梦境整理是策划层的主写入者 | 内置工具与一个外部 `MemoryProvider` | 回合结束可抽取；预取只读 |
| 不写入的会话 | cron、心跳、子代理不产可提升候选 | cron 默认 `skip_memory` | 子代理跳过主线程的记忆抽取 |
| 失败时 | 记忆步骤有超时，不吃掉这一轮回复 | 提供者失败不改主循环的角色交替 | 预取失败就少几条附件 |

## OpenClaw

五条规则：没有隐藏状态，模型只记得写进工作区文件的东西；策展放在回复路径之外；写入时记下出处，而不是事后扫描有没有投毒；打分和门槛是确定代码，模型只在门槛里面做语言判断；记忆失败只降低召回，不挡住回复。

层级：

| 层 | 文件 | 谁写 | 何时进入上下文 |
|---|---|---|---|
| 指令 | `AGENTS.md` 等 | 人 | 会话开始，总是 |
| 策划核心 | `MEMORY.md`、`USER.md` | 梦境整理，或用户直接要求 | 会话开始，且出处合格，有预算 |
| 情节 | `memory/YYYY-MM-DD.md`、transcript | 工作中追加、压缩前刷写、会话结束摄入 | 召回时，不在会话开始灌入 |
| 前瞻 | 长期意图、cron | `intent` 工具、定时任务 | 触发器开火时 |
| 审阅 | `DREAMS.md` | 梦境各阶段 | 不注入，给人看 |

情节层进策划层必须过门。来源等级是闭集：`owner`、`agent`、`untrusted`、`system`。判不出来时，外部内容当 `untrusted`，脚手架当 `system`，永远不默认成 `owner`。会话种类记交互、cron、心跳或子代理。还有观察时间和替代键，新观察替代旧事实，而不是并列堆积。

cron、心跳、子代理可以写任务产物，不能产生可提升的长期候选。已经注入过的记忆、搜索结果和 transcript 摘录有结构标记，再抽也不会变成一条新记忆。

工具结果若声明来自网络，这一轮剩余的助手消息都带污点，记忆分类把它们当 `untrusted`。下一条用户消息清除污点。只有声明了网络来源的工具参与；本地读文件不污点，助手文本保持该轮本来的出处。

梦境默认开启，分阶段。浅层和 REM 去重、暂存、写主题反思，不动长期文件。深层先过确定性门：按检索相关、召回次数、问法多样性、新近、跨日重复、概念丰富度排序，门槛全过才行。`untrusted` 和 `system` 在组提示词之前就排除，召回再勤也不能提升。然后才把合格候选和当前 `MEMORY.md` 交给整理模型：合并、按替代键退休、保持短、用来源锚点指回每日笔记。

整理结果要能通过结构校验、不超出 bootstrap 预算、丢失的旧条目不超过限定比例。被拒则这一扫只追加，不整文件替换。替换前核对整理开始时的内容哈希，中途被人改过就放弃这次替换。接受的重写留下替换前镜像，并把人能读的变更摘要追加到 `DREAMS.md`。

召回分两条。第一条不加模型调用：合格的 `MEMORY.md` / `USER.md` 按预算注入；`memory_search` 用混合相关乘 30 天半衰期的新近衰减，再乘写入时定下的重要度（1 到 10，没有则中性）；触发短语得分不低于 0.72 时，每轮最多注入三条，且只来自策划层。每日笔记和 transcript 再匹配也不自动注入。第二条是召回子代理，默认只在消息明显在问过去、并且第一条没有强命中时才跑。

仓库工作在条目上标项目键，键来自规范化的 `origin` 远程。同一仓库的普通克隆和 worktree 共用一把钥匙，fork 分开。会话最多记四个最近仓库。搜索给这些仓库加权，给其它仓库轻微降权，没标签的保持中性。触发注入更严：条目上的每个项目键都得在活跃集合里。`USER.md` 和长期意图保持用户级，不按项目切开。

`sessions_history` 做跨会话查看时返回打过红的有界视图，去掉思考签名、工具结果细节和工具调用标签，再按字节截断。

## Hermes

内置记忆是 `MEMORY.md` 加 `USER.md`，放在提示词的 volatile 层，所以换事实会动缓存前缀的后部，不动身份和工具说明。外部记忆是插件，配置 `memory.provider`，同时只能一个。内置工具和这一个外部提供者可以并存。

提供者实现 `MemoryProvider`：`sync_turn`、`prefetch`、`shutdown`，可选 `post_setup`。预取大约 8 秒超时。`sync_turn` 只在完整、没被打断的回合之后跑。cron 用 `agent_context=cron`，默认 `skip_memory=True`，定时任务不写记忆。

会话在任何地方结束都要跑抽取和 `on_session_end`：正常回合、驱逐、关闭、TUI 拆卸。调用方先绑这个会话所属 profile 的 scope。agent 不在刷写时从环境变量猜家目录，数据库路径的父目录才是依据。后台线程从 `spawn_context_thread` 起，带着 contextvars。裸线程会掉进启动 profile。

多 profile 打开之后，`get_secret` 在没有 scope 时失败关闭。隔离是 profile 之间。子进程的 scope 在 spawn 前解析进环境，contextvars 过不了进程边界。

提示词把记忆收窄：跨任务仍成立的事实才进记忆；步骤、坑和偏好进技能。怀疑旧对话里有内容时先 `session_search`。

`/learn` 走主循环自己写技能，不把技能正文写进系统提示。技能索引在 stable 层，描述不超过 60 个字符。

## Claude Code

回合入口的记忆预取是非阻塞附件，最多大约五条，不改系统提示。实现挂在 `query.ts`，散在附件和 `memdir`。这和 `extractMemories` 不是一条路径：预取给这一轮看，抽取是回合结束后的副作用。

子代理带 `agentId` 时，主线程那份停止钩子里的记忆抽取不跑。子代理的转录在 `subagents/agent-<id>.jsonl`，不混进主会话的记忆副作用。

`SessionMemory`、`teamMemorySync`、`autoDream` 是服务层的会话记忆、团队同步和后台整理。`AgentSummary` 和工具调用小摘要给界面和 `claude ps`，不是给模型的事实来源。主线程才跑工具调用的小模型摘要；子代理跳过，避免和主线程抢同一份进程级状态。
