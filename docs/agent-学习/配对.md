# 配对

配对回答的是「这个人能不能跟机器人说话」和「这台设备能不能连上 Gateway」。它不授予群权限，也不自动变成命令主人。聊天允许名单、群策略和提权是后面的门。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 私聊陌生人 | 策略为 `pairing` 时发短码，消息先不处理 | 私聊配对加允许名单 | 没有渠道。坐在终端前的人就是操作者 |
| 设备 | 节点以 `role: node` 连接，要设备配对 | 无手机节点协议。桌面用自己的后端令牌 | SSH 或远程会话仍走本机权限门 |
| 主人 | `commands.ownerAllowFrom`。第一次 CLI 批准可以写入 | 网关允许名单和 profile 级令牌锁 | 本机用户。子代理不能替主会话做主 |
| 群 | 私聊批准不打开群 | 群默认按人切会话，授权另算 | 无 |

## OpenClaw

两处配对。私聊配对决定谁可以给机器人发直接消息。节点配对决定哪台 iOS、Android、macOS 或 headless 设备可以加入 Gateway。

私聊策略是 `pairing` 时，未知发送者得到一个短码，这条消息不进入 agent。码是 8 位大写，避开 `0O1I`。一小时过期。同一个发送者大约一小时只发一次配对提示。每个渠道账号最多挂 3 个未决请求，多出来的先忽略。

`dmPolicy: "open"` 只有在有效允许名单包含 `"*"` 时才是公开的。已有配置若是 `open` 却写了具体的 `allowFrom`，运行时仍只放行那些发送者。配对库里的批准不会把 `open` 放宽。

控制界面在设置里的私聊访问请求中批准。批准只给直接消息，不给群。可选通知请求者。还没有命令主人、且当前会话有 `operator.admin` 时，可以把这个发送者设成第一个命令主人。驳回只丢掉这一次请求，不是永久封锁。

命令行 `openclaw pairing approve` 在还没有命令主人时，会自动把这次发送者写进 `commands.ownerAllowFrom`，例如 `telegram:123456789`。已经有主人之后，后来的批准只加私聊访问，不加主人。手写进允许名单的发送者不会自动成为命令主人。没有主人权限时，仅主人可用的命令会回复该怎么设置的那一行配置。

`openclaw channels add` 可以在不走私聊配对的情况下设置操作者账号。跳过则所有权不变。所有权允许 `/update`、重启 Gateway、改配置和批准命令。它不自动授予聊天权，也不替换已有主人，也不把聊天允许名单提升成主人。WhatsApp 扫码登录是把一个 WhatsApp 账号接到 OpenClaw。私聊请求批准的是给这个账号发消息的人。两件事分开。

同一组可信发送者要用于多个渠道时，用 `accessGroups`，类型 `message.senders`，在允许名单里写 `accessGroup:<名字>`。

状态在 `~/.openclaw/state/openclaw.sqlite`：未决请求和已批准发送者，按渠道和账号做键。使用配对 API 的渠道只读这些行，不合并旧文件。旧的 `*-pairing.json` 由 `openclaw doctor --fix` 导入后删除。普通启动不动那些旧文件。这张库等于助手的门禁。

节点连接时 Gateway 建立设备配对请求。控制界面在设备页创建安装码。官方 iOS 和 Android 应用在安装码元数据吻合时自动批准。非官方客户端或元数据不符则留在待批准，先看角色和范围。没有管理员权限时，按钮不可用，改在 Gateway 主机上用 CLI。本机回环可以自动批准。Tailnet 和局域网即使绑在本机，也要显式批准。所有连接都要签 `connect.challenge` 的 nonce。

## Hermes

网关用允许名单加私聊配对。`gateway/pairing.py` 管私聊配对流程。一个 profile 一把令牌锁，保证这个家目录只有一个网关进程握着渠道凭据。适配器在连接时获取 scoped lock，断开时释放，这样两个 profile 不能共用同一个 bot token。

多路复用打开后，每个 profile 有自己的适配器和秘密。私聊是否允许，读的是该 profile scope 里的门禁，不读进程环境。范围已装上且多路复用开着时，scope 里没有的项返回默认，不回退到 `os.environ`，否则启动 profile 的允许名单会拒绝所有次要 profile 的发送者。

忙碌时的 `/approve` 和 `/deny` 必须绕过两道消息守卫并当场分发。这是在批准框挂起时仍能回答，不是配对本身。配对发生在消息进入会话之前。

命令主人和聊天允许在 OpenClaw 里是分开的两列。Hermes 里对应的是：渠道允许名单决定这条消息进不进会话，工具批准决定进了会话之后某次命令能不能跑。

## Claude Code

没有「未知私聊先发短码」这一层。操作者是启动这个客户端的人。远程和 SSH 会话把同一套 `canUseTool` 带到另一台机器或另一条连接上，不另发一套渠道主人。子代理使用不同的拒绝文案，因为它不能替主会话批准。

计划模式和 worktree 限制的是改哪些文件，不是谁可以开始这次会话。
