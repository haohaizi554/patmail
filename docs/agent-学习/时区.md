# 时区

模型看见的时间要有一个参考，而不是混用各提供商的本地钟。日期和时区放在系统提示缓存边界之下，这样跨日只让易变尾失效。精确的此刻不写进提示，需要时再调工具。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 信封 | 入站消息包上用户时区的本地时间 | 发送者前缀。时间不靠渠道信封 | 无渠道信封 |
| 提示 | 易变的时间上下文只有日期和时区。精确时间用 `session_status` | 日期行按天稳定，带时区偏移 | 客户端本地时间 |
| 工具 | 原始提供商时间保留，同时给毫秒和 UTC | 工具结果里的时间戳随内容 | 工具输出原文 |
| 用量日历 | 默认 UTC。指定模式可用 IANA 时区 | 测试和调度按各自的钟 | 无跨会话用量日历 |

## OpenClaw

三处时间各干各的。消息信封把入站包装成带本地时间的前缀，默认主机时区，可用 `agents.defaults.userTimezone` 覆盖。渠道读取一类工具返回提供商原始时间，并带上规范化的 `timestampMs` 和 `timestampUtc`。这两项始终存在，不可配置，原始时间也保留。系统提示里的时间上下文在缓存边界之下，只有本地日期和时区。精确钟点故意不放进提示。`session_status` 可用时，模型调用它来取此刻。

未设置用户时区时，运行时用 `Intl` 解析主机时区，不写回配置。同一解析结果用于消息信封、排队的系统事件、提示里的本地日期，以及心跳的活动时段。钟的 12 小时或 24 小时跟随主机操作系统和区域设置，没有单独的配置项。

跨日只改边界之下的那一段，稳定前缀可以继续复用。心跳是否在活动时段内，用的是这同一个用户时区，而不是模型提供商所在的时区。

用量的日期范围默认按 UTC。指定模式传入合法的 IANA 时区，才按本地日历日和夏令时切分。

## Hermes

系统提示的日期行按天保持字节稳定，并带时区偏移，避免每一分钟重建前缀。运行环境块在易变层的最后。压缩重建时日期仍按重建当天那一条稳定规则。

cron 的时刻表用任务自己的时间解释。漏跑窗口是周期的一半，并有上下限。一次性任务有短暂的宽限。这是调度钟，不是提示里的展示钟。

测试运行把 `TZ` 设为 UTC，避免本机时区让断言漂移。那是测试隔离，不是用户配置。

## Claude Code

时间来自运行客户端的机器。提示和工具输出里出现的钟点就是当时的本地或 UTC 字符串，没有三层表面各自的合同。跨日不会为了保缓存而把精确钟点从系统提示里拿掉，除非客户端自己的提示组装这么做。会话 JSONL 里的时间戳是记录，不是给模型的唯一参考钟。
