# 办事助手可借鉴

对照 `patmail-extension/src/agent/loop.ts` 和 `tools.ts`。当前一轮最多 6 步：先做原文摘录，有工具就执行并写回，没有工具就把正文当最终答复。未知工具、坏 JSON 和抛错已经回成工具消息。原文摘录不用模型改写，是为了避免把没查过的文号写成已经查到。这条和 Hermes「只有压缩可以改历史」、Claude Code「系统提示保持稳定」是同一方向，保留。

下面按落地顺序写。数字取三家规则缩小后的值，适配 6 步，不照搬它们的默认阈值。

## 1. 说做完了，先核对工具

Hermes 的 kanban 闸和 Claude Code 的 `stop_hook_blocking` 是同一件事：模型给出正文时，先看本轮该出现的工具在不在。

用户要建工作流或发文任务时，扫本轮工具记录。对应工具没出现，或返回的是失败，就把这段正文存成候补，再追加一条用户侧说明：「去调用工具，不要只叙述。」最多再推 2 次。步数用尽时用候补收尾，不再另写一句「已经到上限」。不要用硬停把这一轮直接掐掉，那会丢掉模型已经说出的进度。

## 2. 同参数连打就停

OpenClaw 对 6 步助手给出的缩小规则：同一轮里相同工具加相同参数，无进展出现第 3 次就警告，第 5 次硬停。未知工具连续 3 次停。Hermes 对全部无效的工具名也是 3 次后停轮。

PatMail 的 6 步上限挡得住无限循环，挡不住把同一个文号查满 6 次再报上限。硬停时说明卡在哪一次查询。参数抖动但结果不变，先警告仍放行，不要立刻杀。

## 3. 失败不能说办成

OpenClaw 在无可见回复时强制报失败，否决工具时写入 `blocked`，不静默当成功。Claude Code 把拒绝写成 `is_error` 的工具结果。

收尾前扫一遍工具原文。出现失败句，就在这一轮的答复约束里写明：先说哪一步没成。提交类动作保持「不能代点」：起草可以做，提交返回明确的拒绝，让模型换做法或停下来问用户。这种拒绝不要中止整轮，否则连起草结果一起丢。

## 4. 步数用尽时无工具收尾

Hermes 触顶后 `handle_max_iterations` 再请求一次摘要，摘要失败才用固定文案。PatMail 现在直接写入「这轮工具调用已经到上限」。

最后一次请求关掉工具，只根据已经发生的工具原文写：做成了什么、停在哪里。模型没写出正文时，再退回固定文案。若第 1 条闸门存了候补，优先用候补。

## 5. 先裁工具结果，再摘录

三家都是这个顺序。Claude Code 单条默认 5 万字符，同一轮合计 20 万，超限先换掉最大的新结果。OpenClaw 保留头和诊断尾。Hermes 先把旧工具结果收成一行桩，失败不半提交，并有冷却，避免来回压。

PatMail 的查询结果现在整段进对话。先给单条一个字符上限，超出就留头尾和一句「中间已省略」。原文摘录继续只折旧轮次，不要改成让模型写摘要。压缩或摘录连续失败 3 次就停，不要在同一轮里反复试。

每个工具调用都要有一条结果。异常、未知工具、用户中止，都回一条写明原因的工具消息。缺了这一条，下一圈请求会对不齐。

## 6. 技能只放短索引

Hermes 的描述不超过 60 字，因为索引每轮都在，超长会被截掉，路由失效。OpenClaw 和 Claude Code 的系统提示也只放名字、描述和位置，正文在用户点名或模型读取时整段注入，注入位置是用户消息，不是系统提示。

「以 `/技能名` 开头只办这一件」挂在斜杠解析之后：这一轮的用户消息带上该技能正文，并写明只办这一件。常驻列表只留短描述。不要把单次推断自动写成新技能。

## 7. 记忆别每轮改写系统提示

Hermes 和 Claude Code 都把系统提示保持到会话结束。每轮召回挂在当轮用户消息或附件上，和生成并行；没来得及就算了，下一圈再试，不挡第一段回复。Hermes 只在完整且未中断的一轮结束后写入。OpenClaw 给记忆标来源，网络内容标成不可信，不自动注入。

PatMail 现在把最近事实拼进系统前言，对话短、没有提示词缓存时可以。事实变多以后，前言只留不变的办事规则；本轮召回另挂一条消息。写入继续遵守「用户亲口说过，或这次工具返回了」。中断的一轮不写。定时或后台任务不写用户记忆。

## 先不做

这些在三家里是为长会话、多渠道或动态工具目录准备的，浏览器里的专利办事用不上。

- 会话车道加全局车道、认证 profile 轮换、模型回退链。单模型只需把错误分成限流、认证、溢出、超时，溢出时截工具结果，限流时退避。
- 流式并行工具的完整执行器。若以后要并行，只让只读查询并行，建流程、改字段、建任务和 `remember` 独占。
- 子代理。三家的子代理都隔离转录、只把摘要交回父会话，并且故意不碰主会话的界面和锁。办事要改工作台，工具应留在主循环。
- MCP 式的两轮之间刷新工具名单。现有工具是编译期固定的。
- 辅助模型全家桶。以后若要做标题或摘要，单独请求，结果以新消息注入，不要走主循环，也不要改已经发出的历史。
