# 登录

网站登录的口令在本机加密，填进页面。模型看见的是填了几个字段、以及源站。口令再登记进打红器，后面的页面读取不能把它回显出来。第一次没有保存的登录时，用打码提示问人。不保存则这一轮不再问。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 口令 | SecretRef 和认证 profile。页面登录不是这套保险库 | 按源站绑定。加密后注入。工具结果不含口令 | 无按站点的登录保险库 |
| 询问 | `ask_user` 和批准卡。自由文本不授权配置 | 打码提示或桌面卡片。不保存就停止这一轮的询问 | 权限对话框 |
| 回显 | 日志和快照打红 | 打红器挡住随后的页面读取 | 工具结果可能含页面正文 |
| 和钥匙 | 提供商 API 钥匙不是网站口令 | `.env` 的 API 钥匙和站点口令分开放 | 客户端设置里的钥匙 |

## Hermes

对人说登录某个站。第一次到达没有保存登录的登录页时，当场用打码提示问人。之后同一源站直接填。口令加密存在这台机器上，绑定到那个源站，注入页面。模型始终看不见口令。

CLI 和 TUI 先要标识，再要隐藏的口令。桌面是一张保存登录的卡片。保存并登录会存下来并继续。不保存会告诉 agent 这一轮别再问。

之后 agent 列出已存登录，自己输入标识，口令经 Hermes 填入。它看见的工具结果是填入字段的数量和源站，例如一个字段和 `https://github.com`。口令同时登记给打红器，随后读页面不能把口令带回来。

这和提供商 API 钥匙不同。API 钥匙在 `.env` 或秘密源，给出站调用。站点口令只进那个源站的页面。把口令写进 `USER.md`、记忆或聊天，会让模型以后每次都读到明文。这条路径故意不那么做。

打红是启发式。登记进打红器能挡住回显，不能挡住 agent 在填入之前已经从别的文件读到的同一串字符。进程内的插件仍能读 agent 能读的内存。操作系统隔离才是边界。

铁代理注入的是出站 API 的映射，不是浏览器登录表单。两套都避免把秘密放进模型上下文，机制不同。

## OpenClaw

提供商 OAuth 和 API 钥匙在认证 profile。配置不放秘密。浏览器可以带登录过的配置档。那是浏览器自己的配置，不是「模型只看见 filled_fields」的合同。用户在群里交出的短时登录码，提示要求私发回请求者，群里不重复码。

SecretRef 在出网前用哨兵。那是配置秘密，不是网站口令库。

## Claude Code

没有按源站加密、模型只看见填充次数的登录库。浏览器或抓取若把登录页的 HTML 放进工具结果，正文受结果预算，也可能含用户贴进来的秘密。权限询问决定能不能跑命令，不代替打码的口令注入。
