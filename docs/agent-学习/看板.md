# 看板

看板是一份能熬过进程重启的任务队列。每张卡是数据库里的一行，每个工人是带着自己 profile 的操作系统进程。它和一次 `delegate_task` 不是同一件事：委派是函数调用，看板是别人也能看见、也能接着改的交接。

OpenClaw 用会话目标、长期意图、子代理和 cron 拆工作，没有这张跨 profile 的板。Claude Code 的任务工具是这一次编码会话里的清单。下面是 Hermes 的板。

## 两扇门，一块库

人和脚本走 `hermes kanban`、斜杠 `/kanban` 或面板。模型走 `kanban_*` 工具，不去 shell 里再调一遍 CLI。两边进入同一层 `kanban_db`。工人由调度器拉起时，这些工具已经在 schema 里。编排 profile 也可以显式打开 `kanban` 工具集。普通会话默认没有这套工具，所以工具面不会在每次聊天里膨胀。

`delegate_task` 要等孩子回来，孩子没有持久身份，失败就是失败，压缩之后审计会丢。看板创建之后不用等。工人是有记忆的命名 profile。阻塞之后可以解开再跑。崩溃可以由调度器收回。人可以随时评论。一张卡的一生里可以换好几个角色。任何 profile 都能读和写。

工人自己的短推理仍可以在运行中调用 `delegate_task`。那是卡内部的函数调用，不会变成板上的另一行，除非有人去创建。

被 `t_parent` 挡住的工人如果再建一张支援卡，不要把支援卡 `link` 成父卡的孩子。那样支援卡要等父卡完成，父卡又在等支援，两张都不跑。父 id 写在支援卡正文里。`link` 若把一张 `ready` 的孩子降级，会标 `gated: true` 并记下 `dependency_wait`。`unlink` 能放开。

## 行上有什么

一块板是一份 SQLite、一块工作区目录、一个调度循环。默认板就够单项目用。任务有标题、可选正文、一个 assignee（profile 名）、状态、可选租户、可选幂等键。状态包括 `triage`、`todo`、`ready`、`running`、`blocked`、`review`、`done`、`archived`。

链接是父到子的依赖。所有父卡 `done` 之后，调度器才把 `todo` 推进到 `ready`。给已经在跑的孩子加链接会被拒绝，因为它管不住已经领走的工作。例外是当前工人在交依赖阻塞之前，用调度器给的这次运行所有权，链自己的卡。

评论是 agent 之间的协议。工人被拉起或再次拉起时，读整串评论。

工作区有三种：

- `scratch` 是临时目录，任务完成时删掉。用 `kanban_complete` 或 `kanban_request_review` 的 `artifacts` 声明的文件，会先拷进耐久附件。声明了但找不到的文件让任务留在进行中，以便改路径再试。第一次在这台安装上创建 scratch 时，板上会有一条提示事件。
- `dir:<绝对路径>` 指向已有目录，完成后保留。相对路径在派出时拒绝，因为会跟着调度器当时的当前目录走。
- `worktree:` 让整个工作树在完成后仍可用。

`dir:` 信任本机用户。工人以你的 uid 跑。这不是多租户操作系统隔离。

## 完成和验收

调度器拥有的工人在有限迭代预算大约 90% 时收到一次检查点，附在一条新的工具结果上，此时还留有一次能调工具的调用。更小的预算最晚在倒数第二次迭代提醒。一次迭代的运行没有这扇窗。通知先写入会话，再发下一次请求。工人应在核对任务合同之后才 `kanban_complete`，或者写一条进度评论再继续。一次提交或一份 diff 不会自动完成任务。普通对话和委派孩子不继承这个自动检查点。

硬上限、没有工具的最终摘要、连续失败熔断仍在。默认连续两次非成功会自动阻塞，免得空转。工人自己把失败归成凭据撤销或模型没了时，退出码 78，第一次就粘住，因为重试治不好。

带 `--completion-contract OWNER/REPO` 的卡把 PR 验收放进完成边界。散文里的 URL 不算政策。`local-only` 表示故意只在本地。发布后把 `metadata.published_pr` 交给完成。第一个匹配的 URL 永久绑住这张卡，不能换成另一个已经变绿的兄弟 PR。

完成时读取分支保护和必需检查，翻页核对 head 上的 check，再读一次 PR 的 head 和 base。必需证据若缺失、进行中、失败、取消、超时、过期、跳过或中性，就不能完成。没有任何运行记录、读不到政策、GitHub API 失败，也不能完成。没有必需检查的仓库要用 local-only 合同。可选的失败遥测不否决已经接受的必需检查。

`gh` 用的是 assignee 那个 profile 自己的登录：它的 `.env` 里的 `GH_TOKEN` 和 `GH_CONFIG_DIR`。壳里或 systemd 里顺带导出的 `GH_TOKEN` 会从孩子环境里剥掉，不会再加回去。这个 profile 没有自己的 `gh` 登录时，拒绝为未登录，不退到 `~/.config/gh`。未指派的卡仍用周围环境的登录。看得到登录但看不到仓库，算认证失败，写明 profile 和仓库，而不是可重试的基础设施故障。这道门不向 GitHub 写。

拒绝时卡和工作区还在。验收事件记下 PR、SHA、必需上下文、检查 id 和恢复说明。人要动手时用 `kanban_block`。收据和终态写回在同一把 SQLite 锁里再核对运行、状态和合同所有权。已经被收回的工人不能替新的运行完成或附上验收。最后一次 GitHub 读取是完成时刻的快照，不是完成后的持续监视。

## 调度和隔离

调度器默认在网关里，大约每 60 秒：收回过期领取、把就绪任务推上去、原子领取、按 assignee 的 profile 拉起进程。也可以单独跑。工人环境里钉着 `HERMES_KANBAN_BOARD` 和 assignee 的 `HERMES_HOME`，启动 profile 的 `.env` 被剥掉。

板是硬边界。工人看不见别的板。租户是板内的软命名空间。通知从任务所属 profile 的适配器出去，不从复用网关的启动适配器出去。对不上时记一次警告，不静默跳过。

提示词里的看板说明和停手提醒只在 `owned_kanban_task()` 认为这是调度器拥有的工人时出现。仅仅看得到 `kanban_show`，或仅仅继承了 `HERMES_KANBAN_TASK`，不是所有权。委派孩子的标记带着被围起来的板根路径。只有调度器钉住的库路径或这块根下面的路径才拒绝孩子去改。孩子在临时家目录里仍可以写自己的板。

存活看 `(worker_pid, worker_started_at)`，不看裸 PID。PID 被系统复用之后，不能按号码去杀新进程。进程命令行里出现 `serve` 也不能用来判断这是不是看板工人。

`/goal` 不会把聊天目标写成卡。卡上的 `--goal` 只在这个工人自己的会话里打开 Hermes 的继续循环。
