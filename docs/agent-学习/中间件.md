# 中间件

观察钩子报告发生了什么。中间件在执行前改请求，或包住执行回调。工具参数的改写发生在护栏、批准、钩子和真正执行之前。包住执行时，重试、流式、中断和钩子仍由 Hermes 保持。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 观察 | 插件钩子。多数只观察 | `pre_tool_call` 可以挡住或修改。其余观察钩子失败打开 | 钩子事件总线：开始、进度、响应 |
| 改写 | 提供商可以换提示里的命名段落 | `llm_request`、`llm_execution`，以及工具侧的对等中间件 | 钩子可以要求再跑一轮 |
| 顺序 | 钩子有自己的时点 | 工具参数改写在批准之前，所以批准看见的是改写后的参数 | 停止钩子在模型想结束时 |
| 失败 | 未声明的失败按该钩子的合同 | 观察钩子失败打开。能挡住工具的返回值是例外 | 待定钩子有上限 |

## Hermes

中间件是会改变行为的那一类。观察钩子只报告。合同不绑定某一个推理后端。插件可以用它做本地政策、改请求、追踪、自适应路由、缓存控制、选沙箱，或把执行交给别的运行时，而不改计划器、模型适配器、工具注册、记忆或 CLI。

启用后可以：在调用提供商之前改写 LLM 请求参数；在护栏、批准、钩子和工具执行看见参数之前改写工具参数；包住真正的 LLM 回调，同时保留重试、流式、中断和钩子；包住真正的工具回调，同时保留护栏、批准、工具后钩子和结果变换。

注册在插件的 `register` 里，按名字挂上 `llm_request` 或 `llm_execution` 一类。工具侧同样有请求和执行两段。

因为工具参数在批准之前被改写，人批准的是改写之后的命令，不是模型最初写出的那一串。中间件若把一条危险命令改成另一条，批准卡必须显示改写后的内容。反过来，中间件不能绕过批准：批准仍会跑，只是看的是新参数。

观察钩子失败打开，免得遥测弄停回合。`pre_tool_call` 的挡住或修改，以及变换类钩子，是例外。中间件按定义会改变行为，它的失败不能悄悄当成「没挂上」。

辅助模型调用不走主循环的 API 请求钩子。中间件若只挂在主循环上，标题和压缩不会经过它。

## OpenClaw

插件钩子有自己的事件。提供商对系统提示的贡献是替换三个命名段落，或在缓存边界上下注入。那是提示组装，不是把工具参数改完再送去批准。执行批准和提权是会话政策。沙箱里的命令要到提权才离开沙箱，并且创建者角色要求沙箱的会话不能靠提权逃出去。

## Claude Code

钩子是独立于消息流的事件总线，有开始、进度和响应，待定数量有上限。停止钩子可以让模型再跑一轮。它不改写已经发给提供商的请求参数，也不在批准前替换工具参数。权限在 `canUseTool` 里决定允许、询问或拒绝。
