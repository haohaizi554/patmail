# 定时

定时工作是另一条会话，不是把「过两小时再看」写进当前回复里空转。三家都要求：到点的那一次要么跑了并留下记录，要么明确跳过并写下原因。漏掉的周期不靠静默丢掉。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 调度器在哪 | Gateway 内核一个 `GatewayScheduler` | 每个 profile 的 `jobs.json`，由网关里的 ticker 扫 | 编码会话上的 `ScheduleCronTool` |
| 一次触发 | cron 使用一份新会话 | 新建没有历史的 AIAgent | 挂在当前项目会话旁边 |
| 漏跑 | 睡眠醒来后，每个到点登记只派发一次 | 宽限内补跑一次；过了宽限合并成一次追赶，或按配置跳过并记日志 | 还原树里没有独立的发生账本 |
| 和记忆 | cron、心跳不产生可提升的长期记忆 | cron 默认不写记忆 | 子代理和 cron 不走主线程的记忆抽取 |
| 和空闲重置 | 系统事件不延长会话寿命 | 墙钟和空闲都不轮换消息会话 | 不适用 |

## OpenClaw

Gateway 只有一个调度器。维护和 cron 向它登记，一个宿主定时器负责下一次唤醒。持久工作的截止时间留在各自的 store 里，启动时由主人重建，不另存一份调度器状态。机器睡眠后，迟到的那一次唤醒把每个到点登记派发一次。周期任务等回调和它跟踪的工作结束，才开始下一间隔，漏掉的 tick 合并。墙钟补上睡眠，相对延迟在时钟回拨时仍按经过时间走。`beginClose()` 停止接收并取消还没开始的唤醒。`stop()` 等已经在跑的回调。请求超时、流内定时器和子进程清理由各自的操作主人持有。

会话路由上，cron 每次运行一份新会话，webhook 按钩子隔离。心跳、cron 和 exec 可以写会话元数据，但不延长每日重置或空闲重置所看的新鲜度。这些系统事件若排在旧会话上，会话一换就被丢掉，不会贴到新会话的第一条用户提示前面。

cron 的模型是任务自己的主模型，走配置的备用链，除非任务给了自己的 `fallbacks`。空列表表示这次运行严格。它不是用户在聊天里点过的模型覆盖。

压缩和记忆刷写若是可选的，要等回复送达之后才跑。一次性本地命令跳过回合后的可选工作。cron 会话在启动时不做全量会话库清理，避免每次触发都付这份成本。

提示词要求：将来再看、提醒和周期任务用 cron。不用 `exec` 里 sleep，也不反复 poll 后台进程。子 run 结束只说明那一次孩子结束。承诺了后续工作，就要在这一轮结束前把完成或看守路径安排好。

梦境是另一条定时整理，默认开启，写的是记忆文件，不是聊天回复。浅层不去碰 `MEMORY.md`。深层才在确定性门之后改策划层。它和当轮的 `memory_search` 分开。

## Hermes

模型面对的是一个 `cronjob` 工具，动作是创建、列出、更新、暂停、恢复、立刻跑、删除。时间有四种：`30m` 这种相对延迟、`every 2h`、五段 cron、ISO 时间戳。

任务存在该 profile 的 `cron/jobs.json`，先写临时文件再改名。`last_status` 是闭集，界面不能把 `ok` 理解成「人一定看到了」：

| 值 | 含义 |
|---|---|
| `ok` | 跑成了，而且若指定了投递，投递已确认 |
| `error` | agent 运行失败 |
| `delivery_failed` | 运行成功，输出没到目标 |
| `blocked_config` | 派出前的校验拒绝了，这次不消耗运行 |

状态是 `scheduled`、`paused`、`completed`、`running`。旧记录若只有单个 `skill`，加载时收成数组。

默认大约每 60 秒 tick 一次。先拿这个家目录的 tick 锁，再加载到期且仍是 `scheduled` 的任务。每个任务在派出前就把 `next_run_at` 推过这一档，避免崩溃后续上一次重启再打一次。同一次保存写上 `pending_slot`。真正可能产生副作用的领取，以及跑完的标记，会清掉这个戳。编辑、暂停、恢复、立刻跑也会丢掉它。

后来的扫描若发现戳还在、而主人已经不在（本进程里不在运行集，或别的进程超过 300 秒领取租约，或 pid 已死），就把那个时刻放回 `next_run_at`，只恢复一次。恢复后的时刻跟其它过期档一样处理，不会把漏掉的 N 档逐个重放。

执行账本里同一 `scheduled_instant` 已有 `completed` 行，就只把日程往前推，不再跑。`failed` 和 `unknown` 不算完成。一次运行不能用来证明一个当时还没到的时刻。还在未来的时刻不能被领取，所以面板上的立刻跑、webhook 和租约回收不消耗下一档。

宽限是周期的一半，夹在 120 秒和 2 小时之间。宽限内晚到就晚跑，并标成 late。过了宽限就把积压收成一次追赶。`cron.catch_up_missed: false` 时改为跳过并写明原因。一次性任务过了 120 秒宽限就退役，不复活。暂停期间到期的重复档在恢复时保留原来的 `next_run_at`，下一拍按晚到或追赶处理，不从「现在」重新起算。

运行中的领取有 300 秒租约，心跳每 60 秒刷新。心跳若读到主人变了，先再采样一次，确认丢了才取消这次运行。写回结果时再对存储：存储仍承认这次领取，就记下真实的成功或错误；已经被别人领走，就丢掉这份过期结果，不覆盖新主人。

一个网关进程 tick 它服务的每一个 profile 的库。`gateway.multiplex_profiles` 管的是适配器，不管 cron 扫不扫。进行中的状态按家目录加任务 id 做键，两个 profile 可以各有一个同名任务。某个 profile 自己跑着网关时，宿主这次 tick 让开，避免两个进程抢同一份库，也避免投递走到别人的适配器。ticker 在整个 tick 期间绑这个 profile 的 home、秘密和终端范围，包括开库和记失败。领取在 ticker 线程里注册，worker 结束时必须用当时的家目录释放，不能从环境变量再猜一次。

每次触发新建 AIAgent，不带对话历史。技能按顺序作为用户消息注入，然后跑任务提示，再投递。投递失败和运行失败分开记。记忆默认跳过。脚本若 `no_agent`，脚本就是整个任务，另有脚本超时。不活动看门狗默认 600 秒空闲，不是墙钟。忙着的长任务不会被这 600 秒切断。

后台委派活不过重启。要留下的工作写成 cron，或 `terminal(background=True, notify_on_complete=True)`。后者的完成通知要被网关承认才算接住，拒绝时退回同批占用。

## Claude Code

`ScheduleCronTool` 是工具目录里的一项，和 `Agent`、任务板并列，不是一台主机上的消息网关。它把「以后再跑」留在这次编码会话能看见的工具结果里，而不是另起一套渠道投递状态机。

还原树没有 Hermes 那种按 `scheduled_instant` 记账的发生表，也没有 OpenClaw 那种 Gateway 级的单一唤醒定时器。因此不能把这个工具的存在理解成已经具备漏跑追赶和跨重启领取。真正跨重启的定时，在这三家里，是 OpenClaw 的 Gateway 调度和 Hermes 的 `jobs.json`。
