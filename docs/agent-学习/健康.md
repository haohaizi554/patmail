# 健康

会话行不是套接字还活着。渠道可以已经重连、状态健康，而新的会话行还没写出来。健康快照问的是正在跑的 Gateway，不从 CLI 另拨一条渠道连接。顶层的会话摘要是默认 agent 的，不是全舰队合计。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 摘要 | `openclaw status`。`--deep` 向运行中的 Gateway 要带探测的健康 | 网关状态、`hermes doctor`、日志 | 客户端是否在响应 |
| 活连接 | `openclaw health` 只走 WebSocket | pid 加启动时间，或规范匹配器 | 无渠道套接字 |
| 会话列表 | 读的是存着的对话。不能代替渠道健康 | 会话库。FTS 坏了不影响「进程是否在」 | JSONL 是否能打开 |
| 合计 | 每个物理库在汇总里计一次。顶层摘要不是舰队总数 | 每个家目录自己的状态 | 本机项目 |

## OpenClaw

`openclaw status` 是本地摘要：Gateway 能不能到达、模式、更新提示、已链接渠道的认证年龄、会话和最近活动。`--all` 是完整的本地诊断，只读，适合贴出去排查。`--deep` 问正在跑的 Gateway 做一次带探测的健康检查，支持的话包含按账号的渠道检查。`--usage` 是提供商用量，不是连通性。

`openclaw health` 向正在跑的 Gateway 要健康快照，只走 WebSocket，CLI 不直接去拨渠道套接字。`--verbose` 强制一次活检查并打印连接细节。`--json` 给机器读的快照。

在任意渠道里单独发送 `/status`，得到状态回复，不因此叫起 agent。

日志跟随里看 `web-heartbeat`、`web-reconnect`、`web-auto-reply`、`web-inbound`。

Discord 和其它聊天提供商的会话行不是套接字活性。`openclaw sessions`、Gateway 的 `sessions.list` 和 agent 的 `sessions_list` 读的是存下来的对话。提供商可以重连并显示渠道健康，而任何新的会话行都还没出现。活的连通性用渠道状态和健康命令。

按 agent 的会话计数和最近活动只包括那个 agent 的会话，即使多个 agent 共享一个 SQLite 库。状态在汇总里每个物理库计一次。顶层健康会话摘要代表默认 agent，没有默认时代表第一个配置的 agent。它不是舰队合计。正在跑的 Gateway 用驻留的会话行投影提供干净的健康和状态摘要。库的水合和精确的脏行刷新仍保留只读 SQLite 后备。

在场花名册回答谁连着。健康回答 Gateway 和渠道是否可用。锁回答谁拥有状态目录。三份不要互相代替。

## Hermes

网关活性是 pid 和启动时间，不是「会话表里有行」。更新用 `gateway_state.json` 里的代码 SHA 核对舰队是不是还在跑旧代码。能证明过期的网关让更新失败。

doctor 修库之前要先停网关。健康的读和修复的写不要叠在同一个活文件上。

桌面的后端是按连接和 profile 池化的 `hermes serve`。它随应用退出。消息网关是另一个进程。一边的健康不代表另一边还在。

## Claude Code

没有渠道健康端点。客户端能开始一次查询，工具权限能解析，就是这次会话可用。转录文件在，不表示模型提供商可达。
