# 排版

出站 Markdown 先解析成一份中间表示，再按渠道渲染。切块时样式和链接跟着文字一起切开，不在一段样式的中间断开。偏移用 UTF-16 码元，好让 Signal 的范围和它的 API 对齐。表格只在渠道选择了表格模式时才解析。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 管道 | 解析成 IR，切块，再按渠道的标记表渲染 | 渠道适配器自己的格式。流即消息的渠道要求草稿是前缀 | 客户端按自己的 Markdown 画 |
| 切块 | 先按渠道转义和链接改写测量渲染后的大小，再接受那一片源 | 长度限制在适配器。前缀不能回退 | 无渠道切块 |
| HTML | 行内 HTML 保留原字节。HTML 块解析关闭，容器里的 Markdown 仍有效 | 代码块里的路径不被交付物扫描拆开 | 代码块是内容 |
| 表格 | 渠道选择加入才解析 | 按平台能力 | 本地渲染 |

## OpenClaw

中间表示是纯文本加上样式范围和链接范围。样式包括粗体、斜体、删除线、行内代码、代码块、剧透、引用和一到六级标题。一次解析喂所有渠道。

切块把样式和链接范围连同文字切开。按渲染大小切的那一档，先做渠道转义和链接改写再测量，返回被接受的源切片和它的渲染结果。渲染时用一张样式标记表，把范围换成该渠道的原生标记。

原始的行内 HTML 词法在解析时保留原来的字节。属性值里和已识别的行内注释里的 Markdown 标记和实体，不当成 Markdown 内容。没有序列化的作者标签范围，让懂 HTML 的渲染器解释那些标签，其它渲染器保持字面或转义。HTML 块解析保持关闭，这样容器里的 Markdown 仍然有效，正文里的裸 URL 仍按普通链接处理。

Matrix 用 HTML 标签，包括原生表格。自动回复、直接发送和媒体说明用同一套格式器。其它渠道各有自己的渲染器，但吃的是同一份 IR。

这和进度草稿不同。进度草稿编辑的是一条状态。排版管道处理的是最终要发出的 Markdown。两者都可能编辑同一条渠道消息，但切块不能把一段粗体切成两半。

## Hermes

流即消息的适配器要求每一帧都是下一帧的字符串前缀。渠道自己的 Markdown 或 mrkdwn 转换不能发生在草稿帧上，否则会整段重贴。终稿才可以变换。交付物扫描忽略代码块和行内代码里的路径，和「代码块里的标记不是文件」是同一类保护。

Slack 的原生流说的是标准 Markdown，不是 mrkdwn。停止流时的文本是追加。

## Claude Code

本地界面自己渲染 Markdown。没有一份 IR 再切给 Telegram 和 Signal。代码块里的内容留在转录里。
