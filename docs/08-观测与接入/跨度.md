# 跨度

已认证的 Gateway WebSocket 客户端可以在每个请求帧上带 W3C 的 `traceparent`。默认不导出原文、打开内容捕获仍排除系统提示和思考，写在 [追踪](追踪.md)。Gateway 造一个子请求上下文，保留上游的追踪 id 和采样旗标。这次请求里的 agent、运行时、模型调用、提供商、工具执行和 exec 跨度都留在那条追踪上，包括父运行已经结束之后才记下的跨度。追踪上下文按请求，不按连接。长连接上的每一次 RPC 各自带自己的 `traceparent`。并发请求即使工作交错，仍然隔离。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 接入 | 握手之后才接受。`connect` 帧上的 `traceparent` 忽略 | 监控平面要操作者配置接收端 | 无 |
| 畸形 | 128 个字符以内的缺失或语法错误，静默换成一条新的请求追踪。更长则这一帧无效 | 无这道字段 | 无 |
| 默认内容 | 不导出提示、回复、工具输入输出、技能路径或会话键 | 不导出提示、消息、工具参数和结果 | 转录在本机 |
| 伪造 | 调用者自带的出站 `traceparent` 被去掉或替换。解析不出真实跨度上下文时，省略头，不给一个未导出的父起名 | 无 | 无 |

## OpenClaw

这个字段不影响认证或方法授权。`tracestate` 和 `baggage` 不被 Gateway 的 WebSocket 协议接受。

跨度默认带有界标识：频道、提供商、模型、错误类别、只含哈希的请求 id、工具来源和主人、技能名和来源。看起来像带范围的 agent 会话键，例如以 `agent:` 开头的，在低基数属性上换成 `unknown`。OTLP 日志默认保留严重级别、记录器、代码位置、受信任的追踪上下文和消毒过的属性。原始日志正文只有在 `diagnostics.otel.captureContent` 为真时才导出。Talk 的指标只导出有界的事件元数据：模式、传输、提供商、事件类型。没有转录、音频载荷、会话 id、回合 id、通话 id、房间 id 或交接令牌。

追踪开着时，出站模型请求可以带一个 W3C `traceparent`，来自导出器真正拥有的模型调用跨度。诊断用的追踪 id 和跨度 id 只把事件关联到那个跨度。它们不用作出站的 OpenTelemetry 身份。导出器解析不出真实的跨度上下文时，OpenClaw 省略这个头，而不是给一个未导出的父起名。调用者原来带的 `traceparent` 被去掉或替换。插件或自定义提供商选项不能伪造跨服务的追踪祖先。

`captureContent` 只在收集器和保留政策已经批准提示、回复、工具和工具定义文本时打开。它启用有界的、打红的输入消息、输出消息、工具输入、工具输出、工具定义和 OTLP 日志正文。系统提示仍然排除。提供商内部的 `thinking` 和 `redacted_thinking` 也排除。兼容属性只留一个打红的结构标记。GenAI 消息属性省略这些部分。

完成的助手解说用同一开关。内容捕获关着时，解说事件只有时机、序号、运行时和文本长度。开着时，每条事件最多 16,384 个字符的可见解说，走已有的打红输出消息属性。解说文本从不进入普通诊断日志或公开的诊断事件。

工具输入和输出的内容捕获针对内建 agent 运行时的工具执行。OpenClaw 的属性名保持稳定。`gen_ai.tool.call.*` 是给语义约定查看器的副本。外部运行时的工具调用，例如 Codex 和 Claude CLI，发出 `tool.execution.*` 跨度，不带内容载荷。捕获的内容走一条受信任的、只给监听器的通道，从不放到公开的诊断事件总线上。

这和每日更新检查、匿名功能统计、轨迹导出不是同一条管道。那些默认也不带系统提示和思考。这里多的是请求级追踪祖先，以及出站头不能由插件伪造。

## Hermes

网关监控按构造不含提示和工具参数。有界队列、采样和导出失败可以丢数据。没有「每个请求帧一个 traceparent、连接帧上的忽略、解析不出就省略出站头」这一页。

## Claude Code

没有 Gateway 追踪帧。客户端的请求如果带追踪，是那一家 API 的头，不是这道握手之后才接受、并且系统提示仍排除的合同。
