# 指标

Prometheus 文本端点由诊断插件提供，路径是 `GET /api/diagnostics/prometheus`。它听受信任的诊断，以及内部标记的、调度器拥有的诊断事件：队列、记忆和会话恢复。抓取要 Gateway 认证，调用者的有效范围里要有 `operator.read`。写或管理员隐含这个读。不要把它当成公网上不认证的 `/metrics`。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 抓取 | 插件端点。操作者认证 | OTLP 推到操作者配置的接收端。没配就没有这平面 | 无 Gateway 指标 |
| 内容 | 诊断信号。跟踪和日志走 OpenTelemetry 那一页 | 不含提示、消息、工具参数和结果、会话历史 | 转录在本机 |
| 匿名统计 | 功能统计默认关，搭在每日更新检查上 | 监控不是每日匿名清单 | 无 |
| 轨迹 | 会话飞行记录另导出，含提示，要批准 | 轨迹是另一路 Relay | JSONL |

## OpenClaw

内容类型是 Prometheus 文本格式 `text/plain; version=0.0.4`。安装的是 `diagnostics-prometheus` 插件，不是核心里永远开着的抓取口。跟踪、日志、OTLP 推送和 GenAI 语义属性在 OpenTelemetry 导出那一条。指标端点是给 Prometheus、Grafana 或同类抓取器的，不必再跑一个 OpenTelemetry 收集器。

认证走和其它操作者 API 相同的路径。范围不够就抓不到。把它暴露成不认证的公网 `/metrics`，等于把队列、记忆和会话恢复的诊断交给任何人。

这和每日更新检查不同。更新检查默认开，带版本和平台。匿名功能统计默认关，不数单次调用和消息。这也和轨迹导出不同。轨迹含提示和工具时间线，群里私发给主人。指标端点不代替那份支持包。

## Hermes

网关监控经 OTLP/HTTP 送到配置的接收端，按构造不含对话内容。不配接收端，平面就不存在。没有一个默认的 Prometheus 文本路由要求 `operator.read`。本机审计日志是铁代理那份，权限收紧，不是抓取端点。

## Claude Code

没有给抓取器的诊断端点。用量在客户端和提供商。会话文件留在项目目录。
