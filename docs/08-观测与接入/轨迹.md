# 轨迹

Hermes 把对话轨迹写成与 ShareGPT 兼容的 JSONL，给训练、调试和强化学习用。这是库一级的开关。`hermes` CLI 不提供配置键或命令行旗标。`run_agent.py --save_trajectories` 或构造 agent 时把 `save_trajectories` 设为真，每一轮对话结束时才写。批处理运行器总是写，那是它的主要用途。全轮都没有推理的样本由批处理运行器丢掉，免得用不会推理的例子污染训练数据。

## 对照

| | Hermes | OpenClaw | Claude Code |
|---|---|---|---|
| 开关 | 库参数。CLI 没有这个旗标。批处理总是写 | 会话转录是运行时状态，不是训练 JSONL | 项目里的 JSONL 就是转录 |
| 文件 | 成功的进当前工作目录的 `trajectory_samples.jsonl`。失败或中断的进 `failed_trajectories.jsonl` | 转录在 Gateway 主机的会话存储 | 成功和失败在同一份转录里 |
| 角色 | 系统、human、gpt、tool | 会话消息保持渠道和工具对 | 助手、用户、工具 |
| 和监控 | 轨迹含对话。监控平面按构造不含内容 | 默认跨度不含提示 | 无 OTLP 平面 |

## Hermes

交互格式每一行是自包含的 JSON：对话数组、时间戳、模型、是否完成。批处理另有提示序号、元数据、是否部分、API 调用次数、用过的工具集、每个工具的成功失败计数和错误计数。工具统计字典按全部已知工具归一，缺的补零，好让条目之间的模式一致，加载数据集时列对齐。

对话数组用 ShareGPT 的 `from`：系统是 system，用户是 human，助手是 gpt，工具是 tool。文件写在当前工作目录，不写在 Hermes 家目录。批处理可以给每一批指定自己的输出文件。

这和网关监控分开。监控导出的是不含提示和工具结果的生命周期。轨迹在打开之后，保存的是这一轮的对话本身。它也和共享指标分开。共享指标默认关，送的是允许名单上的整包。

## OpenClaw

会话转录留在 Gateway 上，给恢复、压缩和搜索用。没有「CLI 不暴露、成功和失败分成两个工作目录 JSONL、批处理丢掉零推理样本」这一页训练轨迹。

## Claude Code

转录是项目目录里的 JSONL，子代理可以侧写。它是会话状态，不是一份默认关掉、用库开关才写进当前工作目录的 ShareGPT 训练集。
