# 用量

用量以提供商报告的额度为准，不用估算的账单冒充配额。会话花费可以从本地转录补。订阅计划不显示按 token 的美元估计。零美元是有效花费，不是缺失。

## 对照

| | OpenClaw | Hermes | Claude Code |
|---|---|---|---|
| 配额 | 各提供商的用量端点。窗口归一成还剩百分之多少 | 凭据池和备用看的是错误码，不是这张用量卡 | 客户端显示订阅或 API 用量 |
| 会话 | `/status` 在活快照缺 token 时回退转录。非零的活值优先 | 会话库记用量。压缩有用量锚 | 转录里的用量随消息 |
| 费用 | `/usage cost` 从会话日志汇总。今天和 30 天在缓存刷新时可能不完整 | 费用跟实际调用的提供商。混合代理记在聚合器 | API 会话才有逐 token 费用 |
| 归因 | 整段会话记在创建者。不把单轮记到参与者或 API 账号 | profile 隔离。不猜历史归属 | 本机项目 |

## OpenClaw

拉取的是提供商用量端点上的计划名、配额窗口、余额、花费、预算、每日费用、token 和模型归因，或账号状态摘要。没有估算的提供商账单。人类可读的配额窗口一律写成还剩百分之多少，无论对方报的是已用、剩余还是原始计数。没有可重置窗口的，显示余额一类的摘要文字。

`/status` 和 `session_status` 在活会话快照缺 token 或模型时，回退到转录日志。回退补上缺失的 token 和缓存计数，可以恢复运行时模型标签，并在元数据缺失或更小的时候采用更大的、面向提示的合计。非零的活值始终赢过回退。

聊天里的 `/status` 有会话 token。API 钥匙模型才有估计费用。提供商用量只对当前模型的提供商显示。`/usage` 可以关、只显示 token、或完整页脚。`/usage cost` 是本地汇总。CLI 的 `openclaw status --usage` 按提供商拆开。`models status` 在有窗口的提供商旁边列出认证 profile 和窗口摘要。

控制界面的用量页把提供商计划和账单卡放在会话推导的 token 和估计费用之上。Anthropic 和 OpenAI 的管理 API 凭据加上今天、7 天、30 天花费、每日趋势、token 合计、头部模型和费用类别。作曲家的上下文环对订阅提供商显示计划用量：5 小时、每周、按模型的窗口和重置时间。经计划计费的会话隐藏逐 token 美元。API 计费的会话保留估计费用。Claude Code CLI 的安装复用同一份 Anthropic 订阅用量。

`/usage cost` 在今天和近 30 天的合计缓存正在刷新、不完整或过期时发出警告，并建议稍后再跑。会话合计单独加载。控制界面在 5、10、20 秒后再查不完整的合计。冷缓存还没有任何用量时显示加载，不显示零。部分合计保持可见。自动检查结束仍不完整时，要手动刷新。

后台刷新不因为会话库没变就作废已经选中的报告。多个 agent 共享一个库时，报告保留 agent 归因。

默认范围是最近 30 个日历日。历史世系包括会话更早的保留实例。日期范围仍决定图上出现哪些活动。合计和日图来自同一份报告，包括列表没显示出来的会话。

记录在案的零美元是有效费用。只有报告里存在没有标价的用量时，才警告缺价格。筛到已知零费用的会话会清掉这个警告。

「谁启动的」按记录的会话创建者分组。人、agent 和系统创建的会话彼此分开。没有创建者的历史会话标成未归因。这把整段会话归给创建者，不把单轮归给参与者，也不把费用归到提供商 API 账号。不用当前账号设置去猜历史归属。

图表上选中的日子收窄创建者合计。一条会话在多天活跃只计一次。Gateway 的 `usage.cost` 和 `sessions.usage` 默认按 UTC 解释日期。指定模式可以用 IANA 时区，让本地日历日和夏令时生效。

## Hermes

会话和压缩记录自己的用量，用来决定何时压缩，而不是拿去冒充提供商配额窗口。凭据池看到 429 或用量封顶就轮换。备用链看到限流和重置时间就停板。这些是错误分类，不是用量端点的「还剩百分之多少」。

混合代理的费用记在聚合器的提供商上。参考模型只在每轮用户消息时扇出一次，不承担工具循环。界面在聚合器提供商和当前模型提供商不同时标明这一点。

多 profile 的用量留在各自的家目录。不把一个 profile 的会话花费算到另一个头上。

## Claude Code

用量跟客户端的登录和这一次查询。订阅和 API 的展示不同。转录里的计数随消息保存。没有 Gateway 那种跨会话、按创建者汇总、冷缓存不显示零的用量页合同。换模型或压缩会改变后续请求的 token，不改已经写进转录的历史计数。
